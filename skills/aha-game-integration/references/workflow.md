# 标准接入流程

## 1. 工程盘点与接入结论

输入：工程目录、运行入口、构建命令、用户提供的 API 文档/渠道模板。输出：引擎与目录结构、可修改源码范围、现有平台 SDK、开局/结算/暂停/音频/存档位置、原生直连或 SDK 壳的选择理由。

先查看 ZIP 清单，过滤 `__MACOSX` 等元文件；定点读取文档和入口，保留原文与哈希。不要运行附件里的安装、发布或网络脚本来“查看内容”。

## 2. 填配置清单

| 项 | 必需场景 | 填写要求 |
| --- | --- | --- |
| AHA 目标版本与容器类型 | 所有原生调用 | 版本名称、Android/WebView、在线 H5 或 Offline Game |
| `appKey` | 原生广告 | 渠道分配的字符串 |
| `eventId` | 代理埋点 | 渠道分配的数字 appId；不要填写自造事件编号 |
| 页面时长事件 ID | 时长统计 | 核对是否与代理埋点 eventId 相同；适配器当前用同一配置，若不同则单独实例或明确拆字段 |
| SDK game ID | iframe SDK 方式 | 渠道分配，不能复制 5027206 / 5023178 |
| SDK 版本与初始化参数 | iframe SDK 方式 | 附件只有样例，补齐渠道支持的初始化、失败和就绪契约 |
| GA / AdSense client、slot、channel | 使用对应 Web 统计/广告时 | 使用游戏所属配置；不需要时不加载 |
| 事件名称、字段与广告场景名 | 埋点/广告 | 产品和渠道对应表，标出项目自定义名称 |
| 广告频次、奖励规则、布局 | 商业化点位 | 局间时机、冷却、Banner 占位、奖励持久化；不把示例 45s 当平台硬规定 |

配置不全仍可完成适配、测试和报告；默认关闭真实调用。不要通过 URL 查询参数让生产用户任意开启模拟奖励或覆盖广告账户。

## 3. 设计业务事件和广告位

建议的项目自定义事件表（**不是 AHA 官方命名**）：

| 事件 | 触发点 | 字段 | 去重 |
| --- | --- | --- | --- |
| `game_ready` | 首屏资源和操作可用 | game_slug、build_version | 当前页面一次 |
| `match_start` | 新建对局成功 | match_id、mode、player_count、play_type | 每个 match_id 一次 |
| `match_resume` | 用户继续旧局 | match_id | 每次明确恢复操作，不能当新局 |
| `match_end` | 胜负状态首次提交 | match_id、mode、winner_kind、rolls、moves、captures | 与对局存档一起持久化 |
| `ad_request` | 单次广告请求 | request_id、placement、ad_type | 每请求一次 |
| `ad_result` | 广告请求终止 | request_id、placement、status、rewarded | 每请求一次 |
| `reward_granted` | 奖励记账成功 | request_id、reward_type、amount | 以奖励账本防重复 |

不要默认附带昵称、设备 ID、GAID 或完整存档。只传这个事件需要的业务字段。同步 Bridge 返回不证明数据到账；`match_end` 本地至多一次发送与服务器恰好一次不是同一保证。

插屏点位优先局间、结算后重开；不依赖广告成功才能开下一局。激励广告必须有主动按钮和明确收益；没有收益机制时先留接口，奖励策划单独明确。多人对战优先外观/局外奖励，不能为接广告改骰子概率或偷偷增加一方优势。

## 4. 适配与生命周期

复用 `assets/aha`，保持平台协议、广告请求状态、游戏业务分离。普通网页缺少 Bridge 正常游玩。无填充、屏蔽、失败、超时恢复主流程；激励只在完成证据成立后由业务发奖。

暂停原因建议：`ad`、`visibility`、`activity`、`game`、`modal`。第一次暂停时冻结循环/AI/输入、保存进度、停止音频；最后一个原因清除后再恢复。不要通过改用户“音效开启”设置实现临时静音。音频应 suspend 或静音总增益，并考虑已排程音符是否会在恢复时继续。

异步返回时校验对局 generation / match_id 和奖励 request_id，页面退出、换局或广告管理器销毁后的旧结果不能作用于新局。适配器防止同实例重复回调；跨实例、跨刷新奖励去重仍由业务账本负责。

## 5. 两条交付路径

**原生直连：** 游戏入口直接加载平台模块；Bridge 实际就绪后注册监听，首屏可玩后通知加载完成。既有本地存档保持可用；需要宿主存档时另设 schema 迁移和读写冲突规则。

**渠道壳：** 先正常构建游戏，再放入 `game/`，外层入口加载同源 iframe 并初始化 SDK。使用相对资源 URL，避免部署到子路径后资源指向域名根目录。广告所有者在父页，父页可复用 `createAdManager({transport:'sdk'})`；埋点也集中在一个明确位置。

推荐消息结构由接入双方定义，例如 `{channel:'aha-game',version:1,id,type,payload}`。父页只接受指定 iframe 的 `contentWindow` 和预期 origin；子页只接受 parent 和预期 origin。允许列表限定为 ready、指定事件、插屏、指定激励位等，不转发任意协议路径。父页保存该请求 id，结果原样关联；子页超时后标记终止，迟到结果忽略。此消息结构是项目约定，**不是上传模板或 AHA 的既有协议**。本技能未交付通用 iframe 转发实现，应按项目 origin 和渠道壳约束实现并测试。

## 6. 本地与真机验收

| 场景 | 通过要求 |
| --- | --- |
| 普通浏览器 / SDK 加载失败 / Bridge 晚到 | 核心游戏可玩；监听能在明确就绪时补注册；不误发奖 |
| 插屏成功、无填充、受限、超时 | 都能进入下一局；无并发广告；冷却有效 |
| 激励完成、提前关闭、缺 token、抛错 | 仅明确完成奖励一次，其余不给奖励并恢复 |
| 回调重复、迟到、乱序、缺结束 | 不重复结算，不影响新请求，不永久卡住 |
| 切后台 + 广告 + 用户暂停 | 广告结束不解除其他原因；音频/AI/输入符合暂停状态 |
| Banner 失败/关闭/横竖屏 | 无空白条、棋盘和按钮不被遮挡，安全区正确 |
| 开局、恢复、胜负、重开 | 不把重绘/恢复当新局；结算不因重新显示弹窗而重报 |
| 真实 AHA 容器 | 记录客户端版本、包版本、设备、网络、场景、广告结果和埋点到账截图/日志 |

本地执行 `node --test <skill目录>/tests/*.test.mjs`，再执行目标工程现有测试和构建、浏览器核心循环。模拟测试不能替代 AHA 真机、广告库存或统计后台验收。

## 7. 交付记录

交付接入结论、修改文件、配置表、事件表、点位图/说明、测试证据、上线开关与回退方法。用“适配层通过本地模拟”“游戏已接入但未开真实调用”“目标 AHA 真机通过”等准确状态。保留原始包、单独生成渠道包；是否部署按本次用户要求执行。
