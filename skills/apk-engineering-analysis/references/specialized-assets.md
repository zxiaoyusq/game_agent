# 仅在出现相应证据时处理的专项

## Unity 类型树、对象头与引用

UnityPy 通过匹配 DummyDll 生成 MonoBehaviour 字段树时，部分版本的对象固定头可能出现偏移解释错误。导出脚本另用 `parse_monobehaviour_head()` 获取 `m_Script`、`m_GameObject`、`m_Name` 和 `m_Enabled`，覆盖动态树中的对应值，并记录 `header_corrections.json`。

这项修复只校正固定头，不保证业务负载字段完全正确。抽样对照字段类型、原始字节、引用目标类型和实际数量。不要把异常的大 FileID 静默归零；PathID 为 0 才可按空引用处理，其他无法解析的引用列入未解决记录。

Addressables 资源可以在多个子目录，后缀未必是 `.bundle`；应递归按 Unity 容器头识别。主程序与 Bundle 的编辑器版本不同不必然是坏包。序列化文件重名且无法明确区分时中止自动合并，按容器作用域分别分析，避免错误绑定同号 PathID。

## Spine 与组合资产

Spine JSON/二进制骨骼、atlas 文本和纹理需要作为同一组恢复。优先跟随 `SkeletonDataAsset → AtlasAsset → Material → Texture` 的真实引用，不仅凭文件名配对。

1. 识别骨骼版本、动画名、皮肤、插槽及 atlas 页名。
2. 按引用找到完整纹理，验证 atlas 尺寸、页名、区域和旋转信息。
3. 保存原文件，在 `recovered/<组合名称>/` 生成供预览工具使用的副本；如修改 atlas 页名，记录原值与新值及原因。
4. 标明 PMA/直通 Alpha、运行库版本和预览兼容性。不能通过改图片把不兼容数据伪装成成功恢复。
5. 缺一部分时记录缺失依赖；尝试名称/尺寸推断配对必须标为推断，保留失败样本。

默认资源浏览器展示独立图片和音频，不自动播放 Spine 或 3D 动画。需要动态预览时按用户需求增加对应查看器并验证。

## 文本、字体与音频

TextAsset 原始字节先保留；BOM 或字节分布提示 UTF-16 时另导出 UTF-8 副本，记录原编码，不覆盖原始文件。无法确定结构的压缩/二进制配置保留字节和格式线索，不能强行当 JSON。

Font 没有内嵌字节可能是动态字体、系统字体或字形图集，保留字形和材质配置，不把空字体导出计作成功。音频保持实际解码格式和采样信息；没有独立样本时保留失败/无数据记录。

## 关卡与规则验证

先确认关卡结构、索引基准、容器顺序、球/方块顺序、颜色编号、容量、初始空位和特殊障碍，再讨论难度或解法。只检查 JSON 可解析不能证明关卡有效。

以彩球分类为例，可在字段语义明确后独立实现规则模拟器，校验颜色数量、容量约束、非法移动、完成条件、存储解法的每一步及最终状态。顶部可能在数组首或尾，一次移动可能是一颗或同色连组；必须由代码/配置证据确定，不按游戏类型猜测。存储解法通过只说明该初始局面有一条可行解，不能说明任意玩家偏离后提示仍正确。

其他玩法采用各自约束，不能套用彩球规则。随机抽样、全量结构校验和全量解法回放必须分别报告样本量与覆盖范围。测试失败先调查序列方向、版本与数据语义，不随意改关卡让测试通过。
