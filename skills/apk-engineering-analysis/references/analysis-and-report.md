# 分析内容与报告数据格式

## 从文件索引进入核心行为

1. **身份与覆盖范围**：包名、版本、渠道、哈希、证书、全部 split、ABI、引擎与工具版本。列清实际分析哪些 DEX、原生库、资产、外部配置。
2. **工程架构**：启动入口 → 引擎入口 → 业务初始化 → 场景/界面 → 主循环。区分引擎、第三方 SDK、业务模块。用可核实的类、文件和调用支撑架构图，不虚构原始目录或开发团队设计意图。
3. **核心代码**：选择至少两至三条与产品直接相关的关键调用链，描述输入、状态、判断、输出、调用方和数据依赖。记录签名、RVA/地址、字段偏移、指令文件。声明仅能说明接口存在；具体算法必须有指令、IL、脚本或运行证据。
4. **核心功能模块**：输入与移动规则、胜负判断、关卡加载/生成、难度、提示/撤销/重开、奖励、存档、UI 状态、动画/音频反馈。仅分析实际存在的模块。写出模块之间的契约、状态转换与依赖。
5. **美术与配置**：按背景、主体、容器、按钮、图标、特效、字体、音频、主题等实际类别建立目录。记录格式、分辨率、图集、切图矩形/pivot/PPU、材质/Shader、字体回退/字形、动画数据及挂载位置。说明哪些是 SDK 广告素材，哪些有业务场景引用。
6. **配置引用**：配置字段 → GameObject/组件 → Sprite/Texture/Material/Audio，给出具体配置样本和可追踪的来源文件及 PathID。统计已解析、空引用和未解决引用，解释失败原因。
7. **商业化和基础能力**：广告、内购、埋点、远程配置、登录及本地保存，区分“集成 SDK”“存在调用路径”“实测触发”三个层次。
8. **重建建议**：把可借鉴的规则、架构和反馈转化为独立实现方案；估计 AI 实现与原创美术的难点，明确哪些原始实现未验证。研究提取包与新项目资源分开保存；避免在报告正文暴露发现的凭证或玩家数据。
9. **限制与验证**：解码失败、缺失分包、动态内容、混淆、方法共享、反编译错误、未运行验证的功能。列实际验证结果，不生成泛泛的“全部通过”。

多产品比较采用相同维度，但不因缺失证据补造数字。需要流程图可在报告中追加 SVG 或使用目标阅读器支持的图形格式；脚本渲染器只支持段落、表格和代码块，不会自动渲染 Mermaid。

## findings.json 格式

脚本只将 Agent 已阅读证据后写出的结构化结论渲染为报告。以下是格式示例，内容必须替换成本次真实分析，不能原样当最终结论：

```json
{
  "title": "产品名称与版本：APK 工程拆解报告",
  "scope": "输入、渠道、分析范围和运行验证情况。",
  "sections": [
    {
      "title": "工程入口与模块关系",
      "basis": "包内证据",
      "paragraphs": ["结论及其支撑理由；写出具体类、字段、地址或对象编号。"],
      "tables": [{"headers": ["模块", "证据", "职责"], "rows": [["实际模块", "实际证据位置", "经验证的职责"]]}],
      "code": [{"label": "独立重建伪代码，不是原始源码", "text": "在此放入基于证据概括的逻辑"}],
      "evidence": [{"path": "package_summary.json", "label": "输入与引擎证据"}]
    }
  ],
  "limitations": ["具体说明哪些方法、资源或运行行为尚未验证。"]
}
```

`basis` 仅接受：`包内证据`、`指令验证`、`结构推断`、`重建建议`、`待验证`。不同性质结论尽量分章节。`evidence.path` 必须是工作区内真实文件的相对路径，不能填外部网页、虚构文件或目录穿越路径；网络来源以段落写明完整 URL，或另存研究资料后引用。渲染器校验证据文件存在，不自动核验结论是否正确。

## 计数与验收

- 区分 APK 文件数、Unity 对象数、成功导出对象数、导出文件数、失败对象数、媒体文件数及去重后的视觉素材数。一次 Sprite 导出可以产生 PNG 和配置 JSON，二者不是两个对象。
- `unity_objects.json` 是当前导出的规范清单，`exports/` 目录可能保留重跑遗留文件，打包不能简单统计目录数量。
- 检查类型分布与失败清单，不要求所有失败归零，但必须解释无法解码部分。保留字节不算成功解码。
- 使用 `validate_delivery.py` 检查报告/浏览器本地链接、清单中的导出文件及缩略图。`--archives` 额外验证 ZIP CRC、文件数、大小、SHA-256；`--verify-raw` 逐项重新计算解包文件哈希。
- 浏览器验证：报告标题和正文、资源搜索、类型过滤、继续加载、可见缩略图、音频控件、下载链接、控制台错误。静态存在性校验不能代替浏览器交互测试。
- 交付归档需要保留相对目录；`resources.zip` 是资源分析包，不是整个网页的离线镜像。若另打包浏览器，包含其依赖并重新检查所有链接。
