# Cocos 游戏生产与验收

沿用项目中的四阶段：原型定义、美术资源、代码与集成、测试验收。当前任务状态、产物和测试结果以工作流后端及磁盘为准，不能用一段总结文字代替执行。

## 接受任务

先核对项目技术方案确实采用 Cocos。读取项目简报、当前阶段、已确认上游产物、用户本轮要求及选中的技能；通过 `read_game_knowledge` 读取本轮所选品类和技术资料。排序、方块、三消、合成、放置与物理游戏的规则和验收方法分别确定，不能把本案例的试管、球数、解法或撤销作为所有游戏要求。引用包先看入口和目录，再按当前问题读取文件，不一次性把全部资源或日志放入上下文。

用户要求最新 Cocos 时，从官方正式 release 核实版本并固定源码提交或编辑器版本。开发分支的版本字段不能证明正式发布。记录实际构建所用的版本；手工实现 `cc` 接口、仅引用类型声明或改写版本文案都不能证明使用了 Cocos。

源码身份应由实际 Git 提交或已核验的官方归档 SHA-256 证明，并记录生成的引擎文件哈希及运行时版本。提供从清洁目录下载、校验、构建的命令；写死在报告中的版本字段不能替代验证。

## 四阶段产物

| 阶段 | 必须落地的内容 | 进入下一阶段的依据 |
| --- | --- | --- |
| 原型定义 | 游戏定位、参考证据与融合取舍、核心规则、输入和状态转移、内容范围、可检查的验收条件 | 规则无歧义，选定关卡或机制可验证，上游已确认 |
| 美术资源 | 可打开的资源、尺寸和透明度规范、来源/加工/使用位置清单；音效也纳入清单 | 实际文件可读取，使用映射完整，关键画面已检查 |
| 代码与集成 | 真实 Cocos 工程、可重复构建命令、可玩构建、关卡/存档/输入/界面实现 | 构建成功并运行，核心循环可完成，产物可反查源码 |
| 测试验收 | 规则测试、内容校验、浏览器或目标设备实测、截图、失败与修复记录 | 与本轮源码和资源对应的测试通过；未覆盖范围显式列出 |

首次制作可先在原型阶段验证规则；完整画面和体验仍须在后续阶段实现。模型调用成功不等于阶段通过。重跑上游后，重新核对下游依赖，不能沿用过期确认。

## 实现与调试

- 玩法状态用简单、可独立验证的数据结构；Cocos 节点表现从状态更新，避免动画完成回调成为唯一事实来源。
- 同一次输入只提交一次状态变化。移动动画、结算、切关和恢复存档都须处理过期回调及重复输入。
- 按品类建立独立规则验证：离散网格检查坐标与计数，合成检查输入和产物事务，放置检查经济与时间，物理检查时间步和误差；仅对有确定解法要求的谜题做可解性校验。
- 存档校验版本、类型以及本品类状态不变量；未知版本不能直接按当前版本解释。奖励、收益和结算按原型约定保持幂等。有撤销或异步辅助功能时，分别验证合法历史链及过期结果隔离，具体实现取决于玩法。
- 写入失败须独立维护当前未保存状态，普通操作成功提示不得覆盖；局面仍可继续，只有后续真实写入成功才清除。回归在正常启动后于隔离浏览器上下文模拟写入异常，覆盖本项目实际输入、设置、重绘及恢复成功，不能仅检查启动故障。
- 延迟结算绑定当前会话和视图生命周期；导航、弹层变化或重绘时取消或拒绝过期回调。主题重绘只更新表现，不重新触发奖励或安排结算，同时保留初次胜利和正常恢复完成局的行为。对有关卡结算的游戏，通过实际玩法和真实指针进入完成状态，覆盖完成后的重绘、设置、恢复、继续游戏及快速导航；不能注入假胜利或靠延长等待掩盖缺陷。
- 重绘时移除子节点不等于销毁节点；明确销毁旧子树或安全复用。内存回归应通过真实重复点击、等待销毁帧及强制GC，比较堆、引擎节点与孤立节点数量；CDP查询结束释放调试对象组，避免观察工具持有对象。
- 按原型约定处理会覆盖玩家有效进度的操作，取消时完整保留状态；不要给无需确认的即时玩法添加阻塞弹窗。若玩法含隐藏信息，颜色、数字、符号和辅助提示应遵循同一可见性规则。
- 触控目标按实际画布到CSS像素的比例设置命中范围，并随视口重算；用真实浏览器测量和边缘点击验证，检查相邻控件是否重叠，不能用逻辑设计尺寸替代实测。扩展命中区时同时校验所有同层目标间距及边缘动作，弹窗内主题、开关、导航与关闭按钮均应覆盖；断言实际目标动作且其它状态不串改，不能只检查最小尺寸。
- 构建依赖、引擎运行时和实际使用资源应包含在可复现交付中；本机缓存只能加速，不能作为未记录的隐藏前提。
- 验证记录绑定实际源码与资源指纹；验证后修改实现必须重新执行相关检查。并行协作时区分本轮工具写入、验证输出、引用资源和工作区观察快照，不能将全部目录变化都声称为本轮模型生成。
- 同一文件的多次编辑必须串行或一次整体替换，不能并发执行互相依赖的读改写。已有文件先读取再编辑；`write_file` 若只支持新建，不可用它覆盖已有报告。发生文本不匹配或编码错误时回读当前内容后修正，最终回读核对关键段落，不能仅凭单次成功消息判断整份文档完整。

## 根据问题迭代技能

只把实际暴露的问题和验证过的修复写回相应技能：记录触发条件、根因、修正方法、测试命令及证据路径。通用经验放在主技能或专题参考，特定游戏的路径和数值留在案例参考。更新前读取现有内容，保留其他任务需要的能力，避免把单个项目参数写成全局规则。

本版将已验证的引擎与生命周期经验保留在主技能，把排序专用规则和项目数值移到案例参考。1.4.x 的问题、修复与证据均保留在案例中；其它品类的指南尚不代表已有完整成品验收。
