## Skill 独立场景阅读

以下检查是在不参与该 Skill 编写的前提下，用具体任务情景推演指令是否足以指导下一步，不冒充模型行为基准测试。

### 三款配置转换

情景：导入 Guru/HM 的管口到管底数组与批量同色步骤，再导入没有自带解法的 Infinite Joy 隐藏球配置。

按 1.1.0 指令，应先识别空位与容量语义，过滤空位并反转方向，使用少量带解法记录验证移动语义，再批量转换；Infinite Joy 必须由当前规则独立求解。不能以导入成功或来源字段名 normalized 代替可解性证明。主技能与案例参考的职责边界清楚，此场景没有发现需要再次改写的主要歧义。

### 当前局面提示

情景：玩家偏离包内解法，随后撤销、加管或切关，求解器稍后返回结果。

现有指令明确要求提示基于当前棋盘，已能阻止直接播放过期初始解法。建议补充一条必要边界：求解请求及结果绑定棋盘版本或状态哈希，返回时再次核对；搜索预算耗尽只能表示本次未找到提示，不能宣称关卡无解。该补充可避免延迟结果在状态改变后被错误应用。

### 实际 Cocos 引擎构建

情景：构建脚本使用本机引擎缓存，`package.json` 的版本正确，报告中写入一个固定源码提交号。

现有指令要求正式发布、固定版本、实际构建与无隐藏缓存前提，方向正确。建议明确区分“写入提交号”与“验证实际源码”：核对实际源码提交或官方归档哈希，记录最终运行时文件哈希，并提供空目录可重建的命令。仅检验 package 版本与写死的证据字段不能证明本轮实际使用的来源。

这两条建议应在主任务获得相应实际证据后沉淀，避免把未经验证的做法写成已经完成的 Skill 经验。
