# 休闲游戏流程复用与知识组织

2026-10-18。本次优化的目标是让同一条四阶段流程消费不同品类和技术资料；新增指南不代表每个品类已经有完整成品验收。

## 组织方式

| 层 | 内容 | 当前入口 |
| --- | --- | --- |
| 四阶段工作流 | 原型定义、美术资源、代码与集成、测试验收；状态、恢复、交接和证据门禁统一 | `backend/app/services/workflow/engine.py` |
| 游戏品类知识 | 核心状态、规则不变量、内容或数值决策、品类专属验收 | 知识库「游戏品类」；种子在 `resources/game-production/genre/` |
| 技术框架知识 | 实现约定、资源接入、构建和运行、验证接口及已验证程度 | 知识库「技术框架」；种子在 `resources/game-production/framework/` |
| Skill | 如何使用选定知识完成阶段工作、执行验证、记录归属及沉淀经验 | `casual-game-production` 通用流程；`cocos-game-production` 引擎专项 |
| 项目及案例 | 当前项目简报、明确引用、规则选择、实现和实际验收证据 | 各自 `games/` 工作区，不共享输出目录 |

不为每一种玩法另造四阶段 Agent 或引擎框架。同一 Cocos 技术方案可以承载排序、消除、放置等品类；同一品类可以选择不同技术方案。现有文件知识库支持目录、上传、编辑元数据、阅读和下载，本轮没有引入向量数据库或新的检索服务。

## 当前可选范围

- 品类：通用／自定义、分类整理、方块摆放、三消、合成、放置／轻经营、物理／时机，共 7 份指南。无专用资料的玩法可用通用方案，并在原型中明确规则；混合玩法可在新建时补选相关资料。
- 技术：Cocos Web 和 Canvas 2D Web。共有 Web 共同约定、两种技术指南和选型说明，共 4 份资料。两者的执行接口均为 `npm run build`、`npm test`、`npm run check`，输出 `dist/index.html`。
- Cocos Web 有已经验收的 Ball Sort 成品；Canvas 的执行协议已适配，完整成品仍待独立验证。Unity、Godot、Creator 原生及小游戏目前只作为选型方向，不在可执行框架下拉列表中。
- 不能给所有品类套用“关卡可解、倒球、撤销、提示”。例如方块无尽模式可以自然失败；三消需验证连锁状态；合成需验证输入与产物事务；放置需验证收益与时间；物理需验证时间步和误差。

## 已落实的行为

新建项目先选择品类与技术方案，展示自动加入的基础知识，允许勾选补充资料及查看原文。普通项目不携带 Ball Sort 默认参考；彩球简报保留为显式示例，且工作目录留空，由后端分配新目录，避免覆盖既有成品。

服务端 `GET /api/workflow/catalog` 是选项的唯一来源。`POST /api/workflow/projects` 接受 `genre_id`、`framework_id` 和补充的 `knowledge_paths`；注册契约来自服务端，不能通过前端上传任意执行命令。创建时保存方案快照；每次开始运行时再冻结所选知识的正文与 SHA-256，恢复继续读取原快照。用户在知识库更新资料只影响此后新启动的运行。

模型通过 `read_game_knowledge` 按需读取所选正文，事件记录路径、哈希与读取区间。选中资料和实际读取分开展示；读取门禁覆盖全部所选正文，支持分页，未读取完不能完成阶段。知识库当前原文和某次运行的冻结版本有明确区分。

新框架配置统一驱动系统提示、恢复要求、结束及确认时的验证门禁和预览入口。新项目必须有当前 attempt、最终源码对应的 build/test/check 成功证据；旧项目和旧运行保持原契约，不补写推断的方案、不重置已确认状态。

美术交接支持图像、音频、字体、模型和动画。程序化视觉使用 `mode: procedural`，交接非空的设计或生成文件及哈希、用途、来源；代码阶段仍须真实集成，测试阶段验证呈现。设计文档不是完成画面的证据，空清单也不能通过。

通用 Skill 版本为 1.0.0。Cocos Skill 更新至 1.5.0，将排序配置、求解和特定历史链细节移到案例参考，保留引擎身份、生命周期、输入和验证等通用经验。修订通过明确发布记录关联本次验证运行，归属编排 Agent，未冒称为阶段模型生成。

## 后续如何扩充

品类经验进入对应知识库，具体数值和失败案例保留来源及适用范围。新的可选品类在服务端目录登记稳定 ID、对应文档和阶段指引；无需增加状态机。种子导入仅补缺，保留已有正文、元数据和删除记录；不会在启动时覆盖用户资料。

新技术栈先准备构建环境、可重复命令、预览或设备验收入口，拿到真实运行证据，再登记执行适配。当前执行器只支持约定的 Node/Web 命令；不能仅添加 Unity/Godot 文档或改名便宣称已支持原生构建。

DeepAgents 保持项目安装的 0.5.9，不为此改成复杂插件体系。实现参考官方的[定制入口](https://docs.langchain.com/oss/python/deepagents/customization)和[按需知识加载模式](https://docs.langchain.com/oss/python/langchain/multi-agent/skills#extending-the-pattern)，沿用普通工具、系统上下文和检查点。运行环境仍是可信本机、单用户、单后端进程。
