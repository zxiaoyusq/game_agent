# Skill 调用与自动选择

工作台与 MCP 的新运行统一由后端选择 Skill，前端只展示预览并保存人工调整。品类决定规则知识，框架决定适用技术，阶段和明确任务决定当前需要读取的技能；不把所有公司文档一次性载入模型。

| 条件 | 默认选用 |
| --- | --- |
| 所有品类、所有阶段 | 通用休闲游戏生产流程；实际规则读取所选品类知识 |
| Cocos Web | 加 Cocos 生产与验收；Canvas 不默认加入 Cocos |
| 美术阶段 | 加 AI 美术流程、休闲美术风格与视觉规范 |
| Canvas / 原生 Web 换皮的四阶段 | 加 H5 换皮；原型加视觉规范用于市场与方向，后续按阶段读取生产、合入、运行诊断资料 |
| Cocos 换皮的美术、代码、测试阶段 | 加通用换皮流水线，不套用纯 Canvas 资源规则 |
| 美术阶段明确生图、透明素材制作、参考图编辑、结构锁定换皮 | 加生图规范，使用已配置的 generate_art_image，缺配置则如实说明 |
| 原型阶段明确竞品研究或托管小游戏采集 | 加相应方法，区分本地证据研究与未接入的联网操作 |
| Canvas / 原生 Web 的已有 H5 还原、原码迭代 | 各阶段加托管小游戏生命周期 Skill，核验已有输入，不重复采集 |
| Canvas / 原生 Web 的包体、加载、内存优化 | 原型、代码、测试阶段加托管小游戏 Skill 的优化参考；不把该路线用于 Cocos 构建 |
| 明确审查 Creator 工程规范 | 加 Creator 规范作为参考；先体检工程身份，不推断 CFW 或替换 Web 配置 |

品类差异由已选品类知识与阶段指导承接。AHAgames 或 OneConnectRe 引用路径本身不触发采集；常见的“不换皮”“无需生图”“不做包体优化”等否定会抑制相应推荐。复杂需求仍可人工调整，界面给出选择理由和本阶段优先参考文件供核对。

## 一次运行的调用顺序

1. 项目保存品类与技术配置，用户填写当前阶段需求。
2. 工作台或 MCP 预览服务端选择结果。自动模式支持补充与排除，手动模式采用明确列表。
3. 启动时后端重新计算，保存 `skill_selection`，并冻结入口与同包文本。请求重试返回同一个运行，不重新取版本。
4. 提示中仅放入口元数据、哈希、理由、`resource_paths` 起读建议与能力限制；Agent 使用 `read_skill` 读入口，再用 `read_skill_resource` 读必要的支持文本。
5. 工具记录实际读取范围和冻结哈希。阶段结束及评审确认时校验入口完整读取、版本一致和归档未篡改。
6. 中断恢复沿用同一选择和同一输入；更新知识库或发布 Skill 仅影响后续新运行。

文本快照独立于游戏工作区，单文件不超过 2 MB，总量不超过 16 MB。图片、压缩包、大型示例页、隐藏文件及链接不作为模型文本输入；它们仍可在知识库界面查看。未选中的入口不能通过配套文件工具读取。

## 真实能力边界

现有四阶段执行图支持文件操作、本地参考和 ZIP 条目研究、受限素材提取、知识读取、资源清点、图片生成与后处理、npm/Node 项目验证。`generate_art_image` 还需服务器图片 API 配置；`read_file` 的图片理解取决于所选模型。Skill 不会自动注册工具，联网搜索/采集、Creator MCP、ADB、Python 执行器及专业编辑器仍未绑定到此图。

H5 换皮 2.0 的方向选择、设计评审、暂停续接由现有平台 `request_user_input` 和持久检查点承接；人工模式等待真实回答，自主模式明确记录 AI 决策。已有目标和授权不重复提问。来源 HTML 及 Python 渲染器可以在知识库阅读，但当前不执行该工作台，也没有它的选择单回传接口。

因此，读取采集 Skill 可以整理输入与校验要求，不能宣称已经下载；读取 Creator 规范可以审查适用边界，不能宣称已运行编辑器；资源尺寸与哈希清点不能冒充画面审美或真机视觉验收。

实现沿用官方推荐的元数据、入口正文、支持资源逐步加载方式，以及自定义工具加载技能的模式：[DeepAgents Skills](https://docs.langchain.com/oss/python/deepagents/skills)、[自定义 Skills 模式](https://docs.langchain.com/oss/python/langchain/multi-agent/skills)。保持现有工作区隔离，不为加载资料扩展文件权限。
