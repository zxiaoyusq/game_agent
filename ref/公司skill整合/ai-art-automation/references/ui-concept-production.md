# PRD与参考图驱动的UI效果图生产

适用：用户要求从策划、交互蓝图和风格/主体参考生成整套游戏UI概念图，或对整套效果图做局部修订、换色和分期整理。此模块交付完整界面位图及追溯文档；不自动扩大为开发、拆图或代码合入。

## 1. 证据与范围

读取全部指定策划正文、嵌入附件和交互图。建立来源索引，记录路径、尺寸、SHA256；相同图可去重检查，但保留全部来源关系。总览用于覆盖检查，关键页面及模糊细节需放大查看。不能把“文件已枚举”写成“已阅读”。

为每份输入指定职责：用户最新要求控制范围与改动；PRD控制功能、数值和阶段；蓝图控制布局与交互；竞品控制美术材质、配色与氛围；主体参考控制角色身份。冲突单独记录，不继承竞品多余功能、货币、品牌或蓝图旧角色。

建立PROJECT_BRIEF.md、STYLE_GUIDE.md、SCREEN_INVENTORY.md及生产清单。每个页面/弹窗/状态一个稳定ID，动画按关键帧列项并说明不含完整动画。

清单必要字段：

```json
{"id":"N02","name":"新手引导_点击","requirement_source":"策划章节/蓝图路径","source_phase":"正文一期，MVP未列","delivery_phase":"第一期","phase_basis":"用户确认","page_family":"tutorial","state":"step1","reference_roles":[],"exact_text":[],"acceptance":[],"status":"planned","current_path":"第一期/新手引导_点击.png","revisions":[]}
```

阶段与生产批次分开：首批样张不是产品一期，跨端不是产品期次。期次冲突影响归档时先完成无争议项，并请用户确定冲突项；保留原文期次、最终归类及依据，不能静默改写产品范围。

## 2. 风格规范与样张

将风格分析转为可复用关键词：材质、轮廓、光照、镜头、比例、字重、圆角、阴影、主次色、背景氛围。分开记录观察到的竞品风格与实际采用的用户色板。

建立跨页不变量：角色脸型/耳形/花纹/配件/肢体数；导航与页签；阶段指示器；手势图标；模态位置、遮罩及按钮。将统一样式写成正向定义，而不是每张重新设计。

换主色时更新按钮、选中态、强调文字、浅色底和图标描边等语义token；白色保留。场景实物颜色及策划稀有度语义色分别处理，不把蓝地毯/蓝服装等一并染色。

需要首次确认时选2张有代表性的页面（如主场景、面板密集页）；用户已经批准方向并授权批量，直接续做，不反复索要相同确认。

## 3. 批量生成与检查点

默认沿用GPT生图内置image_gen，每个ID单独调用和保存。批量不等于切换CLI/API；GameArtAgent规格只在实际使用其生产路径时建立。先查看本地参考图，再按当前工具契约传引用，不虚构输出路径、分辨率或模型参数。

每次提示词由以下部分组成：

1. 当前页ID、功能、状态、单张完整界面画幅。
2. 参考职责：已确认视觉母版、精确主体、仅布局蓝图；按当前任务选择最少必要参考。
3. 全局风格与本页相关的不变量。
4. 本页层级、精确文案、数值、选中/锁定/冷却等状态。
5. 本次检查项与必须保留项。

先生成页面家族母版，再生成依赖页。每张完成立即保存记录并检查；记录实际prompt、参考路径及职责、工具返回源路径、目标路径、尺寸、hash和状态。保留工具原始输出，复制到用户目标目录。区分generated、reviewed、accepted；模型自检通过不等于用户已验收。

续做前读取磁盘清单，跳过已完成且校验一致的ID。失败重试只处理失败项。不要仅依赖内存里的next index；工具仍在运行时不要启动同一文件的第二个写入者。

## 4. 逐图验收与局部修订

逐张查看：角色身份与肢体数量；文字与数值；选择/未拥有/等级锁定/计时等状态；导航一致性；模态居中和遮罩；是否多出装饰、叉号、额外货币、重复气泡或重影。文件数量、hash和解码检查不能代替视觉检查。

用户给出文件名和带标注截图时，以文件名定位完整原图；截图用于理解改动。两者指向不同界面时，仅暂停歧义项并询问，继续明确项。最终图不保留用户画的红框或圈。

每次修改生成结构化记录：目标ID、原图hash、用户改动、保留项、参考、输出源、修改后hash、视觉结果。局部编辑优先原图加必要样式参考；一次只处理一个明确的修订范围。编辑后检查整个画面，防止修了数值却产生气泡重影等新问题。

明确要求覆盖时：先将旧图保存至独立“废弃/批次时间”目录并校验，再以原功能名替换。中间失败图保留到修订过程目录，不混入正式图。未授权覆盖时使用版本名。不要用脚本绘制/拼接替代用户要求的GPT生图；文件处理、索引和校验可用脚本。

## 5. 分期整理与交付

从清单生成目录，不按文件名前缀猜测期次。同一正式图只属于一个交付阶段；跨阶段共用图记归属与引用，不用复制充数。

迁移前建立old_path→new_path映射、源hash和回退记录；验证所有源存在、所有目标不冲突、最终绝对路径在指定根目录内。移动后更新当前清单、生产任务、功能索引、HTML预览、使用中的MD链接及重新生成索引的脚本。历史prompt/source/编辑参考保持原始记录，另增current_path或迁移映射。

验收：各期数量相加等于计划；每个ID一次；所有PNG可解码；移动前后hash一致；HTML的src/href实际存在并正确转义；废弃图不计入正式数量。索引构建器重复运行后仍保留分期路径。

交付至少包含：阶段文件夹、可筛选预览、功能索引、逐图清单、风格规范、生成与修订记录。报告实际文件路径与验证结果；说明位图概念稿和可运行UI/拆分素材的边界。

## 常见失败与对应检查

|失败|处理|
|每页独立发挥导致阶段点或手势不一致|页面家族母版及组件不变量|
|只改prompt未检查输出|逐图查看，记录实际通过项|
|重新生成修复处却破坏原有内容|限定改动、全图回归检查|
|生成完成但目标目录缺文件|以目标文件解码与清单集合为准|
|整理目录后预览失效|同时更新链接与索引生成器并校验|
|把样张批次或跨端当产品期次|独立source_phase/delivery_phase/phase_basis|
|概念图完成后被迫做源码合入|先选择交付模式，按用户范围验收|
