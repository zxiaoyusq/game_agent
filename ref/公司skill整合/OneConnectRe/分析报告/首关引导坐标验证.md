# 首关引导坐标与连线验证

竞品 `config/tutorials.json` 的 `l1` 前四个 `TouchSlot` 是 `[11,13]`、`[8,14]`、`[10,4]`、`[15,21]`。这里将编号**暂按 `CustomLevel1.txt` 的 5×5 数组从 0 开始、按行编号**映射为 One Connect 的竖屏位置；竞品运行时的槽位编号语义尚未从代码确认，不能将这一映射称为竞品内部实现。

在当前开发版 16 张首关，浏览器自动点击的实际结果：前三组可以依次消除，第四组 `[15,21]` 点击后牌数不变；先消除 `[3,7]`、`[1,16]` 后再点 `[15,21]` 可以消除。这与独立求解器对该盘的结论一致。因此，未经进一步验证不能将第四组直接设置为强制目标，否则可能卡住玩家。

复现：启动项目 HTTP 预览（端口 18750），运行 `node tests/tutorial-first-four.cjs`。该测试是自动点击，不能替代 MuMu 上的自然引导验收；它验证的是当前游戏规则与假设坐标下的兼容性，尚未实现高亮、遮罩、手势、错误说明、计时暂停、退出恢复或引导状态。
