# 结算界面接入边界（当前 Construct 导出）

## 已定位

- `game/level-progress.js` 监听 `screen.SCREEN_BONUS`，在确认当前棋盘为空且剩余计数符合实际容器容量时记录解锁进度。仅收到事件并不代表奖励已领取。
- `game/first-level-transition.js` 对第一关有效通关走独立路径：短延迟后检查已解锁进度，清理奖励对象，再调用 `nextLevel`。首关不能额外展示普通结算或重复调用推进。
- 原始项目模型中 `gameEvent` 的 `nextLevel`（条件 SID 683277711800106）先调用 `init`，再增加 `level` 并重置计时和暂停；开发版钩子还处理配置更新与下一关初始化顺序。不能简单改全局 level 或直接删棋盘伪装推进。
- 原始模型中，奖励箱类型 t35 的自然触摸事件（条件 SID 769785980548122）有动画/广告状态检查、音效、延迟、图集帧变化及奖励对象生成；直接销毁后跳关会绕过这一条原版流程。胜利页面是否保留这条随机奖励链需要按产品设计确定，不能以 UI 改版为由静默移除。
- `levelFailQuit`（条件 SID 509457078819348）负责解除暂停并回到菜单；失败、重开、广告和快照的真实动作需在当前开发版本逐项定位。`game.level_fail` 会清除对局快照，显示与持久化必须分离。

## 接入原则

胜利/失败界面的展示组件只消费经过确认的状态，按钮调用明确的游戏 owner；同一次结果须幂等，界面重开不能重复增加进度或发奖。竞品三颗星的阈值、计分与局外累计尚待 DSH；未确定之前不写假分、不发假奖。现有独立结算 HTML 为视觉候选，按钮仅关闭预览，尚未接入任何游戏流程。

资料来自现有解析模型与开发版源码，属于静态证据；没有执行任何游戏 QA。原始项目模型的 SID 是包版本专属，不应迁移到其他游戏。

- 候选 v5 接在奖励箱完成后的 Famobi levelSuccess 回调前：通关且进度已解锁、非首关时显示新胜利面板；Next 恢复原回调，Home 走已有返回菜单函数。首关与奖励箱入口保持原路径；星级没有规则时不展示。此为静态设计的隔离候选，调用时序、返回、广告、重复触发与进度均尚未经 QA，尚未接入正式版；失败面板仍未对接。

- 候选 v6 将失败面板接入 levelFail 回调：Home 使用原返回菜单函数；Retry 先走同一返回菜单流程，再等待菜单就绪调用原 levelStart。若限定时间内菜单未就绪则停留在现有流程，不强行重试。此实现尚未进行 QA；失败埋点、倒计时、存档清理、广告延迟和首次引导重试仍需由用户验收。
