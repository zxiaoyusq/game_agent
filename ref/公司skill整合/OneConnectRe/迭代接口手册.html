01 广告与宿主接口

实际文件和调用路径

开发版启动 game\game.html，载入 game\host-adapter.js，再通过原有加载链运行 game\custom.js。custom.js 当前在 EVENT_LEVELSUCCESS 和 EVENT_LEVELFAIL 中分别调用 window.oneConnectHost.showInterstitialFor("win") 与 showInterstitialFor("fail")，策略允许时再调用 showAd("Interstitial")；加载完成时调用 window.oneConnectHost.loadingCompleted()。胜负及分数仍交给原有 GAMESNACKS 调用链，接新平台时应一并核查。

host-adapter.js 默认尝试读取 window.top.h5_sdk，要求可以访问父页面对象；也可以通过 oneConnectHost.setAdProvider(provider) 显式注入仅用于广告的提供者，传 null 恢复默认查找。加载完成通知仍走原宿主查找。可用的方法是：

宿主对象方法 参数 当前调用时机 说明
showGameLoadingCompleted() 无 原有加载完成通知 方法缺失或抛错时记录事件，游戏继续
showAd(kind) 目前原游戏调用 "Interstitial" 原有成功或失败事件 返回值可为普通值或 Promise；适配层捕获同步抛错及 Promise 拒绝

oneConnectHost.showAd 返回 Promise，结果 status 当前为 unavailable、returned 或 error。returned 只说明宿主方法正常返回或 Promise 成功完成，不证明广告被填充、展示或关闭。适配层内部记录 ad.request、ad.unavailable、ad.returned、ad.error。custom.js 调用时没有等待这个 Promise，因此当前广告不会通过此 Promise 阻塞游戏流程。

如何接入替换

  1. 由目标宿主提供可访问的 top.h5_sdk，或在具备访问权限的游戏上下文中显式调用 oneConnectHost.setAdProvider({showAd(kind){ /* 平台适配 */ }})；传 null 恢复默认。跨域父页面可能无法直接读取；须按目标平台实现通信，不要假设已支持。
  2. 把目标平台 SDK 初始化、广告位和参数放在宿主/provider 内，游戏只经适配层调用；检查 game\custom.js 中的 GAMESNACKS 调用是否也要按目标平台迁移。
  3. 在 开发预览.html 选择不可用、接口返回、接口报错或异步失败进行本地流程检查。这个模拟不展示真实广告，也不发放奖励。
  4. 获得真实 SDK、广告位、回调契约及平台测试环境后，另行实现广告关闭、暂停恢复、失败处理及需要的变现策略，并在目标宿主验证。

当前有本地模拟的激励生命周期组件（见 07_激励广告生命周期.md），但没有接好的真实激励广告、持久奖励发放或跨会话去重；可通过 game\ad-policy.js 控制会话内插屏请求频率。不要把 ad.returned 当成展示成功或奖励凭据。

调整触发点

当前两处触发点在 game\custom.js 的 EVENT_LEVELSUCCESS、EVENT_LEVELFAIL 分支。更改前应先确认实际事件顺序以及目标宿主要求；改动后分别验证胜利、失败、未填充、异常及关闭后的流程。此文件为压缩形式，修改时应保留备份，避免整段误替换。

验证与回滚

本地运行 tests\host-adapter.test.cjs、tests\ad-outcomes.test.cjs 可检查接口不可用、抛错、Promise 拒绝及返回；tests\panel-ad-failure.cjs 是浏览器中超时结算后返回菜单的模拟验证。依赖和服务器启动方法见第 05 篇。真实展示、关闭、暂停、失败、回调时序及平台后台结果仍需目标 SDK 环境实测。回滚时恢复修改前的 game\host-adapter.js 与 game\custom.js 备份，并重跑流程；baseline\custom.js 可用于核对原始行为，但直接覆盖会恢复裸页面缺少宿主时报错的状态。

插屏请求策略

编辑 game\ad-policy.js：winEvery 为每 N 次胜利允许一次请求（默认 1），showOnFailure 控制失败是否请求（默认 true），minIntervalSeconds 是发送给可用宿主的两次请求之间的最短秒数（默认 0）。默认保持现有胜败触发方式。示例：winEvery: 3, showOnFailure: false, minIntervalSeconds: 45 表示每第三次胜利且距离上次请求至少 45 秒时请求，失败不请求。

该策略仅在当前页面会话内计数，刷新重置；记录的是请求时间，不是广告实际展示时间，SDK 返回不证明播放。跳过时记录 ad.policy_skip 及原因，游戏继续。平台可能有自身频控；正式参数和跨会话策略需要另行确认。无宿主时不记录请求间隔；SDK 调用抛错也计作已发送请求。该策略不控制父页面前贴片或 Banner，未实现激励和真实广告回调。

包装页 Service Worker 现象（2026-10-29）

浏览器从 game/index.html 启动时，外部 adsdk_1.8.0.0.js 注册相对路径 ./sw_transsion.js，本地不存在该文件，出现 404。拦截该外部 SDK 的对照中主菜单加载且未出现此错误。未添加空 Service Worker；是否需要原脚本、缓存行为和真实宿主广告，须按平台提供的接入资料验证。该对照不证明广告或离线功能可用。

显式提供者的受控流程验证

浏览器和 MuMu 独立副本使用仅测试用的 2 秒关卡，实际等待失败结算后，由游戏胜败事件触发显式注入的本地 showAd("Interstitial") 模拟。ad.returned 仅代表模拟方法返回；未播放真实广告。默认不注入提供者，原宿主查找保持不变；切换提供者也不修改加载完成通知。真实 SDK、跨域通信、播放/关闭及平台参数仍需平台提供并验证。测试 tests/ad-provider-injection.test.cjs 和 tests/ad-provider-failure-browser.cjs。

  • 浏览器与 MuMu 独立副本进一步验证：两张牌测试关卡自然清盘、点击结算后触发插屏请求；提供者分别正常返回、拒绝或永不回调时，三种情况均进入下一关。2 秒测试关卡自然超时失败时，同样三种模拟均可返回首页。测试脚本及结果位于 tests/ad-provider-win-browser.cjs、tests/ad-provider-failure-browser.cjs、tests/android_preview/ad_provider_*_mock_20261031.cjs、tests/evidence/mumu_ad_provider_*_mock_20261031.json；MuMu 脚本需独立 analysis/ad_provider_win_candidate/game 与 analysis/ad_provider_candidate/game 候选及对应测试配置。这里的永不回调证明当前游戏不等待 Promise 才继续，不证明真实广告遮罩、暂停归属或 SDK 资源释放正常。

生成、存档和回滚

随机生成器优先搜索成对随机布局，并在预算内采用其他构造策略；生成失败会记录 config.board_error，阻断对局并提供返回首页，不会静默改成原版随机盘。它是本项目实现，不能称为竞品算法。新开生成盘时 game.board_generated 记录种子和策略；恢复存档时直接使用保存盘，不产生新的生成事件。

game.board_configured 表示配置盘已写入；未配置棋盘使用 game.round_ready。两者均不单独证明玩法通过。稳定对局快照分别保存牌位、时间、得分、提示和洗牌数，并检查关卡配置；失败、结算或同页面重新开局会清除旧快照。仅修改逐关自动洗牌策略时保留兼容快照；其他配置变化或快照损坏时回退新盘。首关固定教学可从最近一次稳定快照推导并恢复教学步骤，牌面不匹配教学顺序时回退新盘；第 3、5、7、10 关的单步教学在重新打开后保留稳定棋盘并重新显示未完成的引导。主动返回首页重开仍从头开始；异常终止可能回退到最近一次稳定快照。

第 2 关连接引导在实际完成一次普通配对后写入本地 oneconnect.tutorial2.v1=done，之后重开不再显示；误触、洗牌和失败不会标记完成。存储不可用时不会阻断游戏，但不能保证下次不再显示。

第 2 关引导不会因点击空白或暂停而消失；暂停期间隐藏，继续后重新显示。成功配对、洗牌或失败后结束本次提示，玩家仍可选择其他合法牌对。

编辑器检查随机生成盘时，会先用独立规则模型逐步核验生成器提供的路径，包括牌面相同、连接、移动和最终清盘；通过时显示“生成路径逐步核验通过”。路径不通过则回退到有节点预算的独立搜索；预算耗尽仍显示“未知”。检查只针对显示的样本种子，不保证所有种子，也不能替代游戏实测。

续局校验拒绝超出配置初始牌数的快照，以及牌落在重力范围之外的快照；这些快照回退到新盘。重力落位可以使牌离开初始图形，但只要仍在重力范围内便允许恢复，不要求恢复盘与初始图形完全相同。

回退具体迭代使用 Git 或修改前备份。若要取消全部关卡覆盖，先备份配置，再将其设为 {"levels":[]} 并重新编译；这会改变当前开发体验，不能当作验证或发布完成。原始 ZIP 与 baseline/ 始终保持只读。

棋盘配置、生成或落位失败时，游戏会暂停并显示返回首页按钮，不会让玩家继续操作原版随机棋盘；生成失败详情通过本地 config.board_error 事件输出，落位失败通过 config.gravity_error 输出。返回后进度保留，可以调整配置后重新进入；固定种子重复失败时需修改种子或布局，而非反复重试。

对超过 20 种牌的非矩形重力盘，生成器在原有四次尝试失败后，最多继续尝试至 12 次；前四次已成功的棋盘与原行为一致。多次尝试会增加少数开局的耗时，仍可能失败，失败时显示返回首页的保护界面；不能把有限样本视为所有种子可解。

8×12 旧预设（75 像素、偏移 160/35）存在顶部遮挡，编译器不再接受。已有配置请先备份，再将该 boardSize 的 itemSize 改为 65、offsetX 改为 220、offsetY 改为 100，重新检查棋盘和编译；配置变更可能使进行中的旧棋盘存档失效。

game.level_start 是原有开始信号，game.round_source 补充是否加载快照；二者不是两个独立开局，不应相加计数。页面刷新后本地事件编号会重置，当前没有持久对局 ID 或跨会话去重，后续平台事件名和上报规则待确定。

  • grant(claim, proof, attempt) 必须同步完成一次业务交付并返回 true 才标记本会话已领取。当前无持久化交易账本；真实接入必须将发奖与持久幂等一起设计，不能以这个内存标记代替经济落盘。
  • setProvider({show(callbacks, attempt)}) 只接收已经适配、可信的供应商；它必须先按实际 SDK 契约归一化结果。shown() 表示开始展示，earned({verified:true}) 只表示供应商适配层已确认奖励，closed()、cancelled()、error() 分别结束请求。组件不会因为关闭或普通 Promise 返回而发奖。当前合同中终态后的迟到回调被忽略；若平台允许关闭后再发送奖励，适配层需要先等待并归一化，不得直接照搬。
  • request(claim) 返回状态：rewarded、closed、cancelled、error、timeout、show_timeout、unavailable、busy、already_claimed 或 invalid_claim。请求身份在调用供应商前分配；并发请求返回 busy。cancel() 可解除等待；展示前超时适用 loadTimeoutMs，已展示后不以加载超时截断。可选 maxShowingMs 启用独立展示阶段看门狗，尚未成功发奖时超时返回 show_timeout；若先前已成功发奖则返回 rewarded，并释放本组件的暂停。默认不启用。该计时使用墙钟，包括后台时间，也不能关闭或证明关闭真实广告；只有在平台明确支持超时、关闭和前后台处理后才应配置，不能把本地模拟当真实广告验收。

本地测试覆盖同步回调、重复回调、失败、关闭、无供应商、加载超时、展示后回调、展示后失联、并发、取消、迟到结果及不可信凭据。测试门控和计数器均是模拟，不证明真实广告、真实暂停、AHA SDK、持久发奖或经济链已接通。实际商业化接入前须由平台明确广告位、结果顺序、超时、证据及暂停/奖励所有权，并补真实业务入口、可恢复持久发奖和设备验收。

供应商 show() 若返回 Promise，异步拒绝会结束当前请求并返回 error，释放本请求持有的暂停；Promise 正常完成不代表广告完成，也不触发奖励。若奖励此前已获确认，则保持 rewarded；终态后的迟到回调不发奖。适配层仍须根据实际 SDK 契约归一化，避免将与本次展示无关的后台任务失败作为展示失败。浏览器运行页和 MuMu 隔离副本已验证模拟异步拒绝，未验证真实 SDK。

本地锤子奖励示例

examples/reward-hammer-local.js 是独立测试示例，不加载进正式游戏。开发者可在正在对局的本地页面加载该脚本，创建 oneConnectLocalHammerExample.create({loadTimeoutMs: 2000})，通过返回实例的 setProvider 注入模拟供应商并用 request('本次唯一标识') 发起。模拟供应商调用 shown()、earned({verified:true})、closed() 后，示例给现有锤子库存加一；tests/reward-hammer-local-browser.cjs 验证了发奖后实际使用锤子、同实例重复请求和取消后的迟到回调。此示例不处理真实广告、正式入口或持久化奖励事务；会话结束、多个实例和页面重载之间不保证去重。

暂停尚需真实宿主联调：实际检查发现 cr_setSuspended(true) 会触发原游戏自己的暂停状态，随后恢复引擎并不等于恢复对局。本示例不操作暂停，也不模拟真实广告播放；接入真实 SDK 前需确认前后台、手动暂停和广告暂停的所有权并在设备上验证。

暂停来源已进一步定位：Construct 的挂起回调触发 Browser.OnPageHidden，原游戏随后进入自己的暂停菜单；恢复引擎后菜单仍保留，需要玩家点击继续。浏览器测试 tests/suspend-pause-recovery-browser.cjs 验证暂停期间计时不变、继续后计时恢复，且已有手动暂停在挂起和恢复后仍保留；MuMu 隔离副本测试 tests/android_preview/suspend-pause-recovery.cjs 验证触控继续及计时恢复。这是受控引擎挂起测试，不能证明真实广告返回时的宿主行为，也不提供广告结束后自动继续。
