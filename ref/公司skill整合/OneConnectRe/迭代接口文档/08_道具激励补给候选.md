# 道具激励补给候选

独立候选中的提示、洗牌、锤子、换牌面耗尽后弹出补给界面；每次经平台适配器明确确认奖励完成后增加两个对应道具。换牌面在候选中新增本地库存，默认两次，属于本项目设计，并非声称竞品原规则。

平台应通过 `oneConnectToolRewardCandidate.setProvider({show(callbacks, attemptId) {...}})` 注入适配器。适配器负责将 SDK 的真实展示、完成、关闭、错误和取消分别映射到 `shown()`、`earned({verified:true})`、`closed()`、`error()`、`cancelled()`；普通返回值和 Promise 成功不发奖。无适配器时显示广告不可用。请求并发由生命周期组件限制，单次回调重复不重复发放，跨关卡或重开后的迟到奖励不发放。候选设置了 180 秒展示看门狗防止回调缺失时永久卡住；这不代表已关闭平台广告，正式接入前需依据 SDK 生命周期调整。

本地演示可手动加载 `examples/tool_reward_local_candidate.js` 并调用 `oneConnectToolRewardMock.enable('rewarded')`；`closed`、`error` 可模拟未获奖，`disable()` 撤销注入。此模拟不连接广告网络，不能用于正式发奖。真实 SDK 对接、持久化交易防重、广告展示及关闭回调仍未验证；当前会话级去重不能替代平台服务端校验。

候选对同一请求最多尝试一次库存发放；发放期间重入的完成或关闭回调会被安全处理。若库存接口在修改后抛错，候选不会盲目重试，因此仅能避免重复发放，不能判断该次奖励是否已经持久保存或保证自动补发。正式接入需要平台提供稳定交易 ID，并将奖励凭证、库存变更和交易去重以可恢复的事务方式保存；SDK 适配器的 `verified:true` 只应来自平台确认，不能由普通广告结束事件推断。

提示与洗牌数量目前保存在对局存档中。发奖时 `capture()` 可能因棋盘、洗牌或动画尚未稳定而返回 `false`；此时内存数量已增加，但不会立即写入存档。周期保存之后可能补写，若保存成功前页面退出或存储不可用，奖励可能丢失。不能仅把此次 `capture()` 失败当作发奖失败并重试：内存库存可能已经增加，重试会重复发放。真实广告上线前须完成可恢复、可验证的奖励交易持久化，并覆盖存储失败和退出恢复测试；当前候选不满足这一生产要求。
