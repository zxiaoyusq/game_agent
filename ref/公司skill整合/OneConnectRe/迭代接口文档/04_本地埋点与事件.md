# 04 本地埋点与事件

## 已有入口

- 事件总线和本地缓存：`game\host-adapter.js` 的 `window.oneConnectHost.emit(type, detail)`、`events()`、`analytics(name, detail)`。
- 玩法动作钩子：`game\event-hooks.js`，基于当前 Construct 2 导出事件 SID；固定棋盘相关事件由 `game\board-hooks.js` 发出。
- 原版渠道事件桥接：`game\custom.js` 中 `famobi_analytics.trackEvent` 与 `trackScreen`。
- 查看和导出：运行 `启动开发预览.cmd`，在 `开发预览.html` 右侧查看，使用“下载本次事件”导出 JSON。

事件结构为 `{id, type, detail, time}`。`id` 是当前页面会话中的递增编号，`time` 是 ISO 时间；内存缓存最多 1000 条，刷新后清空。面板按会话从游戏读取事件并可导出，**没有持久化投递、重试或后台上报**。

事件内容按发出时的 JSON 值保存，`events()` 返回独立副本，调用者或原始业务对象的后续修改不会改写历史。请只传可 JSON 序列化的数据；循环引用或无法序列化的值会被记录为 `{serializationError:true}`，以避免异常阻断游戏。普通 JSON 转换规则仍适用，例如对象中的 `undefined` 会被省略。实时监听的同一次 DOM 事件对象由监听者共享，监听代码也应当只读。

## 已有事件

| 事件 | 触发与 detail | 验证或限制 |
|---|---|---|
| `game.level_start` | 初始关来自原版 `EVENT_LEVELSTART`；后续关由关卡递增动作钩子发出，包含 `level`，后续关可带 `score` | 前两关自然推进已观察；原始渠道事件保留为 `analytics.EVENT_LEVELSTART` |
| `game.match` | 原版配对计分动作之后，包含 `level`、`score`、`tip`、`shuffle`、`source` | `source=hammer` 表示锤子消除，`source=normal` 表示其他标准配对路径；后者也可能由自动化触发，不能单独证明是真人操作。当前 SID 不提供牌坐标或无效点击 |
| `game.hint` | 成功消耗提示后，包含当前 `level`、`tip` 等 | 浏览器实际点击验证 |
| `game.shuffle` | 手动洗牌调用后，包含 `level`、`shuffle` | 浏览器实际点击验证；不等同于自动无解洗牌 |
| `game.level_win` | 胜利时发出，包含 `level`；能可靠取得累计得分时含 `score` | 首关自然通关已验证 |
| `game.level_fail` | 原版失败事件，包含 `level`，有时含 `reason` 和累计得分 `score` | 配对后受控超时已验证；其他原因尚需验证 |
| `game.board_configured` / `game.round_ready` / `config.board_error` | 配置棋盘写入、原版回退棋盘就绪或配置错误；detail 含 `level`，错误可含 `message` | 仅代表运行时阶段，不单独证明玩法通过 |
| `game.round_source` | 棋盘来源已选定，包含 `level`、`resumed`、`configured`。`resumed` 表示使用已验证的对局快照；`configured` 表示此关配置了固定或生成棋盘，纯计时配置仍为 `false` | 本地新盘、恢复和首页重开已验证；配置棋盘生成失败不发送。发生在棋盘组装阶段，不能单独证明所有牌已绘出、玩家可操作或一场完整对局开始 |
| `game.board_generated` | 新开生成盘时记录关卡、随机种子、生成策略；重力盘带 `searchAttempts`（随机搜索次数，从 1 开始计数） | `adjacent_lane_fallback` 表示随机搜索耗尽后使用规则矩形兜底；其次数仅统计此前随机搜索，不计兜底构造。静态盘不提供该字段；恢复存档时不重新生成，也不发该事件 |
| `game.auto_shuffle_start` / `game.auto_shuffle_complete` / `game.auto_shuffle_exhausted` | 免费自动洗牌开始、成功或重试耗尽 | 不代表竞品算法；完整解与下一对是不同判断 |
| `game.hammer` / `tutorial.start` / `tutorial.complete` | 锤子使用、教学开始或完成 | 字段与次数以当前本地事件为准 |
| `ad.request`、`ad.unavailable`、`ad.returned`、`ad.error` | 广告接口调用、缺失、返回或异常 | 表示接口状态，不表示真实广告曝光或奖励 |
| `analytics.EVENT_*`、`screen.SCREEN_*` | 原版渠道事件和屏幕事件的本地镜像 | 类型和字段取决于原版调用，不应直接假设为最终平台规范 |

原始事件的 `detail` 由原程序提供；示例以游戏实时输出为准。胜败事件优先使用原始事件的 `totalScore`（包括零）；缺失时，仅当游戏正在对局、运行时关卡与事件关卡一致且累计得分为有效非负数，才补充 `score`。首关自动推进时读取有效的运行时累计得分。该字段是累计得分，不是单关得分；条件不满足时会省略，`reason` 也不保证每次都有。

`game.level_start` 是原有开始信号，`game.round_source` 补充是否加载快照；二者不是两个独立开局，不应相加计数。页面刷新后本地事件编号会重置，当前没有持久对局 ID 或跨会话去重，后续平台事件名和上报规则待确定。

## 如何添加或对接

- 在确定的业务触发边界调用 `window.oneConnectHost.emit('自定义事件名', { ... })`。调用者必须位于游戏页面同一上下文，`detail` 使用可序列化数据。修改前先确认动作真正触发的时机及是否可能重复，记录当前导出数据的 SID 与证据；不要直接沿用其他版本的 SID。
- 本地监听示例：

```js
window.addEventListener('oneconnect:event', function (event) {
  const record = event.detail;
  console.log(record.type, record.detail);
});
```

监听需在游戏 iframe 的 `contentWindow` 内安装，或参考 `开发预览.html` 的同源读取方式；不要将监听示例误写成平台上报。目标平台确定后，再定义事件名、字段、授权、上报地址、失败队列及去重策略，并在独立适配层接入。

## 回归

启动本地 HTTP 服务后运行 `tests\panel.cjs`、`tests\browser-key-events.cjs` 和 `tests\browser-host.cjs`，分别检查开始/配对、手动洗牌/提示、超时失败。自然胜利和下一关记录可查 `progress-board-final.txt`。自动洗牌、暂停、其他失败原因、后台上报及全平台事件尚未完整验证。`tests/match-source-browser.cjs` 和 `tests/android_preview/match-source.cjs` 验证标准配对与锤子配对的来源区分；锤子可能先发出 `game.hammer`，再发 `game.match`，业务侧不可把两条都当作独立消除计数。
