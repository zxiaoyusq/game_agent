## SDK 和广告调用

模板父页加载远程 SDK `https://www.hippoobox.com/static/sdk/adsdk_1.8.0.0.js`，使用 `window.h5sdk` 初始化；实际版本、域名及参数以目标平台提供的信息为准。ZIP 没有 SDK 离线文件。模板中的游戏、发布商、分析和广告位标识均为样本值，不能直接用于本项目。

父页在初始化回调中配置预加载并尝试前贴片；页面 `onload` 和子页消息均可能触发 `gameLoadingCompleted`，需要核实真正的游戏就绪时机和去重约定。模板底部预留 50px banner 区域，是否适用于目标宿主及是否遮挡内容需实测。

| 操作 | 模板子页请求 | 父页处理 | 示例结果 |
|---|---|---|---|
| 插屏 | `postMessage("next", "*")`，设置父页 `MIAD_NEXT` 回调 | `h5sdk.adBreak` 类型 `next` | `breakStatus` 为 `viewed` 调成功，其他调失败 |
| 激励 | `postMessage("reward", "*")`，设置父页 `MIAD` 回调 | `h5sdk.adBreak` 类型 `reward`；`beforeReward` 调展示函数 | `viewed` 调成功，其他调失败；示例只输出日志，不发奖 |

这些名字与 One Connect 当前的 `h5_sdk` 不同，不能只复制模板并认为已经打通。`showAd` 的调用返回也不证明广告已展示或关闭；真实状态必须由平台确认的回调驱动。

## 建议实施步骤

1. 核对平台最新模板、SDK 版本、合法域名、游戏及广告位参数；在独立副本保留原文件并记录回滚方式。
2. 确定保留现有游戏入口的包装方式，校验资源、脚本路径、视口与底部 banner。平台 README 要求父页不变，若必须改父页以桥接或加固，先向平台确认支持方式。
3. 找出 One Connect 的现有广告调用、暂停恢复和奖励消费位置，做适配器将这些动作映射到目标平台的真实协议。先设置回调再请求，控制并发，完成后清理；按平台约定处理超时、SDK 缺失和异常，确保流程可恢复。
4. 激励奖励只在经平台确认的有效完成回调发放，并对同一次奖励交易去重；取消、失败、无回调不发奖。插屏失败也应恢复游戏。
5. 模板消息目标使用 `*`，父页不核验来源，且直接访问父窗口回调依赖同源。需在平台允许范围内校验来源与目标域、处理请求关联、一次性回调及跨域方案；这些是改造建议，模板未内建。
6. 用本地模拟覆盖成功、取消、不可用、超时、重复与并发，验证暂停恢复及奖励；再用平台测试广告位在目标宿主和真机自然验证展示、关闭、奖励、网络、前后台、banner 及完整对局。保留证据、未通过项和回滚方式。
