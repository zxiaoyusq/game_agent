# 01 广告与宿主接口

## 实际文件和调用路径

开发版启动 `game\game.html`，载入 `game\host-adapter.js`，再通过原有加载链运行 `game\custom.js`。`custom.js` 当前在 `EVENT_LEVELSUCCESS` 和 `EVENT_LEVELFAIL` 中分别调用 `window.oneConnectHost.showInterstitialFor("win")` 与 `showInterstitialFor("fail")`，策略允许时再调用 `showAd("Interstitial")`；加载完成时调用 `window.oneConnectHost.loadingCompleted()`。胜负及分数仍交给原有 `GAMESNACKS` 调用链，接新平台时应一并核查。

`host-adapter.js` 默认尝试读取 `window.top.h5_sdk`，要求可以访问父页面对象；也可以通过 `oneConnectHost.setAdProvider(provider)` 显式注入仅用于广告的提供者，传 `null` 恢复默认查找。加载完成通知仍走原宿主查找。可用的方法是：

| 宿主对象方法 | 参数 | 当前调用时机 | 说明 |
|---|---|---|---|
| `showGameLoadingCompleted()` | 无 | 原有加载完成通知 | 方法缺失或抛错时记录事件，游戏继续 |
| `showAd(kind)` | 目前原游戏调用 `"Interstitial"` | 原有成功或失败事件 | 返回值可为普通值或 Promise；适配层捕获同步抛错及 Promise 拒绝 |

`oneConnectHost.showAd` 返回 Promise，结果 `status` 当前为 `unavailable`、`returned` 或 `error`。`returned` 只说明宿主方法正常返回或 Promise 成功完成，**不证明广告被填充、展示或关闭**。适配层内部记录 `ad.request`、`ad.unavailable`、`ad.returned`、`ad.error`。`custom.js` 调用时没有等待这个 Promise，因此当前广告不会通过此 Promise 阻塞游戏流程。

## 如何接入替换

1. 由目标宿主提供可访问的 `top.h5_sdk`，或在具备访问权限的游戏上下文中显式调用 `oneConnectHost.setAdProvider({showAd(kind){ /* 平台适配 */ }})`；传 `null` 恢复默认。跨域父页面可能无法直接读取；须按目标平台实现通信，不要假设已支持。
2. 把目标平台 SDK 初始化、广告位和参数放在宿主/provider 内，游戏只经适配层调用；检查 `game\custom.js` 中的 `GAMESNACKS` 调用是否也要按目标平台迁移。
3. 在 `开发预览.html` 选择不可用、接口返回、接口报错或异步失败进行本地流程检查。这个模拟不展示真实广告，也不发放奖励。
4. 获得真实 SDK、广告位、回调契约及平台测试环境后，另行实现广告关闭、暂停恢复、失败处理及需要的变现策略，并在目标宿主验证。

当前有本地模拟的激励生命周期组件（见 `07_激励广告生命周期.md`），但没有接好的真实激励广告、持久奖励发放或跨会话去重；可通过 `game\ad-policy.js` 控制会话内插屏请求频率。不要把 `ad.returned` 当成展示成功或奖励凭据。

## 调整触发点

当前两处触发点在 `game\custom.js` 的 `EVENT_LEVELSUCCESS`、`EVENT_LEVELFAIL` 分支。更改前应先确认实际事件顺序以及目标宿主要求；改动后分别验证胜利、失败、未填充、异常及关闭后的流程。此文件为压缩形式，修改时应保留备份，避免整段误替换。

## 验证与回滚

本地运行 `tests\host-adapter.test.cjs`、`tests\ad-outcomes.test.cjs` 可检查接口不可用、抛错、Promise 拒绝及返回；`tests\panel-ad-failure.cjs` 是浏览器中超时结算后返回菜单的模拟验证。依赖和服务器启动方法见第 05 篇。真实展示、关闭、暂停、失败、回调时序及平台后台结果仍需目标 SDK 环境实测。回滚时恢复修改前的 `game\host-adapter.js` 与 `game\custom.js` 备份，并重跑流程；`baseline\custom.js` 可用于核对原始行为，但直接覆盖会恢复裸页面缺少宿主时报错的状态。

## 插屏请求策略

编辑 `game\ad-policy.js`：`winEvery` 为每 N 次胜利允许一次请求（默认 1），`showOnFailure` 控制失败是否请求（默认 true），`minIntervalSeconds` 是发送给可用宿主的两次请求之间的最短秒数（默认 0）。默认保持现有胜败触发方式。示例：`winEvery: 3, showOnFailure: false, minIntervalSeconds: 45` 表示每第三次胜利且距离上次请求至少 45 秒时请求，失败不请求。

该策略仅在当前页面会话内计数，刷新重置；记录的是请求时间，不是广告实际展示时间，SDK 返回不证明播放。跳过时记录 `ad.policy_skip` 及原因，游戏继续。平台可能有自身频控；正式参数和跨会话策略需要另行确认。无宿主时不记录请求间隔；SDK 调用抛错也计作已发送请求。该策略不控制父页面前贴片或 Banner，未实现激励和真实广告回调。

## 包装页 Service Worker 现象（2026-10-29）

浏览器从 `game/index.html` 启动时，外部 `adsdk_1.8.0.0.js` 注册相对路径 `./sw_transsion.js`，本地不存在该文件，出现 404。拦截该外部 SDK 的对照中主菜单加载且未出现此错误。未添加空 Service Worker；是否需要原脚本、缓存行为和真实宿主广告，须按平台提供的接入资料验证。该对照不证明广告或离线功能可用。


## 显式提供者的受控流程验证

浏览器和 MuMu 独立副本使用仅测试用的 2 秒关卡，实际等待失败结算后，由游戏胜败事件触发显式注入的本地 `showAd("Interstitial")` 模拟。`ad.returned` 仅代表模拟方法返回；未播放真实广告。默认不注入提供者，原宿主查找保持不变；切换提供者也不修改加载完成通知。真实 SDK、跨域通信、播放/关闭及平台参数仍需平台提供并验证。测试 `tests/ad-provider-injection.test.cjs` 和 `tests/ad-provider-failure-browser.cjs`。

- 浏览器与 MuMu 独立副本进一步验证：两张牌测试关卡自然清盘、点击结算后触发插屏请求；提供者分别正常返回、拒绝或永不回调时，三种情况均进入下一关。2 秒测试关卡自然超时失败时，同样三种模拟均可返回首页。测试脚本及结果位于 `tests/ad-provider-win-browser.cjs`、`tests/ad-provider-failure-browser.cjs`、`tests/android_preview/ad_provider_*_mock_20261031.cjs`、`tests/evidence/mumu_ad_provider_*_mock_20261031.json`；MuMu 脚本需独立 `analysis/ad_provider_win_candidate/game` 与 `analysis/ad_provider_candidate/game` 候选及对应测试配置。这里的永不回调证明当前游戏不等待 Promise 才继续，不证明真实广告遮罩、暂停归属或 SDK 资源释放正常。
