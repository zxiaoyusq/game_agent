# 新功能 UI 开发链路 (ui-feature-pipeline)

## 执行卡（先用这张卡，再读正文）

**我管什么**：新功能或换肤界面的全链路——需求表 → 效果图与视觉基线 → 控件切分与资产清单 → prefab 重组 → 视觉 QA → 固化交付；不管生图工具本身（GPT生图 / imagegen 只是接入），不管引擎底层逆向。

**第一步做什么**：先出阶段 1 的 UI 需求表（区块清单、每区块状态、store 数据来源、入口出口），并判定这是新视图还是旧界面改造——旧界面改造还要先做残留盘点。没出需求表不许开生成图。

**做完怎么算完成**：
- [ ] 有逐界面 UI 需求表，且新视图/旧改造已区分；旧改造附残留盘点截图与审计报告
- [ ] 有用户确认过的效果图即视觉基线，存在 `working/reskin/generated/<批次>/`，命名 `ui_mock_NN_<name>.png`
- [ ] 控件→资源映射表三列齐全（控件 | 来源 | 所在 bundle），"已生成/已后处理/已接入"分状态记录
- [ ] 截图来自**正式构建**（`debug=false`）与真实 UIManager 节点，同 prefab 多状态逐状态截图
- [ ] 已跑三档画幅 + 英/德/法 + 安全区模拟（顶 44px/底 34px），每张对照效果图记录差异
- [ ] 交付报告齐全：修改文件与备份目录 / 复用清单 / 截图联系表路径 / 母版差异量化 / 多语言多分辨率安全区结果 / 构建日志状态

**红线（不可违反）**
- 效果图不是运行时资源：禁止把带 UI 的整屏效果图当背景接入；接入前必须拆成「纯净底层 + 可复用透明控件 + 动态文字与状态」，文字不进切图
- 控件只能按原始宽高比 contain/cover 到目标框，禁止 X/Y 独立缩放；验收直接比对切图原始宽高比与截图外轮廓比例
- 六阶段不许跳步，每阶段未过门禁不进下一阶段；同一界面绝不重复开发（动手前先定 prefab-first 还是代码路径）
- 清单已有控件禁止重复生成/抠图/裁切/重绘；sheet-alpha / RGB / mask / 图集过程文件不接入运行时，只接最终合成 PNG
- 运行时只改文案与状态色，不改版式（位置/尺寸/字号/对齐/溢出以编辑器 prefab 为准）；按公式重设 Label 的 pos/fontSize/contentSize 会抹掉美术调整
- 背景全出血、控件才避让安全区；改前显式备份到 `working/reskin/backups/<里程碑>_<时间戳>/`

**卡住时按顺序读**
- 生图接入方式、参考图与提示词、第一版死因 → `### 阶段 2：效果图生成与 QA`
- 控件切分粒度、多状态共用面板、文件名≠语义 → `### 阶段 3：控件切分与资产清单`
- 母版坐标映射、安全区分离、动态文字安全框、九宫格边界、注册三件套 → `### 阶段 4：重组实现`
- 截图节奏、缓存/黑图/端口陷阱、差异分类 → `### 阶段 5：视觉 QA 闭环`；固化与构建规约 → `### 阶段 6：固化与交付`

全局五步循环与六条铁律见 `references/execution-protocol.md`。

从"功能方案/效果图"到"烘焙完成、美术可编辑、多语言多分辨率验收通过"的完整链路。
提炼自真实三页面 UI 重制实战（B1 首页/B2 游玩/B3 设置，含多轮用户验收返工），
并以项目级 skill 承载项目特定值。每阶段有产物与门禁，未过门禁不进下一阶段。

## 铁律（先读，违反必被验收打回）

1. **效果图不是运行时资源**。效果图只作构图/色彩/层级参考；禁止把带 UI 的整屏效果图
   当背景接入（动态多语言/呼吸动效/安全区都会与烘焙 UI 打架，出现"双层错位/文字重影"）。
   接入前必须拆成三层：**纯净底层 + 可复用透明控件 + 动态文字与状态**；文字不进切图。
2. **控件按原始宽高比 contain 到目标框**，禁止 X/Y 独立缩放——非等比拉伸形变是用户红线。
   验收时直接比对切图原始宽高比与截图外轮廓比例，不凭目测。
3. **复用优先，清单驱动**：先按文件名/尺寸/SHA256 盘点已有成品（"尚未复制进工程"≠"未完成"），
   清单已有控件禁止重复生成/抠图/裁切/重绘；中间资产（sheet-alpha/RGB/mask/图集过程文件）
   不接入运行时，只接最终合成 PNG。
4. **背景全出血，控件才避让安全区**——两者都缩入安全区会在上下露黑边。
5. **文字全部动态 Label**，切图不残留烘焙文字；文字居中以**可见底框**（alpha 包围盒）为准，
   不以整张透明 PNG 为准。
6. **运行时只改"文案与状态色"，不改版式**。位置/尺寸/字号/对齐/溢出一律以编辑器 prefab
   为准（自适应用 Widget + Overflow.SHRINK 在 prefab 内配置）。运行时按公式重设
   Label 的 pos/fontSize/contentSize 会抹掉美术调整——这是"编辑器改了、运行时不一致"
   的第二类根因（第一类是母版重排函数）。

## 六阶段链路

### 阶段 1：理解功能（产物 = UI 需求表）

- 每个新界面列出：区块清单、每区块状态（默认/已领/锁定/完成/on-off）、数据来源（store 字段）、
  入口出口（谁 show 它/它 show 谁）。
- 区分**新视图**（需新 prefab + 注册三件套）与**旧界面改造**（换控件+改布局）。
- 旧界面改造前先做**残留盘点**：从实际注册的视图清单出发，按"可见状态"逐个截图
  （一个 prefab 可能有多状态），统计已替换/残留，产出逐界面截图与审计报告。

### 阶段 2：效果图生成与 QA（产物 = 已确认的视觉基线）

- **生图工具无关**：两条已验证路径——①GPT生图 skill（Azure gpt-image-2：`--ref` 多参考图
  即图1/图2 语义、`--size` 显式指定避免 auto-size 被提示词触发、生成后亮度校验防黑图）；
  ②宿主内置 imagegen 服务（codex 等）。提示词模板一致，仅替换调用方式。
- **参考图两张**：①本项目已验收界面截图（美术风格锚）②竞品对应界面（信息密度/布局结构锚）。
  提示词核心句式："参考图2的布局结构 + 图1的美术风格"；整屏界面 720×1280（或项目设计比例）。
- **第一版常见死因**：复杂臃肿、文字过多 → 重绘时压缩文字、对齐竞品信息密度、一屏一焦点。
- **QA 标准（用户确认后即为视觉基线）**：与需求表逐块对齐；复用项目控件语言（按钮/牌匾/
  角标样式一致）；配色符合项目色调；文字 ≤ 必要文案。
- 效果图存约定目录（`working/reskin/generated/<批次>/`），命名 `ui_mock_NN_<name>.png`。

### 阶段 3：控件切分与资产清单（产物 = 控件→资源映射表）

- 效果图拆控件：面板/标题牌/主次按钮/关闭键/状态图标/装饰/进度条/列表项，分别输出透明 PNG；
  同一 prefab 的多状态**共享面板与按钮**，只换图标/文案/局部装饰（PopResult 五状态共用一套）。
- 切图后检查：实际 alpha 包围盒、四角透明、白边/洋红边、半透明阴影、点击热区。
- 映射表三列：控件 | 来源（复用路径/新生成/代码绘制）| 所在 bundle；"已生成/已后处理/已接入"
  三个状态分开记录，交接与防重复生成都靠它。
- **文件名≠语义**：以母版联系表核对图形语义（实战中音乐/音效图标文件名与画面含义对调），
  冲突时以母版视觉与真实功能为准，并在 handoff 记录交换映射。

### 阶段 4：重组实现（prefab-first 或 代码动态+后烘焙）

- **母版坐标法**：为每控件记录效果图像素矩形与视觉中心 → 归一化映射到运行画布/
  `sys.getSafeAreaRect(false)`；切图以原始宽高比 contain 进目标矩形。
- **重置遗留变换**：布局前先复位 prefab 遗留的 scale/contentSize/锚点，否则正确尺寸仍被
  旧缩放二次变形（实战根因之一：bg 自带 1.3× 缩放未复位导致整屏放大错位）。
- **背景与安全区分离**：背景按 `view.getVisibleSize()` 全出血；交互控件映射到安全区；
  弹窗面板保持视觉中心，不随长屏拉高。
- **动态文字安全框**：Label = CENTER/CENTER + `Overflow.SHRINK`；主按钮文字框≈底框宽
  70–74% × 高 56–62%，小型底签≈宽 64–70% × 高 24–30%；长文本先扩框再 SHRINK（不只缩字号）；
  德语复合词/法语操作名是最窄画幅压力用例；on/off 状态字按旋钮所在侧避让；语言选择用
  独立长按钮，禁止伪装成 on/off。
- **九宫格边界**：含弧形外框/关闭占位圆/花纹等定位细节的整张面板必须 `SIMPLE+CUSTOM`；
  只有明确可拉伸的无细节底纹才 `SLICED`（SLICED 会把面板上的图案拆散搬到别处）。
- **注册三件套**（新视图）：①目录 `app-bundle/app-view/<page|pop>/<name>/{native,resources}/`
  （native .meta isBundle+bundleName）②executor IViewName 注册 ③TS 组件 find-first。
- **底板烘焙残留**：面板源图里烘焙的关闭圆等占位与独立可点击控件重叠时，只留一枚
  （独立 close 精确覆盖占位圆；子弹窗打开时隐藏底层面板防透出）。

### 阶段 5：视觉 QA 闭环（门禁 = 还原视觉基线）

- 截图必须来自**正式构建**（`debug=false`）与真实 UIManager 节点，不用编辑器预览或静态
  合成图代替；同 prefab 多状态**逐状态截图**。
- 节奏：首轮 426×960（或最小画幅）查结构/透明边缘/文字 → 通过后再跑三档画幅 + 英/德/法
  + 安全区模拟（顶 44px/底 34px）→ 避免 在错误布局上批量生成无效证据。
- 多图只看最长边 ≤1280px 的**压缩联系表**；同一图片不重复查看（长任务防膨胀）。
- 环境陷阱：换构建后**换新端口建立新 origin**（同源缓存会复用旧 bundle 冒充新构建）；
  分辨率批次用隔离 Chrome profile 或 `Storage.clearDataForOrigin` 重置测试存档（连续点击
  耗尽体力会弹窗拦截截图，不得误判为页面通过）；WebGL 未稳定渲染会截到全黑，等待后重截。
- 每张截图对照效果图记录差异，区分：真实数据差异 / 底层页面差异 / 刻意产品差异 / 未完成偏差。

### 阶段 6：固化与交付（门禁 = 美术可编辑 + 证据齐全）

- 代码动态路径 → 按 `prefab-bake` 模块七步烘焙回 prefab（多分辨率门禁含横屏极端 case）；
  prefab-first 路径 → 确认运行时零布局代码、Widget 锚定齐全。
- 构建规约：Windows 用 Start-Process 分离 stdout/stderr（EPIPE）；单实例构建（并发构建
  会堆积进程互写 build 目录，产物混合多源状态——构建前清进程+删产物目录）；以
  `build Task Finished` + Asset DB 恢复 + 真实发布页截图为成功证据。
- 交付报告：修改文件与备份目录 / 复用清单与目标路径 / 截图与联系表路径 / 母版差异量化
  （可注明 SSIM/RMSE 及其主因）/ 多语言·分辨率·安全区结果 / 构建日志状态 / 未进入的下一页。
- 工程非 Git 时不用 Git 回滚；改前显式备份到 `working/reskin/backups/<里程碑>_<时间戳>/`。

## 执行顺序决策（AI 效率优化，需用户授权"自选顺序"时使用）

- **默认**：功能逻辑 + 界面实现先行，烘焙收尾批量做，视觉 QA 烘焙后统一跑——减少构建轮次。
- **约束**：同一界面绝不重复开发（动手前先定 prefab-first 还是代码路径）；每页/每状态
  完成即构建+截图+更新交接，不留大爆炸联调；多 agent 交接时写"唯一入口交接文件 +
  资产清单 + 授权边界（禁止重复生成已有资产）"，接手方从断点继续而非从零重做。

## Cocos 编辑器实时通道

Creator 3.8.x 的编辑器操作与中间自检可按 `modules/cocos-mcp-channel/SKILL.md` 执行；2.4.x 或无 MCP 时走本模块文件级/CLI 路径。预览、编辑器引用检查和正式构建/设备验收分别记录证据。
