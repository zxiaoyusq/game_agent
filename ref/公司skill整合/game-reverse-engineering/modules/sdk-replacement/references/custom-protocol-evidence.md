# 自定义协议与离线响应契约

> **何时读我**：发现真实业务不是纯 HTTP JSON，或离线 seed 需要还原帧结构与内容契约。
> **读完能做到**：从受控触发动作对齐包边界，验证魔数/长度/端序/类型字段，建出消息状态机，并用本地夹具交付协议字段表与正常/失败/截断结果。
> **范围**：`GENERALIZED_PATTERN`

范围：`GENERALIZED_PATTERN`。适用：真实业务并非纯 HTTP JSON，或离线 seed 需要还原帧与内容契约。普通域名隔离继续原流程。

1. 把受控触发动作、连接/进程、方向、时间戳与 payload 对齐。TCP 是字节流，包边界不等于消息边界；UDP 需区分消息、分片与应用重传；HTTP/2/WebSocket 等先由协议层还原内容。
2. 用多条消息检验魔数、版本、长度含义、端序、type/opcode、seq、压缩、校验字段。高熵不能区分加密与压缩；TLS 流量不可见时标记可见性限制，不能据此宣称无联网。需要应用明文时只观测已证明的序列化/解码边界。
3. 解析器用长度上限与剩余字节检查，记录未知类型/尾部，验证零长度、截断、多帧拼接和分片。不因一份样本通过就推广到全部版本。长度包括头还是体、CRC 覆盖范围都由证据证明。
4. 建立消息状态机：握手/就绪/请求/响应/重试/失败/关闭以及 request-response 关联。离线替代保持当前 schema、错误语义和原 owner 提交边界；不能用固定成功帧覆盖未理解的资格、广告奖励或支付状态。
5. 优先在本地夹具回放，仅在已授权环境验证网络动作；nonce/会话/时间戳失效不等于业务算法失败。保留原始脱敏样本哈希、解析结果、版本和未解析字节。

交付包括协议字段表、状态机、捕获可见性、正常/失败/截断夹具与结果。继续执行主模块真机 DNS/TLS/HOST 门禁；能解析 payload 不等于原厂连接已隔离。
