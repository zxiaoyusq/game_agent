# 关卡图片与配文映射审计（GENERALIZED_PATTERN）
> **何时读我**：每关图片和配文对不上 / 剧情错配 / 要做关卡图片配文审核编辑器
> **读完能做到**：分清结构审计和语义审计，产出三联表与无依赖的本地审核编辑器，走白名单加原子替换的安全回写，并在 Web 与 APK 产物级复核改动
> **范围**：`GENERALIZED_PATTERN`

适用于按关卡展示图片、标题、剧情配文、出处或多语言文本的 Cocos 项目。目标是回答两个不同问题：

1. **结构是否正确**：关卡顺序、图片引用、语言键和最终产物是否完整一致。
2. **语义是否正确**：玩家实际看到的图片主题，是否与配文和出处真正相符。

结构 PASS 不能代替语义 PASS。文件名、数组下标或键数量全部正确时，仍可能存在“文字写在正确编号上，但内容描述了另一张图”的错配。

## 1. 先找到四个真实真值源

不要先按文件名猜映射。沿运行时调用链确认：

- **显示顺序**：当前关卡 ID 如何映射到配置项，是否存在 0/1 基索引、章节重排、解锁表或远程覆盖。
- **图片身份**：配置最终传给资源加载器的路径、UUID、bundle 和 SpriteFrame；注释和文件名只作辅助。
- **文本身份**：标题、配文和出处对应的 i18n key，缺失键是否回退默认语言。
- **交付产物**：Web bundle 和 APK 内实际打包的数据副本。源码正确不证明产物已更新。

先画出最短链路：

```text
level id -> runtime config -> image asset
         -> i18n key      -> caption / source
         -> build pack    -> Web / APK runtime
```

若存在远程配置、Seed、热更或设备缓存，把每一份都列入版本谱系，不能混称同一真值。

## 2. 结构审计

对完整关卡集合生成机器可读报告，至少断言：

- 关卡 ID 唯一、连续或符合产品定义，缺失和重复分别列出。
- 每个配置项能解析到存在且可解码的图片；记录真实路径、UUID、尺寸和 SHA-256。
- 图片引用顺序与运行时显示顺序一致。不要默认 `imageIndex == levelId`，必须由执行路径证明。
- 每个关卡的标题、配文和出处键均存在；对每种语言分别统计自有键、回退键和最终有效键。
- 注释中的图号或章节名只做审计提示，不作为运行时正确性的证据。
- Web 与 APK 提取出的映射和源码做语义比较；压缩、哈希命名或序列化格式变化不应被误判为内容差异。

结构报告应输出明确计数，例如：

```json
{
  "level_count": 0,
  "missing_ids": [],
  "duplicate_ids": [],
  "missing_images": [],
  "image_mapping_mismatches": [],
  "locale_missing": {},
  "artifact_mismatches": [],
  "structural_pass": false
}
```

数字只是结构证据，不要据此写“全部图片和故事完全匹配”。

## 3. 语义审计用三联表

为人工逐图审核生成一行一个关卡的数据集，至少包含：

| 字段 | 规则 |
|---|---|
| stable_id | 锁定，不允许编辑器自动重排 |
| display_order | 真实显示顺序 |
| image_preview / image_path | 使用项目原图或只读缩略图，不生成替代美术 |
| image_uuid / sha256 / dimensions | 用于确认资产身份 |
| config_title | 配置标题或章节提示，仅作辅助 |
| caption_current | 当前玩家可见配文 |
| source_current | 当前出处、章节或引用 |
| review_status | `UNREVIEWED / MATCH / NEEDS_EDIT / CONFIRMED` |
| caption_proposed / source_proposed | 人工修改区 |
| image_proposed | 可选高级字段，默认锁定 |
| reviewer_note | 记录画面主题、争议和证据 |

人工判断必须同屏看到**图片、配文、出处**。大批量内容按章节或固定批次审核，并保留断点；随机抽样只能发现问题，不能证明剩余关卡语义全部通过。

当内容来自宗教、历史、IP 剧情或外部文本时，出处必须以用户指定的权威版本为准。不能让模型凭记忆补写引用后直接回写工程。

## 4. Excel 与本地编辑器的选择

- 少量条目、主要批改文字：UTF-8 CSV/XLSX 足够。
- 数百张图片、核心任务是看图判断：优先本地编辑器，提供缩略图导航、大图、文本和审核状态。
- 无论界面形式如何，底层都使用同一份可导出 JSON，避免 UI 状态成为唯一数据源。

本地编辑器建议：

- 只监听 `127.0.0.1`，图片目录只读。
- 左侧缩略图/搜索/状态筛选，中间大图，右侧配文、出处、状态和备注。
- `保存草稿` 与 `写入工程` 分开；草稿不得自动覆盖源码。
- 默认只开放配文、出处、状态和备注。图片映射、拼图规格等放入明确的高级模式。
- 支持导出 JSON/CSV；关闭前提示未保存修改。
- 不把程序生成占位图写入游戏资产。审核缩略图只能由原图等比派生，并且不参与构建。

### 可复用的最小 HTML 编辑器

本模块提供 `assets/content-mapping-editor/`，包含一个无 npm 依赖的单页 `index.html`、Python 标准库本地服务、示例配置和双击启动脚本。复制到项目 `working` 目录后，先按当前 schema 修改 `editor.config.json`。当前适配器识别 `levelConfigs` 中的 `imagePath/width/height/time` 与 `quote.N.text/ref`，不是任意 TypeScript 的通用正则回写器。

面向非程序人员时，界面文案应使用“固定编号、通关配文、出处、保存草稿、预览并写入”等自然语言。解析字段名和哈希只放在高级说明或错误证据中，不作为主操作词。

扩展性门禁：

- `expected_levels: 0` 表示动态发现关卡数，不能把历史数量写死为产品上限。
- 页面定时检查源文件哈希；没有未保存内容时自动重载，有未保存内容时先提示保存，不能静默覆盖。
- 新关卡缺 `quote.N.text/ref` 时仍应载入并标记“待补全”；正式写入时才要求图片、配文和出处完整。
- 新文案键只能在已验证的字典结尾追加；写回后重新解析，确认关卡数和三联字段语义全等。
- 530、89 等既有数量只能作为某次验收证据，不能成为编辑器逻辑常量。
- 530 张大图不能在首屏一次加载。缩略图必须用 `IntersectionObserver` 做浏览器可视区惰性观察，仅请求附近的原图，不在磁盘生成替代资产。

## 5. 安全回写合同

写入工程前必须满足：

1. 备份所有将修改的配置与本地化文件，并记录原始 SHA-256。
2. 只更新白名单字段，保持 stable ID、未知字段、注释、UTF-8/BOM 和换行风格。
3. 正确转义引号、反斜杠和换行；用真实中文路径做一次读写回环。
4. 检查 ID 缺失/重复、空配文、无效图片、重复图片映射和语言键冲突。
5. 先生成预览 diff，列出每个变化的关卡、旧值和新值；用户明确执行后才写入。
6. 写入采用临时文件加原子替换；失败时不留下半写文件。
7. 二次导出并与编辑器草稿做语义全等比较，证明没有丢字段或错位。
8. 图片映射变化若会影响 meta/UUID、图集或 bundle，转交资源管线验证，不把改文件名当作完整修复。

不建议制作跨项目通用的正则回写器。不同项目的 TS/JSON/表格结构差异大，应复用本合同，针对当前 schema 写小型适配器并用夹具验证。

## 6. 构建与运行时复验

回写后依次验证：

- TypeScript/JSON 解析与项目静态门禁。
- Cocos 正式 Web 构建，确认产物时间和特征值更新。
- 使用全新 Chrome profile 或新 origin，避免 Service Worker/CacheStorage 复用旧文案。
- 对每个已改关卡保存“图片+配文+出处”同屏截图，并检查 console error。
- 构建 APK 后从包内提取目标配置，重复结构审计并与 Web/源码做语义 diff。
- 模拟器/真机走真实关卡路径，不能只用控制台强设 Label 代替运行时映射。
- 若修改图片映射，额外验证关卡内拼图、通关弹窗和相册等所有消费者使用同一张资产。

## 7. 报告边界

至少分别给出：

- `STRUCTURE_PASS/FAIL`：编号、路径、键、语言和产物一致性。
- `SEMANTIC_PASS/FAIL/PENDING`：逐图人工审核覆盖率与未决条目。
- `ARTIFACT_PASS/FAIL`：Web/APK 是否包含已批准的新值。
- `RUNTIME_PASS/FAIL`：真实路径同屏显示是否正确。

若只完成结构检查，最终结论必须写 `SEMANTIC_PENDING`，不得写“未发现错配”或“全部正确”。已发现的少数语义问题也不能在没有逐图证据时外推为“大多数都错”。
