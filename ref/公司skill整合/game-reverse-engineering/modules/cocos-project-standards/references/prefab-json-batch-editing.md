# Prefab 内容替换与 JSON 批量编辑

> **何时读我**：要用另一个 prefab 的版式**替换**现有 prefab 的内容、要给已有 prefab **注入组件**、要**批量改**所有 prefab 的某个字段（如文字换行/溢出策略）时。
> **读完能做到**：在不破坏注册路径与外部引用的前提下替换内容；用"解析→改字段→原样写回"做字节级最小 diff 的批量修改，并能自证精准。
> **范围**：`[COCOS]` 方法论（prefab JSON 序列化与 index 引用是引擎行为）+ `[DADA]` 具体项目值。

**本文件两条主线的共同前提**：`.prefab` 是**文本 JSON**，可以程序化编辑；**但必须是"改字段"而不是"重写文件"**，否则每次改动都会把整个文件洗成一行/重排，diff 失去意义、合并必冲突。

## 1. 前置校验：JSON 往返必须字节一致

**动手前先证明"解析→序列化"是无损的**。不证明就批量写回 = 赌 43 个文件的格式不被洗。

```python
# 读原文 → json.loads → 再 dumps 回同样格式 → 与原文逐字节比较
orig = path.read_text(encoding="utf-8")
obj = json.loads(orig)
again = json.dumps(obj, indent=2, ensure_ascii=False)
assert again == orig          # 必须相等，否则不要用"整体重写"路线
```

实测结论 `[DADA]`：来源工程的 prefab 是**2 空格缩进的多行 JSON**，`json.dumps(indent=2, ensure_ascii=False)` **往返字节完全一致**（9365 → 9365，0 行差异）→ 可以安全地"解析→改字段→原样写回"，diff 只会是改动的那几行。

**若往返不一致**：改用**文本级替换**（对目标行的字符串做 replace），或在写回时保留原始缩进/键序。

## 2. 批量改字段的四步法

| 步 | 动作 | 判据 |
|---|---|---|
| 1 **侦察** | 统计目标文件数、含目标节点的文件数、节点总数、**现有取值分布**、文件缩进格式 | 能说出"N 个文件 / M 个节点 / 现值分布 / 缩进" |
| 2 **查声明** | 枚举值/字段名**去引擎声明文件（`cc.d.ts`）确认，禁止猜** | 能引用声明的枚举定义原文 |
| 3 **改+写回** | 只改有差异的字段；保持原缩进与键序 | — |
| 4 **复验** | 重新扫描：目标字段**零残留旧值**、解析失败 0 | 计数全绿 |

**第 2 步是核心**：`[DADA]` 实例——把文字溢出策略改成"超框缩字号"时，枚举值是查引擎声明确认的，不是猜的：

```ts
// cc.d.ts（Creator 3.8.x）
export enum Overflow { NONE = 0, CLAMP = 1, SHRINK = 2, RESIZE_HEIGHT = 3 }
// Label 的自动换行开关字段：
_enableWrapText: boolean
```

（`SHRINK = 2` 即"超框自动缩小字号"。不同引擎版本可能不同 → **每次查当前版本**。）

## 3. 用 diff 规模自证"改的是字段而不是重写"

**批量改完必须看 diff 的增删行数，并与预期改动数对齐。**

`[DADA]` 实测：`31 files changed, 291 insertions(+), 291 deletions(-)` —— 正好等于 **282 处换行 + 9 处溢出**，且**无整文件重排**。样例 diff 也只有那两行。

**判据**：`insertions == deletions == 预期改动处数` 且没有大段上下文变动 → 通过。若行数远大于预期，说明发生了重排，必须回滚重做。

**另一个必查点**：**显式换行要保留**。关掉"自动换行"（`_enableWrapText=false`）**不应**动到文本里的 `\n`（如 `'装扮已解锁\n新衣服可以穿啦。'`）。验收时专门确认这类多行文案仍在。

## 4. 用另一个 prefab 的版式替换现有 prefab 的内容

### 4.1 核心手法：保留目标的 `.meta`（uuid）`[COCOS]`

**替换** `assets/.../Target.prefab` 的**内容**为另一个 prefab 的结构时，**必须保留 `Target.prefab.meta` 原样（uuid 不变）**。

收益（`[DADA]` 实测）：该 prefab 的路径注册（`regUI(..., {prefab: "..."})`）与预加载清单、以及所有外部引用**零改动**：

```
LevelUp.prefab  ← 内容换成另一版式，meta uuid `17a12c4b…` 不变
  → LevelSystem.regUI(LevelUpUI, {prefab:"lobby/ui_prefabs/LevelUp"}) 零改动
  → Stage 预加载列表零改动
```

**反例**：换掉 meta（新 uuid）→ 所有引用它的地方（脚本注册、prefab 嵌套、场景）全部断链，且断链往往到运行期才暴露。

**连带必做**：根节点与内部命名改成目标语义名（否则"文件名是 A、根节点叫 B"，后续检索与校验全乱）。

### 4.2 必查：`__id__` 索引引用与重映射 `[COCOS]`

prefab JSON 是**单数组 + `__id__` 整数索引引用**，不是 uuid 引用。

- **删除数组中间元素 → 必须重映射所有 `__id__`**，否则引用错位（指向别的组件，且多数情况下静默不报错）。
- **`PrefabInfo.asset` 会自引用 prefab 自身**。`[DADA]` 实测该字段用的是 `__id__` 索引引用，所以**不需要**改自引用；但若你在别的工程/版本里见到它写的是 **uuid**，覆盖内容时**必须改写为目标 prefab 的 uuid**。
  > 判据：先确认这个字段里装的是整数索引还是 uuid 字符串，再决定要不要改写。**不要凭"应该有自引用"就改。**

### 4.3 必查：目标 prefab 是否缺框架需要的组件

**替换过来的 prefab 很可能没有目标工程的 UI 控制器组件**（源工程用别的脚本驱动）。

`[DADA]` 实测：源 prefab 是纯排版预制体（无控制器），而目标工程的框架靠 `regUI` 从 **prefab 根节点 `getComponent`** 取控制器 → **不注入组件，框架拿不到任何东西**，界面打开即无行为。

**做法**：**从 git 历史里取出旧 prefab 的该组件条目**照抄字段集（最稳），再重新绑定 `@property` 到新节点。

```
git show HEAD:assets/.../Target.prefab   →  取旧组件序列化条目
```

**顺带纪律**：若为对齐工程惯例补了**超出请求范围**的组件（如按钮音效），**必须在交付里显式声明并给出撤销选项**——不能默默改。

### 4.4 `@property` 重绑与对外接口

- 组件注入后，把每个 `@property` 重新指到新结构的对应节点。
- **对外接口（`onOpen` / `onClose` 签名、导出的接口类型、公开方法）保持不变**：这是"替换版式但不破坏调用方"的底线。`[DADA]` 实测交付里明确写了"对外接口一字未改"，且逐个列出绑定结果。
- 若新旧结构**语义不匹配**（例：旧是"运行时动态生成的不定长事件行"，新是"1~5 个固定槽位"），**不要硬塞**——这类冲突应当在动手前向用户提出并取得决定。

## 5. 压缩 uuid 的校验/还原 `[COCOS]`

Cocos 在 prefab 里用**压缩形式**写脚本组件类型。需要比对/构造时可自行还原并**往返自检**：

`[DADA]` 实测规则：**23 字符**的压缩 uuid = **保留前 5 字符 + 之后每 2 个 base64 字符 → 3 个十六进制**；**22 字符**形式保留前 2 字符。

自检样例（来源工程实测通过）：
```
e51dacX6UBAwLUIlu++cZlS  →  e51da717e94040c0b50896efbe719952
```

**用法**：注入组件、校验组件类型存在性时，先还原再比对；**必须用一次已知的往返自检证明你的实现是对的**（上例即为自检用例），再拿去批量校验。

## 6. 与编辑器协同（否则改动会被覆盖）

| 事项 | 做法 |
|---|---|
| 让编辑器读入改动 | 触发资源刷新/重导入；或**重开编辑器** |
| **正在编辑的 prefab 标签** | **先关掉**再刷新——否则编辑器可能用内存里的旧副本**覆盖**你的改动 |
| 触发刷新失败 | 编辑器通道可能已断（连接被拒）；不要重试到死，改为落盘 + 请用户重开编辑器 |
| 通过编辑器通道发命令时 | 注意**引号转义**：转义失败的请求根本没发出去（表现为"刷新没生效"）→ 改用脚本文件发 |
| 删除已删除脚本的**陈旧缓存 error** | 打包器对刚删除脚本的一次性陈旧缓存，**通常下一轮编译自清**；确认"之后不再复现"即可，不必当故障 |
| `LF will be replaced by CRLF` 警告 | 写回用 LF、仓库按 autocrlf 归一化 → **正常**，不影响 diff 规模 |

**默认只改你被要求改的文件类型**：若任务说 prefab，就**不要顺手改 `.scene`**；场景里若也有同类节点，**单独问**再做。

## 7. 备份与回滚（必做）

- 备份目录保持**原相对路径结构**，便于按路径覆盖回去。
- 附 **`manifest.json` 记录每个文件改了几处**——这是"改了哪些、改了多少"的唯一凭据，也是回滚时的核对表。
- 交付里给出**一条命令即可回滚**的说明。
- 命名带时间戳（例：`out\backup-prefab-label-<YYYYMMDD-HHMMSS>\`）。
