# 交付自检清单

> **何时读我**：新建工程定稿前、既有工程规范对照完成时、或任何一次规范类交付收口时。
> **读完能做到**：逐项判定交付是否完整，知道哪些项必须跑脚本、哪些必须登记为未知。
> **范围**：`[COCOS]` 为主。

## 0. 使用说明

清单分三张，**按任务类型选一张**，不要全跑：

| 任务 | 用哪张 |
|---|---|
| 新建工程，要立规范 | 清单 A |
| 既有工程，要评审/对照规范 | 清单 B |
| 任何一次的日常提交 | 清单 C |

**判定用词只有四种**（与全局执行协议一致）：`PASS` / `FAIL` / `BLOCKED` / `NEEDS_CONTEXT`。
**不允许**用"应该没问题""基本符合"结案。

## 门禁脚本

```powershell
# 结构性门禁：命名 / 目录 / 派生文件是否被手改 / 事件成对 的机械可判部分
pwsh -File modules/cocos-project-standards/scripts/check_program_standards.ps1 -ProjectRoot <工程根>
```

**边界（必须理解，否则会误判为"全部合规"）**：

- 脚本只检查**机械可判**的部分。命名语义是否恰当、分层是否合理、抽象是否过度，**脚本判不了**，必须人读。
- 脚本 **PASS 不等于工程合规**，只等于"这几类硬缺陷不存在"。
- 脚本覆盖范围见其 `-ShowCoverage` 输出；**未覆盖项必须回到对应 reference 人工核对**。

## 未知清单（必附）

交付任何规范/工程对照成果时，**必须附未知清单**（模板见 `references/unknowns-ledger-template.md`），至少包含：

- 本模块各 reference **末节"未取证项"** 的汇总
- 目标工程中**无法判定**的项（缺文档、缺权限、缺运行环境），写明"缺什么才能继续"
- 来源文档的**矛盾项**及其**本模块采用的裁决**与理由
