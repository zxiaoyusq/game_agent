# 多语言规范（取词与文案链路）

> **何时读我**：要新增文案、接入语言切换、排查"切了语言没刷新""文案显示成 key"时。
> **读完能做到**：按统一门面取词，正确新增词条，不漏语言切换订阅。
> **范围**：`[COCOS]` 原则 + `[CFW]`/`[DADA]` 具体 API 与工具类。

## 1. 唯一取词入口（最重要）

**原则 `[COCOS]`**：全工程只允许**一个**取词入口，**禁止自实现 `localize` / `t` 助手**，也禁止监听多个语言变化事件。

理由：多处取词入口会导致"缺 key 的处理策略不一致"（有的回落、有的显示 key）、"语言切换只刷新了一半界面"。

来源项目做法 `[DADA]`：

```ts
// 统一经 I18n 门面取词（键缺失时回落到默认文案，{0}/{1} 依次被 params 替换）
const text = I18n.t("SETTINGS_NICKNAME_COOLDOWN", "昵称修改冷却中，{0} 天后可修改", remainDays);
```

门面能力面：`I18n.t` / `current` / `setLanguage` / `resetToSystem` / `isFollowingSystem` / `has` / `onChange` / `offChange` / `availableLanguages`。

**缺 key 的处理口径**：**保留默认文案并告警**，**不要**把 key 显示给用户。

## 2. 新增文案的完整链路

1. 在**多语言配置表**加一行：`id`（= key）+ 各语言列文案 + `Desc`（备注）。
2. 在 UI 用统一门面取词：`I18n.t(key, 默认文案, ...params)`。
3. 若该文案属于某个业务展示字段，**同时**在业务表加对应的 `*_key` 列（见第 3 节）。
4. 跑导表链（见 `config-pipeline.md`）。

**⚠️ 主键陷阱**：多语言表的**主键列不一定是 `id`**——已实测有项目以 `Desc` 为主键 → **新增行必须保证该列唯一，否则导表直接失败**。改表前先确认主键列。

## 3. `*_key` 列模式

**含展示文案的业务表统一加 `*_key` 列，值为多语言表的 `id`。**

| 规则 | 说明 |
|---|---|
| 中文原文列**保留** | 作运行时回退：`I18n.t(key, 中文原文)`，**不得删除** |
| 参数化文案 | 回退文本保留字面占位语义，`{0}` 由词条承载 |
| 无展示消费的字段不加 | 内部定位名、未开发 UI 的展示名，暂不加 `key` 列，避免维护空列 |
| 语言列用 **`PascalCase`** | 业务侧依赖"转大写后与语言枚举比对"；`id` 与 `Desc` 列名固定 |

**注意生成器覆盖**：`schema.ts` 中对新增 `*_key` 字段若存在**手工兼容写法**（`_json_.xxx_key ?? ''`，缺列回落空串），**重跑导表后会被生成器严格版本覆盖**——只要数据文件已含新列即一致；反之会缺字段。改完必须复验。

## 4. 语言切换订阅

```ts
// 订阅返回取消函数；用实例级箭头字段保证 on/off 引用一致
private onLangChange = () => { this.refresh(); };

onAdded()  { this._offLang = I18n.onChange(this.onLangChange); }
onRemoved(){ this._offLang?.(); }
```

**必须成对解除**，且**必须用同一函数引用**——这是 `code-and-naming.md` 里"事件 on/off 成对"在多语言上的具体落地。

**常驻 UI 的简化路径**：用**自动取词刷新组件**（来源项目为 `MultiLanguageText`）挂在节点上，由组件自行订阅与刷新，避免每个常驻界面手写订阅。

## 5. 多语言预制体改造清单（`[COCOS]` 方法论）

把已有界面接入多语言时，按固定顺序推进，避免漏项：

1. **清点**：逐个 prefab 找出所有 `Label` 节点，区分"静态装饰文字"与"业务文案"。
2. **建词条**：业务文案进多语言表，建 `*_key` 列。
3. **改取词**：代码侧改统一门面取词；常驻节点可挂自动取词组件。
4. **防排版崩坏**：不同语言长度差异大（德语复合词、法语操作名是典型压力用例）→ 文字框用 **溢出收缩**策略，长文本**先扩框再收缩**，不要只缩字号。
5. **验收**：每种语言 + 最小画幅各截一次，记录差异（截图验收走 `cocos-qa` + `vision-device-testing`）。

**红线 `[COCOS]`**：**运行时只改文案与状态色，不改版式**。位置 / 尺寸 / 字号 / 对齐 / 溢出策略以编辑器 prefab 为准；运行时按公式重设 `Label` 的 `pos` / `fontSize` / `contentSize` 会抹掉美术调整——这是"编辑器里改了、运行时不一致"的高发根因。
