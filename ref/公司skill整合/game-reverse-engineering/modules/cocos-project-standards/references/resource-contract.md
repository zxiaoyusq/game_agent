# 资源规范（bundle 分域与目录契约）

> **何时读我**：要决定一张图该放哪个目录、新图导入后显示变形/发虚、代码里该用路径还是 uuid 引用资源时。
> **读完能做到**：按用途把资源放对位置，避开图标拉伸这一类高发返工，知道哪些资源可以安全改名。
> **范围**：`[COCOS]`（目录契约方法论、导入行为）+ `[DADA]`（具体目录名与命名，不可复制）。

## 1. 分域总原则 `[COCOS]`

- **单一业务 bundle，按域拆子目录**，不要一开始就拆多个 bundle。拆 bundle 的代价是资源重复与引用跨包失败，收益要到包体真的成为瓶颈时才兑现。
- **判定"是不是 bundle"只看 meta，不看目录名或文档措辞**：Cocos 目录 meta 里 `userData.isBundle === true` 才是 bundle。实测来源项目仅 `assets/bundle.meta` 为 `true`，其下 `lobby/ guide/ modle/ audio/ common/ config/` 的 `userData` 均为 `{}` → 它们是**同一 bundle 内的资源域**，不是多个 bundle。
  > 文档缺陷提示：来源项目的 `目录结构规范.md` 把这些域称作"bundle"，与真实 meta 不符。**写规范时不要沿用这个措辞**，否则后续会有人真的去建多个 bundle。
- 典型分域（可按项目调整，但**每个域必须有明确判别依据**）：

| 域 | 内容 | 判别依据 |
|---|---|---|
| `lobby/` | 主流程 UI 预制体与图片 | 主流程可达 |
| `guide/` | 新手引导 UI 预制体 | 只在引导期加载 |
| `modle/` | **模型类资源**（角色骨架、背景、挂件、道具模型） | 渲染层次与 UI 图标不同 |
| `audio/` | 音频 | — |
| `common/` | 跨域通用（公共 UI、通用预制体、公共图片、动画、特效、材质、着色器、纹理） | 被两个以上域使用 |
| `config/` | 配置资源（`data.json`） | 启动即需 |

## 2. 图片按用途二分 `[COCOS]` 原则

图片先分两大类，**不要混放**：

- **图标（icons）**：会被放进卡片/格子/列表项的小图。按业务类别再分子目录。
- **UI 装饰（ui）**：面板、场景底图、进度条、按钮主题等构成界面外观的图。

```text
images/
├── icons/
│   ├── food/      食物图标
│   ├── dress/     装扮图标
│   ├── avatar/    头像 / 形象
│   └── misc/      其它功能图标（入口/功能/表情/礼物/成就）
└── ui/            面板 / 场景 / 进度条 / 按钮主题
```

**为什么这条重要**：图标与装饰的**导入参数要求不同**（见第 4 节），混在一个目录里就无法批量校验。

## 3. 模型与 UI 图标的判别依据（最实用的分界线）`[COCOS]` 原则

**同是 PNG，也可能要放不同目录**，判别依据是**渲染层次**：

| 配置字段语义 | 归属 | 说明 |
|---|---|---|
| `icon`（UI 图标字段） | `images/` 下的图标目录 | 在 UI 层按矩形摆放 |
| 模型字段（`spine_skin` / `back_path` / `model_file` 之类） | `modle/` | 挂在角色骨骼上或作为场景模型，渲染层次与 UI 不同 |

**纪律**：配置表里"图标字段"与"模型字段"**必须指向不同目录**。二者混用会导致同一张图既要当 UI 图标（要求方形不裁边）又要当挂件（要求紧贴内容），两边都做不好。

## 4. 图标导入规范（防拉伸）`[COCOS]`

**症状**：图标在卡片里被拉伸——有的横着胖、有的竖着长。

**根因**：Cocos 图片导入默认 `trimType = auto` → 自动裁掉透明边 → `spriteFrame` 变成**非方形矩形**（实测出现过 176×232、123×233）→ 而卡片格是方形 → 拉伸。

**修法**：把该图 meta 的 `trimType` 改成 `"none"`（保留完整画布），并核对：

```
userData.width  == rawWidth
userData.height == rawHeight
```

**生产规范**：

- 新图标一律**方形**（`256×256` 或 `512×512`），主体居中、四周留**均匀**透明边距。
- 生图得到的 1024² 图，后处理成方形画布（裁掉透明边 → 缩到目标内尺寸 → 补到方形画布，保持居中）。
- **编辑器导入新图后 meta 会再次变回 `auto`** → 导入后**必须再修一次**（用批量脚本扫）。

**⚠️ 改完 meta 必须让编辑器"重新导入"**：`trimType` 只是 meta 字段，`spriteFrame` 子资源要等重新导入才重算 → 表现为体检脚本已不报 `trimType`，但仍报 `trimmed (176,232) != raw (256,256)`——**这时游戏里还是拉伸的**。

触发重新导入的方式（有编辑器通道时）：让编辑器执行 `asset-db refresh-asset` 刷新该目录 → 等约 10 秒 → **复检到全绿（`trimType=none` 且 `w/h == raw`）才算真修好**。通道用法见 `cocos-mcp-channel` 模块。

**已经踩了、要按症状排查时**：走诊断入口 `modules/cocos-creator-repair/SKILL.md`（含其它黑屏根因）；**批量体检/修复脚本属项目级 skill，不在本总集内**。本节只维护"规范怎么做"这一份。

## 5. 引用方式：路径优先于 uuid `[COCOS]`

- **按"路径 + `/spriteFrame`"引用，而不是硬编码 uuid**。
- 收益：**改名安全**，新增图标**不需要改代码**——代码按"业务类别 → 子目录"拼接路径即可。
- **代码里禁止写死已废弃的旧路径**；目录重构后必须同步清理代码中的旧路径常量，否则表现为"图存在但运行时不显示"。

## 6. 格式与落地纪律 `[COCOS]`

- **Cocos 不认 `.webp`** → 外部交付的 webp **必须先转 PNG** 再入工程。
- **压缩工具留下的 `.bak` 必须删掉**，否则会被当资源打进包（体积白涨）。
- **单图**用 `SpriteFrame`；**九宫格**用 `sprite` 的 `type = SLICED`。
  - 注意：含弧形外框、关闭按钮占位圆、花纹等**定位细节**的整张面板**不能**用 `SLICED`——会被拆散搬位。只有明确可拉伸的无细节底纹才可以切片（详见 `ui-feature-pipeline` 模块同名红线）。
- **同名资源在不同 bundle 里是不同资源**，不要跨域复用同名文件，会混淆引用。

## 7. 命名约定 `[DADA]`（样例，不可复制）

来源项目采用的**前缀式命名**（可作为方法论借鉴：让文件名自解释业务类别，便于按前缀批量校验）：

| 前缀 | 类别 |
|---|---|
| `food_*` | 食物图标 |
| `dress` / `hat_*` / `glasses_*` / `shirt_*` / `sweater` / `vest` | 装扮 |
| `avatar_*` / `pet_avatar_*` | 头像 / 形象 |
| `panel_*` / `scene_*` / `progress_*` / `primary_*` | UI 装饰（面板/场景/进度条/按钮主题） |
| 角色骨架目录 `{skin}/yx_{id}` | 模型 |

**可迁移的部分是"前缀表达类别"这一条**；具体前缀词表属项目值。

## 8. 资源落地路径映射（样例）`[DADA]`

来源项目用"美术交付包 → 工程目录"的固定映射，落地前先查界面资源对照表把缺图补齐再拼预制体：

| 来源 | 目标 |
|---|---|
| `art/**/assets/{asset}.png`（切图） | `assets/bundle/lobby/images/{asset}.png` |
| `art/**/assets/pet/{asset}.png`（部件） | `assets/bundle/lobby/images/pet/{asset}.png` |
| 角色 Spine | `assets/bundle/lobby/modle/pet/{petSkin}/yx_{id}` |

**可迁移的是"先补资源再拼预制体"的顺序纪律**，路径为项目值。
