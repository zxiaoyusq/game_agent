# 通用二进制容器逆向方法论（未见格式的标准打法）
> **何时读我**：拿到一个没有社区工具、没有文档的私有容器或资源格式，需要在 30 分钟内定出打法时。
> **读完能做到**：按四步法（头部侦察 → 锚点定界 → 字段语义验证 → 参照实现互证）定长表/变长记录与偏移量纲，并照无效穷举陷阱清单先排掉八类必废的跑法，再决定是否上穷举。
> **范围**：`GENERALIZED_PATTERN`

适用场景：拿到一个没有社区工具/文档的私有容器或资源格式。本卡是从 12+ 款游戏实挖中提炼的可复用流程；引擎专属细节在各 `engine-*.md`。

## 四步法

### ① 头部侦察（30 分钟定大方向）

- **先找 magic**：文件头 16-32B hexdump；六进制搜索引擎（GitHub code search / Google `"hex bytes" filetype`）+ 已知引擎族谱（同一厂商历代格式往往同构——如 Anvil ver27/28 同布局、RE Engine 历代同 pak）。
- **版本号位置**：头内 ver 字段 + 扩展名数字（RETool 扩展名 = 内部版本号）+ 文件名变体对拍（**六个以上同类文件对拍**，恒定字段 = magic/常量，变化字段 = 实数据）。
- **定长表 vs 变长记录**：算 `count × 候选条宽` 是否正好等于下一段偏移——对得上是定长表（好解）；对不上必有变长记录（如 FO4 DX10、R6S v34）。
- **偏移量纲检查**：偏移是字节还是"块"（R6S v34 用 4KB 块空间，物理位置 = 块偏移 × 0x1000）。偏移全部落在文件尾（名字表贴 EOF）说明表区/数据区顺序与直觉相反。

### ② 锚点定界（变长记录的解法）

- **找分隔魔数**：`BAADF00D` 式记录分隔符出现 = 记录边界锚点（FO4 DX10 实测）。
- **已知明文特征**：扩展名字符串（'dds\0'）、内部 magic（'DDS '/'Oodle'）在流中的固定相对位置 = 下一条记录的 lookahead 判据。**探 lookahead 必须覆盖特征的真实偏移**（特征在 +4 处却只探 4B 会恒失配）。
- **首尾完整性**：记录区结束处无终止符、直接切数据区（FO4 DX10 末条记录后即数据）——把"校验失败"当"表结束"处理，别让末条记录毁掉全表解析。
- 每条记录解析后**立即自验证**（偏移递增、off<文件长、ps≤us），失步立即停下 dump 现场，不要带病走完全表。

### ③ 字段语义验证（拒绝脑补）

- 字段语义用**物理约束反推**：w/h ∈ {64…4096}、DXGI 格式 ∈ 已知集合、块数 = mip 链理论值、sum(块长) ≈ 资源长 − 表长。
- 拿**小样本手工解剖**（几十条记录的文件）钉死布局，再上大文件；两个不同来源的文件交叉验证同一布局（ver1/ver7 同构 = 布局可信）。
- **输出体积 = 理论值逐字节吻合是最终自验证**（DDS mip 链和、FLVER 面数 vs OBJ 实测、glb accessors 实数）。对不上就是字段语义错了，不要硬写。

### ④ 参照实现互证（有社区代码时）

- **编译权威实现跑同一输入，与自研 python 逐字节 diff**（星铁 Mr0k 的金标准方法）——"自己测自己 PASS"不算数，两实现各错各的。
- 公式字节指纹搜索**因编译器变形不可靠**（lea 替代 sub），只能当辅助；密钥/算法优先找开源实现里的硬编码材料（米哈游 mhy1 全系密钥都在 Escartem 源码里）。

## ★ 无效穷举陷阱清单（开跑前必过，一轮 16.2 万候选×2 游戏全废的教训）

1. **异常吞噬 = 静默全废**：候选循环 `try/except: continue` 包住整个解密+验证——解密器对每个候选都抛异常时，结果 100% "无命中"且速度看起来正常。**必须统计"异常数 vs 完成数"，完成数≠候选数即停下来查**。
2. **验证流截断**：验证解压只喂了缓冲区里已有的前 1KB，真实流 = 解密区+后续明文 33KB——**任何 key 都必然失败**。验证器必须先用已知可解样本证明能输出 TRUE。
3. **结构假设未验先跑**：把 A 格式布局套在 B 格式上。先小成本证明结构（签名校验、字段合理性），再上穷举。
4. **红鲱鱼指纹**：已知明文反推出的"keystream"可能是别的字段的巧合 XOR。反推结果要**第二处独立证据**再当路标。
5. **双实现互证**：单实现的"已验证"不可信，两实现跑同一输入必须同输出。
6. **性能姿势**：python 千级候选可以；百万/亿级滑窗用 native C++（MSVC /O2 + std::thread，内联解压/AES）；全库字节扫 + 解压快速失败判据是通用姿势。扫描类任务**先读 4B 验魔数再读全文**。
7. **对齐前置验证（AC3R 教训，2026-10-10）**：宣称某资源"是声明式引用/数据在别处"之前，**先穷举解析起点**（0..32 + 所有 magic 偏移各试一次，用领域量（顶点数/面数/宽高）判定哪个起点产出合法结果）。AC3R 一个"补 16 字节对齐"的错位让整轮判定反了，白扔一轮。
8. **小样本不代表格式**：单件最小文件（如 306B 的 LOD0 占位件）往往是**特例**。至少 3 件、跨 2 个数量级体积复现后再下结论；"所有样本都失败"时优先怀疑自己的解析器，而不是格式。

## 跨语言桥接（python 调 .NET 库的成熟姿势）

- **pythonnet 加载 net6+ 程序集**：`pythonnet.load('coreclr', runtime_config=<运行目录>/xxx.runtimeconfig.json)`——默认 netfx 加载不了 net6 程序集（TypeLoadException System.IO.File）。
- `DOTNET_ROOT=<sdk路径>` + `DOTNET_ROLL_FORWARD=LatestMajor`（库要 net9 本机只有 net10 时的兼容招）。
- AssemblyResolve 白名单劫持（System/netstandard/Microsoft 开头不劫持）；**引用目标类型的首个调用要隔离进 `[MethodImpl(NoInlining)]` 方法**，否则 Main 的 JIT 在 resolver 注册前解析类型 token。
- 反射调用（`GetMethod`）比命名空间 import 稳；UInt64()/Enum.Parse 显式转换；dll 依赖版本不齐时用现有 dll 改名顶替（Oodle 各代 API 向下兼容）。
- 私有程序集 `Private=false` 不进 deps.json 且不探测 app base → 见 engine-tiger.md 坑 1。

## 作业铁律（资产保全与长任务）

- **解包工具没跑通之前，先把原始资产包整体拷 E 盘**（python shutil 多线程最稳；robocopy 会被 bash→cmd 中文路径坑死）；含断点续传；完成后**源/目标数量核对**。游戏卸载后解包工作随时可续。
- **后台 python 长任务一律：多进程 + try/except 容错 + flush 进度 + 幂等可重跑**（单进程遇坏条目会静默死）。
- 临时文件一律放项目目录（C 盘 temp 写满会让整批任务静默失败）。
- cmd 传参：路径不带尾部反斜杠；**含中文的 bat 不能用 Write 工具直接落盘**（UTF-8 被 cmd 按 GBK 读必炸，须独立 .py 以 encoding='gbk' 重写）；bash→cmd 中文引号转义必炸——一律 python subprocess 列表传参。
- **含中文路径目录下的 .bat 无法被 subprocess 调用**（cmd.exe 按 GBK 解析，报 `'E:\download\ȥ�ع���' is not recognized`）。正解：绕开 .bat，直接调它包装的解释器，如 `blender-*/4.2/python/bin/python.exe -B main.pyc <args>`。
- **子进程 stdout 是 UTF-8、本机 python stdout 是 GBK** → 转发日志必 `UnicodeEncodeError: 'gbk' codec can't encode`。正解：`sys.stdout.reconfigure(encoding='utf-8', errors='replace')` + `PYTHONIOENCODING=utf-8`。
