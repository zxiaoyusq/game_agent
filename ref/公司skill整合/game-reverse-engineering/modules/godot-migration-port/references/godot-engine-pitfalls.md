# Godot 引擎行为坑集（GENERALIZED_PATTERN）

> **何时读我**：哥哥在 Godot 移动端（尤其 `gl_compatibility`）上撞到"接好了但不显示/点不动/没反应/有杂音"，比如粒子整组不渲染、按钮命中被别的层吃掉、返回键点了两秒没动静、生成器把美术排版覆盖掉，需要先查现成坑再自己排查时。
> **读完能做到**：按 11 条已实测坑逐条定位症状与判定顺序（先查渲染后端再看层级、先 dump 树序别调 z_index、先分清一次性台阶与每关累积），并知道每条的正确修法方向，避免在错误的对象上做优化或加自愈掩盖根因。
> **范围**：`GENERALIZED_PATTERN`

来源：jigsawcard（Unity 6000.3.16f1 → Godot 4.6.2）一个月迁移与实机迭代（2026-09-11 ~ 10-11，脉络见项目 `docs/DEV_HISTORY.md`）。新增规则更新至 2026-10-12，证据层级以案例记录为准，桌面检查不等同 Android 验收，迁移或二开 Godot 工程（尤其移动端 `gl_compatibility`）时先查这里。

## 1. gl_compatibility 后端下 GPUParticles2D 不渲染

Mobile 渲染选 `gl_compatibility` 时，`GPUParticles2D` 在实机/模拟器上可能整组不显示（MuMu 实测：结算烟花完全消失，无任何报错）。迁移 Unity ParticleSystem 时若目标后端是 gl_compatibility，**直接转 `CPUParticles2D`**（本案例脚本转换 30+27 个发射器一次完成）。判定顺序：粒子"接了但不显示"先查渲染后端，再查层级与触发链。

## 2. GUI 点击命中按场景树顺序，不看 z_index

Godot 的 Control 命中测试按**场景树顺序**（树中靠后者后处理、先命中），与 z_index / 绘制层级无关。实测：`CalendarContainer` 在树中靠后，整块吃掉点击，奖杯 icon 画得再对也"点不动"；调整树序修复，z_index 无效。排查"按钮无反应"先 dump 树序，别先调 z。

## 3. 导航不能被入场/回弹演出挡住

实测主页返回：按钮回弹补间未结束不发 `back_clicked`（实测 631 ms）+ 首页 `AppearSlow` 前 0.5 s 全透明 → 用户感知约 2 s"没反应"。修复：返回立即导航、入场改 `AppearFast` → 约 1.0 s 可见。规则：**导航信号与演出解耦**（演出可被打断），入场动画首帧不许全透明。

## 4. 生成器不得写运行时排版

代码生成器重跑会覆盖编辑器里人工调好的 prefab 排版（位置/尺寸/行高）。分工：生成器只拥有"资源引用与节点结构"，**运行时排版由编辑器层拥有**（生成器不写），并用仓库级审计与回归门禁防回归。

## 5. 动态字体 fallback 要按主字体度量规范行框

`LocalizationService` 的字体 fallback 链会按 fallback 字体度量撑高行框：首页 90 px 标题行高实测 131 → 191。修复：按主字体 ascent/descent 计算 fallback 行框（1,890 项检查通过）。多语言工程上线前按最长语言文本全页面过一遍行框。

## 6. 多语言全量翻译的启动成本

977 词条 × 31 语言用默认 Translation 初始化 p50 605.61 ms；换 `OptimizedTranslation` 后 41.14 ms。多语言 Android 工程必须单独测"翻译初始化"在冷启动里的占比。

## 7. 内存台阶的口径

实测"首次进入一级页面"产生一次性内存台阶（资源首次装载），不是每关重复成本。优化前先分清台阶是"一次性"还是"每关累积"，否则优化错对象。

## 8. 导出与 ADB 互斥

Godot 导出 APK 会打断 ADB 服务，导出后需重新 `adb connect`。禁止同时进行"打包"与"操作设备"两类任务（多 agent 并行时尤其容易互相踩）。

## 9. 接缝与跟随异常先修写入者，再用看门狗验收

区分图集采样裂缝与实际节点未到位。相邻切片用同一整数边界，静止拼合后严格检查 position、size、scale；运动中核对局部与全局变换、pivot 和组成员平移，不能把拾取缩放当漂移。

Godot 的视觉 reparent 也会触发退出/进入树。如果 _exit_tree 共用真正离场的 cancel_drag/kill tween，会中断仍未完成的位移。视觉换父与真正销毁要分开；一块拼图同一时刻只有一个位移 owner。准入拒绝应发生在取消原动画或改共享拖动指针之前。

看门狗必须排除整个活动拖动组和正在运行的位移 Tween，不能每隔一段时间把跟随块拉回槽位。修复回归先禁用自愈，证明动画自然到达，再启用看门狗验证长期触发率；不能以“最终被修正”冒充根因已消失。精度阈值与长期步骤数按当前项目定义。

## 10. 音效范围要与业务动作范围一致

多张牌同时翻面却重复叠音时，先查每个调用点及音频真实时长：一个资源可能是整段翻牌序列，不能按文件名把它当单牌短音。批量 owner 与逐物件动画各播一次，会叠成多份整段声音并挤占混音池。

优先由批量 owner 播一次批次声音，逐物件动画可选择不播；独立物件调用保留原默认。不要用全局时间去重、清空所有播放器或缩减混音池掩盖业务重复，这些做法会吞掉连续两次合法操作和其他音效。

QA 拦截实际播放请求并转发真实服务，核对不同物件数、快速两次批次、独立动作与静音开关；另测动画与输入恢复。调用次数测试和真实资源加载不能替代硬件听感或 Android 音频验收。

## 11. 延迟闭包不要直接捕获会销毁的节点

本案例 Godot 执行直接捕获已释放 Node 的 lambda 时，可能先报 freed lambda capture，再进入闭包正文。因此在闭包内加 is_instance_valid 并不足以防住错误。

对会被重建或释放的目标捕获 WeakRef，在回调内先校验 owner 的 generation/epoch，再取 get_ref，核对对象有效且仍在预期场景。引用有效与所属代次有效是两个独立条件，不能仅凭弱引用保留旧关回调。

启用推断警告视为错误时，weakref 返回值使用明确 WeakRef 类型，避免 := 从 Variant 推断触发编译失败。真实离场仍取消 Timer/Tween；弱引用不替代取消 owner。测试覆盖批次中换关、快速重建和离场，并要求无迟到声音、输入锁死或脚本错误。
