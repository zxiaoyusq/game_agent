# Godot 迁移链路义务清单模板（Obligation Ledger）

> **何时读我**：哥哥在 Godot 迁移交付前要逐条确认某件事到底算不算做完，或要在任务开始时实例化一份义务清单时。
> **读完能做到**：按四件闭合条件（唯一 owner / 规定证据类型 / 验证器通过 / 证据落盘）逐条关闭义务，并把「导入成功、节点存在、截图相似、测试全绿」挡在关闭依据之外。
> **范围**：`GENERAL_DEFAULT`

范围：`GENERAL_DEFAULT`。本模板定义 Godot 迁移/重建链路「什么算真正完成」，任务开始时实例化，交付前逐条关闭。

原则出处：根 `SKILL.md` 明言「导入成功、节点存在、截图相似都不能单独证明完成」。本清单把这句原则拆成可逐条勾选关闭的义务。

## 关闭规则

一条义务同时满足四件事才算**已闭合**：

1. **唯一 owner**：负责证明该项的脚本、门禁或责任人已写明。
2. **规定证据类型**：取得的证据与本行声明的类型一致。声明「真机」的不能用静态截图替代。
3. **验证器通过**：脚本门禁或对照检查产生可复核输出（哈希、报告、截图包、回归结果）。
4. **证据落盘**：证据路径写入本清单与交付报告。

缺任何一件即为**未闭合**。「看起来没问题」「模型认为正确」「测试 failures=0 但未覆盖该项」都不是关闭。

状态允许第三种：**已豁免**。豁免需用户明确同意，并写明理由与影响范围。降级省略的能力（如非关键粒子）走豁免，不许静默消失。

## 使用方法

1. 任务开始时复制本模板，按当前项目范围增删义务行。
2. 每行先填「验证方式」，再动手；验证方式写不出来的义务，先登记未知清单（`references/unknowns-ledger-template.md`）。
3. 每完成一项立即回填证据路径与状态，不凭记忆补写。
4. 交付时本清单随报告交付。未闭合项逐条列出，并登记对结论的影响。

## 常见错误关闭（不得作为关闭依据）

- 「导入成功」≠ O-G1：导入器不报错只说明格式可读，不说明身份与引用正确。
- 「节点存在」≠ O-G5：节点树里有节点，不说明可编辑、不残留、不遮挡。
- 「截图相似」≠ O-G3/O-G7：静态相似不说明动画播放、触发点与状态覆盖正确。
- 「测试全绿」≠ O-G7：测试只证明覆盖到的项；未覆盖状态必须显式标待验。

## 与未知清单的关系

义务无法实例化或无法验证时（例如原版动态 payload 缺失），同步登记 `references/unknowns-ledger-template.md`，两清单编号互相引用。交付结论必须同时给出：已闭合义务的覆盖范围、未闭合义务清单、未知清单。
