# 从原版差距到自测回归的还原闭环（GENERAL_DEFAULT / GENERALIZED_PATTERN）

> **何时读我**：发现重制版与原版有差距、要建差距矩阵并定位根因，或要跑静态/逻辑/桌面/Android 四层自测时。
> **读完能做到**：把「看起来不一样」变成可复现、可定位、可回归的差距行，沿证据链找到真实 owner，选最小可验证修复并按四层顺序回填证据。
> **范围**：`GENERALIZED_PATTERN`

适用于 Unity/Cocos 提取物迁移到 Godot 的 UI、Spine、玩法和数据还原。它描述如何把“看起来不一样”变成可复现、可定位、可回归的问题。项目专属的关卡号、包名、坐标、数值、资源数量和截图路径必须写入案例证据，不能复制到其他项目。

本文只负责单个差距的诊断与关闭。项目阶段、交付物、配置来源、最终 APK 和交接以 [Godot 重制端到端生产流程](end-to-end-restoration-workflow.md) 为准。

## 1. 建立可比较的基线

在改代码前固定双方的版本和状态：原版 APK/包哈希、重制 APK/工程提交、包名与 Activity、设备/模拟器、分辨率/方向、设计分辨率、网络状态、存档哈希和当前关卡。原版与重制必须从相同业务状态开始；用户存档和 QA 存档分离，测试结束恢复原存档。

对原版进行人工确认后再录制关键节点：冷启动、主页、进入关卡、发牌、拖动、成功反馈、提示、暂停、结算、下一步、返回大厅和重启恢复。每个节点记录截图或视频时间码、可见文本、输入动作、音效/动画状态和前台包名。设备切到旧包、ADB 重启、前台 guard 失败或录屏时间轴不确定时，证据标为无效，不得用于对齐结论。

## 2. 建立差距矩阵

每项差距独立成行，至少保留以下字段：

| 字段 | 内容 |
|---|---|
| 场景/事件 | 页面、输入或动画阶段 |
| 原版证据 | 截图/视频时间码、静态资源、日志或数据来源 |
| 重制证据 | 同分辨率同状态的截图、录屏、日志或代码位置 |
| 差距类型 | 资源身份、尺寸/坐标、层级、时序、交互、状态/存档、音频、打包/平台、证据污染 |
| 现象 | 可观察的具体差异，不写“感觉不对” |
| 根因假设 | 资源引用、父级变换、owner、事件边界、ABI 或旧产物等可检验假设 |
| 修复责任 | 具体脚本、场景、资源生成器或导入器 |
| 验证动作 | 最小复现、定向测试、实机回归和通过标准 |
| 状态 | 待定位、已修复待回归、已回归、无效证据、待取证 |

先按影响分层：阻断启动/输入/存档的功能问题；影响大面积布局的坐标/资源问题；局部视觉、时序和音频问题；仅文档或证据卫生问题。优先处理能造成后续假差距的版本、存档、前台应用、资源身份和坐标系问题。

## 3. 从现象定位真实 owner

沿一条可追溯链定位：

```text
原版证据 → 资源身份/配置 → 场景节点 → 运行时 owner → 稳定事件 → 业务提交 → 反馈/清理
```

静态文件存在不能证明运行时可达；节点名不能证明它是当前 owner；动画名存在不能证明业务分支会播放。先查加载索引、PPtr、SkeletonData、脚本调用和事件顺序，再做修改。对 UI/Spine 还要单独记录坐标系（CanvasLayer、Control/Node2D、锚点、pivot、父级 scale）和层级（z/sibling/Overlay）。

## 4. 选择最小可验证修复

- 资源问题：先保留源字节和哈希，修正引用链、atlas region、trim/original bounds 或逻辑画布；不要用截图或批量拉伸掩盖身份问题。
- 几何问题：从设计分辨率和完整父级变换重算，分别检查位置、尺寸、锚点、旋转、透明留白和九宫格边距；不要只改局部 scale。
- 动画/层级问题：把固定宿主和时间线写进 `.tscn/.tres`，运行时只更新业务状态和播放参数；跨弹窗效果使用固定根级 Overlay。
- 功能/数据问题：保留原 owner 和稳定提交点，明确输入、前置条件、库存/存档、反馈、奖励和退出清理；同一事件只允许一次提交。
- 延迟问题：每个 Timer/Tween/回调绑定宿主和 generation/epoch，在暂停、离场、换关、下一次输入和销毁时可取消。
- 平台问题：先比较桌面与 APK 的插件 ABI、资源路径、首帧和日志，再进行设备视觉对照；不要用桌面通过替代 Android 通过。

每次只改变一个根因假设相关的最小范围，并先留下失败证据和回滚点。修复完成后先做原问题的最小复现，再扩大到相邻状态；不要在未确认根因时连续叠加延迟、全局扫描或自动替换。

## 5. 自行 QA 的四层顺序

### A. 静态门禁

- 资源 manifest、PPtr/pathID、atlas bounds、SkeletonData、`.tres/.tscn` 引用无缺失。
- 固定宿主只有一个，owner 正确，编辑器重新打开可见可编辑。
- 生成器幂等，重复运行不增加节点、不覆盖用户图、不产生重复 fileId。
- 原图哈希、导入配置、APK 内资源和插件库记录齐全。

### B. 可重复逻辑回归

用确定性 fixture 或回放验证：启动/重载、正常输入、快速连续输入、越界/取消、暂停/返回、末步、奖励幂等、提示库存、下一关、存档写读和跨进程恢复。对连接组等玩法，断言真实拖动后的模型快照、槽双射、组形状、可视坐标和提交事件，不能用 `auto_solve` 或“绝对归位”替代。

### C. 桌面场景与编辑器检查

重新打开场景，检查固定 UI/Spine 的尺寸、锚点、层级、初始动画和可编辑性；运行时连续打开/关闭/重置多次，确认不重复创建、不残留 Timer/Tween/粒子、不遮挡输入。对原版和重制在同一设计分辨率抓早/中/晚帧，逐行回填差距矩阵。

### D. Android 实机回归

构建后核对 APK SHA-256、包名、Activity、版本、ABI、插件库和资源清单；安装的是本轮候选，且前台 guard 始终正确。按真实流程截图/录屏，收集 UI dump（可用时）、OCR、Logcat、设备元数据、存档前后哈希和网络状态。检查冷启动、主页、关键输入、动画首帧/中帧/末帧、暂停返回、后台、杀进程恢复和下一关。出现 `FATAL EXCEPTION`、ANR、native crash、包切换或证据时间轴不确定时，该项 FAIL 或 NEEDS_CONTEXT，不能由视觉猜测覆盖。

## 6. 失败后的定位循环

1. 保存失败截图/录屏、日志、状态哈希和当前构建，不先覆盖证据。
2. 把失败归到资源、几何、层级、时序、owner/状态、平台/ABI、存档污染或旧产物八类之一。
3. 用最小 fixture 重现，确认假设能预测失败；不能预测就回到 owner 和引用链继续取证。
4. 实施一个最小修复，运行静态门禁和原失败步骤。
5. 通过后跑相邻分支与核心回归；尤其检查暂停、返回、重载、重复打开、末步和用户存档是否被污染。
6. 在差距矩阵写入“根因、改动、证据、回归范围、仍未覆盖项”，再决定是否进入下一项。

“无错误日志”“节点存在”“动画名存在”“截图看起来接近”都只能作为局部证据，不能单独关闭一行差距。

## 7. 交付和 skill 回填

每个里程碑形成：差距矩阵、源/目标哈希、修改文件、构建产物、测试命令、实机证据目录、失败与回滚记录。只有重复出现且已在多个边界验证过的做法才抽成 `GENERALIZED_PATTERN`；只在一个游戏、一个关卡或一个录像中成立的内容保留 `CASE_ONLY_*`。达到图片/会话阈值时先写 `HANDOFF.md` 并创建干净续作，避免把上下文或无效录像当作证据继续传递。

## 8. 叠图、色彩与落子声音的增量诊断

`GENERALIZED_PATTERN`：用户观察到多卡同图时，先查实际存档和传给视图的历史，再查每张 TextureRect 的纹理路径，最后让三张不同中间色测试纹理同时绘制并读回像素。路径不同不代表渲染正确；共享材质也不能未经复现就定为根因。Godot canvas_item fragment 的 COLOR 已包含默认纹理采样，再乘 texture(TEXTURE, UV) 会压暗中间色；纯白/纯黑测试无法识别 RGB 平方，圆角裁切应只修改 alpha，验证保留 modulate 的作用。

动画逐帧分析须按真实 PTS 区分容器、当前卡、历史卡各自的方向、遮挡顺序、旋转及回落。画面出现横移不等于整个牌堆应平移。时间线固化到场景，缺历史时不要复制当前图；需要按实例关闭轨道时使 Animation 资源场景独立。拟合轨道仍须标为拟合，不冒充恢复出的原曲线。

声音测试走真实棋盘提交路径：无效/取消、有效但无新增连接、有新增连接分别检查实际播放器，不以“文件存在”验收。成功连接音不能无条件播放，也不能误用章节解锁声；具体候选音轨的原版调用身份与听觉对齐仍应独立标记证据状态。
# 通关演出、主页状态机与外围插件增量（2026-09-13）

## 防止末次反馈被切页截断

完成事件到达不等于所有局内演出已经结束。Combo 评价字、Emoji、边缘光效可能比棋盘的完成延迟更长；若 Game 立即打开 WIN 或结算页，会造成“资源和触发都存在，但玩家看不到”的假缺失。

建立固定演出协调 owner：

1. 完成事件只把 context 交给协调器。
2. 协调器观察当前局内反馈的真实可见/播放状态，并设有限等待上限，禁止无限卡住。
3. 等待结束后按业务资格选择条件分支，例如每日激励；没有资格则直接进入普通结算。
4. 每次 present 递增 epoch；返回、重开、换关和离场统一 cancel Timer/Tween/Spine。迟到回调先比对 epoch。
5. QA 至少覆盖“反馈仍在播”“无反馈”“条件激励”“普通分支”“等待超时”“等待中取消”。真机用连续两次有效操作制造末次反馈，再录完整切页链。

## 首页 prefab 动画恢复

- 从原宿主收集状态族，而不是只抄一个 idle：页面进入/快入/循环/点击/退出/章节切换，Logo 的 down/hold/up/click，按钮的 default/down/hold/up/cancel/click/light-up。
- 把状态和已证时长固化到 `.tres AnimationLibrary`，在 `.tscn` 固定 `AnimationPlayer` 宿主。切页信号应在退出动画完成后发出。
- Timeline 曲线缺失时，只做不会改变布局语义的轻微缩放/透明度拟合，并在报告中列出拟合幅度。不要加入无证据的左右平移，也不要因资源名含 logo/puzzle 就替换真实宿主。
- 输入 QA 覆盖按下、保持、抬起、拖出取消、焦点丢失、离场复位；否则按钮容易永久停在压缩态。

## Godot 外围系统恢复与 QA

- 先输出原 SDK surface catalog，并给每项标 `static_confirmed`、`dynamic_confirmed`、`design_inference` 或 `reconstruction_contract`。
- Runtime 使用 Autoload facade；provider adapter、广告 policy、奖励 ledger、事件 catalog 和 config 分层。默认 Null/Local provider 不联网。
- 未同意时 analytics/ads/attribution/crash/push 均阻止；service disabled 与 consent false 分开返回。先 gate/policy，再创建 reward transaction。
- 广告展示结果只有真实 shown/impression 才计入频控；rewarded 只有 earned+proof 才提交奖励。
- 远程配置先 stage，在稳定边界 apply；动画或 gameplay active 时拒绝提交。
- 事件 contract 必须校验唯一名和必填字段，并禁止 PII/持久用户 ID。代码能调用 `track_event` 不等于埋点设计已经完成。
- Godot 动态读取 JSON 不一定被资源依赖扫描发现；所有 export preset 显式 include，并以最终 APK 启动日志证明配置可达。
- 未接正式供应商时只宣称“离线插件契约完成”；真实广告、归因、支付、推送和后台埋点需要网络、平台和回执证据。

## Android 存档字节门禁

PowerShell `>` 读取设备文本可能把 LF 转成 CRLF，导致本地备份哈希与设备原始字节不同，即使 JSON 语义完全一致。设备验收应通过 `adb exec-out` 直接保留原始 bytes，测试前可先做 JSON 语义比对，finally 恢复测试开始时捕获的原始 bytes，并再次核对 SHA-256。

## 后期解锁系统：从静态宿主到完整状态矩阵

排行榜、每日挑战、图鉴等后期功能不能只恢复主页入口和一个弹窗。每个系统至少建立以下矩阵，并为每格标记 `static_confirmed`、`runtime_observed`、`controlled_runtime_confirmed`、`snapshot_default`、`design_inference` 或 `unknown`：

| 阶段 | 必查内容 |
|---|---|
| 资格 | 本地进度、远端时间、实验桶、持久状态、离线/不可用 |
| 首次开放 | 入口变形、红点、首次说明、匹配/扫描、手势引导、只播一次 |
| 局内 | 收集物生成、飞行、计数、音效、奖励事务 ID |
| 结算 | 收集物汇入、榜单位移、连胜、晋级/降级/不变、Daily 专属结果 |
| 返回主页 | 待播队列、图鉴新增、跨章顺序、延期弹窗优先级 |
| 周期结束 | 倒计时、赛季结束、领取、续期、无网恢复 |

业务 owner 先提交不可变 completion snapshot，再由演出 gate 消费显式 `rank_result`、`collect_elements`、`daily_result` 等 payload。禁止只凭关卡号或资源存在推断分支。固定 gate 节点建好后还必须从真实结算 owner 调用 `present()`，并用集成测试证明“有 payload 播放并阻塞退出、结束后放行；无 payload 直接放行；skip/cancel 清理”。只测 gate 自身会掩盖“从未接入调用链”的空实现。

图鉴新增演出要追踪原版 `IsNew/IsFirstNew`、当前/前一章、章节切换待播位和结算收集 helper。跨章时先完整呈现旧章最后一块，再切换到新章；动画回调只确认展示，不重复授予收集物。

## 受控原版数据探针与当前快照默认值

静态符号无法确认门槛时，可以在用户授权后做可逆探针：

1. 停止原包，以原始 bytes 备份所有参与判定的 PlayerPrefs、save、SQLite/WAL；记录 SHA-256。
2. 每个候选值都从同一备份重新开始，只改一个判定维度；启动原版，让它自己跨过边界。
3. 观察原版写回的状态位、页面、动画和日志。人工直接把 `Unlocked=1` 只能识别页面，不能证明自然门槛。
4. 把“静态存在”“诊断强开”“受控边界确认”分开记录。没有产生预期状态也属于有效排除证据。
5. `finally` 恢复全部权威文件，并从设备重新读回 SHA-256；任一不一致则探针无效且不得继续。

配置名相近不代表语义相同。例如一个 `daily_unlock` 可能表示每天开放多少普通内容，而 `Daily_Unlock` 是活动页面资格。先定位读取 owner、值域、写回键和运行效果，再映射字段。

任何配置字段仍未知时，将当前受检版本的实际状态和值写入独立 snapshot defaults。该规则覆盖位置、功能资格、内容配额、AB 分组、视觉样式、奖励数值、payload 和功能开关，不能缩窄成“只补位置”或“只处理自然解锁规则”：已观察的 false 保持 false，缺失 payload 保持空数组/null，包内当前策略值保留来源；不要用看似合理的关卡数、默认奖励或占位文案补空。后续远端 SDK 接入只替换 snapshot provider，不改 UI owner 和演出契约。

snapshot defaults 必须成为运行时代码的单一缺省来源，并用测试证明页面入口、解锁演出和条件分支实际读取它；只把数值写进报告或 JSON 不算完成。显式本地状态、SDK 回调或服务端 payload 可以覆盖快照缺省值，但要记录覆盖来源，便于区分当前版本默认值和后续接入值。

## 连续活跃语义与民用日期测试

界面俗称“连续登录”不能覆盖原代码语义。必须同时检查持久键、helper 类和写入调用点：如果 owner 是 daily-first-win，启动应用只允许检查断档，只有当天首次完成才加一。日期逻辑使用可注入 civil-date provider，覆盖同日幂等、相邻日 +1、断档归一、最长纪录、时钟回拨、时区跨日、重启与 pending replay；Rank 首次开放等高优先级流程若会延期火苗，保存 pending，而不是丢弃或重复奖励。

## 粒子视觉 1:1 的同阶段门禁

复杂烟花/彩带不能按一个 prefab 名整体近似。先逐模块提取每个 ParticleSystem 的 enabled/renderer、材质纹理、texture-sheet 行列、emission/burst、shape、lifetime、speed、size/color/rotation over lifetime、velocity/limit、simulation space、父级 position/scale、sorting layer 和触发时间。源 renderer disabled 的宿主保留但不绘制；图集必须按原行列随机单帧，不能把整张 sheet 当一粒。

比较必须取原版连续录像的真实 PTS，与重制的同业务时刻制作起爆、峰值、衰减联系表。逐阶段检查边框先导星光、主线状烟花的起点/方向/拖尾、彩带密度、前后景、统计框出现时间和清理。若中心粒子类别、构图或页面时间线明显不同，即使 emitter 数量测试、场景解析和 GPU 捕获全绿也仍是 FAIL。无法等价的 Unity 3D UIParticle 投影、Shader 或 ClampVelocity 要列为残差，继续迭代或明确未完成。


## 入口反证、外循环模式与条件演出的真实生产者

1. 截图文件名不能证明页面身份。对“去收集/图册/章节”等相近名词，必须记录点击前→命中控件→点击后页面和包名。旧报告被实机反证时，在旧报告顶部添加纠正，不能只在新文档里悄悄改结论。
2. 相似资源可能属于不同外循环模式。先追模式持久化键、迁移状态与入口owner；不能将旧元素图册、新章节图片和活动积分合成一个功能。每种计数应有独立身份和来源，禁止循环少量占位图填满格子。
3. 存在rank_result消费端但正常游玩没有生产者，仍是空实现。必须测试输入→玩法提交→本地/外部provider→不可变结果→演出→继续。无结果时查本地数据库、已选机器人、时间积分表、掉落权重，不得直接归因“尚未接SDK”。
4. 优先使用当前设备已选参与者和活动时间快照，而非重新猜全量候选的抽样算法。将已确认字段与随机/平分/插值等拟合规则分别记录。活动内排名变化不等于周期段位晋降，未知下一周期不能自行续期。
5. 多条件结算用待播队列与消费位。新增rank不得return吞掉daily/collect；回包在其他演出期间到达，要排队补播；晚到演出须重新置商业系统animation_active。测试取消、重复继续、跨局回包、动画中返回与多条件共存。
6. Spine重绘除外框Alpha外，增加内部地标检查：书脊、页边、折线等位置必须与原骨架对齐。原版部分出屏的构图不能重画成完整居中构图后仅靠缩放修复。底图与骨架共用原坐标容器，整体适配。
7. UI适配还要审查AnimationPlayer写入的position/offset：静态场景居中但入场后错位，可能是动画覆盖了布局。滚动列表要测实际长内容、首尾裁切和玩家定位，六行快照填满屏幕不等于完整排行榜。

8. 不得用直接调用 `_on_pressed()` 代替按钮验收。必须模拟 MouseMotion/MouseButton 的真实 GUI 分发，并在最终 APK 上触控一次；检查 `mouse_filter`、disabled、父级遮挡和节点顺序。高 z_index 只保证绘制顺序，不能替代输入层级设计；被弹层遮住的底层按钮在禁用时应停止截获输入。
9. 居中 Node2D 演出宿主与左上角 Control 全屏页之间要显式保存坐标转换。在完整游戏层级、导出包与非设计分辨率中检查矩形，而不是只测单独实例化场景。不要把“看得到”当成“点击区域正确”。
10. 自动通关取证应等待真实 ready/提交状态。画面识别被合并光效、弹跳或相似色块干扰时停止发手势；可只读权威棋盘 checkpoint 来规划下一次实际触控，禁止直接写完成标志。断言截图中的页面与阶段，不得仅凭文件名 win_stamp.png 宣称印章已捕获。
