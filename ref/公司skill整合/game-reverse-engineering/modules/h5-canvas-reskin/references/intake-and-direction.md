# 方向预输入与概念选定

范围：`GENERALIZED_PATTERN`。适用于成品 AHA/H5 换皮，无方向时必须在全量制作准备前引导。此阶段不修改游戏，也不把国家、年龄或产品类型自动等同于一种审美。

## 入口分流

- 有项目状态：先恢复其简报、有效目标、授权与未完成项。用户暂停时保持暂停。
- 已有明确效果图及执行范围：读图，保存具体文件和 hash、来源/用户选择证据，承接已选方向。缺少的市场信息只问会改变结果的部分，跳过重复问卷。状态中的确认记录可引用已有聊天原话；不得伪造新的页面点击。
- 有产品目标但无图：只补缺项，再进入风格选型与少量概念图。
- 仅有成品、方向未知：先生成工作台并显示第一轮选择题；允许只核对游戏身份、入口和少量代表画面，不能先跑全量资源工程。
- 引擎未知：必要指纹识别可并行于问卷；确定非 H5 时保留已获得的产品简报，技术执行交给真实引擎模块。

## HTML 选择题：按答案分轮，每轮 1—3 个关键问题

1. **产品简报**：目标市场/国家（支持其他及不确定）、目标用户/体验、产品方向（原题材精修 / 本地化 / 新主题 / 品牌统一 / 不确定）。已有信息带入，不替用户提交默认值。
2. **视觉方向**：AI 结合实际玩法、图标显示大小、画面与技术约束，提出少量有解释的风格候选；用户选择形式、配色和题材。允许查看全库、自定义图和“请推荐”。推荐必须有理由，不能伪称市场调研结论。
3. **实施边界**：用户尚未说明时，在计划页明确语言、保持项（UI轮廓/路线/玩法功能色等）、改动范围、交付与验收平台、候选/返修限制。只补会影响当前执行的缺项。

用户选“不确定”表示请求建议，不能当成已确定的美术方向。AI 应在 HTML 中提供少量可比较建议，让用户选择；等待真实答复时可整理已知输入，不能超时自动开工。

## 风格唯一来源

加载可发现的 `azure-image2-generation`（GPT 生图）及 `casual-game-art-style` 模块。按其中现行索引读取 `style-masters.md`、`regional-palettes.json/md`、`project-baselines.md`。不要复制一套会漂移的模板正文到本模块。

- 形式目录当前为 T01—T08；以实际文件为准。工作台脚本动态读目录并记录来源版本与 hash。
- 地区配色与形式独立；当前 SA/NG/PH 是库内方案，不是全球市场边界。库外市场用自定义或提案，不能直接继承相近地区的配色和文化内容。
- 当地内容、语言、UI 家族、玩法功能色独立记录。形式模板不授权改镜头、布局、格位或程序逻辑。
- 历史 M03 等编号先查具体项目/图像；不能将 M03 静默当成 T03。没有上下文时在 HTML 让用户比较可能含义，保留待确认。
- 原始竞品证据、历史项目样张、当前项目概念图、已选目标分别标注。脚本内嵌的灰度商店局部仅帮助理解形式，不是八套已生成获批的项目方案；未经用户要求，不把竞品彩色图直接送入生图。
- 风格库缺失时先说明缺什么，继续采集产品简报并允许自定义；不编造库内 ID，也不安装/配置付费后端。

## GPT 生图使用两次

**概念探索**：先有产品简报与可比较方向，再按用户范围调用 GPT 生图。用同一代表屏、同一状态、必要布局约束生成少量候选；地区、题材和形式分别落实，避免同时改变太多维度而无法比较。数量遵守用户限制；未指定时先给少量有差别的方向，不能先批量生产整个资源库。

**正式生产**：选定具体概念图和实施范围后再次调用生图技能。按技术契约生产素材，实际输入所选效果图或完整局部并标明职责；概念图不是可以直接覆盖的图集，裁切作成品须符合用户许可与契约。生图后端遵守 GPT 生图当前规则：本机有原生工具时优先原生，批量逐图调用；不因选风格或批量而擅自改用额外付费 API。

## 设计确认

HTML 应并列显示本项目候选图、版本、差异与局限。用户可选定、具体反馈或退回。确认记录绑定项目、简报/方向摘要、候选 ID/版本与真实文件 hash；有效状态保存后回显。页面勾选、下载、仅保存草稿不是采用证据。

已有目标可在状态 `concepts` 登记为来源明确的现有设计，再引用真实授权记录；不为了走流程重生用户已批准的图。目标有技术缺陷时单列并局部修复，不能擅自丢弃。进入计划前应能回答：做给谁、什么产品方向、按哪张图、什么能改、如何判断通过。
