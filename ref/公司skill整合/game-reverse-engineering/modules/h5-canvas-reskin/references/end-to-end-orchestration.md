# 从方向到运行验收的阶段编排

范围：`GENERALIZED_PATTERN`。先读模块执行卡；无方向时从 `intake` 开始，有有效状态/目标则从当前阶段继续。主要沟通使用同一 HTML 工作台，聊天短消息提供页面入口和需回传的选择。

| 阶段 | 给用户看 | AI 执行与退出证据 |
|---|---|---|
| intake | 市场、用户、产品定位的选择题 | 按已知事实预填，真实选择形成简报；不确定项给建议，不伪造确认 |
| direction | 现行风格、配色、题材的少量推荐与来源 | 用 GPT 生图美术指导筛选，用户选择后形成明确组合；“请推荐”仍留在本阶段 |
| concept | 同一代表屏的真实候选图与版本 | 调用 GPT 生图探索；具体选定记录绑定图像 hash，禁止拒绝候选进入当前生产 |
| plan | 接下来逐项实现的动作、保持项、交付与验收平台 | 主动列出原版基线/轻索引、代表屏、同族生产、累计合入、QA 与交付；已有执行授权记录原话出处后直接继续，不重复请求 |
| representative | 原版 / 确认目标 / 游戏实景 | 冻结基线，建轻索引并查关键契约；生产代表素材实际回填，证明视觉、装配和自然输入，失败先集中校准 |
| production | 当前有效资源族和技术/视觉状态 | 同族批量调用生图、处理与检查；有效候选有用途、引用、版本和技术状态，未知/未通过单列 |
| integration | 清单中的实际合入项与可运行入口 | 先备份再累计回填；按原尺寸/名字/容器/图集契约检查最终像素，记录变更与回滚 |
| qa | 同状态三列图、自然操作证据和失败原因 | 按约定 H5/模拟器/真机/宿主跑资源、输入、玩法、弹窗、状态、拼接与稳定性；各结果独立，缺条件记未知 |
| delivery | 当前完成度、可玩入口、工程/包、缺口、验收入口 | 主动引导用户查看 HTML 并反馈具体资源/界面。开发、运行 QA 与用户视觉认可分别记录，不以数量或静态图判全部完成 |

## 连续执行与中断

- 具体设计和执行范围明确后，在授权内持续完成后续动作；以代表屏为校准单元、以资源族为批量单元，避免每件反复问用户或出包。
- 仅方向选择、显著超范围变化、新成本/次数限制等需要决定时等待。不要把每阶段都变成新的批准关卡；HTML 的步骤预告不是新的权限要求。
- 原版基线、只读索引和可逆制作准备不需逐项批准；纯美术任务继续禁止改变游戏代码、布局或图集坐标，必要代码改动先给最小提案。
- 用户暂停后保持暂停，不启动自动目标或定时任务；只有明确恢复才能续跑。本技能不会自动建立监控。
- 原因相同的失败集中返修，遵守用户候选/成本限制。一个条目不能无限迭代；明确保留的未通过项不自动修到别的方案。

## 状态、证据与失效

轻量状态字段与命令见 [HTML 工作台](html-workbench.md)。每个里程碑更新阶段、有效资源、下一步、证据、未知项并重新渲染同一页面。不需要每张图片写长日志。

整体方向或产品简报变化：旧设计/执行确认失效，相应资源不再算本次有效范围；历史文件和记录保留。仅局部反馈：先确定影响的资源、屏幕与 QA，再使该范围失效，不自动推翻全项目。重跑必须针对新版本或新失败证据，同一 hash 无变化不重复构建。

技术检查、素材视觉、游戏内装配、自然玩法与用户接受分别出结论。代表屏须有实际运行证据才能扩大到批量；最后 QA 须用最终合入版本和约定平台。自然输入与调试调起分列，浏览器与 AHA 宿主证据不能互相替代。

流程完成后在模块 landing-log 记录实际结果与证据边界；技能/工具夹具通过不能记成目标游戏验收通过。
