# 工具接口说明（按需重实现）

> 范围：`GENERALIZED_PATTERN`。
> 本模块提供可移植的 [HTML 工作台脚本](../scripts/render_workbench.py)，用法见 [HTML 工作台](html-workbench.md)。它只管理选择、证据与沟通，不代替生图或游戏集成。下列其他工具仍是接口说明：来源案例脚本含本机路径，按当前项目实现或参数化，不直接照抄。

## 1. 分流与规划

| 工具 | 输入 | 输出 | 要点 |
|---|---|---|---|
| 资源分类器 | 导出目录 + 代码引用清单 | 机读分类（每资源一个 `category`） | 四类判据见 `pipeline.md` §1；**必须输出"角色"字段**供报告使用 |
| 资源规格表 | 分类 + 图集帧表 | `ASSET_SPEC.json` | 尺寸/帧名/所属图集/是否复合图标 |

## 2. 拼接类

| 工具 | 输入 | 输出 | 要点 |
|---|---|---|---|
| 拼条带 | 原 N 段图 | 一条连续长图 + 各段高度 | **按引擎视觉顺序**堆（见 `pipeline.md` §2.1） |
| 画边界辅助线 | 长图 + 段高 | 参考图（带细线） | 让模型知道切分位置在哪 |
| 切回 | 候选长图 + 段高 + 顺序 | 原 N 段图 | 按引擎实际相接顺序和原段尺寸切回；接缝上下大局部及整屏视觉复核，禁止把线性摊差或边界压平当默认修法 |
| 离线切片自测 | 合成夹具 | 断言结果 | **花 API 之前先跑这个** |

## 3. 亮度与色相

| 工具 | 输入 | 输出 | 要点 |
|---|---|---|---|
| 底板亮度对齐 | 成品 + 原版（逐张配对） | 重写成品 | 仅当批准目标确需该亮度时才使用分位映射；参考目标实景和实际可读性，alpha 按契约处理 |
| 色相回锁 | 成品 + 原版（仅玩法对象族） | 重写成品 | 仅针对需要保持功能色的玩法对象，按目标与真实语义选择是否回锁；不默认覆盖用户指定的目标配色 |
| 亮度/色相审计 | 成品 + 原版 | 每张的差值与判定 | 判据：可见区亮度均值差、主体色相差、最小色相间距 |

**主体色相怎么取**（务必写清口径）：取**可见区**中饱和度 ≥ 自身 P60 的像素 → 取**中位色** → 转 HSV 的 H。
用均值会被高光/暗侧带偏。

## 4. 风格量化

| 工具 | 输入 | 输出 | 要点 |
|---|---|---|---|
| 四级层级审计 | 背景族 + 交互族（成品与原版各一份） | 三项指标 + 「背景 < 交互区」判定 | 饱和 / 局部对比(std) / 边缘(梯度均值) |
| 风格审计 | 两批成品（或成品 vs 原版） | 细节密度 / 对比 / 明暗跨度 / 饱和 / 高光 / 硬边 | 期望方向**按资源族分支**：图标要"更立体"，底板要"更安静" |
| 边缘密度对比 | 逐张成品 + 原版 | 倍数表 | 「背景太花」的判据；**同时报"是否过分安静"** |

## 5. 运行时取证（H5 / canvas）

| 工具 | 输入 | 输出 | 要点 |
|---|---|---|---|
| CDP 步骤执行器 | 一个步骤 JSON（`eval` / `wait` / `drag` / `tap`） | 每步结果 | 自然输入；按用户指定的浏览器、模拟器或真机采集并标明实际来源，设备截图用对应设备通道 |
| 停摆看门狗 | 时长 / 阈值 / 是否自动玩 | 现场三件套（截图+运行时快照+logcat） | **两类检测都要有**（画面停摆 / 逻辑停摆）；**先自证再长跑** |
| 入口枚举器 | 从代码提取的入口名列表 | 每个入口的健康前后快照 | **确定性枚举**，替代随机压测；判据含"场景根是否被清空" |
| 压力驱动 | 时长 | 操作数 / 停摆数 / JS 异常栈 | 带 `window.onerror` 钩子；**不得引入崩溃**（会污染 A/B） |
| 拖拽测试 | 目标区域 | 输入是否被接收 | **随机拖拽不成消除 ≠ 输入失灵**（见 `runtime-diagnosis.md` §1.7） |
| A/B 对照 | 两个包 + 同一套压测 | 前后快照对比 | **必须保证两组被执行的操作序列可比** |

## 6. 验收

| 工具 | 输入 | 输出 | 要点 |
|---|---|---|---|
| 硬门禁 | 成品包 + 原版包 | 一条命令跑完全部门禁 | 含"**已声明修复 vs 未声明改动**"的区分（见 `upstream-defect-patterns.md` §4） |
| 分类质检 | 分类 + 成品 | PASS / EXEMPT / MISMATCH | 门禁**按类别分档**；有"豁免"档 |
| 对照页生成 | 原版目录 + 成品目录 | 单文件 HTML | **带生成时间戳 + 两侧来源路径**；图片数/破图自检 |
| 界面留档 | 包 + 界面清单 | 逐屏截图 + `screens_manifest.json` | 自然交互优先；调试或状态注入只作为渲染诊断并标注，不能称自然解锁；截图记录状态和来源 |
| 对比页自检 | HTML 文件 | 图片数 / 破图数 / 结构 | 属性可能用**单引号**，正则要兼容 |

## 7. 编排

可按项目契约组合一个 `post_batch_art` 式的收尾流水线；亮度对齐和色相回锁均非默认必做：

```
资源分流与代表样 → 同族批量生成/处理 → 按需检查透明与功能色 → 累计回填 → 同批集中验收
```

**每一步都要能在中途单独重跑**（改一张图不必重跑整条链）。

## 8. 两条实现纪律

**① 脚本必须参数化路径。** 不要硬编码本机绝对路径 —— 换个项目就跑不了，
也违反 `DO_NOT_COPY_LITERAL_VALUES`。项目根目录、皮肤名、资源族一律走参数。

**② 每一个"审计"工具都要能同时吃原版与成品。**
判据几乎永远是「与原版的相对关系」，只能量成品的工具**没法给结论**。
