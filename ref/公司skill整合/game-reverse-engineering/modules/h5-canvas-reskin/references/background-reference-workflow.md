# 背景与效果图参考：快批执行

适用：已有原游戏、已指定效果图或已选中的候选，需要重绘地图/棋盘背景并实际装入游戏。用户指定的输入、禁止参考、候选次数、裁切方向及保持内容优先。

## 一次建立参考，不让原图夺回风格

1. 原版用来确定真实空间骨架：道路或河流的实际类型与走向、地形边界、主次层、交互留白和切片/滚动/循环顺序。先查游戏实际显示，不凭效果图猜路线。原版可参与初次结构输入，但用户禁止作为本轮生成参考时，不得传入；结构证据仍用于生成前设计和生成后的比对。
2. 以用户指定界面、版本、状态的效果图或完整局部为外观依据，生图时**实际传入**，不能只看过或写“按效果图换色”。分开标记：当前候选负责构图及必须保留的主体；效果图对应局部负责形体概括、色彩、材质、光照及地区装饰；若使用原版，其角色仅是必要的结构/资源契约。不要传入未授权的旧成果或其他同屏方案。
3. 为各材质按需准备一到数张足够完整、能看清风格的目标局部，例如草地/植物/木屋和道路/河岸分别参考；避免 UI、数字、按钮或手势混入背景，也不要把裁切直接当成最终资产。分别说明每张图影响什么、不能改变什么。重要场景元素可以静态绘入，只有查到真实调用关系才归类为独立精灵。
4. 用户选定已有候选后，后续以该候选为编辑基准；若用户说本轮仅用候选和目标局部，就不传原版。只修改指定缺陷，技术问题单列，不能因接缝或个人审美擅自替换、回退或重生用户认可的背景。用户确认保留且接受未通过项时停止该项返修。

## 样式与实际显示

- 先根据实际显示窗口、裁切、滚动、拼接确认主要地区装饰在哪里会被看见；按真实资源契约调整画面素材的留白、允许的裁切或扩展，不改程序布局。用户要求向某侧取景时，保留主景和空间结构，检查全部目标屏宽；扩展缺口采用完整、无重复的自然延展，不镜像主景，不用长距离交叉淡化。
- 用户要求“03 圆润饱满休闲风”时，先按项目上下文与已批准参考识别该编号；本案例指 GPT 生图 P-SA-M03-V8 的造型偏好，**不是** T03 硬质浅浮雕。将其作为形式参考，与目标效果图具体配色、地域题材结合：草木、屋顶、石块和静物有清晰大体块、圆润饱满的体积与简洁高光，细节概括，避免尖碎、密集硬刻纹和写实脏灰；在不改变既定道路、镜头与 UI 装配的前提下应用。其他项目不自动继承本案例配色或形状。
- 在单次生图请求中，分别描述构图不变量、目标参考的具体颜色/材质/造型、目标风格和禁止烤入的动态 UI。草地与路径分开取色，避免模型把灰绿道路生成为蓝河、或把自然绿草生成为荧光绿。现有候选过暗/偏灰时以目标局部为准，不以“更暖/更亮”的文字代替视觉参考，也不强行复用原版色彩。
- 地图循环要按原程序相接顺序看整屏与接缝上下大局部，核对路线及地貌连续、物件不截断/重复/重影。接口像素接近不是视觉无缝；不能用几百行跨物件叠化掩盖断裂。修补只动被授权的区域，并在新图集和实际 H5 屏上复核；用户决定保留未通过的接缝时照实列出，不自动继续尝试。

## 集成与交付

代表屏校准后同族批量处理、一次累计回填和集中验收；保留状态差异，按用户指定的 H5 或设备来源展示原版、目标、当前实景及未通过项。无有效资源变化不重复构建。用户评价只作用于其明确指出的对象和范围，不等于整项目通过。
