# 逆向拆解交付模板：系列 md 文档 + 单文件交互式 HTML 全书

## 执行卡（先用这张卡，再读正文）

**我管什么**：把逆向拆解结果整理成系统性交付物——系列 md 拆解文档 + 单文件交互式 HTML「设计解析全书」+ md→HTML 注入；不管拆解取证本身（取证属上游模块），也不做多文件外链型站点。

**第一步做什么**：在拆解工作根目录先写 `docs\_EVIDENCE_INDEX.md`（证据包索引：路径表 + 已确认背景事实 + 写作规范），所有分析代理共享它；`00_README_总报告.md` 留到最后写。

**做完怎么算完成**：
- `_EVIDENCE_INDEX.md` 先于一切分析代理落盘，每个结论都能顺着它回到具体文件与行号。
- 每份 `01~NN_<系统名>.md` 都回答了四问（它是什么 / 怎么运转 / 为什么这样设计 / 自研抄作业注意什么），并用 `[证据]`、`[推断]`、待验证三档标注。
- HTML 为单文件自包含，在 `file://` 与静态服务器下都能打开，且无任何外部引用。
- 每章渲染正常、SVG 无文字溢出、标签页/搜索/排序/证据开关可用、console 零 JS 错误。
- `md2book_template.py` 重跑幂等（先清旧 `<!--MDDEEP-->` 段），深度面板表格样式与正文一致。

**红线（不可违反）**
- HTML 禁止引用任何 CDN、外链图片、字体文件；图表只能内联 SVG 手绘或用 CSS 条形/脑图。
- 读不到的数值一律写"待验证"，禁止编造；`[推断]` 不得伪装成 `[证据]`。
- 敏感信息（密钥/价格/API key）只写键名与形态，不输出真实值。
- md 编号数量与 HTML 章节按目标游戏实际系统增删，不得硬套 16 章基线。
- 验收必须用真实浏览器（截图 + console + DOM 统计），不许以"应该没问题"代替。
- 换游戏时只改转换脚本顶部 `MAPPING`，不逐处改注入逻辑。

**卡住时按顺序读**：
- 目录结构怎么摆、证据包放哪 → 本文件「一、交付物目录规范」。
- 标注口径、字数、语言风格 → 「二、md 文档分类法」的 2.2–2.4 节。
- HTML 组件、图表与注入细节 → 「三」的 3.3 CSS 组件清单、3.5 SVG 规范、3.6 注入脚本。
- 收口前逐条自检 → 「五、质量门禁」。

全局五步循环与六条铁律见 `references/execution-protocol.md`。

范围：`GENERALIZED_PATTERN`（方法可迁移；md 编号数量与章节主题按目标游戏实际系统增删，HTML 章节结构同理）。
来源案例：Gossip Harbour v3.97.0 全量拆解（2026-08-31，16 章 / 17 幅 SVG / 376KB 单文件）。

## 一、交付物目录规范（拆解工作根目录）

```
<Game>_APK_work\
├─ apk\                      原始 APK（base + splits）
├─ device_pull\              设备端拉取物（明文 metadata / catalog / 存档 / BI 实包）
├─ extract\
│  ├─ unpacked\              APK 解包原文件
│  ├─ assets_out\            分类资产：textures/sprites/audio/texts/configs/fonts/meshes/misc
│  ├─ manifest.csv           全资产清单：bundle, path_id, type, name, address, out_file, w, h
│  ├─ il2cpp_dump\           C# 桩 + 元数据 JSON（Unity 游戏）
│  └─ lua_decompiled\        脚本解包产物 + ALL_STRINGS.txt（字符串常量合集，分析第一手证据库）
├─ preview\                  可视化站（Spine 播放器/图库/音频/特效目录，python -m http.server 即用）
├─ docs\                     ①系列系统文档 ②总报告 ③证据包索引（见第二节）
├─ tools\                    全套可复用脚本（每个脚本注明"可复跑"）
└─ logs\                     过程日志与探针产物
```

## 二、md 文档分类法

### 2.1 编号与命名

- `docs\00_README_总报告.md`：交付对照表（用户需求→交付物）、目录结构、方法论（破解记录）、**自检记录**（逐项遍历遗漏并补全/标注"待验证"）、可复用脚本清单、已知边界。**最后写，先写目录骨架。**
- `docs\01~NN_<系统名>.md`：一系统一文档。建议章节序按"总览→核心循环→局内→局外→剧情→商业化→活动→数据SDK→美术→性能→服务器"的认知顺序。
- `docs\_EVIDENCE_INDEX.md`：证据包索引——给后续分析代理/协作者用的路径表 + 已确认背景事实 + 写作规范。**第一个写**，所有代理共享它。

### 2.2 每份系统文档的内容规范

每个系统必须回答四问：**它是什么 / 怎么运转 / 为什么这样设计（意图）/ 自研抄作业要注意什么**。
推荐骨架：

```markdown
# 0X 系统名（游戏名 vX.X.X）
> 证据缩写表 + 标注约定
## 1. 系统概述与架构          （总述 + 数据流）
## 2..N 机制分解              （每机制：表格[机制|证据|意图]）
## N+1. 数值驱动方式          （本地表/本地键值/服务端三层，谁管什么）
## N+2. 结论速览 / 对自研的启示（编号要点）
```

### 2.3 证据标注体系（硬性规范）

- `[证据]`：可复查的 文件+字段/字符串/行号（如 `ItemDefinition.lua.strings.txt L96-124`）。
- `[推断]`：基于证据的合理性分析，禁止伪装成证据。
- 读不到的一律写"**待验证**"，禁止编造数值。
- 敏感信息（密钥/价格/API key）只写键名与形态，不输出真实值。
- 全文引用统一缩写（如 `ALL_STRINGS` / `TXT` / `IL`），在文档头声明。

### 2.4 写作语言风格

- 中文；自然语言叙述 + 表格为主体；关键结论加粗。
- "设计—做法—意图"三列结构优先于流水账。
- 每份文档 3000~6000 字（过短=证据不足，过长=没消化）。

## 三、单文件交互式 HTML 全书规范

### 3.1 硬性技术约束

- **单文件、自包含、零外部依赖**：不引用 CDN/图片/字体文件；图表用内联 SVG 手绘，统计图用 CSS 条形（`.brow/.tr/.fl`），脑图用 CSS 树（`.mind`）。
- **暗色主题**，与资产预览站风格统一。
- 文件规模预期 300~500KB（含注入的 md 原文）。

### 3.2 章节结构模板（16 章基线，按游戏增删）

```
0 导读与阅读指南（KPI 大数字卡 + 证据体系说明）
1 一图看懂这个游戏（核心循环飞轮 SVG + 竞品坐标表 + 数字名片）
2 技术架构总览（分层架构 SVG + "为什么这样架构"）
3 经济系统（货币三卡 + 数值三层驱动 SVG）
4..N 按游戏核心系统逐章（标签页组织子机制，每机制配图/表）
N+1 商业化、N+2 活动运营、N+3 数据埋点、N+4 美术音频、N+5 性能、N+6 服务器热更
N+7 设计意图深度解读（"设计-做法-意图"三列表 + 用户旅程时间线）★全书点睛
N+8 自研落地蓝图（照抄清单 + 配置表最小集 + 避坑表 + 合规红线）
N+9 附录（文件索引 + 拆解流水线 SVG）
```

### 3.3 CSS 组件清单（内嵌样式类，直接复用）

| 类 | 用途 |
|---|---|
| `#side/#topbar/#prog` | 固定侧栏导航 + 顶栏搜索 + 阅读进度条 |
| `.kpi .kb` | 大数字统计卡 |
| `.card .hi / .grid2 / .grid3` | 玻璃卡与栅格 |
| `.tblwrap / table.tbl` | 可点击表头排序的深色表格 |
| `.tag .b/.g/.o/.p/.c` | 彩色小标签（枚举/清单） |
| `.fig .cap` | SVG 图容器 + 图注 |
| `.bars .brow` | CSS 条形图 |
| `.mind ul .n(.root/.b/.g/.o/.p/.c)` | CSS 脑图 |
| `.tabs button / .tabpane` | 标签页 |
| `details.acc` | 折叠面板（深度原文用 `details.acc.deep` 紫边变体） |
| `.callout(.warn/.ok)` | 提示框 |
| `.ev .inf` | 证据/推断 标注徽章（可全局开关 `body.hideev`） |
| `.pill / .kpi / code / mark` | 杂项 |

### 3.4 交互 JS（≤80 行原生）

- 滚动进度条 + 回到顶部显隐；
- IntersectionObserver 侧栏 scrollspy；
- 搜索框：输入即按章节文本过滤（`section.style.display`）；
- 证据标注全局开关；
- 表头点击排序（数值/中文 localeCompare）；
- `tab(btn,id)` 标签页切换。

### 3.5 SVG 图表绘制规范

- viewBox 宽 760~920，节点用 `<rect rx="10-12">` + 双行 `<text>`（主标题+灰色小字）；
- 箭头统一 `<marker>`，配色沿用主题变量（蓝/绿/金/紫/青）；
- 每图必配 `<div class="cap">图 X-Y · 一句话图注</div>`；
- 文字必须验证不溢出（浏览器 getComputedTextLength 抽查）。

### 3.6 md 全文注入（深度原文面板）

每份 md 全文转换为 HTML 并以紫边折叠面板注入对应章节末尾，转换器 `modules/deliverable-book-template/scripts/md2book_template.py`：
- 支持：标题/表格/代码围栏/引用/有序无序列表/行内粗斜体代码/分割线；
- 幂等注入（重跑先清除旧 `<!--MDDEEP-->` 段）；
- 映射表在脚本顶部 `MAPPING = [(md文件, section_id, 面板标题), ...]`，换游戏只改这一处。

## 四、工作流 checklist（顺序执行）

1. 拆解完成、`manifest.csv` + `ALL_STRINGS.txt` 等证据库就绪。
2. 写 `_EVIDENCE_INDEX.md`（先于一切分析代理）。
3. 派发并行分析代理产出 `01~NN.md`（每代理喂证据索引+明确四问+字数要求）。
4. 写 `00_README_总报告.md`（含自检补全）。
5. 建 HTML 骨架（head/CSS/侧栏/JS），逐章手写精编内容（SVG 图表来自 md 的表格化结论）。
6. 跑 `md2book_template.py` 注入全部 md 原文。
7. **浏览器验收门禁**：每章渲染、SVG 无文字溢出、标签页/搜索/排序/证据开关可用、console 零 JS 错误、深度面板表格样式一致。
8. 修复后复验，更新项目记忆。

## 五、质量门禁

- HTML 单文件可在 `file://` 与静态服务器下均正常（无绝对路径资源）。
- 每个结论在书中可溯源到 md（深度原文面板），md 可溯源到文件行号。
- 自检章节必须存在且逐项有结论（补全/待验证二选一）。
- 验收用真实浏览器（截图 + console + DOM 统计），不以"应该没问题"代替。
