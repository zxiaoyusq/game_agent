# 宿主 H5 原码还原与持续迭代

**适用**：用户已提供 AHA Games 或其他宿主内嵌 H5 的原包、解包或游戏目录，希望自然拆解、尽可能保留体验，并长期修改美术、关卡、埋点和商业化。可与采集阶段衔接；已有包时无需重新挖商店接口或强求设备缓存。适用于多种 H5 引擎；Construct 2 仅是下文的一个案例。

**范围**：方法为 `GENERALIZED_PATTERN`；最后一节 One Connect 的具体文件、SID、尺寸、规则与结果为案例专属，其他游戏必须重新取证。用户指定目标、输出目录、允许修改范围和验收设备优先。是否生成美术、改玩法或重建按用户授权及当前阶段执行；用户要求先选风格时不得擅自选定或批量生成。

## 1. 基线与启动：先确认是什么、能自然到哪

1. 默认保留原包和已有解包只读，记录身份、来源与 SHA-256，在用户指定的目录建立可回退的原版基线和实验/开发副本；用户明确指定直接编辑的范围时按其授权执行，覆盖前备份。用清单/哈希比对源与基线。不要清理用户旧工程。
2. 用 `engine-identification` 确认运行时、入口、资源与编辑源；判断是否有原工程文件。只有导出数据不等于可恢复完整编辑工程；不要把已知 Construct、Phaser、Unity 或其他引擎套成 Cocos。
3. 先原样运行并记录启动、console/pageerror、网络与宿主桥接；对缺失 SDK、跨域或容器差异单独取证。在独立副本做最小可观察模拟，明确哪些是真宿主、哪些是模拟，禁止以模拟的接口返回冒充真实广告、奖励或回调。
4. 通过自然点击/触摸逐步取证菜单、主题/关卡选择、玩法、暂停/恢复、失败、结算、奖励、过关、重开和下一关等实际可达状态。逐张记录环境、版本、入口、触发方式与截图路径；未到达标注未验证。若用户允许调试路径，可另列探索证据，不能冒充自然解锁。
5. 产出方便直接打开的截图及原版资源预览：分类图集/帧、独立图、背景、字体、按钮状态、特效及音频；建立文件→引用→界面映射并标明推断/未知。资源尺寸、数量和静态截图不能单独证明播放、交互或玩法。

## 2. 原版路线可行性：最小实验后再决定重建

在可回退的**独立实验副本**验证：替换一组确实被使用的资源；改一个可定位的配置/计时参数；调整一个可识别的 UI 位置；各自用运行截图、点击或状态对照证明生效，记录影响和恢复方法。用户允许改代码/UI 时不得套用其他项目的“只换图”限制；仅美术任务则遵守实际约定。不要把临时测试色当作最终美术方案。

对照两路线：原逻辑保留程度、关卡读取/修改/新增、事件可插拔、宿主与广告接口、可定位可构建回归、运行风险及维护成本。优先评估原版继续开发，**结论必须由实际行为与改动证据支持**；无法可靠满足用户需求才提出重建比较。不用“能打开”“资源提取数量”“静态解析成功”替代完整玩法、胜负和重开证据。影响路线选择的实质障碍要简短列出，再依用户授权推进。

## 3. 关卡、埋点、广告：交付能实际调用的边界

| 能力 | 先取证，再实现 | 运行验收与未证实边界 |
|---|---|---|
| 关卡 | 查数据来源、生成/固定规则、索引、计时、棋盘、状态与推进 owner；先确定只读数据和真正的提交边界。若生成式规则不存在固定关卡表，明确等价配置覆盖的意义 | 原或等价配置可读/编辑；新增后续配置；在实际游戏中自然加载并可玩，验证胜负/推进。数量成对不等于可解；上限、所有规则和更高关需分别取证 |
| 埋点 | 查原事件及真正动作 owner；定义本地事件名/字段和启停/调整入口；原始事件与规范化事件分开 | 自然开始、关键操作、胜利、失败、重开等与本地记录逐项对账；监听/本地导出不是已上传。平台命名、上报、隐私和服务按用户提供的契约另接 |
| 广告与宿主 | 找真实调用点、宿主 provider、同步/异步返回、暂停归属和回调消费者；隔离游戏与平台接口 | 无 provider、抛错、异步失败及恢复通过本地模拟；返回不等于展示/关闭。真实 SDK、广告位、关闭、激励和奖励幂等必须在真实契约/平台下另验，未提供时如实待接 |
| 维护与性能 | 记录原始输入、开发源、配置、资源、生成物、启动/构建及回滚；保留错误和性能指标入口 | 复现→定位→修复→原触发路径回归；浏览器 FPS/对象量是局部诊断，不能等同设备性能或宿主验收 |

**构建真源纪律**：说明每个可编辑输入和生成文件；从基线重新生成的文件不可单独手改，否则构建会覆盖。修改前检查其他补丁的合入顺序与可复现性，失败要保留有效旧输出或明确异常状态。配置对每个入口做类型、范围、重复和资源引用检查；单次成功不能证明所有随机布局、主题、设备都通过。

用户提供匹配 CombiMons 父页面 SDK 模板时，另读 [模板接入与验证](combimons-host-sdk-template.md)，核查入口、真实 SDK 与广告回调；不能直接用其 API 替换任意游戏宿主。

**交付文档**：提供可直接查看的总入口，逐模块写实际绝对路径、用途、替换或新增步骤、参数/事件约定、回滚方法、最小运行示例、已验证范围和未解决项。至少覆盖广告、资源/UI、关卡、埋点、启动/构建/诊断/回归；不存在的能力明确写“未实现/未验证”，不要为交付而虚构 API、SDK 或服务。

### 美术替换接口与 H5 换皮模块衔接

H5 资源换皮要按 [h5-canvas-reskin](../../h5-canvas-reskin/SKILL.md) 的 `component-restoration.md`、`pipeline.md` 执行，而不是只交一个图片目录：全量轻索引及真实状态去重；当前高风险或装配不明项目才深入定位帧/锚点/trim/旋转/拉伸及引用；真实格式与尺寸、帧、透明语义和用户批准目标分开记录。平铺背景先查真实相邻顺序和滚动裁切；仅按实证或用户约束锁轮廓/alpha，功能色重在辨识。经用户认可的目标和候选不能因指标擅自替换。

按“少量代表屏样本 → 用户要求时确认 → 同族批量 → 一次累计回填 → 同状态实际尺寸整屏对照 → 按共同原因返修”推进。图集整块复制 RGBA、检查有效候选/帧完整性/未修改区域与透明边缘；截图和资源若被内嵌在交付 HTML，修改后同步后处理及重建对应页面。记录原版、目标、候选和最终运行来源，调试调起不冒充自然操作。数据和布局改动以用户授权为准；仅美术任务才按该模块的非美术文件不变约束验证。当前不存在的 `skin_map`、批量图集工具或自动对照应标“需建设”，不能虚称已有。

### 版本对账与可复现交付

- 为原版基线、开发源、配置、构建输出、本地体验入口和线上 Git/部署各列实际路径、版本或提交、构建命令、关键文件清单与必要哈希，确认预览实际加载的脚本和资源来自哪个输出；不可用的条目标未知。迁移前后核对入口、资源和可运行链，用户授权清理旧版本时先确认范围及保留物，避免误删唯一源或数据。
- 查看 Git 跟踪状态、忽略规则、当前分支与远程目标：本地生成物存在不代表同事可拉到；区分提交源码并提供重建步骤，或用户要求时提交构建产物。按用户授权选择提交/推送，避开并发任务未完成的改动，推送后核对实际远程结果；不可因本地构建成功声称线上已更新。

### 宿主加载页与接口归属

- 分别定位游戏入口、父页面/宿主和平台 SDK 的加载页、图片、进度来源、生命周期和回调消费者；用包内引用、接口契约及实际宿主行为佐证归属。缺少平台契约时把归属和接入责任列为待确认，不把某一案例的平台模式外推到其他游戏。外层模拟、进度样式和本地可运行均不证明真实平台的加载与回调通过。

### 背景与动效性能

包体/加载/低 RAM 优化另按 [H5 包体与运行优化](h5-package-runtime-optimization.md) 执行：包含最新修改保护、动态资源删除依据、脚本/配置去重、缓存一致性、真实触屏、测量工具自证及设备内存口径；具体数值留在项目证据。

- 按场景和状态明确用户要修改的背景、动效类型、出现时机、循环/强度及预算；复用已有资源前先查纹理和分层，移动图片不等于可移动其图案。检查不同视口和位移全过程的覆盖、拼接和边界，避免露底或 UI 遮挡。
- 统计新增资源及对象数量，按实际平台测启动时间、帧耗时、内存和包体，区分下载体积、解压体积与运行时纹理内存；验证页面隐藏、暂停、切场景、动画结束时定时器/节点/纹理的生命周期，预加载应有明确触发点和释放策略。先查静态及动态引用、配置、平台入口和回退路径再删除资源；不确定是否使用时保留并标注。模拟或单机指标不替代目标设备实测。

### 对比汇报与局部图片修改

- 面向非专业读者，优先按玩法流程和实际变化组织同状态原版/新版截图或短录屏，新增内容单独呈现；标注来源、触发、版本及未覆盖范围。不要把录屏没覆盖当成原版没有，也不要把截图、概念图或生成演示当真实运行表现。控制嵌入媒体体积并验证交付页面的可读性与引用完整性。
- 要求“只改文字或局部、其余不变”时，优先使用可编辑源或可控局部编辑；检查文字、尺寸、版式和未经授权区域，必要时做区域差异检查。生成式重绘若改变其他画面，应修复或如实报告，不能称为像素未变。

## 4. 验证边界与阶段收口

- 原包校验、资源映射、代码/静态检查、浏览器自然交互、模拟宿主、真机浏览器、目标 AHA 宿主及真实 SDK 各是独立证据；报告实际来源、设备、触发路径和结果。
- 自然路径至少以项目实际可达流程取证：开始→操作→暂停/恢复→失败/过关→返回或下一关→重开；用户要求的每项编辑与接入都需要运行示例。可用程序**只读取**棋盘/事件状态辅助选择自然点击，但不能改棋盘、删对象或强制胜利后称“自然通过”。
- 显示未闭合事实：例如首版缺接口、结算卡住、部分状态无法自然到达、规则不明、棋盘无法证明可解、原始源码不可编辑、外部 SDK 和设备条件缺失。保留精确复现、错误、证据与恢复步骤。
- 小步做可对照的批次；用户要求先看原版和确定方向时，先交截图与资源入口，其余不依赖方向的玩法/配置工作可继续。阶段结果写成阶段结果，不宣称最终项目整体完成。

## 5. Construct 2 导出案例（仅用于方法对照，不能直接复制）

在 One Connect 的本次包体中，`data.js` 是无字段名的嵌套项目数据，运行时和对象引用表可用于定位变量、动作及事件；无 `.capx` 不表示已恢复可编辑 Construct 工程。实验副本证明一张标题图集、一个初始时间及开始按钮位置的改动分别在浏览器生效。

原版裸页面缺少宿主接口时，加载及失败结算的调用会报错；在开发副本提供可观察的降级后，浏览器可自然超时、返回并重开。它只证明本地模拟适配，不证明真实广告与宿主回调。

关卡的研究定位到原版生成/洗牌后、创建牌对象前的稳定边界：实验配置在该边界写入，再沿原版创建和判定流程运行；还需处理“下一关初始化先于关卡编号递增”的时序。已在开发副本自然清空前两关并进入第三关，验证该案例的逐关时间及固定棋盘加载，操作通过读取状态选择点击而非强制跳关。牌面成对不等于可解；更后关卡、所有随机种子、目标宿主与真机均不能由此推定通过。

本例的对象编号、事件 SID、数组形状、牌型数量、时间和文件路径只对该包成立。每次新包/新版本重新核对身份、数据布局、调用者与动作顺序，拒绝盲用钩子；验证失败应回退并记录未知项。
