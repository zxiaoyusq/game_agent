# 宿主小游戏：采集 → 拆解 → 还原 → 持续迭代

**作用**：作为 `hosted-minigame-harvest` 的端到端导航，按任务进入相应阶段；已有产物先核验再复用，不强制重新采集。每一阶段只加载所需模块；不把本导航当成各引擎的通用解包工具。用户的目标、路径、授权和验收平台优先。

## 阶段入口与退出条件

| 阶段 | 输入 / 动作 | 实际产出与退出条件 |
|---|---|---|
| 0 目标与身份 | 明确游戏、版本、合法可访问来源、修改范围、原版体验、平台与输出路径；已有 ZIP、解包或工程先检查身份和完整性 | 项目清单：目标与限制、源和版本/哈希、已有证据、待补项；不同版本不混用 |
| 1 采集与入库（需要时） | 只有缺包或用户要求批量采集时，按本模块执行卡和 `harvest-pipeline-and-gates.md` 区分包体/流式/动态容器，取原包、元数据与素材 | 按该阶段 G1–G6 验证来源/格式/包哈希与索引；非采集任务不要求商店接口、账号、root 或原包不可得的散列字段 |
| 2 识别与静态拆解 | 冻结原包和解包，指纹识别引擎与版本、入口、资源格式、代码/数据、宿主桥接、可编辑源及外部依赖。按实际引擎路由 `engine-identification`、Cocos/Unity 相应模块；导出数据和完整工程分开标注 | 原包/基线身份与哈希、工程/资源索引、引用映射、未知清单；静态推断不冒充行为证明 |
| 3 原版自然运行与视觉基线 | 在独立环境自然操作，记录菜单、选择、对局、暂停、失败/过关、重开及推进等实际可达状态；采资源与截图对照，记录来源与触发方式 | 可查看的截图/资源入口、运行错误和宿主缺失、未到达清单；调试调起只证明探索，不冒充自然解锁 |
| 4 路线验证 | 在独立实验副本分别验证资源、可定位参数及 UI 改动的显示与交互，并跑自然核心循环；评估原逻辑可维护性和重建路线 | 记录每项修改/效果/回滚、原版与重建比较、未闭合风险；优先以实际证据评估原版，不以启动或计数代替可玩 |
| 5 开发与持续迭代 | 根据实际输入和授权推进资源、美术、关卡、事件、广告、性能与 Bug 维护；H5 换皮路由 `h5-canvas-reskin`，玩法/SDK 选择适用引擎模块 | 按用户要求和适用范围，逐项在游戏中验证可编辑配置与新增、事件和本地宿主模拟；仅采集/截图任务的非请求项记 N/A。形成所需的可构建、可回滚、可迭代交付，不伪称真实 SDK |
| 6 回归与交付 | 区分文件检查、浏览器、模拟器、设备、目标宿主和真实 SDK；按用户指定平台自然实测完整循环，记录哈希与可复现路径 | 附证据、恢复/构建入口、各模块替换步骤和未完成项；条件不足明确报告，不能把低层证据升级为最终验收 |

## 模块衔接

- 包体/商店采集 → `hosted-minigame-harvest` 既有 S0–S5；已经提供原包时从阶段 0/2 开始。
- 引擎身份和容器 → `engine-identification`；Cocos/Unity 的解包和玩法进入各自模块。不能把仅适用于 Cocos 的玩法逆向脚本/条文直接用于 Construct、Phaser 或其他 H5。
- 原码 H5 自然运行、可行性、配置/宿主与接口交接 → [hosted-h5-restoration.md](hosted-h5-restoration.md)。
- 关卡可视化、跨会话解码任务、可验证经验按里程碑回写 → [iteration-editor-and-delegation.md](iteration-editor-and-delegation.md)。
- H5 美术 → [h5-canvas-reskin](../../h5-canvas-reskin/SKILL.md)，按其轻索引、目标参考、契约、代表样本、批量回填、自然运行对照和诊断流程。用户允许代码/UI 修改时将差异和回归单列；仅美术任务遵守仅美术契约。
- 重置前的平台/用户/竞品调研与分析报告（阶段 0 之后、阶段 4 路线决策之前）→ [reboot-market-analysis.md](reboot-market-analysis.md)。
- 用户提供匹配的 CombiMons SDK 模板时，按 [模板接入与验证](combimons-host-sdk-template.md) 核实父页、游戏入口和广告契约，案例不代表其他宿主。
- 指定 Android 真机或正式宿主验收时按对应环境/设备技能执行，实测来源和不足须如实报告；没有管线/SDK/设备时不编造 PASS。

## 贯穿约束

1. 原包、原解包、基线、实验、生产与生成物身份明确，先备份再覆盖；用户指定工作目录和已有工程优先。
2. 用户要先看原版再选美术方向时先交原版截图与资源，继续不依赖风格的工作；不得擅自选定最终风格或批量生成。
3. 实验成功仅证明对应修改；接口模拟仅证明本地行为；关卡可加载不证明全关可解；静态/资源通过不证明玩法和真机体验。
4. 所有交接文档列具体路径、用途、怎么改/运行/验证/回滚；不可用或需外部 SDK、用户方向或额外环境的事项写明缺口。
