# H5 包体、加载与低内存优化

范围：`GENERALIZED_PATTERN`。适用于已有可运行 H5 游戏的包体和运行优化，涵盖下载解压型宿主及流式 WebView；依当前引擎、加载器和设备重新确认实现。迁移判断方法和验证方式，不迁移某游戏的脚本名、资源数量、机型、关卡、阈值或收益百分比。

## 1. 接手时先保护当前有效版本

- 对开发源、生成配置、构建输出、体验入口和原版包分别记录实际路径、Git 根/分支/HEAD、工作区及暂存区改动、关键文件哈希与构建命令。用户要求在最新修改上继续时，以当前有效磁盘输入为起点；从旧提交导出会漏掉未提交改动。
- 对照所有实际入口和安装调用，确认预览加载的文件，而非按文件名或修改时间判断新旧。同目录的开发入口、默认入口及预览可能并不同步；Service Worker 也可能继续提供旧脚本。
- 备份当前源与实际发布物，再建立候选。列出需保留的近期功能和受保护文件；构建前后复核。源文件留作开发输入，发布裁剪交给构建器，避免通过删开发源实现减包。

## 2. 先分清优化的是哪种成本

| 指标 | 测量口径 | 能回答的问题 |
|---|---|---|
| 下载归档大小 | 实际交付 ZIP 的字节数，含目录/文件头开销，记录压缩方法和参数 | 下载包和流量是否减少 |
| 解包资源总量 | ZIP 内普通文件原始字节之和，另列文件数 | 落盘量及文件项是否减少；不直接代表解压耗时 |
| 页面传输与请求 | 实际 HTTP 传输字节、请求数、缓存/SW/Content-Encoding 状态 | 此加载路径的网络成本；与 ZIP 口径分开 |
| 加载耗时 | 按实际链路记录下载、解包、解析执行、图片解码/上传及可交互终点；不可观测段标未知 | 哪一段决定用户等待；并行阶段不可简单相加 |
| 运行内存与帧耗时 | 按 §7 区分 JS、进程和图形资源，记录场景、峰值及采样长度 | 目标设备是否稳定；不能由压缩文件大小推定 |

默认先保持现有归档策略，单独比较资源/代码变化；需调整策略时再做同输入对照。提高压缩等级、改格式或使用 STORED 都只是候选：同时观察下载、解包、解码和启动，不能只选 ZIP 最小或解压最快的一项。PC 读取 ZIP 的时间只算本机诊断，不能代替宿主解包实测。

原版比较保留真实上游 ZIP、来源时间、身份及可信来源散列；自行重打包不能冒充原下载包。本地历史包不是已复核的当前线上版本。MB/MiB 和比较范围写清，新增玩法/主题的版本不能直接当作同内容压缩对照。

## 3. 资源删除需要可达性证据

建立轻量清单：相对路径、真实格式、字节数、像素/图集帧、加载 owner、引用方式、出现状态、候选动作与未覆盖分支。先按总体积和大项排查，再按风险深入。

静态全文搜索是入口。继续查字符串拼接、数字帧、图集映射、CSS URL、配置表、引擎运行数据、主题/语言、音频格式回退、失败恢复及离线路径。胜利彩纸、后期背景等可能仅在特定分支加载；单次启动无请求、无完整文件名命中，均不足以判未使用。

把已证明不可达的候选从发布白名单排除，运行覆盖其原 owner 和相关分支，再核查网络错误、图集缺帧和回退路径。未覆盖且引用不明的资源保留并登记。CSS/插件同样需核对真实调用者和 DOM 状态，不能见到旧 SDK 名称就整段移除。

## 4. 常见手段及采用条件

| 候选 | 采用前确认 | 验证重点 |
|---|---|---|
| 删除旧资源/开发副产物 | 明确源与发布物、动态引用和回退覆盖 | 源仍可重建；最终归档没有缺项或冗余回流 |
| 合并小脚本 | 原执行顺序、独立 script 作用域/严格模式、顶层声明、注册副作用、async/defer、动态加载、相对地址、CSP/完整性要求与缓存粒度 | 冷/热启动、恢复器及关键功能；请求减少不自动等于速度提高 |
| 配置模板去重 | 明确数据生成阶段与消费者的写入行为 | 全量值、类型、顺序和初始化语义一致；修改一份不污染其他关卡/实例，共享只读数据需有相应契约 |
| 图片重编码/格式转换 | 查实际 magic bytes、解码兼容、alpha、帧和显示用途；对代表素材先试算 | 文件收益、实际尺寸画质/边缘、目标机解码与峰值；无收益就保留原文件 |
| 图集裁边/重排 | 核对 trim、旋转、原尺寸、锚点、帧映射、padding/extrude、过滤采样及引擎实际分配 | 下载体积与实际纹理分配分别比较；同状态边缘/动画不变，不能仅凭空白面积批准 |

压缩图片的文件大小、解码像素面积与 GPU 分配是不同指标。RGBA 面积估算只作诊断，实际还受格式、mipmap、对齐、缓存和引擎生命周期影响。裁边后重新编码可能使文件增大；这时应按任务的下载、内存和画质约束决定取舍，不能用单项理论收益宣布成功。

若保留媒体没有必要重编码，可逐字节比较发布物与源，直接证明其内容保持；确实改图时转入 [H5 换皮验证](../../h5-canvas-reskin/SKILL.md)，检查资源契约和同状态真实画面。

## 5. 保持体验的运行优化

- 先定位重复工作再改：例如 UI 每帧写入相同 textContent/样式，会反复触发节点变更。仅在值变化时更新，以相同空闲场景比较变更次数，同时验证数字变化、状态切换和动画仍正常。
- 对背景、粒子、图片解码/缓存分别找 owner。按结束、切场景、暂停、隐藏和销毁检查定时器、回调、节点、纹理引用；反复进入退出后观察是否回落。引擎/其他场景仍持有的资源按引擎生命周期释放，不能强删共享纹理来换取瞬时指标。
- 预加载按首屏与后续场景分预算，记录触发和保留时长。延后加载需验证第一次使用无白图或阻塞；无限预加载会把请求节省转成内存峰值。降低 DPR、动画数量、音画质量属于体验变化，按用户目标另作取舍，不能作为“体验不变”的默认优化。
- 新加输入监听应检查真实鼠标、触屏和必要的取消路径。引擎的 preventDefault 可能阻止合成 click；触屏适配需过滤多指、拖动/长按，避免 touch 与兼容 click 重复触发，并保留原输入释放链。不要在上层吞掉 touchend，使引擎一直处于按下状态。手势阈值依当前坐标系与操作取证。

## 6. 加载对照与测试工具先自证

前后包使用同一设备/浏览器、视口/DPR、网络和 CPU 条件、存档及可交互终点。隔离测试存档，避免覆盖用户进度。多次采样并列原始值和中位数；CPU/网络模拟用于可重复对照，不等于低端真机。分别说明冷 HTTP 缓存、热缓存、首次 SW 安装及离线重启，改完包重新测最终产物，不能套用中间候选的结果。

就绪条件采用实际画面/可操作状态及引擎状态交叉确认。若自动化包装器对异步谓词的等待语义不明，先验证持续 false 会超时、延迟 true 不会提前完成、reject 会报告错误。Promise 对象被当真值会制造“瞬间通过”；一旦反例成立，先修测试，必要时由宿主循环 await 页面求值，明确比较解析后的结果并设截止时间。该问题须按当前工具版本复现，不能概括成所有浏览器工具都不支持异步谓词。

调试存档直达后期关卡只算定位诊断。道具失效时，使用同一测试状态对照优化前快照，核查解锁、库存、引导和历史条件；若前后同样失败，登记测试前提或原有问题，不能强行解锁/补发后声称自然入口通过，也不能未经定位归因于优化。

## 7. 低内存设备与生命周期证据

| 观测 | 应记录什么 | 结论边界 |
|---|---|---|
| 设备 RAM | 真机/模拟器、型号、系统可见 MemTotal 与采样时 MemAvailable；注明系统保留及单位 | navigator.deviceMemory 是浏览器粗略分档，不能据其认定物理 RAM；约 3GB 设备的低可用内存也不是 1GB/2GB 物理机 |
| JS 堆/DOM/对象 | 场景、操作序列、峰值、GC 是否人为触发、操作前后和反复循环后的回落 | GC 后小堆或短时节点不增长，不证明加载峰值小或长期无泄漏 |
| 进程内存 | 包/进程归属、采样范围、renderer/WebView/GPU 等可得数据及共享口径 | Chrome 主进程可能含其他页面；单进程 PSS 不是游戏独占 RAM，不能把包含关系不明的数据相加 |
| 图形资源 | 实际纹理尺寸/格式、缓存和引用、场景切换与上下文恢复 | JS 堆不覆盖所有图形/原生分配；理论 RGBA 面积不是实测显存 |
| 帧耗时 | 场景、采样长度、平均值和尾部/卡顿，必要时排查 CPU 归因 | 短时流畅不代表长时间游玩、内存压力或所有低配机稳定 |

按任务覆盖冷启动、进入关卡、最高复杂度背景/特效、重复切换与重开、暂停/返回、后台恢复及长时间游玩，记录峰值、回落、丢帧和崩溃。目标为 1GB/2GB 时分别取得对应真机证据；没有设备就明确未覆盖，不以限速、少量可用 RAM 或浏览器分档替代。

页面隐藏、浏览器标签切换、Android Home、进程被杀和宿主重建分别取证。模拟 WebGL 上下文丢失只证明该恢复路径。恢复后同时核查状态/分数、画面、纹理和真实输入；暂停画面正常时，通过原生继续入口恢复后再截图和操作，保留用户、广告、宿主等原有暂停归属，不能只看变量就判恢复成功，也不能无条件解除合法暂停。

真机视觉正式验收仍按 [vision-device-testing](../../vision-device-testing/SKILL.md) 的管线执行；局部 Chrome 冒烟或脚本采样明确单列，不冒充该管线或真实宿主验收。

## 8. 最终构建与交付

从当前有效输入构建到临时发布目录，检查成功后替换目标输出，避免半成品污染体验入口。同步所有实际入口、启动恢复器和缓存清单；按最终字节更新版本/哈希。逐项检查归档路径、文件内容、资源引用、清单缺项及旧文件残留；同时验证正常联网、首次缓存、断网刷新/进关和下一版本更新，防止旧 SW 把新旧代码混用。

报告分别列脚本/静态、桌面浏览器、真机浏览器、目标宿主和目标 RAM 档的实际覆盖及未执行项。启动、进关、主要功能、视觉/触屏和释放应有对应证据；只读 ZIP、语法通过、截图相似各不能替代其余层级。

交付保留：前后实际字节/文件数及口径、最终包哈希、来源与构建命令、受保护改动对账、采用和放弃的方案及原因、原始测量和场景证据、回滚输入、未解决问题。项目专属数值和设备事实写入项目报告或 [landing-log.md](landing-log.md)，不要提升为其他项目的预算或通过阈值。
