## S0 目标确认与形态判定

| 动作 | 命令 / 判据 |
|---|---|
| 宿主是谁 | 桌面图标名 → 点击 → `dumpsys window \| grep mCurrentFocus` 拿包名；`dumpsys package <包名>` 拿版本 |
| 形态 A/B/C | 见 `SKILL.md` §1 表；**A 型的决定性证据是"缓存目录里有每游戏元数据文件"** |
| 设备能力 | 模拟器/真机是否 root：`adb root` → `adb shell id` 看是否 `uid=0` |

`root` 只影响**路线 2（读 data 目录）**；路线 1（接口直取）**不需要 root、不需要设备**。

## S1 落点测绘

仅当任务需要设备缓存或判断“未玩过”时，按权限与实际宿主查相关落点；接口直取或用户已给包体不要求设备。来源案例曾检查以下位置：

```
/data/data/<宿主包名>/files/            # 包体缓存 + MMKV 配置
/data/data/<宿主包名>/databases/        # 有的宿主把账本放这
/sdcard/Android/data/<宿主包名>/files/  # 原生 APK / 大型资源落点
```

**仅在需要且可访问时查找的三类案例文件**：
1. **每游戏元数据**（案例名 `gameInfo`）：直接给 `gameId / 包体直链 / md5 / resourceId`。定位：`find <cache> -name gameInfo`
2. **游玩账本**：MMKV / DB 里的 `game.opened_<id>` 一类键。
3. **zip 游戏管理器状态**：MMKV 名常含 `zipGame` / `h5GameCache`。

> MMKV 不是文本，用 `strings <file>` 先看键名，够用；要读值再上 MMKV 解析或 protobuf walk。

## S2 契约发现

见 `store-api-contract.md`。已知 ID 时只需能取得目标的必要端点；只有需要搜索或枚举时才需相应发现接口。

## S3 发现集与"未玩过"判定

| 输入 | 处理 | 风险 |
|---|---|---|
| 用户给 `gameId` | **直接打详情**，不做名称解析 | 无 |
| 用户给名称 | 打搜索端点，按 归一化精确 → 双向包含 → 首位 三级降级 | **同名歧义**：案例中某名称全站不存在，只能落到最相似项 → 必须标注 `FUZZY` 并请用户确认 |
| 用户给分类/关键词 | 分类端点 + 搜索 + 推荐流多轮取并集 | 推荐流每次随机，需多轮；**并集 ≠ 全站目录** |

**"未玩过"判据（两个来源都要查）**：

```
未玩过 = 不在包体缓存里（无对应 gameInfo/缓存目录）
      且 不在游玩账本里（无 game.opened_<id> / game.loaded_<resourceId>）
```

只查缓存会漏"玩过但缓存被清"的游戏；只查账本会漏"下载了没玩"的游戏。

## S4 拉取

### 包体

```
对每个目标：
  url / 可用散列 / size ← 当前来源字段（例如 AHA 的 bundles）
  若本地已有文件且可与来源散列核对一致 → 可复用（CACHED）
  否则下载到独立临时文件 → 校验归档 → 来源散列可用时比对
  相等 → 来源散列一致；不等 → 保留诊断并标记 MD5_MISMATCH，不覆盖已有有效包；来源未提供散列时记录 SHA-256，不称上游一致
```

### 素材

五个位置各自独立取（缺就跳过，不报错中断）：

| 文件 | 字段 | 备注 |
|---|---|---|
| `icon.*` | `iconPictureLink` | 详情或批量接口 |
| `hotgame.*` | `hotGameImageLink`（案例） | AHA 案例中在批量接口取得、单次上限 20；当前来源的端点和限制需重新取证 |
| `banner.*` | `banner` | 详情接口 |
| `theme.*` | `themePictureLink` | 详情接口 |
| `preview.gif` | `imageLink` | 动图，可能是 `.gif` |

保留原始 URL 的 query，除非已确认当前字段是非必要提示；签名、鉴权或版本参数可能依赖 query。

### 文案

`description`（一句话）+ `introduction`（详情）+ `tags` + `source`（开发商）+ `category/rate/byteSize`。

## S5 编目交付

产出四件：`manifest.csv/json`、`art_manifest.csv`、`index.html`、校验报告（+ 未知清单）。

**索引页必须做到**：
- 每卡片含**文件夹名**（便于与磁盘对账）、icon、banner/hotgame/theme/preview、名称+id、分类/评分/大小、开发商、两段文案、标签、包体文件名 + MD5 + 在线入口
- **全部图片为相对路径本地引用**（`src="http..."` 计数必须为 0），离线可开
- 带搜索框 + 分类筛选（74 张卡片量级下人工翻页不可用）
- 图片后缀**从 `artFiles` 清单解析**，不硬编码 `.webp`

## 门禁 G1–G6（按请求和来源能力适用）

| 门禁 | 判据 | 不过说明什么 |
|---|---|---|
| **G1 包体可读** | 所请求的 ZIP 检查魔数、归档结构与解压/完整性；非 ZIP 按实际格式核查 | 排除错误页和可检测的截断；不能仅凭头两个字节证明完整 |
| **G2 包体一致** | 来源提供可信校验值时，对应算法逐个比对；没有时记 N/A 并单独记录本地 SHA-256 | 哈希不一致可能是版本或下载错误；未提供来源哈希无法证明一致 |
| **G3 素材真实** | 每张图按 magic bytes 属于其**后缀声明的格式**（webp=`RIFF..WEBP`、jpg=`FF D8 FF`、png=`89 50 4E 47`、gif=`GIF8`） | CDN 无视后缀返回了别的格式 → 必须改名 |
| **G4 引用完整** | 索引页 `src` 引用的每个本地文件都存在，缺失 = 0 | 清单与实际文件不同步 |
| **G5 无乱码** | 页内替换字符 `U+FFFD` = 0，且 Latin-1 乱码对 = 0 | 抓取时按 Latin-1 解了响应体 |
| **G6 编目齐全** | 所请求清单覆盖目标，记录可得身份、来源、状态和校验值；来源无官方哈希标“未提供” | 防止静默漏项；素材清单未请求时记 N/A |

**判定优先级**：有来源散列时 G2 不一致即未通过一致性校验；没有来源散列时 G2 为 N/A，只报告本地身份哈希，不能称来源校验通过。G3–G6 仅适用于请求了相应素材、页面和编目的任务；适用项失败必须如实报告，其他项不凭空增加。

### 现有校验脚本的能力边界（必须单独补验）

`modules/hosted-minigame-harvest/scripts/harvest_validate.ps1` 面向完整批量索引；它当前的 G1 只检查 ZIP 的 `PK` 文件头，**不验证 ZIP 中央目录、解压或 CRC**；G2 对空 `md5` 字段直接跳过，但总输出仍可能写 `ALL GATES PASS`。它还依赖批量 `manifest.csv` 和 `index.html`，不适合直接作为单包无索引任务的完整验收。

因此：通过该脚本只证明它执行了哪些具体检查，不能声称包体完整或上游哈希一致。另用适配当前格式的归档完整性检查，对来源提供的官方哈希逐个比对；未提供官方哈希时记录本地 SHA-256 并标明缺口。单包按请求范围编目，不为适配该脚本虚构素材、索引或 MD5。脚本报非零时保留日志与失败项。

## 失败分类与下一步

| 现象 | 通常是 | 下一步 |
|---|---|---|
| 详情端点 404 / `game not found` | gameId 不存在或已下架 | 核对 ID 来源；记为 `NOT_FOUND` |
| 对象没有 `bundles[]` | 可能是其他字段、下发路径、流式或原生形态 | 查当前契约和其他来源；证据不足时记未确定，不能直接排除目标 |
| 连续多请求失败 | 可能限流，也可能是网络或鉴权问题 | 先看状态码和实际证据，再按当前来源限流与退避；来源案例间隔 ≥1.2s |
| 批量接口返回数 < 请求数 | 可能存在静默上限或部分失败 | 核对当前服务与逐项状态；来源案例上限 20、曾用 6/批，不应直接照搬 |
| 图打不开 | 后缀与真实格式不符 | 跑 magic bytes 改名（G3） |
| 中文变 `ä¸æµ·` | 响应体按 Latin-1 解码 | 见 `powershell-harvest-pitfalls.md` 坑 3 |
