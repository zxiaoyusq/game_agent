# CombiMons 父页面 SDK 模板：接入与验证

**何时读**：用户提供匹配的 CombiMons 包或明确要求参考此父页面 + iframe 模板。**范围**：模板专属事实；通用流程仅迁移为核验方法，API、地址和回调契约必须对当前模板和平台重新确认。

## 模板身份与结构

样本 `CombiMons.zip` 的 SHA-256 为 `083e38fa7563c13e3646837424647bf3a0340329a09b5bcbd71ea362a28318da`。归档仅含根 `index.html`、`readme.md`、`game/index.html`、`game/index.js`。README 约定父页面不改、完整游戏放入 `game/`；实际父页面 iframe 加载 `./game/index.html`，示例游戏页注释称 `game.html` 与实际入口不一致，以父页面实际引用为准。若现有游戏已有 `index.html`、相对路径或构建流程，保留并核对依赖，设计可回滚的入口；不能盲目覆盖。

父页面从远端 `https://www.hippoobox.com/static/sdk/adsdk_1.8.0.0.js` 加载 SDK；ZIP 不包含该 SDK 的可离线副本。该 URL 和版本仅是样本事实，供平台核验，**不是所有宿主的通用地址**。模板内 publisher / game / 分析 / 广告位标识属于样本，不复制到其他项目；向平台取得目标游戏的参数、允许域名、SDK 版本及正式集成文档。

## 样本调用链（静态事实）

1. 父页面初始化 `window.h5sdk.init(...)`，其配置中的 `adsence.callback` 调用 `athenaSend("game_start")`、`adConfig`，准备就绪后调用 `adBreak({type:"preroll", ...})`。父页面还在 `window.onload` 调用 `gameLoadingCompleted()`，并接受子页同名消息再次调用；两个信号都可能产生，父页加载完成不等于游戏资源已就绪。`a_bridge` 是否存在会影响初始化与 iframe 加载路径，目标容器中需实测。
2. `game/index.js` 中 `showNext()` 发送 `postMessage("next", "*")`，然后在父页面的 `MIAD_NEXT` 设置 `_callback` 和 `_failback`；父页面调用 `h5sdk.adBreak({type:"next", ...})`，`adBreakDone` 的 `breakStatus === "viewed"` 走成功，其他状态走失败。
3. `showReward()` 同理发送 `"reward"` 并设置父页面 `MIAD` 两个回调；父页面调用 `adBreak({type:"reward", ...})`，`beforeReward` 调 `showAdFn()`；`adBreakDone` 的 `viewed` 走成功，其余走失败。示例回调只是打印日志，游戏暂停、继续和奖励发放并未实现；不能把函数调用当成真实展示或奖励到账。
4. 页面保留底部 50px 广告区域及示例配置；这只是模板布局，不代表其他平台要求固定 50px。真实 banner、适配和遮挡需要平台和设备验证。

## 按目标游戏接入

1. 保存原 ZIP、基线和修改前文件，核验模板版本、游戏入口及 SDK/宿主契约；在独立开发副本接入。保留父页面和游戏原有相对路径，按 SDK 提供方约定配置真实标识、加载域名和发布方式。根模板声明不要改父页面：任何父页面改造先确认提供方支持或取得其批准；不要声称通用适配已经存在。
2. 查明目标游戏原宿主接口、广告触发点、暂停/恢复与奖励代码，做接口映射。模板 `window.h5sdk` + iframe 消息并不等同于某游戏自有的 `h5_sdk` 或 `showAd`；需要适配器承接已有调用，保持游戏时序。仅 Promise 返回或发出请求不代表广告完成。
3. 在供应方允许的边界内，接入前安装回调、控制单次请求并清理；按其正式回调语义处理展示、关闭、不可用和错误。奖励仅在经确认的有效完成信号到达后发放，并按请求/奖励交易去重；失败、超时、异常不发奖且安全恢复。插屏失败也须确保游戏可继续。不要把示例 `viewed` 的含义外推到别的 SDK。
4. 该示例采用 `postMessage(..., "*")`，父监听器不验证 `origin`/`source`，且子页直接访问 `window.parent.MIAD*` 依赖同源可访问。限制目标 origin、验证来源、请求关联/单飞、超时与一次性回调属于建议改造，**模板本身未提供**；跨域需设计双方可用的消息协议，并先确认父页面改造许可。SDK 缺失、初始化失败、回调缺失须有可观察降级，不能假报成功。
5. 先用隔离本地 mock 覆盖初始化、加载完成、插屏和激励成功/取消/不可用、异常/超时、重复或并发及恢复/奖出去重；再按平台测试配置在实际宿主和设备验证真实 SDK、广告位、展示、关闭、奖励、banner、前后台及网络。保留每层证据和回滚入口。

## 已知证据与缺口

2026-10-29 对样本做静态阅读、ZIP 完整性检查及本地浏览器 mock：`viewed`、`dismissed`、其他状态均按上述分支回调；构造未可信来源消息被父监听器接收；模拟两个重叠激励请求时第二回调执行两次、第一回调未执行。模拟无真实 SDK/网络广告，不证明线上 SDK 的行为或真实设备结果。目标平台参数、加载回调正式语义、真实广告、跨域部署和对父页面改造的许可均待确认。
