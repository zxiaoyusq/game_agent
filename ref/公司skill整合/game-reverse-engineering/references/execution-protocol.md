# 执行协议（任何任务都按这五步走）

**这是本总集的唯一执行入口协议。** 命中任何游戏逆向 / 重建 / 二开任务，先走完下面五步，再去读模块正文。范围：`GENERAL_DEFAULT`。

不要通读整个技能包。按表定位，读一份，做一步，再决定下一步。

## 五步循环

| 步 | 动作 | 通过判据（做到才算进入下一步） |
|---|---|---|
| **1 定位** | 读根 `SKILL.md` 的「任务意图快速分发」表，按用户原话命中对应行 → 得到模块名与第一个动作 | 能用一句话说出：「任务是 X，走模块 Y，第一步是 Z」 |
| **2 读执行卡** | 打开 `modules/<模块名>/SKILL.md`，先只读顶部「执行卡」 | 能复述该卡里的「第一步」和「做完标准」 |
| **3 做第一步** | 只做执行卡写的第一个动作，不发散、不预读其他模块 | 产生了执行卡要求的第一份产出（清单 / 基线 / 证据 / 备份） |
| **4 按需读参考** | 从模块的「参考文件索引」里挑**当前卡点对应的那一行**，只打开那一份 | 卡点有解，且能指出具体做法在哪一节 |
| **5 收口** | 跑模块「做完标准」+ 全局交付门禁 | 完成判据全绿，且交付物含未知清单 |

## 铁律（违反即返工，无例外）

1. **一次只走一个模块。** 任务跨模块时，按第 1 步的表逐行叠加，不要「都看一眼再决定」。
2. **没有证据不写结论。** 包内字符串、桥接日志、模拟器画面都不是运行时证明；证据等级见 `references/global-rules.md`。
3. **案例字面值不许复制。** 包名、域名、appId、签名、版本号、路径、设备序列号、Trait/事件名、hook 偏移、资源数量、时间阈值一律重新取证，清单见 `references/scope-map.md` 的 `DO_NOT_COPY_LITERAL_VALUES`。
4. **先备份再改动。** 改文件前备份；动服务、配置、构建产物前先说副作用和风险。
5. **交付必附未知清单** `references/unknowns-ledger-template.md`；三条主链路（Godot 迁移 / 换皮 / SDK 替换）另附各自义务清单。
6. **失败就报失败。** 不确定写「不确定」，缺条件写「缺什么」，不写没有证据的「已完成」。

## 卡住时（按顺序试，别跳）

1. 回模块「执行卡」的**红线**，确认没踩线。
2. 读模块「参考文件索引」里标 `GENERALIZED_PATTERN` 的那一行（可迁移的判断方法）。
3. 读 `references/global-rules.md` 的对应边界：解密边界 / Android JSB 边界 / 采集负面清单 / 工具环境。
4. 还是无解 → 登记到未知清单，写明「缺什么才能继续」。**不要编答案。**

## 报告状态只用这四个词

| 状态 | 含义 |
|---|---|
| `PASS` | 有落盘证据，且证据等级达到该任务要求 |
| `FAIL` | 有证据证明不成立，并写清反例 |
| `BLOCKED` | 缺权限 / 环境 / 设备 / 素材，写明缺哪一项 |
| `NEEDS_CONTEXT` | 缺项目事实（owner、包身份、版本谱系），写明要重新取证什么 |

## 需要走全链路时

首次做完整逆向工程（识别 → 提取 → 修复 → 换皮 → 烘焙 → 构建 QA → SDK → 真机），按 `references/end-to-end-pipeline.md` 的 0–6 阶段顺序走，每一阶段仍回到本文件的五步循环。
