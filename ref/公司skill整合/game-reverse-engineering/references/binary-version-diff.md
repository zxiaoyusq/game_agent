# 跨版本差分与符号迁移

> **何时读我**：游戏更新后要迁移函数、Trait/JNI/字段定位，或要判断回归来自哪个版本变化。
> **读完能做到**：为每条匹配和差值标注证据等级与状态，产出带双方哈希/地址的映射表，并只对拿到显式证据的项执行改名或类型提交。
> **范围**：`GENERALIZED_PATTERN`

范围：`GENERALIZED_PATTERN`。适用：游戏更新后迁移函数、Trait/JNI/字段定位、验证回归来源。不是全量自动重命名或旧偏移复用。

## 小范围证据配对

旧/新各自保存 SHA-256、版本、架构、编译格式、分析库和地址基准。先区分算法修改、资源/配置修改和 SDK/壳修改，不把远程快照变化误判成本地二进制变化。

从有来源的导出/元数据签名/独特字符串 xref 开始，结合调用图、参数和返回类型、状态读写、常量和结构关系配对。一条字符串、相同函数长度或 LLM 相似度只能产生候选；编译优化、泛型共享、拆分/合并、内联和签名改动必须保留一对多/未匹配。

每轮只导出目标函数与必要邻居，保存反汇编和伪代码，不把整个 so/IDB 塞进模型。候选命名缓存按两个输入哈希 + 函数地址 + 工具/规则版本索引。

## 证据等级（差值与匹配项）

每条匹配或差值必须标注证据等级。等级回答「证据是什么性质」，状态字段回答「验证到哪一步」，两者并用，不互相替代：

| 等级 | 含义 | 典型来源 | 允许的动作 |
|---|---|---|---|
| 显式证据 | 运行时或字节级直接证明 | hook 命中、真实执行日志、双方字节/哈希对比、导出元数据签名匹配 | 可提交应用；可关闭义务清单义务 |
| 静态候选 | 静态分析产生的对应关系 | 字符串 xref、调用图、参数与返回类型、常量与结构关系 | 只做候选；改名/类型需再取得显式证据 |
| 仅推断 | 由相似度外推的对应关系 | 函数长度、LLM 相似度、编译特征泛化 | 显式保留在映射表；不得应用；不得作为回归依据 |

升级与降级：静态候选补得显式证据后升级；仅推断项取得一条静态佐证后升为静态候选；任何证据冲突即整体降级并标 `rejected`，不保留「置信度」数字。

差值同标：静态 diff 出的差异只是**候选差异**，不是因果证明。「新旧版本此处不同」要指向行为结论，必须先取得运行时差异证据；未复核的静态差值默认登记为未知项。

## 映射与提交

映射至少包含：`old_sha256/new_sha256`、`old_address/new_address`、双方地址类型、候选语义、函数/直接调用/间接调用/全局变量/字段偏移类别、证据引用、`evidence_grade`（显式证据 / 静态候选 / 仅推断）、冲突和状态。状态是 `candidate / corroborated / runtime_checked / rejected`，不得只存一个“置信度 95%”。

直接 call 的指令地址不同于 callee；虚调用槽位不同于函数入口；字段偏移只附结构上下文。新分析库先备份，以注释保存候选；只有证据相互印证才应用类型/改名，记录原名称和撤销动作。旧库与目标二进制不修改。

迁移涉及运行 hook/patch 时，重新证实新版 owner、签名、对象生命周期、模块映射与触发动作；失败则回到候选定位，不沿用旧固定偏移。至少抽检相关正常/失败分支、状态写入和调用链，玩法变化继续执行原模块 RNG/候选分布门禁。

来源：逆向AI.zip `binary-diff/SKILL.md` 的函数级结构比对与五种映射类别；不吸收固定模型、并发数、低成本宣传和自动把候选当事实的动作。路径/哈希见 [合并记录](minimaxh3-absorption.md)。
