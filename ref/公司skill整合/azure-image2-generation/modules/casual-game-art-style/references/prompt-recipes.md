# 提示词编译：形式与本地化分开

## 从证据到项目，不从竞品整屏复制

1. 在[模板](style-masters.md)中选择有截图依据的形式特征：造型、线条/明暗/材质、UI结构、场景组织。
2. 从本项目载入地区方案、四级职责、UI家族和当地内容清单。竞品的色相、饱和度/对比层级、功能色安排、题材、物件、角色和文化符号均不迁移。
3. 根据玩法与资源契约确定视角、布局和可改形范围，再编译简短画面描述。

生图提示词默认不写竞品名称，也不直接传入彩色竞品整屏；用已抽取的形式描述，配本项目参考。若用户明确要求图像参考，逐图注明职责，但不能声称一句“忽略配色/元素”即可保证不泄漏这些内容。

## 一份当前简报

记录交付阶段、模板/项目基准、本地方案与内容、控件家族、不可变项和允许变化项。反馈更新选择，而不是不断追加排除词。只给本次相关规则，不发送完整skill、历史失败或其他七种模板。

比较形式时固定本地化内容、功能色、布局与视觉占面范围；比较配色时固定形式。对象身份固定不等于外形完全固定，但真实碰撞、球体外轮廓、格位、点击区域和文字可读性优先。

## 可选短模板

```text
制作[用途/画幅]，使用本项目[当地内容清单]。
形式：[所选模板的造型、轮廓/绘制、表面表现]。
UI：[稳定组件结构与当前控件家族]；场景：[与主体协调的概括和空间组织]。
本地化：[地区方案ID/本项目色板]；玩法功能色独立，非玩法区沿用项目四级职责。
保持[布局、视角、身份、文字/数值、功能色或资源契约]；允许改变[明确范围]。
本次重点：[一至两个关键要求或返修项]。
```

具体色值和题材均来自项目，不从模板截图填入。模板短句是形式片段，不能替代本地化段和真实布局约束。

## 对象协调，不做机械变形

全屏协调的是绘制完成度、概括尺度、材质组织和空间可信度；物件、UI、植物和建筑各有结构。正常矩形面板可与曲面物件同屏，不能把手绘感写成全屏波浪，把漫画写成剪切棋盘，把简模写成所有内容方块化。

若用户明确指定块面/剪纸/斜切等特殊造型，将其写成当前项目定制方向，并检查功能边界；不要将这一偏好伪装成竞品的通用规律。若用户要求比较造型，在允许范围内明确比例、转折和轮廓差异，不靠只改光泽或纹理冒充。

## 返修与验收

采用“保留已成立项 + 修改对象 + 修改维度”。背景发灰而对比合适时只回补本地色彩；按钮弱时修家族的物底分离与完成度；细节过密时删无功能小结构，不把所有层一起压灰。

先检查：玩法身份/布局与功能色 → 项目配色、控件一致与四级职责 → 形式是否符合所选模板证据 → 图标复杂度与场景焦点。竞品相似度不能覆盖本地化要求；本地化正确也不等于形式已达标。

先检查代表图，再执行已授权批量；出现共同缺陷先修代表图。保存实际提示词、参考职责与真实偏差，不用规则文字证明画面已通过。
