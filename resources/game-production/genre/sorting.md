# 排序解谜

状态：已有 Ball Sort Web 成品案例；其它排序变体仍需重新定义规则和验收。

## 核心状态与循环

状态包含容器顺序、容量、元素类型与顺序、可见性、目标和辅助资源。循环为观察局面 → 选择来源与目标 → 检查是否合法 → 原子提交移动 → 展示反馈 → 判断完成。

必须决策：移动单个元素还是连续同类批量、空容器接收规则、容量是否一致、完成是否要求满容器、隐藏信息何时揭示、是否允许撤销/加容器/提示，以及覆盖进行中局面的处理。

## 规则不变量与关卡

- 普通移动保持元素数量和类型计数，不超过容量；批量动作作为一次事务处理。
- 输入数据明确顶端/底端和空位语义；引用解法按本项目规则重放，不能凭字段名假定一致。
- 固定解谜关若承诺可解，应给出合法解法或求解证据。搜索超时只表示未找到解，不能报告已证明无解。提示绑定当前局面，不能继续输出过期路径。
- 难度结合颜色数、容量、空位、混合程度、约束与实际解法长度；隐藏信息单独评价。改变数值或重排容器不自动成为新关卡。
- 若支持撤销，历史相邻状态必须对应合法事务；有界历史要保存截断边界。若不支持撤销，不引入该系统。

## 最小验收证据

覆盖空来源、满目标、类型不符、批量边界、完成判定及真实通关。对存在的提示、撤销、隐藏信息和辅助道具分别验证；隐藏信息不能从数字或同色判断中泄露。记录关卡合法性、解法回放和真实交互证据。

## 本项目可追溯案例

`games/ball-sort-fusion` 使用官方 Cocos 3.8.8 Web 引擎，包含 100 经典、12 高管和 20 迷雾关。实际验收为 9 项规则/存档测试、26 条浏览器检查，依据 `docs/agent-production/acceptance.json` 和 `games/ball-sort-fusion/workflow/test.md`。其中迷雾关复用经典棋盘并改变信息条件，不应称为 20 个全新棋盘。

该案例证明了这套排序规则和指定浏览器环境的交付，不证明其他品类、原生包、实体手机或 Safari 已通过。跨品类项目按需参考其存档、输入和证据方法，不复制整套游戏参数或模板。
