## 结论与证据边界

确证于提供的反汇编文本：shotPowerLimits 所得序列的前两个元素经 0x2706e20 调用，结果分别存入返回结构 +0x20/+0x28，并在调用方按相同偏移转存到新对象。返回结构 +0x08 的容器来自另一个配置键，不能归为 shotPowerLimits。此前回复及进度消息中相反的容器归属撤回，以本报告统一的数据流为准。

0x2706e20 的调用方式已定位，函数内部转换规则未证明；0x26fac38 未取得函数体或调用证据。五处 MatchShotSolver 短函数是类型指针比较和条件返回，不能当作求解器。当前材料不足以还原真实力度曲线、单位、范围、物理积分、碰撞参数或击球评分算法。这里的确证仅指所读文本中的静态指令关系，不代表已重新核验二进制、证明运行可达或完成动态实测。

## 地址与方法

全部地址均为 AArch64 ELF link VA，不是文件偏移或进程绝对地址。既有交叉引用方法仅扫描 ADRP 后有限距离内 ADD 的字符串起点匹配；既有直接调用扫描仅覆盖 BL 到指定起点。它们遗漏间接调用、尾调用和其他寻址方式。FDE 是展开范围，不独立证明业务所有者或函数语义。

## shotPowerLimits 的上游与转换链

令 R 为 0x18b09d4 入口 x8 指定的返回区，函数在 0x18b09f8 将其保存为 x19。入口 x0 保存为 x20，作为后续查找的第三个参数；其业务含义未知。

|位置|静态行为|结论|
|---|---|---|
|0x18b0a5c–0x18b0a80|调用 0x1c128d8；构造键地址 0x11cc3f0（shotPowerLimits）；以返回对象 +0x40、键对象和 x20 调用 0x26c1074|存在按键访问路径，尚未证明查找/覆盖规则|
|0x18b0a84–0x18b0a94|比较结果 +8 字节与 4；选择首指针或备用指针到 x23|类型标签数值确证，正式类型名未知|
|0x18b0aa4–0x18b0ac0|x0=x23，x8=x29-0x30，调用 0x26e630c；检查临时结果标签 5|与序列提取相容，完整函数语义未知|
|0x18b0b0c–0x18b0b24|初始化 sp+0x50 的三字容器；加载 begin/end；数量为差值算术右移 4；调用 0x18b15a4|元素步长为 16 字节的容器构建路径|
|0x18b0f84–0x18b0f90|清零 d0；x0=[sp+0x50]；调用 0x2706e20；str d0 到 R+0x20|第一个元素对应的调用结果存到 +0x20|
|0x18b0f94–0x18b0fa4|清零 d0；x0=[sp+0x50]+0x10；调用同一地址；存到 R+0x28|第二个元素对应的调用结果存到 +0x28|

统一链路：shotPowerLimits → 条件选择的 x23 → 0x26e630c → 临时序列 → 0x18b15a4 → 栈容器 sp+0x50 → 首地址及首地址+0x10 → 0x2706e20 → R+0x20/R+0x28。非法标签分支使用备用容器，不能承诺异常配置同样得到有效元素。当前调用区间未见访问前的长度至少为 2 检查；这不能证明完整程序不存在其他校验，也不能宣称已复现越界。

R+0x08 的区别：0x18b0a14/18 使用另一个键地址 0x122e53e，其选择结果保存为 x22；0x18b0f04 将 x22 送入 0x26e630c，0x18b0f68–0x18b0f80 在 R+0x08 构建容器。该键文本未取得，不命名。它与 shotPowerLimits 的栈容器是不同来源。

### 0x2706e20

确证：上述两个调用前 x0 指向相隔 16 字节的元素，d0 清零；调用后 d0 以 64 位浮点寄存器存储指令落盘。同一配置组装函数对其他字段也调用该地址。

推断：与通用值读取/转换为 double、接受浮点默认参数的接口相容。

未知：实际返回类型的符号证明、标签分支、字符串解析、整数转换、缩放、钳制、舍入、默认值和异常处理。不能从调用前 d0=0 推出力度下限为零，也不能从字段名推断元素必定为最小/最大速度、冲量或牛顿。

### 0x26fac38

未取得函数体或已读文本中的调用点。证据包文件名 query=26fac38 返回 0 项，仅说明文件名未匹配，不能当作全包内容或原库全量检索。大型 analysis/native_elf_符号.json 只读取开头 6000 字符，不能声称已完成符号排查。当前无法解释该地址与 0x2706e20 的关系或转换语义。

## 下游消费与持有者

0x18b31fc–0x18b35e0 调用方：

- 0x18b335c/60 根据 [x21+0x18] 是否为零选择分支。0x18b3374 直接使用所选对象调用 0x18b09d4；另一分支在 0x18b338c 调用 0x18b2c08，随后在 0x18b339c 调用。两分支均令 x8=sp+0x38，x1=x20。不能命名为在线/离线或真人/机器人分支。
- 两分支之后以 w0=0xa8 调用 0x2798774；其分配器身份为模式推断，新对象地址保存为 x20。
- 0x18b33d0 从 sp+0x58 加载 q0，即返回区 +0x20/+0x28；0x18b33e4 将 16 字节写到新对象 +0x20/+0x28。
- 0x18b3414/18 将新对象保存到调用者入口对象 +0x20。这里的“调用者对象 +0x20”与“新对象 +0x20”属于不同基址，不能混用。

目前追踪到转换结果持有对象；未找到后续读取两个字段、输入归一化、初速度计算或冲量施加指令。配置组装不是已定位的真正击球算法。

|0x18bc818|startSolving lambda 0|+0x10|

确证：这五个范围没有轨迹积分、候选枚举、碰撞或评分指令。推断：与 std::function 的目标类型查询辅助实现相容。类型字符串包含 simulateShot(const ShotAttempt&, double) 相关编码，但 double 的业务含义未知，不能命名为时间步、力度或误差。

## 最小复现步骤与补证优先级

以下步骤是待执行方法，不是本轮成功日志：

1. 按 manifest.json 顺序拼接 parts/arm64.part000 至 part005，逐块验证哈希，再核对完整 ELF 哈希。不要执行目标库。
2. 读取 ELF program headers，按覆盖目标 VA 的 PT_LOAD 计算文件偏移 p_offset + VA - p_vaddr；要求目标落在文件映射范围内。运行地址需另外计算 load bias，不能默认 VA=文件偏移或进程地址。
3. 反汇编 0x18b09d4 对应完整函数及 0x18b15a4，按上述地址逐步记录寄存器和栈槽。核验容器构造/复制的被调函数语义及异常分支，检查 sp+0x50 在两次转换前的来源。
4. 优先导出 0x2706e20 和 0x26fac38 的实际函数边界、完整控制流、常量及被调函数；查类型标签分支和返回寄存器。得到函数体前不决定转换公式。
5. 从调用方入口对象 +0x20 所持对象查找新对象 +0x20/+0x28 的读取者，追到归一化、方向计算、速度/冲量写入；同时查 shotPowerLimits 配置写入与覆盖层。
6. 沿五个类型查询辅助函数的代码指针引用恢复函数对象布局，验证槽位后寻找调用实现，继续追踪真实模拟循环、碰撞、终止条件及评分。
7. 有匹配原生环境时，再做只读动态观察：保存版本、maps、load bias、输入标签/原始值、转换结果和最终速度；不在当前环境伪造这些观测。

验收条件：每项结论能回溯到真实成员、哈希、地址及指令；确证/推断/未知明确分开；不给缺证字段补单位、范围或曲线；把方法与实际执行区分；报告真实落盘并读回。转换和求解器完整恢复目前未达到，属于明确保留的证据缺口。
