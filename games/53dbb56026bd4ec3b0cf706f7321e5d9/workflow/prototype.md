## 关键结论

1. 模式 0 是 Disc Pool，模式 1 是 Carrom，模式 2 是 Freestyle。菜单分别传 0、1、2（L9814–9873），事件经 L1689–1692 到 `_0x48e98f`，L2062 保存为 `_0x5d148e`。
2. Disc Pool 开局没有红球；Carrom 和 Freestyle 才创建红球（`_0xd3d8fe`，L2971–2982）。
3. Carrom 中红球入袋立即设置待覆盖与续杆标志；任一颜色普通球入袋都会清除待覆盖标志，没有在清除前核对该球是否属于当前击球方。它与“必须再进自己的球”不是同一套条件。
4. Carrom 的覆盖不是完整独立枚举状态。规则主要依赖 `_0x4268e2`，红球图标则由后续动画回调写入 `_0x404020`。两者可能短暂不一致。
5. Carrom 在普通球计数达到 9 后先判终局，随后才可能返红球；终局使用场上红球数组是否为空，未直接检查待覆盖标志（L3412–3426）。
6. Freestyle 红球按类型取 50 分，普通两类分别 20、10 分；无犯规时分数在动画完成回调提交。停球结算入口直接清除待覆盖标志，不实施 Carrom 式下一杆覆盖。
7. 多处分支为空、动画提交状态和计时器缺少局编号隔离，存在需要复现的规则和生命周期风险；静态证据不能证明其出现频率或用户实际可见结果。

## 四袋入袋控制流

这不是袋传感器碰撞回调决定规则：`_0x49d791` 每个逻辑步检查棋子与袋点距离 `<= 0x14`（20 个游戏坐标单位）。物理接触监听位于 `_0xf8ddc7`，用于碰撞音效、阻尼与特效；入袋规则由主循环另行扫描。距离函数 `_0x2bd695` 使用两点坐标差的平方和开方（L5846–5852）；袋编号依据 L881–898 的 `_0x2fc10d` 坐标表为 0 左上、1 右上、2 左下、3 右下。每个棋子使用 if/else 链，满足前袋后不会继续检查后袋。

红球每袋相同的同步顺序：播放音效 → `_0x5ebd99=true` → `_0x4268e2=true` → `removeFromWorld()` → 从场上红球数组移除并保留展示对象 → 入袋特效 → 仅模式2加入 `_0x31089b` → 启动15 tick入袋动画。`removeFromWorld` 实际销毁物理 body、设 null、移除子特效（L10520–10526）。`_0x253500(array,obj,true)` 只 splice 后提前返回，保留对象用于动画（L5770–5782）。

模式非2：15 tick完成回调再启动20 tick飞往当前方 HUD 的动画；第二次完成才赋 `_0x404020` 并显示 `check_unfilled`。玩家赋值 L4876–4885、4956–4965、5036–5045、5116–5125；对方赋值 L4901–4910、4981–4990、5061–5070、5141–5150。模式2在第一层完成处为空，不建立该覆盖展示引用。

普通球四袋都会：若待覆盖则写勾选贴图并启动提示动画；按当前方/模式决定是否续杆；无条件清 `_0x4268e2`；销毁 body 并移出本色数组；按条件入队。玩家球清标志 L5180、5218、5256、5295；对方球清标志 L5343、5382、5420、5459。提示贴图是表现，不能代替覆盖逻辑事实。

普通球入队存在额外门槛：非模式2且另一颜色场上数组已经空时，不入队，相关分支及动画完成函数为空（玩家 L5185–5186等；对方 L5348–5349等）。因此“物理已入袋”不等于“必然计分”，终盘同杆两色入袋还受扫描次序影响。

## 逐模式规则路径

### Disc Pool（0）

开局：红球数组为空，双方普通球各9（L2974–3005）。没有正常可达的红球覆盖循环。与 Carrom 共用 `_0xbdafb3` 非2分支（L3304–3436）。无犯规普通球归其颜色所属方计数：玩家在动画完成后 +1（L3350–3376），对方在动画完成后 +1（L3378–3401），不是按本杆击球者统一记分。进自己的球续杆，单进对方球不会设置续杆；空杆换方。

击球器入袋：标记 `_0x530863` 并播放 Foul 提示；结算时本杆自己的入队球返场，对方球仍走计分（L3312–3348）。若此前没有续杆标志，调用 `_0x464a16(currentSide)` 退回一枚已计分本方球；分数<=0则不退（L3052–3057、3405–3408）。随后强制换方。

终局 L3412–3420：若当前为玩家，则仅当玩家计数==9且红球数组为空判玩家胜，否则玩家负；当前为对方则对称。正常模式0红球为空；但同时达到9、普通球未入队等边界仍需实验。

### Carrom（1）

开局创建一个红球，双方普通球各9。红球入袋不进普通计分队列、不会给普通球计数直接+1；设置待覆盖和续杆，红球在 HUD 等待。

状态变化：

| 可复现事件 | 源码直接支持的变化 |
| --- | --- |
| 只入红球，无犯规 | 红球场上数组清空，待覆盖=true，续杆=true；停球后不返红球，当前方再击 |
| 待覆盖下一杆完全空杆 | 回合入口清续杆=false，待覆盖保留；非终局时 L3422–3426 调返场、清待覆盖、隐藏勾选，再换方 |
| 红后入本方普通球 | 清待覆盖；本方进球设续杆，普通球按颜色计数；红球不返场 |
| 红后仅入对方普通球 | 同样清待覆盖；若是下一杆则续杆通常仍false，换方但红球不返场；若同杆先入红球，红球已置续杆true，可能继续击球 |
| 普通球先入、红球后入（不同逻辑步） | 普通球先清待覆盖，随后红球重新置true；本杆普通球并不自动按历史事件覆盖后来的红球 |
| 红球与普通球同逻辑步满足入袋 | 扫描顺序为击球器→红球→玩家普通球→对方普通球，普通球在红后清标志；不是按连续物理碰撞时间排序 |
| 红球与击球器同杆入袋 | 红球不在队列，犯规最终强制续杆false；非终局时待覆盖true触发红球返场 |
| 已覆盖的红球后续发生犯规 | 待覆盖已false，不能仅凭犯规推定会退红球；需分别观察本方普通球退回路径 |

返场 `_0x52e61d`（L2903–2969）：中心有重叠则按2单位步距搜索上下左右，范围小于100；只有 `_0x404020` 存在才启动15 tick动画，完成后新建类型0实体、加入红球数组、移除展示并置null（L2948–2966）。搜索穷尽没有显式失败处理。调用返场后即清待覆盖，未 await 新实体创建。

犯规计分：共用 Disc Pool 的队列/退一球逻辑 L3312–3408；红球不会因该队列条件自动返场，因为正常 Carrom 红球没有入队。退普通球 `_0x464a16` 先减分，再用20–30 tick动画创建实体、避重叠、入相应场上数组（L3058–3106）。

终局优先级至关重要：L3412–3420 在返红 L3422–3426之前 return。玩家计数达到9且红球场上数组为空即可走玩家胜分支，即使 `_0x4268e2` 仍true；红球仍在场时当前方清完本方普通球可走负分支。这里没有专门调用 Foul 提示，不能把“终局判负”写成“明确判犯规”。红球与对方最后一球同杆入袋也没有独立命名规则，需合并计数、数组和异步顺序分析。

### Freestyle（2）

开局红球存在，HUD采用积分进度（L1865–1875），目标 `_0x153877=0xa0` 即160（L522附近声明）。分值表 `_0x1c2aac=[0x32,0x14,0xa]`（L644），按 `_type` 分别红50、玩家色20、对方色10，双方均可通过任意颜色进球续杆。

所有入袋棋子（含红球）进入 `_0x31089b`；停球后 `_0xbdafb3` 模式2入口先 `_0x4268e2=false`（L3168–3170）。无犯规：为每颗生成分值文本、按当前击球方选择积分目标，动画完成才加分（玩家 L3240–3249，对方 L3265–3271）；红球无需下一颗球覆盖。

有击球器入袋犯规：队列内所有颜色和红球都返场（L3177–3208），本杆不加这些分；L3279强制续杆false。没有在此分支调用 `_0x464a16` 退历史得分球。

延迟终局 L3280–3285：任何一方分数>=160即结算，但胜负参数直接按当前击球方 `_0x209883` 选择，不比较究竟谁达到阈值。通常加分给当前方，异常存量/旧回调下仍需验证。L3287–3293存在待覆盖且无续杆时返红并减50的代码，但入口已清标志、模式2无HUD红引用，正常流程不应直接当作有效覆盖惩罚规则。该分支使用 `playerScore` / `oponentScore`，当前文件只找到 L3289–3290 两处，实际积分字段却是混淆变量；若异常触达，可能抛 ReferenceError 或操作外部全局，未读取其他文件不能断言全局必不存在。

## 异步、物理、输入及误差边界

- 玩家有效释放：强度>=0.25才击球，力度为strength×100×1.25；击球后关闭操作并约2300ms逻辑延迟进入停球检查（L3667–3680）。AI实际可达链为 `_0xd6b627`→`_0x4662ac`→`_0x223471`→`_0x4b3cc6`（L3697–3794）；L3701后旧代码不可达，不按其5000ms解读。
- 停球：`_0x56abf7` 逐数组裁剪低速并检测awake（L3129–3158）；仍运动则每50ms逻辑延迟重查（L3161–3165）。棋子及击球器速度绝对值和<0.2时休眠（L10489–10500、10645–10653）。没有实测最长停球时间。
- 回合队列处理后再延迟：有队列为1000ms，无队列为500ms（L3167、3277、3303、3403、3435）。这些不是 Promise 屏障，不能证明全部动画已完成。
- `_0x338c29` 用 Tweener空对象将ms转tick（L5590–5601），不是原生setTimeout。暂停时 `_0x49d791` 在L4699返回，因此此类延迟停住；匹配界面等原生setTimeout（L9038–9045、9315–9321）是另一时间域。
- 每逻辑步先更新动画/特效（L4702–4704），再扫描击球器、红球、玩家球、对方球，最后物理step(1/60,10,10)及clearForces（L5491–5492）。`_0x4bf21a` 累计ticker delta，while>1每次执行一个逻辑步（L5499–5504），本段无显式补步上限；严格大于1还保留边界余量。
- 棋子半径16，密度0.45、摩擦0、恢复系数1、线性阻尼1.8、角阻尼0.2，bullet=true（L10423–10483）；换算100坐标单位/物理单位。不得将bullet设置当作高速永不漏袋的证明，因为袋检查仍为离散点距离。
- 非首桌倒计时按逻辑步递减，到期直接换方（L4725–4737）；基础步数由桌子及升级决定（L1764、L627后配置）。首桌不执行该倒计时。待覆盖标志没有在回合入口清除，因此覆盖等待中超时的跨方影响必须实测。
- `_0x5e7a5f` 和 `_0x50a0ff` 重置犯规/续杆而不重置待覆盖。续杆窗口不是固定秒数，而是下一次回合的击球及停球结算；倒计时和暂停会影响实际时间。
- 同帧红后普通球能先写勾选，红球35 tick两段动画随后又写未勾选，存在提示与规则标志相反的静态风险。Tweener遍历数组且完成时splice（L11356–11365、L11484–11489、L11588–11591），可能让相邻动画本步跳过，具体延迟须实测。
- 新局和菜单活动标志是布尔值，未见局编号；空对象延迟回调不能靠清棋子数组取消。`_0x47e567` L2781–2902未关闭活动标志，领奖可重复触发与旧回调污染是待验证风险，不能写成已复现。

误差验收建议（非原项目已承诺数值）：入袋阈值在19.9/20/20.1游戏单位分别记录，逻辑标志/积分/球数要求完全一致；视觉轨迹跨浏览器位置容差暂定1游戏单位，最终以同版本引擎固定输入对照调整。固定逻辑步事件顺序要求一致，墙钟耗时容差不作为规则正确性条件。保持离线、轻量，实验不增加线上遥测或生产依赖。
