## 结论分级

### 逻辑必然

1. `_0xbdafb3` 在局内且物体已停止时进入结算。Freestyle 对应本次追踪的模式值 2 分支，该分支在 L3169 同步将 `_0x4268e2=false`，随后才处理捕获集合、创建计分或回球动画，并在 L3280 安排最终回调。即使捕获集合为空，该清除仍执行。
2. 四个红球入袋分支是本文件检索到的全部 true 写入点，分别为 L4841、4921、5001、5081。每次都先令 `_0x5ebd99=true`，再令 `_0x4268e2=true`。因此单独一次重新入袋得到的状态是 true/true，不能直接满足罚分条件 true/false。
3. 红球入袋后同步销毁刚体、从 `_0x3231b3` 移除，再创建入袋动画。动画中的红球精灵继续存在，不能据此认为它仍参加物理与红球检测。
4. 延迟回调先检查当前 `_0x3fddb3`，再检查分数是否达到目标，最后才检查 `_0x4268e2 && !_0x5ebd99`，见 L3282–3290。若保持清除后的状态，该罚分块跳过。
5. 若该罚分块实际进入且前面的 `_0x52e61d()` 正常返回，先清除红球标志，再读取并复合赋值 `playerScore` 或 `oponentScore`。对应标识符在 game.js 中各只检索到这一处。若所选标识符在执行环境中没有绑定，复合赋值读取将抛 ReferenceError，并中断该次回调后续 HUD 更新与换手。即使存在数值绑定，这两行也没有直接修改实际计分变量 `_0x4d3bf1` / `_0x41f634`。

### 条件性风险

1. `_0x338c29` 为每个任务创建独立空对象目标，未返回任务句柄，也未捕获局号。新局清理只按棋子等具体目标 extract，无法匹配这些匿名空对象。已读取的重置和退局路径没有取消这些任务。因此在任务到期前发生重置时，旧任务能够保留到后续更新。
2. 旧回调到期时若当前不在局内，会直接返回并结束。若新局已经将 `_0x3fddb3` 设为 true，则该布尔检查不能辨别局生命周期，旧回调会读取新局分数、当前玩家及两个标志。该结论由闭包读取和重置代码直接支持。
3. 即便罚分条件不成立，旧结算回调仍可能执行换手，旧轮询任务仍可能在新局调用 `_0xbdafb3`，旧 AI 等待任务也可能继续。它们具有影响新局的代码条件，但本轮没有实际对局复现。
4. 罚分风险还需要重新形成 true/false。可供后续验证的交错候选是，新局红球检测先形成 true/true，另一个先到期结算回调或倒计时换手随后仅清 `_0x5ebd99`，再由仍存活的旧 Freestyle 回调读取。候选还需同时满足当前局有效、分数未达标、红球标志未被其他代码清除，以及真实输入和调度顺序可达。现有证据没有完成这条玩家操作路径的证明。

### 未验证

没有证明正常单次击球必然触发罚分异常，也没有证明快速重开或正常 UI 跨局能在指定窗口完成上述全部条件。没有执行原包、浏览器、真实对局、真机、模型回放或新的本机实验。用户描述的人工 true/false 回调实验与空集合完整函数实验仅作为用户提供的既有观察记录，本轮未重跑，未当作本轮验证通过。

## 四个红球分支与数组生命周期

`_0x49d791` 在 L4833 复制 `_0x3231b3` 再遍历，按洞索引 0、1、2、3 的 if/else 链检测距离是否小于等于 20。四支入口为 L4838、4918、4998、5078。每支顺序一致。

1. 播放入袋音效。
2. `_0x5ebd99=true`。
3. `_0x4268e2=true`。
4. `removeFromWorld()`。L10520–10526 显示它同步 destroyBody、将 body 设为 null 并移除附属表现对象。
5. `_0x253500(_0x3231b3, coin, true)`。L5770–5775 先 indexOf，再 splice。成功找到且第三参数 true 时立即返回，保留精灵用于动画。
6. 创建洞口特效。
7. 模式2将精灵加入 `_0x31089b` 捕获集合。
8. 添加 time=15 的入袋动画。

四支动画完成函数在当前模式2下均为空分支，见 L4860、4940、5020、5100，未重新设置两标志，也未把原对象放回红球数组。其他模式的后续动画主要设置 `_0x404020` 与覆盖提示。由于真实数组已 splice，后续更新复制的数组不再含该红球。同一次复制中洞检测也是互斥分支。

红球进入检测集合的来源已检查。L2971–2981 新局模式非0时创建一个 type0 红球。L2903–2969 的回红球函数通过 `_0x404020` 动画结束后创建新红球。L3190–3204 的模式2犯规回球动画也可按棋子类型重建并加入数组。L3330–3344 为其他模式的对应回球。L3085–3102 另有类型分流的回球实现，其通常创建类型为玩家或对手的棋子，不能仅因存在最终 else 就断言普通 Freestyle 会额外创建红球。

因此普通回合论证需要区分两类情况。非犯规捕获的原红球已移除，入袋动画不能重新触发检测。犯规回球可以重新创建物理红球，但回球完成本身不设置标志，仍需再次触发距离检测，而检测又会将两个标志一起设为 true。

## 调度与物理执行顺序

### 时间参数

`_0x338c29` 位于 L5590–5601，通过 Tweener 将毫秒参数转换为 `time=ms/1000*60`。它使用模拟更新单位，不能直接当作真实墙钟 setTimeout。

| 调度位置 | 名义参数 | 模拟时间单位 |
| --- | --- | --- |
| L3678、3792 玩家及当前有效 AI 击球后 | 2300 ms | 138 |
| L3163 物体仍 awake 时重试 | 50 ms | 3 |
| L3280 Freestyle 空捕获结算 | 500 ms | 30 |
| L3277 后捕获非空结算 | 1000 ms | 60 |
| L3514 AI 换手后等待 | 500 ms | 30 |
| L3774 AI 蓄力后等待 | 500 ms | 30 |

L3709 的 5000 ms 调用位于 `_0xd6b627` 的无条件 return 之后，不能计入该函数当前正常入口的有效路径。

L5499–5504 用累积器接收外层 delta，条件是严格大于1，每次减1并调用 `_0x49d791(1)`。长帧可能一次循环多个步，未见此循环的补步上限。L5491 固定物理步长为 1/60，迭代参数10、10，并清 forces。实际墙钟时长还受外层 ticker、暂停、补步及任务遍历跳步影响。

### 单步顺序

L4699 暂停标志成立则整步返回。否则依次更新动画管理器、粒子、Tweener，之后检查局内状态，再处理倒计时、击球器入袋、红球数组、两组普通棋子数组，最后执行物理 step。

因此在同一更新步内，Tweener 中到期的结算回调先执行，后面才进行新的红球入袋检测。新检测不可能倒流改变前面已经完成的条件判断。同一步中红球检测又早于普通棋子检测，若两类球都入袋，后者可能清红球标志。

### Tweener 遍历细节

L11356–11365 按当前实时数组从前向后遍历。L11430–11440 添加任务时先 extract 相同目标的已有 tween，再 push 新任务并 start。匿名调度每次采用新的空对象，彼此不会因相同目标被替换。

L11531 累加 elapsed，L11535–11538 包含半步阈值钳位。对于本轮关注的整数时长且每步确实更新1次，30/60/138单位分别需要对应数量的实际 tween 更新。L11589–11591 非循环任务先 stop 再调用 onComplete，L11484–11489 的 stop 会从实时数组 splice 当前任务。

这使当前位置的下一个任务可能因为数组前移且循环索引继续递增而被跳过本步。回调 push 的新任务也可能在同一遍历被访问，取决于索引与数组变化。不能将插入次序直接等同于严格的墙钟到期顺序，也不能承诺所有500 ms任务都恰在30个外层模拟步后执行。以上属于源码推导，未运行调度器验证。

## 普通回合的完整链

有效击球调用 `_0x24bb4a` 关闭瞄准和输入，关闭回合倒计时，然后安排138单位后的首次结算。玩家力度门槛为0.25，见 L3672。输入使能还受当前玩家、`_0x55e693` 及 `_0xf86500` 控制，见 L3655–3659。

首次结算若有棋子 awake，则只安排3单位后的重试，不清标志，不进入计分。停止判断遍历当前三个棋子数组和击球器，L3129–3157。trimVelocity 在 L10489–10500 对速度绝对值之和小于0.2的刚体置睡眠。该阈值是实现条件，本轮没有测量物理误差或手感。

真正结算先停止棋子并清红球标志，再处理捕获集合。非犯规时按 type 索引 `[50,20,10]` 创建加分动画，玩家时长为15至小于25单位，对手15单位，完成时修改实际分数。捕获非空将最终结算等待改为60单位，空集合保持30单位。犯规时改做20至小于30单位的回球动画并清续手标志。

最终回调以实际分数达到160为结束检查，L522、3283–3285。未结束时检查罚分条件，再依据当前玩家与续手标志调用 `_0x5e7a5f` 或 `_0x50a0ff`。这两个函数都清续手标志。正常有效回合下一次击球输入是在最终回调换手后开启，不能任意假设等待窗口内玩家已经开始下一杆。

在单一、未重置且没有旧任务干扰的回合中，现有证据支持先清标志并跳过该罚分块。不能据两个裸分数标识符存在，就直接报告普通对局必抛异常。若要升级为所有物理状态下的不可达证明，还需封闭验证回球位置、残留任务、倒计时与输入生命周期。

## 跨局重设与残留任务

公开对象 restart 在 L412–413 直接调用 `_0x5480e3`。L2025–2026 另有同作用包装，本轮检索未发现该包装的调用点。正常匹配启动链为选择桌子 L2438–2446，匹配事件 L2432–2435，`_0x1260d2` 末尾 L1889 调用重置。公开 restart 的代码存在不能等同于已经证明玩家界面提供该按钮。

重置 L1754–1806 会清分数、清红球标志、更新局内布尔值、清各棋子集合、重建棋子并开启首回合。L5784–5810 的清集合操作按对象移除其 tween。它没有指向 `_0x338c29` 临时空对象的引用。

退回大厅 L2031、选择模式 L2060、其他页面 L2075/L2085、匹配开始 L2416 会将局内布尔值设为 false。Tweener 更新位于局内检查之前，故退局本身不冻结旧任务。旧任务在非局内到期就返回，若到期时已处于新局则通过现有布尔门槛。暂停 `_0x5a2c78` 则停止 ticker，并由更新入口的暂停标志阻止模拟更新，不能把暂停期间真实经过的秒数直接算作任务进度。

结束函数 `_0x47e567` 的已读完整正文 L2781–2902 没有将局内布尔值清 false，展示结果后待后续事件切回选择页。不能把展示结果等同于所有旧任务已失效。

旧 Freestyle 最终回调没有重新检查模式值，也没有局号与击球号检查。它读取执行时的当前变量，不能假设使用安排时的当前玩家或分数。跨局旧结算进入新局这一生命周期风险具备源码依据。至于从普通 UI 在剩余30或60单位内完成重开，或以多个旧任务构造 true/false，本轮没有计时或操作证据。

## 既有观察与本轮核验

用户提供的既有观察包括，人工将回调环境设置为 true/false 且无 playerScore 全局时出现 ReferenceError，以及完整函数在空捕获集合时先清标志再换手而未触发异常。两者分别覆盖条件块行为和完整结算入口，覆盖范围不同，可以同时成立。
