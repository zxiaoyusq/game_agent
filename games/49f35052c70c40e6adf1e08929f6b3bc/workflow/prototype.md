## 部分状态及分类

以下是按调用顺序推导的可能状态，不声称真实引擎必然如此。已出杆标记是认领记录，不是施力收据。

|异常位置|可能已发生|分类与处置|
|---|---|---|
|参数校验/纯向量预计算|无世界修改（须重构保证）|准备失败；拒绝无效参数，允许有界重新规划|
|标记/隐藏/定位|已认领、UI关闭、位置或速度部分变化|提交前失败；不能仅清标记重进旧路径|
|sensor 调用|本地标志已 false，fixture 可能未变或已变|提交前失败；核对两个状态并受控恢复，恢复也可抛错|
|Vec2 构建|sensor 已改变，未到施力调用|向量构建失败；与纯准备失败分开，因已有副作用|
|setAwake|可能已唤醒，尚未进入施力|提交前失败；awake 不证明施力|
|进入 applyForceToCenter 后抛错|可能未提交、部分修改或已提交|提交不确定；永久禁止同杆重放|
|施力正常返回后，清理/登记延迟抛错|接口已正常返回，后续监督可能未建立|提交后异常；补齐幂等监督，绝不再施力|

只在调用前写 submitting、正常返回写 submitted；catch 若仍 submitting 就是 unknown。外层 test 总 catch 无法区分上述位置，须将阶段记录放到实际边界。submitted 仅证明接口返回，不证明轨迹正确或物理步进成功。零速度、未位移、休眠均不能排除尚未积分的累计力；禁止据此重试或直接换手。

## 候选 A：最小安全恢复（建议优先评审）

状态循环：Ready → Preparing → Armed → Submitting → Submitted/Unknown → Observing → Settling → Resolved；任何阶段可进入 RecoveryRequired 或 Cancelled。只允许 Ready 且当前 AI、活动、未暂停、世界有效时接收一次命令；运动及恢复期间关闭双方出杆入口。

每杆上下文保存不可变 matchEpoch、turnId、shotId、worldGeneration、striker/body 引用、阶段、调用次数及 settleOnce 标记。新局、返回、销毁、重建世界先失效旧 epoch；所有 tween 的更新和完成、计时、停球检查、计分、换手均核验完整身份，不能只检查布尔活动状态。取消旧动画与回调同时保留身份拒绝，防止已入队任务。

1. 纯准备阶段先计算有限向量及合法范围，记录稳定起始状态。认领后在任何世界副作用之前建立唯一监督所有权；监督建立失败则不开始修改世界。不能让日志/提示异常重新开放提交。
2. 提交前完成必要定位及 sensor/awake 操作并记录边界。禁止在提交窗口中 await 或允许物理步进/重入。身体及世界引用再次校验。
3. 写 Submitting 后仅调用一次底层施力；返回即写 Submitted。异常保持 Unknown。调用预算在进入接口前消耗，catch/finally 不重置去重标记。至多一次调用会牺牲部分未出杆的自动恢复能力，不能承诺恰好一次实际施力。
4. 已证明未进入施力接口的失败：冻结输入和模拟，在可核验快照、完整副作用清单且恢复成功条件下恢复准备态，最多一次重新规划并换 attempt 身份；否则进入明确恢复界面。不能盲目反向 setSensor/setAwake，也不能复用旧回调。
5. Submitted：保留物理演化，幂等挂接观察/结算；不得重新定位、清力或休眠来掩盖异常。Unknown：默认隔离本局并显示恢复选择；只有经匹配版本引擎证明异常后世界仍完整可步进，才可按“视为已消耗本杆”继续观察。不得仅凭可移动就认定提交完整。
6. 监督器由应用生命周期管理，不依赖 test 成功后的延迟。暂停/后台停止有效运行时长累计；恢复时先验身份和世界再观察，禁止补发。候选每 100ms 前台检查、5s 未推进物理 tick 转故障、30s 有效运动上限转恢复界面；数值仅设计起点，须按真实长杆测量调整。事件循环阻塞不能由同线程计时器强行保证即时恢复。
7. 结算用 shotId 单一入口，先认领 Settling，再以幂等事件账本按球/杆去重；换手最多一次。旧版计分含动画完成回调，仅增加入口锁不足以使中途失败事务化；无法证明分数与返子完整时进入恢复，不能重跑整个 _0xbdafb3。

## 候选 B 与取舍

B 为完整杆前检查点加世界重建：包含所有球、速度、角状态、规则分数、待入袋/Queen/返子事件、随机状态及异步任务。Unknown 后废弃旧世界和全部事件，完整恢复后使用新 epoch/shotId 重放。仅恢复 striker 位置不是回滚；已发奖励/存档等外部效果不能假定撤销。成本和规则审计范围明显较大，当前证据不足以承诺。

不采纳 catch 后清标记重试、按 awake/速度判断未施力、超时直接切玩家、finally 强制休眠/清力/结算。它们分别可能造成双力、误判、运动中换手或丢失合法结果。

## 物理、规则与界面契约

保留既有 PixiJS/Planck 工程，不因 native-web 登记值迁移框架。旧快照可见 step(1/60,10,10) 后 clearForces；累加 ticker delta 并 while >1 补步，所读片段未见补步上限。最新版本步长、锁世界契约和内部累计力行为未知，本轮不修改。碰撞、入袋、计分及胜负沿用匹配版本规则；旧版袋口距离判断可见 <=20，不能代替连续碰撞或最新模式验收。恢复不制造进球、罚分或获胜。

成功定义为同杆调用次数 <=1、结算与换手 <=1、旧任务零写入，且在健康世界完成正常循环或到达明确可操作的故障退出。失败定义为身份串局、重复施力/计分、无界轮询或错误恢复。正常棋盘布局保持；恢复时中央英文提示 Shot recovery required，按钮 Restart match / Back to menu，禁止提供含糊的 Retry shot。此为候选文案，未制作界面。

计数及身份误差容忍为零。物理轨迹不要求位级一致；实施前冻结同版本无异常基线，按相同物理 tick 比较，候选位置容差 1 棋盘像素、速度容差 0.01 引擎单位仅用于非边界回归；入袋、得分、胜负及贴边分支须逐项核验，不靠宽容差放行。
