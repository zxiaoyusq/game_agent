# Solitaire Klondike Classic — 平台接入版

根目录 index.html 与平台提供的模板逐字节一致。游戏实际入口为 game/index.html。
可直接部署在支持 HTML/JS/JSON/XML/SVG/MP3 的同源 HTTPS 静态站点，无需 Node 或 Brotli 解压服务。不要用 file:// 打开。

2026-11-04 QA 修复：初始新局和 Replay 发牌完成立即保存，刷新不会回到旧进度；动态视口重排不重置牌面。窄屏 HUD 目标至少 44 CSS px。首次提供独立三步互动练习（发牌、向上叠牌、A 归位），不改正式牌局；完成才记录，跳过不算完成，可从 Settings → How To Play 重看。

请整体上传 game/，不要只替换某一个 JS。修复脚本、入口与原生游戏均带统一版本参数，避免部署后缓存混用。旧存档保留原键，不清除用户数据。

底部 50 CSS px Banner 完全由外层模板负责；游戏内不再重复预留 Banner。保留竖屏、底部牌桌和 Auto Complete 浮层。

启动广告由外层模板负责。游戏资源创建出牌桌后，额外发送 gameLoadingCompleted。只有确认换新局（含结算后开新局）才请求插屏；Replay 同一牌局不请求，首次发牌与恢复存档不额外请求。插屏采用 120 秒游戏侧硬冷却，从进入游戏或最近一次全屏广告请求结束起算，包含激励及无填充结果；冷却中直接开局，不排队补弹。无填充、关闭、异常或超时均继续游戏。平台原有 45s 频率提示保持不变，不替代本地冷却。

platform-bridge.js 将 next/reward 请求和 MIAD_NEXT/MIAD 回调接通。广告期间保存并暂停活动场景、输入和正在播放的声音，完成后恢复原状态，不改用户声音偏好。120 秒无回调会恢复游戏；在旧广告完成前阻止新请求，迟到或重复回调不补发奖励。

顶部 HUD 的 Hint 和 Undo 是激励入口，保留位置和 44×44 点击区域，带小视频标识与 Ad 提示。点击后先显示“观看广告获得 1 次提示／回撤”的确认框；确认观看并成功返回 viewed 才执行原生操作一次。取消、关闭、无填充、超时或 SDK 不可用均不执行，不发放可累计次数。无撤销历史或按钮禁用时不拉广告；观看期间换局、销毁场景或操作失效时不把奖励误用到新牌局。

激励接口：await window.SolitairePlatform.showReward()。仅 result.rewarded === true 时可以发奖励。也提供 FBInstant.getRewardedVideoAsync() 的 loadAsync/showAsync 兼容入口，失败会 reject。用户主动激励不受本地插屏冷却限制，平台自身的库存、频控仍可能导致不可用。上述激励广告门槛仅用于平台版；独立离线版的提示和回撤仍免费。自动提示和 Auto Complete 未额外接广告。

回调桥依赖父子页同源。父页 SDK 加载失败时游戏可继续，广告返回 unavailable。根模板本身没有 SDK 失败兜底与消息来源校验；本次未擅自修改平台模板。游戏兼容层仍使用原本地存档键，新部署域名不能自动继承 localhost 的存档。

本包使用已有 1 MB 离线版的压缩美术与 23 个音效，字体与图集逻辑尺寸不变。仅不打包当前 loadSounds 从未加载的 bg_music.mp3；未删除源文件、未再压低画质。为适配普通静态托管，将自包含 SVG 还原为 .svg 文件并同步调整资源引用，脚本为正常 JS。因此解压体积不同于采用 Brotli 存储的离线版，ZIP 仍控制在 1,000,000 字节以内。

平台 SDK、广告和统计依赖联网；广告账户、域名白名单、库存和真实发奖资格仍需平台环境验收。本地 mock 验证不等于真实广告已投放。
