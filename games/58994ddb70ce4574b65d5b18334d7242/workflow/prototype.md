## 2. 新增目标身份审查

`_0x3d12d7` 从数组取出 `_0xe88441`，`slice/concat` 只复制容器，不克隆棋子。基线位置尝试与七个替代位置仍对同一 `_0xe88441` 计算方向。B 返回：

```js
{ pos: _0x4b85cd, dir: _carromFallbackDir, _carromFallbackTarget: _0xe88441 }
```

**PASS（静态身份语义）：** 返回的是实际选中棋子的对象引用，不是坐标副本、索引或同色任意棋子。`indexOf(target)` 和 `disc === intendedTarget` 是引用身份；同坐标其他对象不会被当作目标排除。

边界：

1. 目标仍在当前棋盘数组：身份检查生效，后续扫描仅豁免该对象。
2. 目标被移除：保护函数直接返回原偏差，并不取消杆；这是 fail-open。正常链路已有快照，发射时数组成员减少/替换会被 `_carromAiBoardChanged` 捕获并重算，最多两次；不能单凭保护函数声称已覆盖移除。
3. 原对象被同坐标新对象替换：`indexOf` 不命中；快照按引用也判变化，不按坐标误认。数组重排但身份和分组不变不会触发变化，这是合理的顺序无关。
4. 同一对象跨颜色/皇后组：保护器只检查当前数组并集，因此仍接受该引用；快照另检查 group，可阻止正常链路旧方案发射。
5. 对象还在数组，但物理 body 已销毁、sensor 状态已变或被复用：身份本身不证明物理有效。快照没有 body/fixture/生命周期代数，位置不变时可能漏检。需要实体 generation 或物理有效性检查。
6. 重复对象：快照构建可收录重复项，变化检查通过 Map 检出重复而重试；保护器自身不检查重复结构。
7. `_0x3d12d7` 在所有替代位置也不畅通时仍返回原方案。此项是参考中明确保留备用杆可用性的取舍，不是新增保护引入；不得将其描述成备用杆无障碍保证。

## 3. 方向、预览与实际发射逐步推导

令 `a=shot.dir=atan2(target.y-pos.y,target.x-pos.x)`，`δ` 是随机生成的偏差（通常 0 或正负 0.05～0.10 rad），`δ'` 是保护返回值。

### 3.1 正负号

保护检查方向：`a-δ`。

AI 发射传给击球器的参数：`b=π-a+δ'`。

击球器发射函数的实际速度：

```text
v = speed * (cos(-b+π), sin(-b+π))
  = speed * (cos(a-δ'), sin(a-δ'))
```

因此 **PASS（静态代数）：保护方向与实际发射同号**，不是应该检查 `a+δ`。正 δ 使实际几何角变小，负 δ 使角变大；屏幕 y 向下时正 δ 对应视觉逆时针，负 δ 对应视觉顺时针。不要仅凭引擎参数 `π-a+δ` 判断偏差方向。

### 3.2 预览

AI 瞄准赋值：

```text
previewAngle = -(π-a-2π)-δ' = π+a-δ'
```

预览箭头原始指向上方，旋转为 `previewAngle-π/2`，箭头从原点向 `(-cos(previewAngle),-sin(previewAngle))` 伸出。因此其前向为 `(cos(a-δ'),sin(a-δ'))`。玩家发射也使用 `2π-previewAngle`，与 AI 的 `π-a+δ'` 等价（模 2π）。

**PASS（静态公式，非实际截图）：** 同一未变更的 shot/δ' 下，预览前向和发射速度前向一致。保护在预览角赋值前调用，归零会同时影响预览和被闭包保留的发射偏差；没有“画带偏差、发不带偏差”的直接符号错误。

限制：预览原点取当时击球器显示 x/y，发射前强制设置物理 `worldX/Y=shot.pos`。通常最后一次移动补间结束在 shot.pos.x，二者应重合；但显示位置不等于物理 body 的普遍保证。外部移动/重叠推开/渲染同步滞后可造成原点跳变；shot.dir 或 pos 被后续修改也会让预览与发射分离。实际图像纹理方向、坐标同步必须运行验证。

## 4. 保护器真正的几何语义

由参考常量：击球器逻辑/物理半径 `r_s=34*0.8*0.8=21.76`；普通棋子物理半径 `r_c=16`；统一膨胀半径 `R=37.76`；尺度为 100 显示单位/物理单位。

`_carromFallbackSafeDeviation` 计算目标相对向量 `q=(x,y)`、距离 d。对测试角 θ：

```text
p=q·uθ
h²=max(0,d²-p²)
t_target=p-sqrt(max(0,R²-h²))
travel=(h²<=R² && t_target>=0) ? t_target : d
```

它调用 `_carromStartPathBlocked(pos, θ, travel+R, target, true)`。后者的 `end=max(0,length-R)`，所以实际线段终点就是 travel（不是 travel+R）；对每个非目标对象 C，将投影夹紧到 `[0,travel]`，判断到该线段的距离平方是否 **严格小于 R²**。

### 静态命中时

当目标在射线前方且真正相交，travel 是击球器中心第一次接触目标的距离。非目标中心落入该有限线段的 R 胶囊体，等价于该非目标膨胀圆在该时间范围产生严格穿入。此处的终点圆帽不是多扫一个 R 的实现错误：它恰好检测在目标接触点之前已开始接触的非目标圆。

返回条件：

```text
blocked(a-δ) && !blocked(a) ? 0 : δ
```

| 偏差 blocked | 原方向 blocked | 返回 | 含义 |
|---|---|---|---|
| false | 不计算 | δ | 保留偏差，不保证命中 |
| true | false | 0 | 撤销新增障碍风险 |
| true | true | δ | 原杆也被挡时保持原策略 |

它只做一次撤销，不尝试反号、不缩小偏差、不换目标，不检查进袋线路。

## 5. 用户要求的逐项边界与误杀/漏检

下列具体布局采用局部平移坐标，能平移回合法基线；数值结果是手工几何推导，未运行。

### 5.1 正/负偏差：镜像成立

S=(0,0)，T=(300,0)，R=37.76，δ=+0.10。偏差射线角 -0.10，目标横距约 29.95<R，首次目标接触约 275.5。令障碍 C=180*u(-0.10)+(0,-30)：其偏差横距约 29.85<R，原方向 y≈-47.97，原路横距>R。偏差扫描会堵，原路畅通，返回 0。将 C 关于 x 轴镜像并取 δ=-0.10，结论对称。无需对正负分别写不同算法。

### 5.2 目标被移除

直接调用保护器时返回原 δ（不取消），**FAIL 若要求“目标移除即中止”**；标准提交链通常由快照兜底触发重试。删除发生在瞄准前，保护可能先展示旧目标方向，直到发射重试才纠正，因此不能说预览全过程有效。

### 5.3 偏差错过目标

S=(0,0)、T=(600,0)、δ=0.10：`d*sin(|δ|)≈59.90>R`，偏差必错过目标。

- 无其他障碍：blocked=false，δ 保留。**FAIL 若将函数名字解读成“安全偏差必命中”**；但如果需求仅是不新增早期障碍，这不是必然功能缺陷。
- miss 时 travel=d，扫描到 d 的终点圆帽。C=620*u(-0.10) 的偏差首次接触 582.24<600，原方向侧距≈61.90>R，会将偏差归零。
- C=650*u(-0.10) 的首次接触 612.24>600，胶囊不包含，δ 保留。可见 miss 分支是人为有限范围，不是无限射线第一碰撞。
- 在 miss 分支用 d 截断，若产品只想管“未偏差目标首次接触前的阻挡”，会对其后、d 之前的障碍产生语义上的误杀；若产品想管“错过目标后所有危险”，又会漏掉 d 之后的障碍、撞边后反弹。

### 5.4 障碍在目标之前/之后

必须比较**接触进入距离**，不是中心顺序。若目标接触为 t，障碍中心投影 a_c、横距 h_c，则障碍进入为 `a_c-sqrt(R²-h_c²)`。

- 明确早于目标并严格穿入：命中分支会检测；原杆畅通则 δ 归零。
- 障碍中心在目标接触点之后，但其膨胀圆已覆盖接触点：扫描会检测，这是正确的早接触，不应误报成“目标后障碍误杀”。
- 真正接触在目标之后：命中分支不应该撤销 δ；此后连锁碰撞、目标进袋路径不属于本保护范围。
- 接触时间完全相同：扫描为严格 `<R²`，在只有端点等距接触时可能放行；真实解算器 simultaneous contact 不能承诺先撞目标。无 epsilon/并列策略，是边界漏检风险。
- 原/偏差两方向都有障碍：返回 δ。函数不是总安全门禁；这也是保留原玩法的重要边界。

### 5.5 切线、重叠与近距离

- 目标切线：目标判定用 `<=R²`，可以算 targetEntry；障碍切线检查用 `<R²`，严格切线放行。数值符号、solver slop 和接触容差可能将切线变为碰撞。两处边界定义不同，不能称严格首次碰撞证明。
- 障碍与出发点重叠：线段投影夹紧到 0，可检测。但原方向也堵，因此整个 guard 通常仍保留 δ；发射基线占位复查会阻止正常提交。
- 目标距离 `d<=R`：保护直接返回 δ。即使已重叠也不消歧。正常合法基线占位一般排除 `<R`；等于 R 可通过，而 d<=R 的 guard 又豁免。需定义刚好接触时能否发射。
- 目标和障碍互相重叠、并列接触：真实物理解算会推开/多接触，静态目标排除不足以预测后续；不可将归零当成稳定结果。
- 如果碰撞体不是当前统一半径，例如异形 fixture、额外 fixture、sensor，统一 R 会误杀或漏检。当前所读普通棋子圆半径16与击球器21.76确实匹配，不能空泛声称已有半径错误。

### 5.6 异常坐标与数值

- 目标、shot.pos、shot.dir、deviation 非有限：保护原样返回 deviation，fail-open，甚至保留 NaN；不是总数值校验器。
- 非目标坐标异常：路径助手返回 blocked=true；两个方向均 blocked 时 guard 仍保留 δ。正常链路快照位置检查与发射有限检查另行兜底。
- 空/null 棋子在某些占位检查中会先访问坐标而抛异常；保护函数不能覆盖上游所有输入异常。应在建立棋盘数据时维护有限合法结构。
- 极大但有限的坐标可使差值/平方溢出：distance 非有限时直接返回 δ。`d²-p²` 有消减误差，接近切线易偏移；不应以 clamp 到0 视为精确相交证据。用相对向量二维叉积计算横距、Math.hypot 和实际合法坐标范围更稳妥。
- shot.dir 不再指向当前 target 时，miss/背后目标落入 travel=d 分支，仍排除 target，不要求沿当前方向能命中它；近目标漂移尤其需要独立验证。

## 6. 调用时机与静态快照/真实运动边界

### 已读标准调用链

```text
_0x50a0ff：AI 回合、500ms 调度、候选选择
  → 无候选时 _0x3d12d7
  → _0xd6b627：有限检查，保存棋盘快照，启动移动
  → _0x4662ac：20～30 tick 每段，最多四段移动
  → _0x223471：生成一次 δ，调用保护，写预览并开始 10～20 tick 蓄力
  → 蓄力后再等 500ms（30 tick）
  → _0x4b3cc6：检查回合、重复提交、快照、基线和占位；必要时最多重算两次
  → worldX/Y 设置到方案 pos，按保存 δ' 发射
```

移动最多四段来自 `_0x17bf57>2` 的强制最终定位，不是无限递归。guard 到实际发射约40～50个模拟 tick（名义0.67～0.83秒）；快照建立更早。暂停会改变墙钟时长。`_0x338c29` 的毫秒参数转换成 Tweener tick，不能全部视作原生 setTimeout 墙钟等待。

### 快照的真实覆盖

快照记录棋子引用、group、显示 x/y，发射前 Map 对照：数量/身份/分组变化、非有限、任一坐标差值 **>1** 判变化。它并非完全静止保证：

- 恰好1单位漂移、每轴0.9单位漂移被放行；对角总漂移可达 sqrt(2) 单位。
- 位移从最初快照比较，不是只比较上一帧，可捕获单方向累计漂移>1。
- 离开后返回同一位置、body 更换、速度/角速度/awake/sensor/半径改变，都未记录。
- 读取的是表现 x/y；所读 update 在每 tick 将 body 位置拷给表现，再执行物理 step。因此在某些调度边界，显示坐标可比刚步进的 body 旧一拍。可证实源码的扫描/step顺序，具体回调相位需实测。
- 棋盘容器/边界/袋口变换未入快照。单纯父容器平移且全部物体同变换不改变相对几何，不能直接判为错误；只有坐标空间混用或物理边界相对变化时构成风险。

### 风险优先级

**高：发射时未重做偏差路径判断。** 1单位容差内的横向漂移足以把接近切线障碍推入当前偏差路径，而 guard 的 δ' 已冻结；初始快照没超阈值、基线不堵，就会发射。即使发射前重做静态检查，也不自动解决具有非零速度的目标/障碍在飞行中的运动。

**高（按产品安全语义）：miss 不保证撤销、身份/异常 fail-open。** 如果目标是严格目标首碰必须补约束；如果只防偏差新增障碍，应保留这类范围并明确命名/文档。

**中：预览位置与提交位置存在两种来源。** 正常结束补间时应一致；发射前瞬移修正、外部 mutation 或不同同步相位可造成预览原点跳变。发射前若需要修改 δ'，必须重画并重新展示或重启瞄准，不能静默改变实际方向。

**中：切线、并列碰撞、数值容差未定义。** 首碰应以事件/解算规则为准，不能把浮点严格比较视为物理次序证明。

## 7. 性能代价（仅复杂度，不是实测耗时）

令 N 为棋盘数组总棋子数。

- 新增目标字段 O(1)，不克隆棋子；对象引用保留到 shot/回调释放。
- guard 每次瞄准先 concat 一份数组，再 indexOf，O(N) 时间/O(N) 临时引用空间。δ=0 仍先做 concat/indexOf 后返回；缺字段在调用者外层不进入 guard。
- 非零有效 δ：调用一次偏差 blocked；仅偏差堵时才调用原方向 blocked，最多两次。每次路径助手另 concat 一份数组并 O(N) 扫描，可早退出。
- 因而每次有效非零 guard 最多三份棋子数组容器（一次 membership、两次助手），整体 O(N) 而不是 O(N²)，没有逐帧采样或 solver 模拟。每个 blocked 算目标投影及开方；助手 cos/sin 一次、每棋子投影/夹紧/平方。
- 快照已有 O(N) 项对象分配；提交检查 O(N) Map、delete/set；备用位置七次尝试、被占位时二维间隙搜索及排序属于既有链路，不把全部耗时算到本次新增。
- 重试最多两次，但每次移动/瞄准、快照和 guard 都可重新发生。更保守保护会改变偏差归零比例/难度，应记录触发率和得分分布而不只看崩溃率。
- 若优化：先 δ===0 返回；每次评估共享一份有效静态棋子列表；不保留跨棋盘版本缓存。不需先引入空间树，先测真实 p50/p95 和 GC。

## 8. 原型定义与参考取舍（仅用于下游验收，不新增产品）

### 玩法/核心循环

沿用参考 Carrom 回合循环：观察静止棋盘 → 选合法基线 → 选普通候选或备用目标 → 预览与蓄力 → 单次发射 → 物理碰撞/进袋 → 原规则结算 → 下一回合/重试。本轮只审查 AI 备用偏差，不新增关卡、经济、皇后规则或玩家自动瞄准。

- **审查成功**：应撤销的新增阻挡能撤销；原本可用偏差不无故归零；默认预览与提交共用方向；过期方案不提交；原结算不重复。
- **审查失败**：目标实体错认、非法数值发射、按约定语义应拦未拦、应留误杀、旧回合提交或显示/物理方向分离。
- 首次碰撞不等于得分，保护器不写分。参考使用 `CarromDiscRules.hasWon(...)`，该外部模块未提供，不能推定完整胜负/皇后结算已验收。保留原计分与胜负 owner。

### 物理与输入边界

- 参考静态步长：1/60秒，step参数10/10；ticker 累计 while >1 推进固定tick，没有在已读循环中看到本地最大补步数。长帧过多补步可能造成阻塞；PIXI ticker自身是否截断需依赖版本证据。
- 已读棋子 bullet=true、圆碰撞体，但不据此声称连续碰撞无穿透；真实速度、反弹、阻尼和 contact event 需运行检验。
- 合法输入只在当前回合可瞄准/可放置状态；玩家拖拽按指针 identity/type 过滤，释放 strength>=0.25 才发射，最大150显示单位拖距、最大力度125。AI力度也上限125。无效输入应不提交，重试不增加计分。
- 本审查建议下游冻结“选择/移动/瞄准/提交/运动/结算/结束”状态，轮次与方案版本显式关联；输入窗口外拒绝重复发射；暂停/恢复不提交旧回合。
- **现有数值容差**：坐标每轴1单位（快照）；碰撞严格相交 `<R²`，目标用 `<=R²`；无角度误差门槛、并列事件门槛。
- **建议验收容差（待代码阶段落实，非原版事实）**：代数单位测试角差模2π<=1e-10 rad；浏览器首步实际速度与预览前向<=1e-6 rad，原点<=0.1逻辑单位；临界碰撞在 0.1单位带内标作 ambiguous 并重新规划/按约定规则处理，不承诺并列先撞目标。运动轨迹跨帧率可用1逻辑单位作为初始对照带，但首碰身份在非临界布局必须一致。需要用真实 solver slop 校准，不将建议数值冒充实测。

### 界面布局与语言

本轮不制作新UI。保留参考棋盘、基线滑杆、击球器、瞄准箭头与双方HUD；可选的下游审查视图采用 Canvas 2D 绘制，规则函数与渲染/输入分离，展示原方向、偏差方向、目标首接触点与障碍胶囊体。不会因此迁移或替换本轮 PIXI/planck 参考运行系统。

若下游需要审查视图，默认 English、html lang=en：`Fallback Shot Review`、`Base Direction`、`Deviation`、`Target`、`First Contact`、`Board Changed`、`Replan`、`Run Case`、`Reset`、`Static Prediction Only`。中文浏览器不自动切换语言。本轮报告为中文，未生产玩家文字图片。

### 修订建议，不是本轮已实施补丁

1. 将“仅防新增障碍”写入函数契约；若要求必首碰目标，则必须显式 hitTarget、live entity、非并列、原/偏差进入距离条件，不能仅替换某个正负号。
2. 发射提交边界重新核验目标实体、物理坐标及选定路径；检查失败重规划并重新展示预览。不在发射瞬间静默改角，仍由现有提交 owner 负责一次发射。
3. 运动开始前验证静止/速度上界；若允许棋子运动则需要时间化碰撞预测，而不只是显示坐标快照。
4. 用同一个不可变 shot 版本保存 origin、direction、deviation、round/turn、board generation；预览与发射从同一最终向量派生。
5. 明确切线/同时碰撞策略，物理 fixture 与几何半径共用来源；异常应中止重算/交回合，不向物理引擎传非有限值。
