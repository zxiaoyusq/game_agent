## 玩法与核心循环

玩家从待放区选择形状，拖到棋盘预览，合法释放后占格、同时消行列并得分，再选择下一块；三块全部用完才补充。无尽追分，无固定胜利目标、限时或步数限制；所有待放形状均无合法位置时失败。单局时长暂以 3—5 分钟为体验假设，后续真实试玩评估，不作为已验证结果。不增加撤销、提示、离线收益、存档或跨局成长。

棋盘为 6×6，`board[y][x]` 取 0（空）或 1（占用），x 向右、y 向下，范围均为 0—5。形状不能旋转或镜像，放置坐标是形状局部原点在棋盘上的整数坐标。

| 标识 | 局部格坐标 [x,y] |
| --- | --- |
| dot | [0,0] |
| bar2 | [0,0], [1,0] |
| bar3 | [0,0], [1,0], [2,0] |
| square | [0,0], [1,0], [0,1], [1,1] |
| corner | [0,0], [0,1], [1,1] |

供块：每组三块，有放回抽取，五种形状等分概率区间，允许重复；组内可任意选择，消费后剩余列表保持相对顺序。初始种子默认 1，生成器采用 32 位 LCG：`next = (1664525 × seed + 1013904223) mod 2^32`，通过 `floor(next / 2^32 × 5)` 索引上述固定顺序。生成器状态显式保存在 seed。种子 1 首组为 bar2、bar2、bar3，后续 seed 为 2165703038。不筛选可放形状，不提供保底，不保证每个随机局面可解。

## 状态与事务规则

规则状态包含 board、pending、seed、score 和 status（playing/over）。拖拽状态属于后续输入层，不写入规则棋盘。

1. `place(state, slot, x, y)` 检查进行中状态、整数有效槽位、整数坐标及全部形状格无越界/重叠。失败返回 `{ok:false,state}`，输入不变。
2. 合法动作复制棋盘并占格；从同一份放置后棋盘识别所有满行、满列，取格坐标并集后一次清除。交叉格仅清除和计分一次，不按行列遍历先后改变结果。
3. 消费所选形状。仅当剩余列表为空时使用当前 seed 补三块。
4. 本次得分 = 放置形状格数 + 清除的不同格数 × 10；无额外连击或多线奖励。单点同时补满一行一列时清除 11 格，得 111 分。
5. 在清除及必要补块之后遍历所有待放形状的全部棋盘锚点；至少一块可放则继续，否则 status=over。结束后拒绝放置。新局调用 createGame，重置棋盘、分数与种子供块。

纯函数输入契约是内部合法状态：6×6 二值棋盘、已定义形状、非空正常待放列表、有效 seed 与分数。不包含任意损坏存档或外部不可信对象的结构校验。SHAPES 是规则常量，调用方不得修改内部坐标数组。

## Canvas 方案与界面交互草图

目标为 Web/H5 浏览器原生 Canvas 2D，使用 JavaScript ES 模块，不加载 Cocos 或其他引擎；本轮规则仅依赖 Node 内置模块，不引入 npm 依赖。浏览器实现和版本证据归后续阶段。

竖屏逻辑画布暂定 360×640：顶部标题、分数与 DOM 重开按钮；中央棋盘占 312×312（每格 52 逻辑单位）；下方三个待放槽；底部规则与状态提示。DOM 提供关键按钮语义和可读状态。布局值为设计草图，尚无画面或触控测量证据。

规则层使用本轮模块；渲染层只读已提交状态并按需重绘；输入层使用 Pointer Events，把客户区坐标依次映射到逻辑画布、棋盘格。内部画布按 CSS 尺寸和受控 DPR 缩放，窗口变化重新计算映射。

拖拽开始保存槽位和抓取偏移并捕获唯一 pointerId；移动仅更新预览，按原点吸附网格显示合法/非法反馈。合法释放仅调用一次 place；越界、重叠释放、拖出后释放、Escape、pointercancel、失去捕获或页面隐藏均取消，恢复待放显示，棋盘、库存、seed 和分数不变。其他指针忽略；取消和结束后清除拖拽标记，避免重复提交。此处是输入约定，尚未实现或通过浏览器验证。

结算后显示最终分数与再来一局。页面隐藏无需累计时间收益，取消当前拖拽即可。
