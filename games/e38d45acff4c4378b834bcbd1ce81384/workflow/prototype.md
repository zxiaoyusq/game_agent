## 结论

公开 `pause/resume` 是空函数，局内菜单暂停由 `_0x3e61d0` 控制，而广告直接操作 ticker 与静音。三者没有统一的暂停原因所有权。不能简单让公开 pause/resume 覆写 `_0x3e61d0`，也不能将公开 resume 直接实现为 ticker.start：前者可解除仍打开的菜单暂停，后者可解除尚未结束的广告停止。建议以独立原因集合控制有效冻结，保留菜单自身状态，并统一广告的启停仲裁。

现有菜单暂停能阻止主更新及其内部 Tween、游戏延时、倒计时和物理步进；它不能自动阻止原生 timeout、所有输入事件或外部 SDK 回调。暂停入口需要同步取消瞄准和滑条拖动；恢复不得补发暂停前的松手出杆。

## 游戏状态、物理与输入契约

本轮不重新设计玩法或布局。已有核心循环为玩家摆位/拉杆 → 松手提交 → 固定物理演化与入袋 → 等静止 → 计分、犯规及女王处理 → 下一回合或结算。局内标志 `_0x3fddb3`、玩家回合 `_0x209883`、可操作 `_0x55e693`、瞄准 `_0xf86500`、roundId/turnId 和 resultCommitted 应分别保留语义。暂停不等于失败、结束或重开，不应因暂停调用结算、清速度或递增回合。

物理已读数值：每逻辑步 1/60 秒、速度/位置迭代均为 10；100 显示坐标单位对应 1 物理单位；棋子 Circle 半径 16/100，striker 半径为 34×0.8×0.8/100；动态体设 bullet，边界为静态 Edge；入袋由更新中的中心距离 <=20 显示单位判定，非将接触回调直接计分。trimVelocity 在速度绝对值之和 <0.2 时睡眠。不能据 bullet 保证任何高速场景不穿透。

普通模式计分回调按入袋棋子增加一分；Freestyle 分值表为 [50,20,10]，目标 `_0x153877=160`，存在女王 pending 与犯规退分/退子。普通模式 target/hasWon、回合时限等依赖未提供的 CarromDiscRules；因此不宣称完整规则已验证。胜负提交有 resultCommitted 去重，多个计分/回合回调有 round/turn 校验。暂停期间应冻结分数、回合计时、棋子及游戏回调，广告奖励的真实结果需单独按广告事务保存，不能当作可丢弃的出杆输入。

玩家输入窗口沿用已存在的按下门禁和身份匹配，力度阈值为 0.25；未提供真实时间制松手窗口，不新增虚构毫秒要求。已有布局是 640×1137 基准 PIXI 画布、中央棋盘、上方双方 HUD、底部摆位滑条和暂停菜单。修复无需新素材、改菜单文案或改语言；参考英文教程继续保留。本轮未检查 HTML lang 或图片实际文字。

## 最小可测修复建议（未实施）

1. 在闭包内新增独立 `hostPaused`，保留菜单状态；定义有效冻结为 `hostPaused || menuPaused || adPaused`，需要隐藏冻结时另设 visibility 原因。每个调用方只增删自己的原因，公开 pause/resume 对同一来源幂等。公开 resume 不关闭菜单、不重开、不出杆；无 token 的公开 API 不采用盲目计数，避免重复 pause 造成永久冻结。若宿主需要多个独立来源，需先明确 token 契约，不能假设现有 API 支持。
2. 统一 `_0x49d791`、真实玩家输入入口/提交点、滑条回调和最终 AI 出杆的冻结门禁。菜单 UI 与棋盘输入分别处理：菜单原因下仍可操作关闭/退出/教程，宿主或广告原因下阻止所有用户业务操作。不要整体禁用后无条件恢复整棵 stage 的 interactive 值；应结合当前场景、回合和控件业务许可恢复。keyup/cancel 等清理事件仍允许执行。
3. 首次进入有效冻结时取消正在进行的瞄准和滑条拖动，清指针标识、隐藏并清零力度、清滑条 `_sliding`，必要时重置缓存按键。取消函数必须在对象尚未初始化时安全，且不能因 `_0xf86500=false` 提前返回而遗漏残留状态。教程取消提示的恢复应在解除全部原因后做一次，不在冻结中启动新业务动画。恢复后须重新按下才能拉杆；暂停前排队的 up 不得提交。
4. 优先保留 ticker 驱动渲染及事件系统，使用业务更新门禁冻结现有 Tween、物理、回合计时和 `_0x338c29`，无需逐个暂停/重建 Tween。广告若保留 ticker.stop，必须由统一仲裁器管理广告原因与 ticker 的运行意图，替换所有正常/异常直接 start 路径；不要只改公开接口。仲裁器不能在加载前提前启动 ticker，也不能误启原先已停止的实例。暂停菜单继续依赖 ticker/交互的具体行为需依赖版本及运行证据。
5. 进入/解除冻结处理 `_0x990fb7` 的暂停债务：暂停期间不积累逻辑步，转换点清残余或明确保留不足一步残余，并在 ticker 恢复首帧丢弃停机跨度；不更改 1/60 物理步长、不清刚体速度。当前代码的 while 无上限，PIXI 是否裁切首帧 delta 未知，必须测试后再决定是否加小范围补步上限；避免顺带改变正常物理节奏。还需处理 Tween 回调中途引入暂停后，本次 update/while 继续运行的重入边界，在推进后续子系统前重新检查。
6. 原生 timeout 不能全部替换成 `_0x338c29`：匹配场景此时 `_0x3fddb3=false`，该函数会丢弃回调。应给匹配流程增加独立场景代次与可冻结调度，保存剩余时间，退出时取消，恢复后仅执行当前实例任务；200ms 装饰音效可在冻结/场景失效时丢弃。广告 SDK 生命周期继续接收，奖励结果先按广告事务去重记录，影响场景/模拟的继续动作在允许时提交，不能阻断必要清理或重复发奖。
7. 重开/退出统一清本局手势、旧任务和菜单实例/遮罩；重开只重置本局与菜单原因，保留 host/ad 等外部原因。外部原因未解除时可初始化新局但不推进，或延后初始化；本报告建议前者以缩小改动，并要求测试证明。退出后旧回调不能修改新场景，补场景代次，保留现有 round/turn/result 去重。页面隐藏是否采用冻结在本建议中明确为新增策略，不能把当前隐藏仅静音说成完整暂停。

只改公开函数为 true/false、只 stop ticker、调用菜单函数代替宿主 pause、恢复时调用 restart、clear/finish 全局 Tween，均不足以达到上述契约。
