## 1. 实际局部差异

旧版备用函数在完成目标选择与摆位避重叠后，直接返回位置及指向目标的角度。

当前版在相同前置逻辑后：
1. 计算当前位置到同一目标的方向和距离。
2. 用 `_carromStartPathBlocked` 判断计划起段。
3. 仅当起段受阻，依次扫描七个固定基线点。
4. 候选先通过 `_0x23a7dc(candidate,37.76)` 的摆位检查，再通过起段检测；选择第一个通过的点并更新方向。
5. 返回方案。

七点为 x = 162、215.5、269、322.5、376、429.5、483，y 恒为 421。从左到右优先，不随机排序、不评分、不更换目标。

**七点均失败时保留搜索前已经修复摆位重叠的随机位置及其方向，仍返回 `{pos,dir}`。** 不是返回 null，也不是恢复进入函数前击球子的实际世界位置。

已有 null 条件须单独区分：目标池及兜底池皆空，或找不到可摆放的基线位置。新增七点起段失败不产生新的 null 条件。

`_carromStartPathBlocked` 两版定义相同；四个普通规划函数的相关调用也已经存在。不要把整套起段检测、基线修复、重规划或结算保护算成这次新增。

## 2. 起段碰撞几何与半径

helper 验证原点、角度、长度；非法输入或负长度返回 true，合法零长度直接返回 false。令方向 u=(cos(angle),sin(angle))，L=min(length,43.52)，对每个非目标棋子中心 C 求：

```
t = clamp(dot(C-origin,u),0,L)
D = C-origin-t*u
blocked = dot(D,D) < 37.76^2
```

这是半径 37.76、中心线长最多 43.52 的线段胶囊检测，不是仅检查投影落在段内的棋子。起点后方及终点前方半径内也会被端帽覆盖。

半径证据：
- 普通棋子 `_0x19677d=0x10=16`，Circle 半径为 16/_0x541423。
- 击球子 `_0x1c6272=0x22*0.8=27.2`，fixture 半径参数为 `_0x1c6272*0.8/_0x541423`，折回像素为 21.76。
- `_0x541423=100`；世界坐标 setter 除以该值，显示更新乘回。显示中心与物理中心按同一缩放关联。
- 因而 37.76=16+21.76；43.52=2*21.76。规划中另有 15 的棋子几何参数，不能拿它替代真实 fixture 的 16。
- 以上构造数值两版一致；未验证运行依赖是否动态修改 shape 或引擎接触容差。

严格小于意味着理想数学相切不阻塞；未增加 epsilon。引擎接触容差、浮点舍入、后续运动及角度误差仍可能造成实际接触。

短路径用其实际长度；零路径不扫描棋子。无效非目标棋子坐标令结果为阻塞；目标先按身份跳过，再检验坐标。

fallback 不调用既有完整/较长路径检测 `_0x3ea989`。起段安全不保证全程安全、首先撞到目标、进袋、遵守目标色规则或避免犯规；墙和袋口也不在 helper 的障碍集合中。

## 3. 目标身份、玩家与模式

障碍集合始终包含全部活的 AI 普通棋子、玩家普通棋子和 queen。排除条件是 `disc===intendedTarget`，不是 id、type、颜色或坐标。

备用目标由活棋数组随机选出，传递的是原对象，因此该调用的身份排除正确匹配目标；两组普通棋子的 id 可重复，改成按 id 排除反而可能漏掉其他棋子。坐标相同的 clone 不会排除真实对象；恢复/罚子重建的新对象与旧对象不同，快照身份检查可捕获这种变化。

目标池：
- mode2：AI 普通棋子 + 玩家普通棋子 + queen。
- 非 mode2：AI 普通棋子仅剩一个且 queen 存在时选择 queen；其他情况选择 AI 普通棋子。
- 上述池空时再拼入玩家棋子及 queen；仍空返回 null。

mode0 不生成 queen；mode1 有 queen/覆盖结算；mode2 为 Freestyle。菜单资源标识对应 discpool/carrom/freestyle，但外部 `CarromDiscRules.layout/target` 未提供完整依赖核验，具体颜色映射、所有计分参数不可仅凭混淆标识推定。

玩家/AI 是回合阵营，不等同先手：随机先手只决定谁先开始；教程玩家先手。AI 使用上方 y421，玩家使用下方 y828。新增七点搜索只接入离线 AI 备用出杆，不替人类摆位，也不依玩家先后手翻转基线。

## 4. 真实调用链与输入窗口

```
AI 回合 _0x50a0ff
  → 约 500ms 逻辑延迟
  → 四个普通规划函数
  → 有限数、基线、摆位复验及评分
  → 有候选：_0xd6b627(best)
    无候选：_0x3d12d7 → _0xd6b627(fallback,100)
  → 保存棋盘快照
  → _0x4662ac 移动动画
  → _0x223471 瞄准/力度/误差
  → 约 500ms 逻辑延迟
  → _0x4b3cc6 复检和 shoot
  → 物理运动、入袋扫描
  → _0xbdafb3 等待睡眠、计分/queen处理、续杆或换回合
```

延迟通过 Tweener 逻辑帧运行，不能当作后台独立墙钟 setTimeout。移动过程最多三次扰动，第四次到指定 x。AI 输入窗口关闭玩家 slider；玩家回合才开启。round/turn guards 防止旧回合回调误操作；同回合 shot guard 防止重复发杆。

实际发杆前检查：快照棋子数量、对象身份、数组归属、有限坐标，以及单轴坐标变化是否 >1 px；同时检查 x∈[162,483]、y===421、摆位不重叠。**不重新调用起段 helper，不重新检查完整路线。** 小于或等于 1 px 的变化并不保证保留擦边裕度。

瞄准阶段按桌档概率加入角度误差，概率数组为 [.8,.7,.6,.35,.2]；误差绝对值 [0.05,0.10) rad。shoot 接收 `PI-plan.dir+error`，其物理向量使用 `PI-shootAngle`，因此实际行进角为 `plan.dir-error`，无误差时与计划方向一致。检测计划角而非误差后的实际角，所以安全计划仍可能被扰动到障碍上。

## 5. 无安全替代、卡局和计分边界

七点全不安全：仍有有效摆位方案，起段阻塞本身不会触发 null、重试或跳过回合；后续摆位/快照复检通过即继续发杆。因此这次有限搜索不会因一直寻找安全路线而自身无界，但其语义是尽力改善，不是安全保证。

真正的发杆复检失败：同回合备用重规划最多两次，超过后退出；备用 null 也退出。普通分支交给玩家，queen pending 分支进入受保护结算。上述机制既有，不归于新增改动。

结算 `_0xbdafb3` 等待所有活棋子及击球子不 awake，仍 awake 时以约 50ms 逻辑延迟重复等待。已有 trimVelocity 会在速度绝对值之和 <0.2 时睡眠，但没有运行证据证明所有异常状态必然稳定。结算依赖、宿主暂停、广告与逻辑帧推进均是相关边界，不能证明整个游戏绝不会卡局。

计时器不是所有档/模式都启用，条件为 table!==0 或 mode===0 且非 tutorial；table0 的 mode1/2 不可假定存在统一超时兜底。queen pending 的 timeout ticket 经入袋扫描后再 flush/结算，需专项回归。

玩法循环保持原有：摆位/瞄准/出杆 → 物理碰撞和入袋 → 睡眠结算 → 计分、queen处理 → 续杆/换回合/胜负结果。此次不定义新胜负条件。`_0x47e567` 是结果提交/UI函数，不是 AI 入口；`game.test` 在调用它并 return 后的规划代码不可达。`_0xd6b627` 中 return 后旧直发代码同样不能作为真实调用链。

## 6. 风险优先级

1. 高：七点全失败仍返回受阻起段；若需求是绝不立即撞非目标，则静态行为不满足该要求。若需求是尽力改善且必须继续出杆，这恰是保守保留策略，不能自行改成拒绝出杆。
2. 高：检测只覆盖起段且发杆角误差后不复检；不是完整可达性或命中保证。
3. 中：七点离散采样可漏掉点间安全区；同一随机目标固定不变，其他目标即使可达也不尝试；左优先有策略偏置。
4. 中：严格相切、<=1 px 的快照容忍以及引擎容差可导致边缘误判；默认没有安全裕度。
5. 低/需数据：固定额外线性扫描和数组分配；未实测性能。已有规划、摆位密集轴搜索与结算等待更可能需要单独采样，不能混入此次新增成本。

## 7. 新增计算成本

设 N 为三组活棋子总数。
- 初始起段安全：新增一次 helper，O(N)，可能早退。
- 初始受阻：最多七个候选；新增 helper 总数最多 8 次，摆位扫描最多 7 次。
- 简单扫描上界 15N 个棋子循环访问；目标跳过也算访问，但不是每次都做距离计算。实际受碰撞早退及候选跳过约束，不能把 15N 当典型工作量或声称必然达到。
- 临时合并数组累计分配 O(N)，最多 8 个起段数组和 7 个摆位数组；同时存活量及 GC 时序未测。
- 三角函数、距离与固定候选数量均是常数倍；不是 O(N²) 或指数搜索。

原有初始摆位向左右扫描（最多约161轮）、开放基线区间排序 O(N log N) 以及普通规划的 helper 调用，均不算本次新增。没有毫秒、帧率、内存或 GC 实测数字。
