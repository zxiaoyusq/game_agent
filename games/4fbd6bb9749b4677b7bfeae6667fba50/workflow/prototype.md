# Carrom 备用选杆多目标策略边界审查

## 1. 结论与范围

本轮仅为原型阶段的只读静态审查，唯一写入产物为本报告 `/workflow/prototype.md`。不修改工程、参考、物理、结果处理或 UI；不进入美术、代码或测试阶段。

**结论：候选建议在明确约束下可作为小范围策略扩展，但不能据此判定实现已合法、已验收或胜率已提升。** 扩展点应严格位于：当前随机目标在原有初始摆位及 7 个基线采样位置都未得到畅通路径之后。仅从同一次构造的目标列表中按有限、无重复顺序尝试其他目标；找到首个符合原几何谓词的目标/位置对才整体替换；没有找到则返回原备用杆，包括原位置、方向、目标引用及 `false` 标志。

这里“不更改结果”解释为不改计分、犯规、胜负及结算规则/处理代码，不是保证每次射击的轨迹、入袋结果或最终比分相同。换目标/方向本身可能改变实际结果；若要求逐杆结果完全相同，此改进与该要求不相容。报告没有把这一解释当作用户已确认的实施授权。

## 2. 现版可见行为

为便于讨论，仅给列表起符号别名：`A=_0x2a9c75`、`B=_0x3e4566`、`R=_0x3231b3`，不在证据不足时将 A/B 直接断言为具体玩家颜色。对混淆属性的 `length/concat/floor/random` 解读符合用户描述及邻近明文用法，但本轮未独立执行字符串解码器。

### 2.1 候选列表构造

| 条件 | 可见构造 |
|---|---|
| `_0x5d148e === 2` | `A.concat(B,R)` |
| 非上述分支，且 `A.length === 1 && R.length > 0` | `R.slice()`，不包含那枚 A 中棋子 |
| 其他 | `A.slice()` |
| 以上结果为空 | 在空结果上追加 B 和 R |
| 追加后仍为空 | `return null` |

这张表是程序的列表构造，不是已经验证的完整 Carrom 合法目标规则。尤其“ A 恰有一枚且 R 非空”是强约束分支，不能被多目标搜索改成 A 与 R 的并集。空 A 的 B/R 兜底同样是原有行为，不能称为本次新增，也不能只因它原本存在就证明符合所有规则阶段。

### 2.2 摆位与路径搜索

1. 从上述列表中随机选择一个索引作为目标，再随机选择基线 x，y 固定为 `_0x429ae3`。
2. 若摆位重叠，以步长 2 从该 x 向右、再向左尝试；右侧使用严格 `<`、左侧使用严格 `>` 边界。循环在偏移 0 时可能重复检查同一位置。
3. 若仍重叠，调用 `_carromFindOpenBaseline()`；其返回 `null` 时直接 `return null`，否则使用返回 x。函数体不可见，不能证明它一定返回合法、有限坐标。
4. 对修正后的初始位置计算方向、到目标的欧氏距离，调用 `_carromStartPathBlocked(pos,dir,distance,target,true)`。
5. 初始路径受阻时，按 i=0…6 检查 `xmin+(xmax-xmin)*i/6` 七个位置。重叠位置跳过；第一个未被路径谓词判阻的位置即采用。
6. 若七点都没有通过，不丢弃备用杆，返回原位置、原目标、对应方向及 `_carromFallbackWasClear:false`。若通过则标志为 true。

“初始位置”指经过摆位修正的位置，不是必须保留原始随机 x。路径最多检查初始点加七点，但点可能重复、重叠点被跳过，所以不是保证八个互异有效摆位。原重叠搜索不等于针对目标进行连续基线可达性搜索。

## 3. 建议的候选语义与回退不变量

以下是审查约束，不是已编写的补丁，也不是用户已选择的最终参数。

- **单次列表快照**：只使用此次调用已经构造的列表 L；不重新拼接全盘、不从障碍物列表追加目标、不更改规则分支。`slice/concat` 只复制列表，棋子对象仍是引用，不是不可变棋盘快照。
- **完整保留原流程**：原目标初始路径畅通，或七点中任一点畅通，立即维持现版选择；不能趁机寻找更高分目标。
- **保存回退基线**：仅在现版原目标搜索失败后保存原备用杆 S0。此时位置应是摆位修正后的原位置，方向指向原目标，标志为 false。新增失败尝试不得写坏 S0，也不得把它替换成最后一个失败目标。
- **外层目标、内层位置**：每个其他目标先试 S0.pos，再按现版 i=0…6 七点顺序试。目标 T1 的八点搜索完成后才进入 T2。位置外层/目标内层会改变“首个可达目标”的含义，不视为等价。
- **有界无重复顺序**：设额外目标上限为整数 K≥0，实际额外尝试数 `k≤min(K,n-1)`，n 为 L 的长度；跳过原索引，且不重复尝试同一索引。循环至多走完有限列表，不递归调用 `_0x3d12d7()`，不无限重抽随机数。
- **重复棋子语义**：相同对象或同一棋子 ID 若在 L 中重复出现，必须在测试中暴露。可用调用内身份集合避免重复搜索，但不能顺便去重原随机抽取列表，否则原抽取权重也变了。完整遍历时不同目标数可能小于 n−1。
- **“可达”限于采样谓词**：新候选必须使用相同摆位判定、同一方向函数、实际位置到新目标的距离、同一目标引用及相同 `true` 参数。不能用旧目标距离或旧方向检测新目标。
- **整体提交**：只在摆位及路径均通过时，同时采用新 pos、dir、target 和 true 标志。返回字段仍仅维持现有契约，不新增打分/进袋保证等语义。
- **全失败严格回退**：原流程 `null` 仍是 `null`；原流程能返回 S0 而扩展无通过候选时，返回 S0，不重新抽目标、不返回 `null`、不残留失败候选元数据。非变更路径要求数值及目标身份相同，不只要求形状类似。
- **下游兼容**：`_carromFallbackSafeDeviation` 只有声明，必须核对其消费者如何使用标志、目标与方向。基础方向通过不证明偏转后的方向仍安全；不能将扩展用于关闭原偏转安全逻辑。

有限 K 与“其他目标全部受阻”必须分开：K<n−1 时，只能说“本次预算覆盖的额外目标均未通过”，不能说 L 中所有其他目标均受阻。即使遍历整个 L，仍只能说“所有目标在约定采样位置均未通过”，不能证明连续基线上不存在路径。若要涵盖所有其他列表项，K 至少覆盖 n−1，并以实际合法列表最大长度限制总预算；本轮没有选择一个未经实测的硬编码 K。

## 4. 规则合法性、红棋与自由模式

**可证明的集合边界**：若新增返回的目标始终属于原 L，就没有新增列表之外的目标。**不能证明的规则边界**：L 是否在当前回合真实合法，仍依赖列表 owner、模式、红棋状态、当前玩家、犯规/覆盖阶段及棋子存活性。

- 非自由分支 `A.length===1 && R.length>0` 时，新增搜索只能在 R 中进行。即使 A 的最后一枚很好打、R 全受阻，也必须保留原备用行为，不能改投 A。
- 调用方提出红棋/自由模式，但 E-01 没有证明 R 的字段身份或 mode=2 的枚举映射。若它们分别代表红棋与自由模式，应保留现有分支，并对真实映射单独取证；不从命名或一般桌游规则补造现版规则。
- 若 mode=2 确为自由模式，列表应保持 A+B+R 的原顺序/权重来源；多目标选择可能偏向列表较早的颜色/类型。自由模式的红棋分值、覆盖要求或归属状态均不在片段内，不能宣称“自由模式所有棋子总是合法”或“红棋必优先”。
- R 为空时不得生成虚拟红棋；A 非空且不满足特殊分支时不得擅自加入 B；A 为空时按原 B/R 兜底，不重新制定双方颜色策略。
- 目标属于 L 仍不保证首个实际碰撞物就是它，也不保证不会碰对方棋、犯规或碰入击球子。路径函数体与物理模型未知。
- 所有尝试应只读棋盘，不击球、不摘除棋子、不预记入袋、不改当前玩家、分数或红棋覆盖状态。规则提交仍归原 owner。

## 5. 旧局重入、存档与输入边界

E-01 的函数体是同步函数，不可因此推出整个 AI 调用链同步、安全或无重入。正常同一 JS 栈中异步回调不会任意打断它，但辅助函数可能有副作用/同步回调，调用前后也可能发生新局、换回合、存档恢复或对象重建。

- 搜索状态、已访问集合、预算与回退杆均应为调用内数据，不能形成跨局缓存，也不能持久化旧目标对象引用。
- 原 owner 的稳定选杆/提交边界必须保留；在物理尚运动、用户瞄准、暂停或已结算期间，不因“备用可用”而新开射击路径。
- 生成杆与实际射击若跨异步边界，需沿用并验证原局/回合/当前操作者标识，以及目标仍在当前盘面。过期结果不得在新局提交；不能在本次小改中凭空引入新的全局生命周期 owner。
- 同一回合只提交一次射击，失败重试计数沿用原有边界，不因目标扩展变成多次真实击球。
- 旧存档恢复后列表应由原逻辑重建/核验；不能用旧序列化对象混进 L。本轮不迁移存档 schema，不新增随机状态保存需求。

## 6. 随机性与公平

现版可见目标索引随机抽取与初始 x 随机抽取；空 L 时在抽取之前退出。按 floor/random 解读，目标抽取对列表索引等权，不一定对互异棋子等权，重复项会带来权重。

建议若重点是保留原随机消耗，可将“从原随机索引下一项开始循环到尾再到头，跳过原索引”作为一个**无额外 RNG 调用的候选顺序**，但不是本轮已批准的实现方向。不要递归重跑函数，因为会重抽初始位置、改变后续随机流并重复摆位搜索。

任何固定顺序都有选择偏差，不能写“随机起点保证可达目标均匀”：例如 L=[a,b,c]、a/b 可达、c 受阻，原目标 a/b 成功保留；从 c 往后循环先选 a，则最终 a 概率 2/3、b 概率 1/3（假设三项索引等权且几何稳定）。预算截断还会偏向离原索引较近的可达目标。若失败后每次都从列表头开始，头部偏差可能更强。

随机打乱其余项可以减少某些顺序偏差，但会新增 RNG 消耗，并改变之后的全局随机序列；均匀重选可达集合需要更多评估，不等价于“首个通过即停”。公平、无额外 RNG、首个通过即停并非自动同时成立。是否要求可达目标等权、颜色无偏或双方同等能力属于后续产品取舍，不能自行声称已经满足。

应保持同一方/模式的一致预算，不使用付费、连胜连败、用户身份、结果预知或远端胜率目标改变 K/排序。只改变 AI 备用选杆也可能改变人机强度，不因为双方遵守同一规则就断言体验公平。需分别记录原抽取分布、扩展触发率、最终目标分布、模式/颜色分布和预算截断率。随机流调用数不变不代表策略分布或真实战绩不变。

## 7. 最坏 CPU 开销与预算

下述均为静态调用上界，不是耗时实测；假设辅助函数会终止、坐标有限、基线宽度 `W=xmax−xmin>0`。

令 `Q=ceil(W/2)`；原 ±2 摆位修正至多 Q 次循环、每次至多 2 个摆位判定。原函数显式摆位判定上界为 `2+2Q+7`（首次检测、修正循环、修正后复检、七点检查），另加 `_carromFindOpenBaseline()` 内部未知成本 F。调用该函数后可见片段未再显式复检其返回位置，需核对其契约。

原目标方向、距离和路径检查分别最多 8 次，其中七点只有摆位合法才检查路径。新增 k 个目标若复用同一已修正初始位置、且不重复运行 ±2 与 open-baseline 搜索：

- 额外路径判定、方向及距离计算各最多 `8k` 次；总路径判定最多 `8(1+k)` 次。
- 不缓存七点摆位结果时，额外摆位判定最多 `7k` 次；若初始点也复检，另加 k 次。缓存七点可避免这些重复，但只在棋盘不变且摆位谓词纯净/不依赖目标时等价，当前未证实，不能默认采用。
- 列表构造成本 O(n)，构建目标顺序及去重扫描至多 O(n)；额外临时候选位置分配可达 O(7k)，应关注 GC，但不是内存实测。

令一次摆位判定成本为 C、一次路径判定成本为 P、一次方向/距离成本为 D，则不缓存时总成本量级为：

`O(n) + (2+2Q+7+7k)·C + 8(1+k)·(P+D) + F`。

若两个判定都线性扫 m 个物体，且无更多内部采样，则约为 `O(n+(Q+k)m)+F`；若路径谓词还沿路径进行 s 次采样并扫物体，则路径项可能为 `O((1+k)sm)`。未提供辅助函数体，不能给出实际复杂度、毫秒上界、低端机帧率保证或“棋子少所以无影响”。全遍历 K=n−1 时，路径调用上界 8n，额外 8(n−1)；例如仅作为算式示例 n=19 时总上界 152，不能将 19 当作已核验的现版最大列表长度。

必须避免每换目标都重跑初始随机摆位修正或递归重抽，这会重复 Q/F 成本并改变行为。预算以确定性目标/判定次数为主；单靠墙钟超时会令不同设备选择不同目标。应在真实目标设备/宿主上测扩展触发局面、全受阻局面和原摆位修正最坏局面，记录调用次数、P50/P95/P99/最大耗时、长帧与 GC。当前无设备约定及耗时证据，不替调用方设一个声称安全的 K 或毫秒预算。
