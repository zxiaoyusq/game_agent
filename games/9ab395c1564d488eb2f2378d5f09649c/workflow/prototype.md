# Carrom Disc Pool ARM64 比较器与构造调用链静态审查

## 1. 范围、结论与证据等级

本轮为 prototype 阶段的**中文证据审查**，不是新游戏制作，也不是原库恢复或算法验收。工作区初始目录清单为空，报告为本次新增产物。

**本次未对原始 so 独立反汇编，未运行目标程序，未做动态验证。** 实际执行的是参考文件读取、ZIP 条目与哈希核对、上传指令文本的人工语义推演和跨文件一致性复核。提取 JSON 不称作独立反汇编；ZIP 中的反汇编文本是上游提供的产物，也不是本次从原始机器码重新生成的第二独立证据。

结论摘要：

1. 五个指令窗口都出现“准备参数 8 → 调用共同目标 → 将计算的表地址写到返回指针首字 → 将栈上指针槽地址传给辅助调用 → 非空时经表的第二函数槽间接调用”的相似结构。它支持多态对象初始化、转移/登记和清理的候选解释，不直接证明排序。
2. 五处写入地址均等于 `table_candidate + 8`。若采用常见 AArch64 C++ Itanium ABI 解释，JSON 的 table_candidate 更像 RTTI 指针位置，前 8 字节为待核对的 offset-to-top，写入位置是虚表 address point。**不能将 table_candidate 自身直接当作对象存储的 vptr 值。**
3. 五处都落在所报 FDE 候选 `[0x18c6b20, 0x18c76a8)` 内；入口窗口与调用方的栈上暂存、随后分配 0x28 参数及传递、最后清理的形态，支持“构造/初始化比较策略集合”候选。FDE 不是 C++ 函数语义身份，无法据此命名具体类、构造函数变体或证明范围内全部代码必执行。
4. `context.direct_callers` 报告一处 `0x18b3440 BL 0x18c6b20`；ZIP 的 `caller_18b31fc.txt` 在相同地址列出相同调用，且包含字节列 `b84d0094`。两份提取材料一致，但来源独立性未证实。不能称“唯一真实调用者”。
5. 五个候选函数体可在“文本准确”的条件下推导字段比较返回值，但字段业务含义、消费者的返回值协议、组合优先级、稳定排序、最终选球/选杆以及是否运行于机器人路径均未证明。

采用本报告内的三级标注：**材料事实**（上传文件直接载明）、**条件推演**（材料准确时可推出）、**待验证假设**（需要新证据）。原始 so 与运行事实不因重复出现的哈希或相同指令文本而自动升级。

## 3. 五处表指针逐项复核

E-01 中，`adrp x8, #0x27a2000` 与第一条 ADD 形成 B，第二条 `add x8, x8, #0x10` 形成实际写入值 P。窗口中两次 ADD 之间仅有 `str x0`，没有给出的 x8 改写，故这五个窗口内的数据流比“仅在若干指令内找 ADD”更具体。

全部满足 `B = T - 8`、`P = B + 0x10 = T + 8`，且 C 由 E-02 的 `T + 0x18` 重定位条目指向，因此 **C 位于 P + 0x10**。

### 3.1 必须区分两种槽位基准

若虚表假设成立，常见解释为：

|相对 B|相对 T|相对 P（对象中存储的 address point）|材料/假设|
|---|---|---|---|
|0|−8|−0x10|offset-to-top 候选；未提供原始 8 字节，不能宣称为 0|
|8|0|−8|RTTI 指针候选，E-02 的 addend 指向 typeinfo_candidate|
|0x10|8|0|五表都指向 0x18b2ed4|
|0x18|0x10|8|各表不同的候选函数；随后非空清理 BLR 使用此槽|
|0x20|0x18|0x10|各表候选比较体 C|
|0x28|0x20|0x18|五表都指向 0x18cb8dc|

E-02 中 typeinfo_candidate 依次为 `0x27a2d10 / 0x27a2d58 / 0x27a2da0 / 0x27a2ec0 / 0x27a2f08`，name_relocation 分别为它们 +8：`0x27a2d18 / 0x27a2d60 / 0x27a2da8 / 0x27a2ec8 / 0x27a2f10`。这种两字级形态与 RTTI 相容，但没有给出 typeinfo 首字指向的 ABI RTTI 类型、继承信息或完整名字原字节，仍不是 RTTI 结构验证。

条目类型 1027 与 AArch64 `R_AARCH64_RELATIVE` 相容。普通 ELF 加载时，位置 `load_bias + relocation_location` 写入 `load_bias + addend`；addend 不是已加载指针。重定位位置是表项存储位置，不是代码调用点。未复核 ELF 头及重定位原表前，这仍是对提取格式的条件解释。

### 3.2 生命周期形态与边界

每窗在共同目标 `0x2798774` 前设置 `w0 = 8`；把其返回值存入 `[sp+8]`，再把 P 写入 `[x0]`。它**像**申请 8 字节的对象，但 `0x2798774` 尚未解析，不能直接断言为 operator new、堆分配成功或完整对象大小恰为 8。

辅助调用参数模式为 `x0 = x19`、`x1 = x2 = sp+0x10`、`x3 = sp+8`。`x3` 指向对象指针槽而非直接传对象；`x1/x2` 相等不自动证明空范围，需函数签名及实现。`eor x8, x20, x0, lsl #1` 的输入来源不完整，不能把 `[sp+0x10]` 擅自命名为优先级或距离。

辅助调用后重新读取槽、置零、非空时读取 `[对象]` 再读取 `[表+8]` 并 `blr`。若对象首字仍为 P，间接目标就是上表的 P+8 候选，**不是** P+0x10 的比较体。该形态与所有权转移后的残余临时对象清理、虚析构/删除相容；是否被辅助调用清空、表是否被改写、目标是否真的析构均未知。

## 4. vtable 与其他合理解释

**优先工作假设：C++ 多态比较策略对象。** 依据是 RTTI 邻接关系、候选函数指针组、B+0x10 的首字写入、非空对象按表分派和重复的生命周期形态。若 P/P+8 对应完整析构与 deleting destructor，两个相邻槽也合理；但 `0x18b2ed4`、各 P+8 函数和 `0x18cb8dc` 未提供完整实现，槽名均不确认。

其他可检验解释：

- **手工函数指针/操作表**：对象首字指向带元数据的 ops 表，也会产生同样的 load-load-BLR。需确认 ABI RTTI 的首字、负索引、析构特征及继承/thunk，才能区分。
- **类型擦除策略包装器或登记对象**：辅助函数可能存储、包装、转移策略而不是调用排序；类名字符串可指向包装类型，8 字节形态可只是首级代理。需跟踪辅助函数写入、容器布局和最终分派点。
- **局部构建中临时对象、构造期表或子对象 address point**：存在 construction vtable、基类子对象/调整 thunk 的可能，当前窗口不足以排除。需 offset-to-top、完整继承信息及同一对象生命周期的 vptr 写入轨迹。
- **其他分派协议**：共享槽可能是克隆、释放、查询类型或适配方法；比较代码也可能供过滤、择优或三态决策使用，并非标准排序谓词。

“纯名字表、数据常量表、仅字符串辅助函数”单独解释不了首字间接分派与函数候选组，解释力较弱；但 RTTI/vtable 假设也不得因为名字贴切就写成事实。不主张这些解释概率相同，不给缺依据的数值置信度。

## 5. 构造候选范围和直接调用链

### 5.1 0x18c6b20：初始化形态，而非已确认构造身份

E-01 所报 FDE 左闭右开 `[0x18c6b20, 0x18c76a8)`，长 `0xb88 = 2952` 字节。五处 ADRP/STR/辅助 BL 均在其中。只读取到入口 24 条指令和五个局部窗口，**没有范围全体 CFG、结尾或 LSDA**。

入口 `sub sp,#0x50`、保存寄存器、`x19=x0`；零向量 `stp q0,q0,[x0]` 写入前 32 字节，`str w8,[x0,#0x20]` 写入 `0x3f800000`。若字段为 binary32 是 1.0，但材料没有声明类型，也可为整数/标志原位值。随后调用 `0x18c798c`，准备另一个混合值、以参数 0x10 调用共同目标，再调用 `0x18b9d00`。这些支持“在传入存储上初始化某对象/集合”，但不能证明具体类、总大小、完整构造函数或调用链 owner。

### 5.2 有材料支撑的局部链

```text

  0x18b3454: BL 0x18b4084
```

条件解释：在栈上构建临时状态，将其通过 `0x18b4084` 移动/复制进另一块存储，交给 `x19+0x28` 相关位置，再清理临时对象。需要解析这些辅助函数才可确认移动、复制、注册、替换或析构，**不能将它们直接命名为 sort、append、constructor/destructor**。

E-05 提供调用指令字节列，增强可追溯性；本次没有重新解码这些字节或检查原文件偏移。E-01 所述 direct B/BL exact-target 扫描只给出一条 BL 结果，不能排除间接调用、中部入口、thunk、其他段、运行生成路径。未提供指向 `0x18b31fc` 的上一级完整引用，局部链在此停止，不补造“机器人入口”。

### 5.3 上游分支和旁链不能混拼

E-05 的 `0x18b335c` 读取 `[x21+0x18]`，`0x18b3360 CBZ` 将局部普通流分为两支：非零支在 `0x18b3374` 调用 `0x18b09d4` 后于 `0x18b3380` 跳至 `0x18b33a8`；零支在 `0x18b339c` 调同一目标后顺落汇合。因此在这段普通局部流内两点是**择一分支**，不是两次必定串行执行。两支汇合后可走向 `0x18b3440`，但外部调用不返回、异常、间接转移等仍可中断；不声称每次业务动作都到达。

`0x18b09d4` 只因其范围包含 shotPowerLimits 字符串而被标注，不能证明已解析真实力度曲线。E-06/E-07 的 `0x1aa30b0 → 0x1aa3458` 属于另一 queenCovered 候选链；没有到五比较器构造候选的直接连接。E-08 的 `0x1aa3e04 → 0x1fa8e80` 属于另一消息构造相关窗口，不能因“shot/构造”标签相近就连入本链。

E-09/E-10/E-11 的 MatchShotSolver 类型名、lambda/std::function 包装与短 FDE 也不能命名 `0x18c6b20`，更不能证明该范围是 simulateShot 主算法。

## 6. 候选比较体的条件语义

以下仅按 E-02 指令文本与 AArch64 条件码推演。令 a 来源 x1、b 来源 x2；返回写入 w0，`0xffffffff` 在有符号 32 位解释下为 −1。参数/返回 ABI 未确认为实际业务签名；尤其不能把 −1/0/+1 直接当 C++ bool less 谓词。

|候选 C|载入字段|条件推演：w0 的有符号 32 位解释|
|---|---|---|
|0x18cb8b4|a、b 的 +0x48 无符号字节|a=b 返回 0；a=0,b≠0 返回 −1；a≠0,b=0 返回 +1；a、b 均非零但不等也返回 +1|
|0x18cbbe4|a、b 的 +0x4c 32 位字|按无符号比较，a>b 返回 −1；a<b 返回 +1；相等 0（LS，不是有符号 LE）|
|0x18cbefc|a、b 的 +0x50 32 位字|按无符号比较，a<b 返回 −1；a>b 返回 +1；相等 0（HS，不是有符号 GE）|
|0x18ccb5c|a、b 的 +0x28 64 位浮点|FCMP 的 MI 成立时 −1；EQ 成立时 0；否则 +1。有限值表现为较小 −1、相等 0、较大 +1；unordered/NaN 返回 +1|
|0x18cce74|a、b 的 +0x30 64 位浮点|与上行相同；字段不同|

重点边界：

- 第一项若 +0x48 限定为 0/1，则对应清晰三态关系；若允许不同非零值，`cmp(a,b)` 与 `cmp(b,a)` 都可为 +1，不满足通常三路比较的反对称性。不能凭 ldrb 把字段认定为规范 bool；需跟踪写入者或实际值域。
- 整数字段涉及 `0x80000000` 等时仍按无符号顺序；不将其解读为有符号负分或负犯规数。
- 两个浮点体没有给出的 epsilon 容差；+0/−0 为 EQ，NaN 为 unordered。若 NaN 可进入并按标准排序协议消费，可能破坏所需关系，是否有上游有限值约束未知。
- 上述字段可以是缓存评分/惩罚、标签、派生指标，不一定是可见计分、真实击球路程或力度。名字仅为解释线索。

### 6.1 不能推断的排序与运行路径

五个 ADRP 地址的递增顺序只能称**材料中的代码布局顺序**。前三个窗口与后两个窗口之间存在未读取段：第一窗尾到下一窗头各缺少边界指令，第三到第四之间还有更大间隙；即使覆盖完整直线，也需证明入口、跳转与外部调用返回。不能写“运行时依次建立这五项”或“只建立这五项”。

即使后续证实按此顺序插入容器，也不证明消费者按插入序遍历；即使按此序比较，也不证明是字典序首个非零决策，可能是加权累计、重排、反向遍历、条件筛选、独立排序或择优。当前材料不能证明：

- 主键/次键顺序、字段单位、升降序最终含义、稳定性、tie-break、严格弱序；
- 最优击球候选、机器人目标选择、玩家输入到求解器的完整路径；
- 运行次数、条件可达性、对象实际保存位置、跨线程执行、异常/失败行为；
- 物理模拟步长、碰撞规则、进球计分、胜负、输入窗口、可接受物理误差。

## 7. 后续可复现验证方案（尚未执行）

以下是验证设计，不是已完成步骤。需要用户另行提供原始匹配 so 与可用授权分析/运行环境后执行；当前静态报告任务无须为未知项暂停，也未扩展到下一生产阶段。

### V-01：先闭合构建与地址坐标

取得只读原件，计算 SHA-256，应与声明哈希比较；不匹配则新建版本分支，停止沿用本报告偏移。记录 ELF64/EM_AARCH64、Build-ID、APK/base/split 归属、工具版本、输入哈希。读取 PT_LOAD，并对每个目标计算 `file_offset = p_offset + (link_va - p_vaddr)`，仅在文件覆盖 p_filesz 内取字节。保存头/段/重定位解析输出与命令日志，不能依赖文件偏移恰等 link VA。

### V-02：重新生成最小独立静态证据

用可用的独立反汇编工具对 `[0x18c6b20,0x18c76a8)`、`[0x18b31fc,0x18b35e0)`、五个候选比较体、辅助目标和共同调用目标取原始字节及解码；按 4 字节边界核对 ADRP/ADD/STR/BL/BLR。独立解析 `.eh_frame` FDE/CIE 和可用 LSDA、分支目标、异常 landing pad，检查入口、冷块、结束边界。保存 `evidence/native-independent/` 下的字节转储、指令文本、工具版本与差异表。

全量直接 B/BL 搜索覆盖可执行段，区分 BL 与尾跳 B、精确入口与中部目标；再追踪 thunk、literal/GOT/重定位/数据表及间接分派。将“发现的调用者集合”和“扫描覆盖范围”分开记录，不能以零命中否定间接调用。

### V-03：逐字级验证虚表/RTTI

对五个 B 前后、各 typeinfo_candidate 及名称指针取足够原始字节和完整重定位，核对 B 的 offset-to-top、T 的 RTTI 指针、P 的函数项和 typeinfo 的首字 ABI 身份/继承结构。逐个确认槽目标位于合法可执行段、完整函数及 thunk。特别对比 P+8（清理间接目标）与 P+0x10（比较体），解析共享 `0x18b2ed4`/`0x18cb8dc`。

判定条件：ABI 负索引、RTTI 结构、对象首字写入及实际分派关系能共同闭合，则升级为已验证虚表；否则保留手工 ops 表/包装器解释，不强制命名析构槽。

### V-04：解析所有权与比较消费契约

追踪五个辅助 BL、`0x18b4084`、`0x18b3f40`、`0x18b3d94` 和 `0x2798774`：参数签名、对象首字/指针槽修改、申请/失败方式、容器写入、移动/复制/释放。定位调用 C 或 `[P+0x10]` 的消费者，核对 x1/x2 对象身份及 w0 返回的使用（符号、零/非零、反向或归一化）。继续追踪 +0x48/+0x4c/+0x50/+0x28/+0x30 写入者、单位、范围、有限值保障及容器读取顺序。

判定条件：不能仅在构造阶段见到表，就宣布该比较体被调用。排序优先级需消费控制流及冲突样例共同支持。

### V-05：候选返回值与关系边界样例

在签名确认后，先于独立 ISA 模型或验证夹具复现已提取指令语义；夹具结果仍不是原库动态证据。用原库受控观察/经确认 ABI 的测试入口再对比。未经签名确认，不对任意函数指针主动调用。

- 字节：0/0、0/1、1/0、1/1，以及 1/2、2/1、255/1；重点核对非规范 bool。
- 无符号字：相等、0/1、1/0、0x7fffffff/0x80000000、0/0xffffffff，并交换两参数。
- 浮点：小于/大于/相等、+0/−0、±Infinity、接近但不相等值、NaN/数值、数值/NaN、NaN/NaN；必要时区分 qNaN/sNaN 与浮点状态。
- 检查返回编码、自比较、反对称性、传递性及等价关系；按已确认消费者协议判定，不能套用错误 bool 谓词规范。

### V-06：真实运行链与最终优先级

在授权目标进程中记录模块哈希、ABI、maps 与对应 PT_LOAD，求证 `runtime_va = load_bias + link_va`，不能把首个 executable mapping 起点一概当 bias。记录调试/观察工具版本、线程、单调事件序号、父子调用关系及模块相对地址；只读观察，不修改游戏状态或收集账号/凭据/网络隐私。

观察入口候选、五处表写入、辅助函数、实际比较体入口/返回、策略容器与最终消费选择，按对象指针和生命周期关联，避免把不同对象/线程的日志拼成一个顺序。分别触发冷启动、重复初始化、真实求解请求、相关模式/开关与异常路径；未出现调用只证明本次样本未观测到。

优先级用受控冲突候选验证：让两个指标各自偏好不同对象，再逐项构建平局，观察实际访问序、返回值消费与最终选择；重复输入与多次运行记录对象和配置。只报告覆盖的模式/版本/样本，不提升为所有运行路径证明。

### V-07：若后续另行研究物理玩法

本任务没有原型玩法实现授权，不能为填模板自行设计 Carrom 规则。未来需从真实模拟入口独立取得：固定/自适应 dt、补步上限/长帧策略、碰撞与触发器、进球与犯规计分、成功/失败、输入允许窗口、重开和浮点容差，并按固定初始状态与输入在快/慢帧复测。上述指标当前全部为**未证实**，比较体 +0x28/+0x30 也不能替代轨迹与物理步长证据。
