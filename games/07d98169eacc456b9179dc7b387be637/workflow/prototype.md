## 3. 可用模型与不能直接声称的最大值

设 A 为 +0x30 的 double（摘要关联 minPower 查询），B 为 +0x28 的 double（摘要关联 maxPower 查询），t 为钳制后的 d0，k 为 +0x174 的32位输入。定义 R 表示实际指令、精度、舍入和 FP 状态决定的计算结果，而非实数运算：

```text
t = clamp_as_implemented(input)
r = R(A + t * (B - A))
m = r
if compare_as_implemented(r, B) 表示相等:
    m = R(r + lookup_extra(k))
后续以 m 和角度相关值构造两个分量，写到目标 +0x50/+0x58
```

这只是摘要的可检验伪模型，不是恢复源码；没有补写 lookup 的越界默认值或假设额外兜底。

在有限实数、A≤B、t∈[0,1]的理想模型中，基础值介于 A 与 B；如 B>A 且算术精确，r=B 对应 t=1。但程序使用 double，不能直接把这些实数性质当作逐指令保证。

**结论：B 是摘要所述插值端点，不是已经证明的整条出杆链全局硬上限。** 若相等分支可达且查询返回正值 C，写入前标量可为 B+C；C<0 则可能降低；C=0 则无数值增益。摘要没有证明 C 的符号/大小，也没有给出追加后的再次钳制。该“没有给出”不等于完整程序一定不存在后续钳制、归一化或覆盖。当前不存在可报告的 minPower、maxPower、bonus 实测数字。

## 4. 浮点边界判断

1. **满杆不等于已证明触发。** 若用独立 double 减/乘/加，t=1 也未必得到 B。理论反例（不是竞品配置）：默认舍入到最近，A=2^54、B=1，则 B−A 舍入为 −2^54，最后 r=0≠B。该例违反通常的 min≤max 预期，但摘要没有证明该不变量。减法先舍入时，后续融合乘加也不能自动修复它。不能把反例当实际配置缺陷。
2. **未满杆也可能触发。** 理论反例：A=1、B=1+2^-52，t=0.75，r 会舍入到 B；A=B 且输入/中间值正常有限时，各 t 都可能得到 B。t 是 nextDown(1) 时也可能落到同一端点。故正确名称是“结果端点相等分支”，不是已经证明的“仅满杆分支”。
3. **越界输入可饱和。** 按摘要对普通有限数的钳制语义，input>1 与 input=1 给出相同 t；input<0 与 input=0 给出相同 t。只修改上游归一化 power 到大于1，不能借此越过插值端点饱和，但仍可能走 bonus 分支。
4. **特殊值不明。** 需要区分 `fmin/fmax` 与数值型变体、比较选择、实际分支条件与 FPCR。NaN 在有序相等语义下不相等，但未知条件码不能直接当作有序相等；±Infinity 也可能被输入钳制，或因配置端点产生 Inf−Inf/0×Inf→NaN。+0 和−0通常数值相等但位型不同。摘要不足以决定所有这些路径。
5. **融合与执行顺序重要。** `fsub; fmul; fadd` 与先 fsub 再 fmadd 的舍入点不同；不能用 JavaScript、十进制显示值或实数公式替代目标指令。需记录 double 原始64位、FPCR 舍入/非正规数处理，并验证中间值。
6. **误差不得改写业务条件。** 审查 r==B 分支时，不能用 |r−B|<epsilon 代替目标条件。复现分支应按目标比较语义一致；double 中间值按位核对（NaN另记类别/载荷）。三角函数输出可在确认数学库后制定 ULP 容差，但分支命中不得因输出容差被判“通过”。本轮没有可据以承诺的竞品物理轨迹误差。

## 5. Force 改造判断

“Force”没有唯一语义，本轮不要求澄清，按两种常见含义给出边界：

- **把上游 power 改得更大来获得更强出杆：** 摘要中的0–1钳制阻止普通有限输入直接扩大 t。因此“只把入参设成大于1即可无限增力”的解释不成立；这不否定 B 或 bonus 自身变化的效果。
- **在自有/获授权实现中增加独立力度参数或覆盖最终标量/向量：** 数值结构支持设计候选。例如在端点插值和 bonus 之后、方向分解之前，引入明确定义的 m_override；或将端点/bonus配置参数化。但这只表明算法上有可插入边界，**不证明目标二进制可安全 patch，不证明现有字段的单位就是 Force**。

如要改造，应先确认 +0x50/+0x58 的消费者：直接设置速度、施加冲量、每帧力累积或只是命令缓存的区别会影响质量、dt与效果。必须定位唯一提交 owner，验证对象生命周期、后续覆盖、合法出杆状态、协议/权威端校验和回放一致性。未经签名与地址基准核验，不给 patch 字节、运行地址或 hook 成功承诺。

修改 A/B 会同时改变整条曲线及“r==B”命中集合；修改输入 t 的钳制会改变合法范围；修改 bonus 参数会改变端点附加效果。三者不是等价的 Force 改造，也不能由本摘要推定玩法平衡或碰撞安全性。本轮无改动、无联网操作、无在线作弊验证。

### V-03 +0x174 是否装备等级

受控对照：同一装备ID改变等级；相同显示等级更换装备ID；尽可能固定品质/其他强化条件；重复重启和切换出杆模式。记录实际装备状态、+0x174原始32位、派生索引、选中记录ID、double返回值。无法独立控制变量时显式登记混杂因素。

通过条件：UI等级变化与字段变化的可重复对应，加上写入数据流和所选记录键的证据，才能命名为“等级”。若随装备ID变化而非等级变化，则否定纯等级解释，改查ID/索引映射。单次相关性不足以证明身份。
