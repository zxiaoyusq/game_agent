# Carrom 本地 GameSnacks 无广告标记行为复核

## 范围与结论

本轮为原型阶段的只读审查，不制作新游戏、不修改源码、不执行 SDK 或浏览器，不推进美术、代码或测试阶段。当前本机 SDK 摘录与页面标签以用户任务文本为主要证据；旧 ZIP 只作为历史背景。除本报告与逐字节提取的研究副本外，没有实施代码变更。

在用户给定的初始化条件下，H=false、G=false。所示 break 方法仍先调用 postMessageHandler.send({messageType:'AD_BREAK'})，但 reward 和 next 均不会通过后续两个分支进入 window.adsbygoogle.push(t)。该方法没有在这两个门控均不通过时调用 beforeReward、beforeAd、afterAd、adViewed、adDismissed 或 adBreakDone 的代码。因此不能期待此分支主动报告 unavailable 或自动结束请求。此结论限定于给定实现；不能扩展为所有运行路径永远无回调、整个页面无广告，或 AHA 宿主也有同样行为。

## 当前摘录的准确语义

| 项目 | 可确认的行为 | 不能据此确认的行为 |
|---|---|---|
| 属性解析 | 按 hasAttribute 判断存在性；两属性缺失则 H/G=false | 属性字符串写成 false 不等于禁用；仍存在即为 true |
| reward | H=false 时不执行所示 reward push | 不能保证任何其他广告所有者、包装器或宿主也禁用激励 |
| next | G=false 时不执行所示插屏 push | 不能保证外层字符串 next 路径不请求广告 |
| AD_BREAK | send 方法仍先被调用；消息仅有 messageType，没有 t 的类型与回调 | 调用 send 不等于消息已送达、宿主已展示广告或已回调 |
| 回调 | 所示方法在门控拒绝时没有直接调用广告回调 | 无法由短摘录排除其他监听器或后续包装器调用回调 |
| 返回 | 所示函数没有显式返回结果，正常走完为 undefined | undefined 不是已展示、已失败或奖励完成证明 |

以上假定执行到 break 且前置 send 没有抛错。nonce 与 data-user-activity-metrics 不是这两个商业化开关。旧 SDK 中 activity 属性控制用户活动监听，不能代替 H/G。Pn.ga 在初始化时读取属性形成对象；若初始化后才改 DOM 标签，不能假定已有实例会重新解析。初始化前改写、重新加载 SDK、直接修改实例或覆盖方法则须另行取证。

旧 SDK 的 it 构造器还在 H||G 为真时才 push 预加载配置，并在 SET_AUDIO 时按同一条件 push 声音配置。因此在旧实现与当前保持一致的前提下，两开关均 false 也跳过这些准备入队；用户只提供当前 break/解析摘录，当前构造器是否相同仍待证。开关为 true 也仅允许入队，不代表 SDK 已加载、库存可用或展示成功。

## 用户 1.5 秒观察如何解释

E-03 与 E-01/E-02 的门控静默跳过相容，但不是独立因果证明。观察窗口只支持“该测试条件下 1.5 秒内未观察到所记录回调”，不支持“永远不会回调”或“平台规定 1.5 秒超时”。拦截广告 SDK 本身也可能造成外层无回调，必须记录究竟拦截了父页 h5sdk、子页广告消费者还是二者，以及调用的是 GameSnacks.ad.break、h5sdk.adBreak 还是 postMessage 字符串。不能把三种入口混为同一次链路。

## 历史运行链与当前可核查位置

### 内层 GameSnacks

旧 game.html 先载入 local-save.js，再载入无两项商业化属性的 developer_v2.js，然后安装本地存档，最后载入 Pixi、Planck 与 game.js。它不是本轮新建的原生 Web 工程，不按框架默认要求改造它。

旧 SDK 未提供 data-target-origin 时选择 Jt 空 send/u 实现；因此即使 break 调用了 send，旧配置的 AD_BREAK 也不实际跨帧发送。当前任务只提供部分标签与 SDK 摘录，此历史细节不能替代当前实现核查。旧 SDK 的 gameOver/levelComplete 另有直接 window.parent.postMessage('next','*')，发生在 L/M 的自动商业化门控之外。

### 激励准备与消费

E-08 第 2683–2716 行：_0x2e33a4 发起准备请求，beforeReward 才保存展示函数到 _0x420004 并将 _0xcd5b2f 置 true；初值分别为 null/false（549–550 行）。_0x4d02b5 在没有展示函数时直接返回，不调用传入业务回调；有函数才登记消费者并调用展示函数。adViewed 向消费者传 true，adDismissed 传 false，afterAd 恢复音频/ticker、重试准备并清消费者。不能用广告关闭代替观看完成。

无属性且实际使用此 SDK、无其他写入时，准备请求不会到达广告消费者，beforeReward 不会由所示路径触发，可用标志保持 false、展示函数保持 null。第 2237–2263、2856–2888 行中的额外激励按钮绑定受可用标志守卫；第 2061–2067 行也按该标志调整大厅奖励标记。大厅还存在直接调用 _0x4d02b5 的 ad 事件（1694–1697 行），不能概括为所有入口必然隐藏；若该事件仍可触发，null 展示函数会导致直接返回。

第 4783–4785 行在对局更新分支内以计数递减重试准备，初始化重置为 60*20；这是代码计数，不可未经 ticker 时间语义核对就称为固定 20 秒定时器。

### 普通开局与基础奖励

第 2455–2463 行选择桌台后保存、调用 _0x248455，随后直接调用 _0x3153fe，未将开局放入广告完成回调。第 2662–2681 行 _0x248455 只在 beforeAd 中停 ticker/静音，在 adBreakDone 中恢复并调用可选续接函数；当前这个开局调用没有传续接函数。因此门控导致既无 beforeAd 也无 adBreakDone，不会仅因这对回调缺失而停住此开局链。若其他实现已触发 beforeAd 后失联，则是另一类恢复缺陷，不能沿用此结论。

第 2798–2811 行结算有一次提交守卫，SDK 通知异常被捕获；第 2854–2855 行胜利基础金币直接增加并保存，额外激励加奖另受可用标志和成功布尔值约束。历史代码支持“基础对局与基础奖励不以广告成功为前提”的静态判断；没有独立证明当前本机完整一局可玩。

### 外层页面

E-07 独立加载远端 h5sdk，初始化后可请求 preroll；监听字符串 next/reward 后直接调用 h5sdk.adBreak，另有 Banner 请求。这些调用不读取子页 H/G。AD_BREAK 对象也不等于字符串 next/reward。外层 reward 的 adBreakDone 将 viewed/dismissed/其他状态映射为 rewardSuccess/rewardDismissed/rewardFailed，但 E-08 搜索未找到明文 rewardSuccess 消费者；混淆存在，不能因此断言所有动态监听均不存在。至少当前读取证据未闭合“外层返回消息→内层激励消费者”的链。

因此无属性只能约束所示内层 push 路径，不能称为整页无广告配置，更不能推出已接入或已禁用 AHA 广告。远端 h5sdk 源码未取得、未下载、未执行。

## 普通对局、离线与玩法边界

保留现有观察→瞄准/施力→碰撞运动→回合判定→结算/再开循环与现有界面，不新增菜单、奖励或规则。游戏面向玩家默认英文，本轮没有编辑任何文案。旧页面为外层 iframe 加底部 Banner 占位，内层为 Pixi 表现与 Planck 物理。

广告开关不直接修改物理步长、碰撞体、计分、成功失败、输入窗口或物理误差。上述参数在本轮无修改需求，不另造数值；当前本机参数与完整规则未提供，未声明已经核验。物理、碰撞、计分和操控验收均不属于本轮 SDK 只读复核结果。

“无广告”“离线可玩”“离线可持久化”是三件事。旧 local-save.js 在 SDK 无 channel、无 gameData、可访问先行捕获的原生存储等条件下提供本地存档；不能推出当前版本相同。旧包可见本地玩法资产和独立开局链，但外层仍加载远端 SDK且直接访问 h5sdk，未证断网冷启动、资源完整性、存档写失败反馈与完整对局。网页已打开后能继续也不等于清缓存断网冷启动可玩。

## 无需猜测供应商合同的修复建议（仅建议，未实施）

1. 在业务层显式维护“本渠道广告禁用/不可用”配置：自动插屏跳过后继续原业务；激励隐藏或禁用入口，主动点击时给出可关闭的英文不可用反馈，不伪造观看完成、不发额外奖励。此策略可由产品定义，无需猜测 SDK 是否会补回调。
2. 将普通开局、基础奖励和再开一局从广告完成条件中解耦；只在已实际获得广告暂停原因后释放该原因，避免无广告路径依赖一个不会到来的 adBreakDone。保留用户暂停、后台等其他暂停原因。
3. 对业务等待建立请求身份、一次终态、离场清理及迟到结果拒收。应用可为尚未展示的无响应请求制定本地超时并恢复入口，但超时不是 SDK 状态，更不是观看成功；展示后的失联策略及回调顺序须核对真实合同。不得将用户 1.5 秒观察直接用作生产超时。
4. 父子消息增加明确 origin/source 校验、允许列表与请求关联；错误/缺 SDK 时给业务明确不可用终态。消息格式由双方应用约定，不能称为 GameSnacks/AHA 既定协议。
5. 移除或隔离“SDK 缺失时用 fallback 直接调用 adViewed”的历史模拟奖励路径。E-08 第 11380–11415 行 fallback 含此逻辑，且初始化采用已有 GameSnacks 或 fallback（此前读取的初始化段）；有对象时不自动替换，部分对象损坏时也不会可靠补齐。关闭广告与移除 SDK 不是同一变更，不应靠删除 SDK 获得无广告版本。

不能当作确定修复：盲目补两个属性、把属性值写 false、伪调 adBreakDone/adViewed、猜测 h5sdk 与 GameSnacks 合同相同、给 AHA 套用当前门控、宣称父页已自动改写子页。开启广告需当前配置与合同；这些措施本轮均未实施。
