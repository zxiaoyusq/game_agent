## 2. 一句话玩法与核心循环

观察星星 → 点击或触摸命中 → 计数加一 → 星星出现在新位置并轻微缩放 → 再次寻找和点击；第五次有效命中显示胜利，点击“重开”回到零次。

无跨局成长、关卡选择或奖励系统。打开页面直接开局，不增加开始页。单局目标约 5–15 秒，仅为体验预期，待真实试玩核验，不作为限时规则。

## 3. 规则、状态与边界

### 最小规则状态

- `phase`：`playing` 或 `won`。
- `count`：整数 0–5。
- `targetIndex`：0–4，决定星星中心位置。
- `roundId`：重开时递增，使旧输入和动画回调失效；无需跨会话保存。
- 配置常量：`goal=5`、五个归一化位置、命中半径。
- 表现状态独立保存：缩放动画起点和进度、当前布局、活动指针、短暂输入锁。动画不是计数或胜利状态的唯一来源。

### 位置与命中

首版不引入随机数。按可用游戏区域的归一化坐标固定出现：

| 当前计数 | 星星中心 (x, y) |
| --- | --- |
| 0 | (0.50, 0.50) |
| 1 | (0.24, 0.28) |
| 2 | (0.76, 0.70) |
| 3 | (0.24, 0.72) |
| 4 | (0.76, 0.28) |

归一化坐标仅对应 Canvas 游戏区域，不包含标题、计数或按钮。中心须处于至少 40 CSS px 的安全内边距内；窄屏时通过安全范围映射，而非裁切星星。重开回到首个位置。

星星基础图形约 56×56 CSS px，稳定圆形命中区半径 32 CSS px（直径 64），不随缩放动画变化。页面最低验收宽度为 320 CSS px。相邻位置需真实不同，不能靠缩放在原位置冒充移动。

### 状态转移

| 当前状态与动作 | 状态结果 | 反馈 |
| --- | --- | --- |
| 首次打开，无有效存档 | playing，count=0，targetIndex=0 | 显示星星、0 / 5 和简短玩法说明 |
| playing，命中，count<4 | count 加一，targetIndex=count | 即时更新计数，星星移到下一个位置并播放入场缩放 |
| playing，命中，count=4 | won，count=5，targetIndex=4 | 显示“采集完成！”与 5 / 5，停止接受采集输入 |
| 点击空白、取消指针、动画锁内点击 | 不变 | 不扣分、不重开、不排队补点 |
| won，再点击星星或空白 | 不变 | 保持胜利，无重复结算 |
| 任意阶段点击“重开” | playing，count=0，targetIndex=0，roundId 加一 | 清除旧动画/指针状态，恢复首个星星 |
| 调整窗口或切换屏幕方向 | 规则状态不变 | 重新布局和绘制，命中区保持对齐 |

成功条件为恰好累计五次有效命中。没有失败条件、倒计时、生命或步数限制。无效点击不能改变计数。

不变量：`0 <= count <= 5`；`phase=won` 当且仅当 `count=5`；游戏中 `targetIndex=count`，胜利后固定为 4；每个完整指针动作最多提交一次采集；重开后旧局事件不可影响新局。

## 4. 输入、动画与生命周期

- 统一使用 Pointer Events 支持鼠标和触摸，不叠加 touch/click 造成双计数。
- 仅接受主指针及鼠标主键；一次 pointerdown/pointerup 成对且都命中同一个目标才采集。pointercancel、明显拖出或跨局释放均取消；多指中的其他指针忽略。
- 指针坐标先通过 Canvas 的 bounding rect 转换到逻辑坐标。设备像素比仅影响绘制清晰度，不影响 CSS 命中尺寸。
- 每次星星出现用约 160 ms 缩放：0.90 → 1.06 → 1.00，不漂移、不闪烁，不添加粒子或复杂装饰。动画期间短暂锁定采集输入，重开始终可用；输入不排队。等待动画结束后下一次点击才有效。
- 第五次采集即时结算，可保留星星做同规格轻微缩放；完成后不继续移动。
- 支持 prefers-reduced-motion：跳过缩放且不保留动画等待锁，规则保持一致。
- 页面隐藏时取消活动指针、停止动画推进，不增加计数。返回时清理过期锁并从已提交规则状态绘制，无离线收益或时间结算。
- “重开”为语义化 DOM 按钮，支持键盘焦点和 Enter/Space。说明与计数为 DOM 文本，计数/胜利提示使用状态播报；Canvas 不承担唯一文字信息来源。

### 最小保存与恢复

代码阶段要求包含存档与恢复，因此只保存本局必要状态，不扩展成长系统。使用版本化 localStorage 记录 `{version:1,count,targetIndex,phase}`，有效采集与重开后立即写入。刷新恢复有效进度，包括胜利状态；新开局位置序列固定，无需保存随机源。

读取时校验类型、版本和上述不变量；损坏、未知版本或越界数据重置为新局，并给出简短可见说明。不存储动画、指针或旧局回调。写入失败不阻止当前局继续玩，但持续显示“进度无法保存，刷新后可能丢失”；仅在后续真实写入成功时清除此提示。该持久化属于既定代码阶段要求，不增加用户账号、云端或跨设备同步。

## 5. 界面与视觉交接

- 单页居中布局，明亮近白背景（#F8FAFC），深色文字（#0F172A）。
- 上方：标题“星点采集”、说明“点击星星，采集 5 次即可获胜”、计数 `0 / 5`。
- 中间：唯一 Canvas 游戏区域，手机建议宽为可用宽度（两侧各 16 px），高约 360 px；桌面最大宽 480 px、高约 420 px。短屏允许正常页面滚动，不遮挡重开或挤压目标。
- 下方：始终可用的“重开”按钮，最小触控高度 44 CSS px；胜利提示占固定文本区域，避免出现后引起目标偏移。
- 星星为单个程序化五角 SVG，填充 #14B8A6，可用 #0F766E 细描边提高轮廓识别；透明背景，建议 viewBox="0 0 64 64"，禁止包含外链、脚本或外部字体。SVG 作为真实图像资源供 Canvas drawImage 使用，实际游戏渲染仍为 Canvas 2D，不称作纯 SVG 游戏。
- 无图片生成 API、外部字体、复杂装饰或音频。采用系统字体。资源不得依赖网络。
- 美术阶段须先 inspect_assets，再实际交接非空程序化资源或设计文件，并用 inspect_assets 返回的当前哈希填写 `workflow/art-manifest.json`。清单顶层 `mode=procedural`，每项 path、sha256、usage、source 为非空字符串；来源说明为本项目程序化绘制，不编造第三方授权。
- 建议下阶段输出：`public/assets/star.svg`、预览文件、`workflow/art.md`、`workflow/art-manifest.json`。这些是交接要求，当前尚未创建，不能当成已完成资源。

## 6. 首版范围与技术交接

只做一页、一个星星、五次点击胜利、计数、重开、短缩放、响应式输入与最小本局恢复。无需教程关、随机难度、关卡系统、积分排行、音效、AI 对手、联网服务、广告或账号。

原生 Canvas 2D + Web/H5；不加载 Cocos、不引入物理引擎。建议精简为独立规则模块、页面输入/渲染模块、SVG 资源以及少量构建和测试脚本。规则函数可以脱离 DOM 执行；渲染只读取已提交状态。资源加载失败须给出诊断与重试入口，不把空白游戏区视作成功。

后续固定命令与输出：
- `npm run build`：输出 `dist/index.html` 及其相对资源。
- `npm test`：真实规则与数据测试。
- `npm run check`：启动隔离端口的本地服务器，访问最终 dist，实际启动 Chromium 并执行桌面鼠标与手机触摸交互，结束时自动关闭服务器。
- 三项在代码阶段与测试阶段各自实际执行；恢复尝试也重新执行，不能引用旧通过日志。
- 构建只依赖包内相对路径，在 `/pipeline-star-check-20261109/` 等独立子路径验收；运行时无外部请求。
- `evidence/` 保存真实浏览器截图、正常速度动画连续帧或录像、执行结果和源码指纹；`releases/` 保存源码 ZIP 与试玩 ZIP。最终展开构建小于 10 MB。
- 最终 check 通过后不得重建或修改 dist。报告可以补写；测试阶段不得修改上游源码或美术，发现缺陷应返回代码阶段修复并重新验证。
