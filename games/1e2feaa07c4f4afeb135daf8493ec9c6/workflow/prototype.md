# Carrom 配置对象与解密路径交叉复核

## 范围与结论

本轮为原型阶段的只读原生证据研究，仅新增本报告；不制作游戏、不修改参考库或配置、不执行解密，不推进美术、代码与测试阶段。研究日期：2026-11-13。

结论：操作者提供的重定位关系与 AArch64 上常见 Itanium C++ ABI 的 PackageManager RTTI／虚表结构相容，但尚未验证虚表头、RTTI 的动态类型、对象构造写入及完整边界。操作者提供的静态 BL 链加强了配置加载候选与 decryptAES128 名称包装候选之间的关联，不能证明具体文件、特定输入或实际执行路径进入该链，更不能证明解密成功。

## 证据等级与来源

- A：本轮工具实际读取的归档文字与归档工具返回的条目元数据。读取旧分析记录属于独立读取记录，不等于独立复算其机器码结论。
- B：操作者本机新扫描摘要；本轮未独立执行扫描。
- C：基于 A/B 与 ABI 常规布局作出的条件性解释。
- D：尚待执行的验证方案。

## ABI 结构交叉复核（C）

### RTTI 候选

按常见 64 位 Itanium C++ ABI，`std::type_info` 派生对象通常以 RTTI 自身的 vptr 开头，下一机器字为类型名指针。若 `0x27eb9a0` 是该对象起点，则 `0x27eb9a8` 恰为 +8 的类型名指针槽。`14PackageManager` 与长度前缀为 14 的类名编码相容。

这不能单独证明该区域是 RTTI：仍须检查 `0x27eb9a0` 的重定位目标是否指向 `__class_type_info`、`__si_class_type_info` 或 `__vmi_class_type_info` 对应虚表地址点，并验证所在段、对齐、邻接内容与其他引用。若为普通 `__class_type_info`，常见基础布局为 16 字节；若为单继承类型描述，则还会有基类类型指针；多继承类型描述还涉及 flags、base_count 与基类数组。未确认类别前，不能断言 RTTI 对象止于 `0x27eb9b0`，也不能根据类名判断无继承。

### 虚表候选与地址点

如果 `0x27eb920` 是虚表的 typeinfo 指针槽，则常见布局推导如下；所有地址均为 ELF link VA，未加运行时 load bias。

|地址|条件性解释|现有证据|
|---|---|---|
|`0x27eb918`|地址点前 -16 的 offset-to-top|未提供原始有符号机器字，必须核验|
|`0x27eb920`|地址点前 -8 的 RTTI 指针|B：指向 `0x27eb9a0`|
|`0x27eb928`|候选虚表地址点，槽 0|未提供值；需构造／析构写入证明|
|`0x27eb930–0x27eb940`|候选槽 1–3|未知，不命名|
|`0x27eb948`|候选槽 4，地址点 +0x20|B：指向返回未知字符串的函数|
|`0x27eb950`|候选槽 5，地址点 +0x28|B：指向返回 `ValueMap.plist` 的函数|
|`0x27eb958`|候选槽 6，地址点 +0x30|B：指向返回 `GameConfiguration.plist` 的函数|

槽号仅在地址点确为 `0x27eb928` 且中间结构连续时成立。不能因前三个未知槽就自动标为析构函数；析构变体与调整 thunk 均须核验函数体和调用点。真实表前还可能有 vcall/vbase offsets，不能把 `0x27eb918` 固定视为整个虚表组起点。

若 offset-to-top 为 0，与完整对象中的主虚表相容，但不能单独排除构造虚表；若为负值，与非零偏移基类子对象的次虚表相容。构造阶段、虚继承及 thunk 的 this 调整需另行分析。

### “完整对象范围”必须区分三个对象

1. **RTTI 数据对象**：候选起点 `0x27eb9a0`，终点由 RTTI 类别和真实内容决定，目前未知。
2. **虚表／虚表组数据**：目前仅有分散槽值。即使 RTTI 候选位于 `0x27eb9a0`，也不能将两者之间的整个区间直接算为虚表，不能把 `0x27eb958` 当作最后一槽。需扫描前后结构、符号尺寸、重定位、其他 typeinfo 表头与全部代码引用，识别次虚表及相邻独立对象。
3. **运行时 PackageManager 完整实例**：虚表长度不等于实例大小。需结合构造函数的 vptr 写入、基类构造、this 调整、分配尺寸、成员访问最大偏移与析构过程求范围；分配可能包含派生类、数组、封装或自定义分配开销，单一分配值也不够。当前没有可靠的实例大小或完整对象首尾地址。

三个返回字符串函数若确为虚槽，只能支持“多态提供字符串／配置名称的接口候选”。尚不能据此认定该对象直接读取、解密或解析对应文件。

## 调用链、桥接入口与数据可达性

### 旧证据可支持的交叉检查（A）

E 的配置交叉引用记录给出：

- `0x1e418fc` 引用 `Configuration reload start`，所在 FDE 为 `[0x1e41898, 0x1e41b0c)`。
- `0x1e3f710` 引用 `GameConfiguration.plist`，FDE 为 `[0x1e3f710, 0x1e3f71c)`。旧证据只有字符串引用；“返回该字符串”来自 B。
- `0x2711cc4` 引用 `decryptAES128`，FDE 为 `[0x2711cb0, 0x2711cd4)`。这与短名称／分发包装候选相容，不能认定此 36 字节范围实现 AES。
- `$load_configuration` 在 `0x1c113b8` 的引用处于 `[0x1c112cc, 0x1c11440)`；`load_configuration` 在 `0x1e37314` 的引用处于 `[0x1e36818, 0x1e3b6d8)`；`downloadClientConfiguration` 另有候选引用。名称关联不能证明注册成功、回调目标或网络下载实际发生。

旧方法仅扫描 ADRP 后至多 8 条指令的 ADD 地址匹配，存在寄存器被改写的误报风险，且遗漏间接、literal load 等引用；FDE 是展开范围而非业务函数身份证明。

### 新 BL 链应如何解释（B/C）

`0x1e419e8` 落在上述 reload FDE 内，应先作为调用指令位置理解，不能直接称为函数入口。链中其余节点究竟是 BL 目标入口、调用点还是范围标签，需逐边输出实际 BL 指令地址、机器码、解码目标与所属基本块。不能把连续箭头替代完整调用图。

在操作者摘要成立的前提下，可报告“存在通向 `0x2711cb0` 及 `0x2711b58` 的静态直接调用候选路径”。其中 `0x1e40a34` 有条件跳转，因此不能声称每次 reload 都走完全链。还需证明每条调用所在基本块可达、分支条件可满足、各次调用正常返回，并检查异常、提前返回及尾调用。

`valueMap` 字面量不等同于 `ValueMap.plist` 文件路径，也不证明它与 PackageManager 对象中某个虚槽存在数据联系。json/plist 字符串不证明实际采用的格式、解析成功或加密方式。`decryptAES128` 名称与 BL 路径不确定 mode、padding、密钥、IV、输入或输出。

### 桥接可达性的三个缺口

1. **外部入口 → native 回调**：需要确认桥接机制、实际注册表、名称槽、回调地址与参数转换。当前不能指定为 JNI、Lua、JS 或其他机制。
2. **native 回调 → reload／PackageManager**：需要控制流、对象来源、vptr 与真实间接调用目标，不能用相邻表项代替调用证据。
3. **具体配置字节 → 候选处理链 → 返回使用者**：需要路径解析／读取返回值、缓冲区与长度的 def-use、每个分支以及最终解析／消费端。当前没有任一具体文件进入该链的完整证明。

## 可复核的动态观察方案（D，未执行）

前提：使用合法可调试的匹配构建及隔离测试数据；调试器设置观察点／断点会影响时序，应记录其方式，不宣称零扰动。禁止补丁、强改分支、修改寄存器或回写配置。

1. **地址基准**：记录设备、进程、模块 Build ID／SHA256、maps 与 PT_LOAD。结合映射文件偏移和段布局计算 load bias，再以 runtime VA = load bias + link VA 定位；不能直接把任意首个 maps 起点当 load bias。
2. **对象归属**：在候选构造与虚调用处观察实例地址、当前 vptr、slot 地址、实际函数目标和必要的 this 调整。用 offset-to-top 反推完整对象位置时标注构造期／子对象限制，并与分配和成员访问证据交叉检查。
3. **自然触发**：通过已有正常加载／重载操作触发入口，记录线程、调用栈、分支结果与事件序号。不要直接调用尚未确认签名的函数，也不要以强制调用证明正常入口可达。
4. **逐次关联**：关联外部入口、native 回调、reload、文件读取、候选处理函数和返回消费端；使用调用实例、父子事件、缓冲区生命周期与复制关系，不能只凭地址相同或时间接近关联。
5. **最小数据记录**：默认只记录路径来源、输入长度、输入／输出摘要、返回状态、解析状态、分支及模块偏移；未知 12 字节字符串不输出，密钥／IV／令牌／用户数据不采集或展示。若必须识别敏感参数，仅记录角色及来源位置，内容脱敏。
6. **对照样本**：分别观察 ValueMap 与 GameConfiguration 的正常加载、缓存命中和已有错误路径；不修改原始配置。若需要损坏／缺失输入实验，应另行获准使用隔离副本，不在本轮执行。重复自然触发，记录异步回调与条件分支差异。

确认“文件进入该链”的最低条件是：明确实际读取对象和字节摘要、跨复制／转换的数据关联、候选路径各实际调用及对应分支、返回值与使用者属于同一调用实例。确认“解密成功”还须识别实际算法路径、成功状态及输出格式／语义校验，并排除旁路明文、缓存或错误回退。只命中断点、输出可打印字符、解析器名称或名称为 decryptAES128 均不满足。
