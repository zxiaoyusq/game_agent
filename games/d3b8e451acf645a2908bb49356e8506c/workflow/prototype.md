## 已核实的初始化与调用链

1. index.html L51嵌入game.html；L65从外网加载adsdk，L76–102调用h5sdk初始化。该外层广告SDK与GameSnacks存储桥是不同路径，不能把h5sdk存在当作宿主存储已连接。
2. game.html L33先加载developer_v2.js，仅设置data-user-activity-metrics，没有data-target-origin，也没有rewarded/interstitial monetizable属性；L97–100依次加载Howler、PIXI、Planck、game.js。原工程使用PIXI/Planck，不是纯DOM实现；本轮不为框架标签重写现有游戏。
3. developer_v2.js L2的Pn.ba读取当前脚本data-target-origin；缺失时选Jt空消息处理器，channel保持null。L1的Gt创建storage=new Dt(channel)。L1的Dt先尝试hash的gameData，再尝试query，执行decodeURIComponent、atob、JSON.parse；L2的Cn.ea/da负责取参数。gameData是启动数据，不是浏览器持久存储。
4. Dt的外层解析有catch，但仅检查typeof n是否为object；null和数组仍可通过，内部七键也未验证。参数获取发生在try之前，URL解析错误不受该catch保护。Cn.da只接受列出的协议及有效hostname，因此不能承诺file://双击运行；建议用固定HTTP origin的本地静态服务。
5. developer_v2.js L1的Dt.prototype.getItem读取this.g；setItem在channel非空时发送消息，并更新this.g；无channel时仍更新内存。代码没有本地落盘，也没有持久化ACK。L2结尾通过Object.defineProperty(window,"localStorage",...)设置抛错getter，要求使用GameSnacks.storage。不能在SDK后直接访问window.localStorage，也不能宣称修改该属性可安全恢复原存储。
6. game.js L902–906为启动函数；资源加载注册在L1118–1119，完成回调L5513–5515进入_0x3690db；L1121–1125先调用_0x5ecd40读档，再创建界面和启动相关流程。读档异常因此可以中断后续初始化，这是静态控制流结论，尚未浏览器复现。
7. _0x5ecd40在game.js L1166–1174遍历七键，取值后对truthy原始值直接JSON解析，无逐键try/catch或结构校验。随后_0x13b722在L1175–1213把数据写入运行状态，直接使用数组length、索引和Number转换。坏JSON、null数组、超长数组、错误类型均有风险，合法JSON不等于合法用户数据。
8. _0x3a0318在L1239–1248先经_0x9b0cd（L1215–1237）收集运行状态，再逐键序列化并写SDK。没有事务、异常隔离、保存状态提示；中途失败可能留下混合版本。

## 最小改造与回滚方案（待主工作区实现）

### 路径隔离

采用独立离线入口和一个小型存档模块，避免修改压缩SDK。宿主入口保留原脚本属性、初始化顺序、GameSnacks.storage和消息协议；本地预览显式走离线入口，不以hostname、iframe存在或SDK超时判断模式。宿主连接失败只能提示并保留待保存状态，禁止偷偷转为本地权威存档，禁止自动把预览数据迁入宿主。

离线入口在developer_v2.js执行前用try/catch捕获浏览器原生Storage实例并封装于闭包，SDK加载后模块仍使用已捕获引用。捕获失败则降级内存并持续提示“Progress cannot be saved on this device.”。不暴露或替换全局localStorage，不使用新iframe绕过宿主限制。捕获逻辑只存在于明确的离线入口。

主工作区仅需：新增离线入口及存档模块；把game.js读档和保存两个边界接入模块；添加独立DOM状态提示。保留现有表现、输入、物理和资源。宿主适配器继续输出原七键JSON字符串；离线适配器使用独立命名空间carrom.offline.save.v1，绝不写无前缀七键或清空整个origin。

### 读取与损坏恢复

读取状态：loading → ready / recovered / volatile。所有路径先创建全新默认对象，只读取允许的七键；任何getItem、解析、结构与业务校验异常均不得阻断游戏初始化。先构造完整候选，再一次性应用到运行状态，避免半加载。

离线使用一个带version=1、revision、savedAt和data七键的JSON快照，另留一个上一份有效备份。主档有效则采用；主档无效且备份有效则恢复备份；均无效则使用默认并提示“Saved progress could not be loaded. Default progress is in use.”。未知版本拒绝自动覆盖，原文保留。读取恢复不立即写默认值覆盖坏档；仅后续真实用户提交且成功保存后建立新档。坏档证据只在容量允许时保存有界隔离副本，隔离失败不阻断启动，不无限累积原文。

宿主仍读取七键，不改宿主wire格式。逐键隔离语法错误，保留原始值和错误诊断；对tables、upgrades、strikers、stones作关联组校验，失败时整组回默认，避免索引/装备不一致；合法金币、教程、冷却可独立保留。缺键使用各自默认。禁止clear/remove或启动时把默认值回写到宿主。坏档回退只保证安全启动，不保证恢复已损坏的历史资产。

lastRewardTime在未来时保留原值，不将其变成0；剩余冷却限制为0至4小时并显示时间异常提示，防止负倒计时或立即重复奖励。离线墙钟可被玩家更改，本最小方案不提供反作弊，也不引入服务器。精确到4小时边界保持现有严格大于语义，测试覆盖边界前、等于和边界后。

### 写入失败语义

状态：clean → dirty → saving → clean / error。业务提交先更新内存并生成完整候选；写失败保留当前会话进度和dirty快照，不回滚已展示奖励，不自动重复业务事件。持续显示“Progress is not saved. Keep this page open and retry.”及“Retry”；仅最新revision真正写成功才能清除错误，旧重试不能覆盖新快照。关闭后可能丢失未保存进度，不能显示已保存。

离线提交：序列化和完整校验 → 若当前主档有效，将它写入备份 → setItem一次写入完整新主档 → 读取核对版本/revision及内容。备份或主写失败停止并保留旧主档，不删档腾空间。首次保存无有效旧主档时可直接提交。不要备份损坏主档覆盖有效备份。读取核对只能证明当前浏览器Storage可读回，不能承诺磁盘断电持久性。

宿主setItem无ACK；无抛错只记为“已提交SDK”，不得记为“宿主已持久化”。逐键写任一失败保留dirty、记录失败键、提供重试；允许相同值重复提交，但不重复发奖。七键跨键原子性在现协议下无法保证，真实宿主重启后恢复需单独验收；若必须保证事务，需另行确认宿主支持的快照/ACK协议，不在本轮伪造。

同origin多标签并发不承诺合并；最小实现检测storage事件及revision冲突，提示另一页面更新并暂停覆盖，要求重新加载后再提交。快照与备份不是防篡改机制。

### 广告与回滚

index.html L104–139监听外层消息，L127–135按breakStatus发送rewardSuccess/rewardDismissed/rewardFailed；未校验source/origin。game.js全文字面检索rewardSuccess无命中，仅此不能证明所有混淆动态监听均不存在。已读game.js L2666–2699使用GameSnacks的beforeReward/adViewed/adDismissed及回调；L2229、L2843–2845仅在回调真值时加额外奖励。developer_v2.js L1的ad.break还受脚本monetizable属性控制，而当前game.html未设置这些属性。两套广告路径不能视为已连通，未加载外部SDK不等于广告成功。

离线入口不加载外部广告SDK、不生成viewed、不调用成功奖励回调；广告按钮显示“Ads unavailable offline”，基础转盘或胜利奖励保持原有规则。宿主广告路径保持原协议，本次存档补丁不扩充广告桥。消息来源校验和请求去重作为宿主接入核验项，若需改协议另行实施。模拟回调只能用于负向/去重测试，必须标注模拟，不能作为真实广告验收。

回滚按独立提交移除离线入口/模块并恢复两个接入边界；SDK和参考包始终未改。本地命名空间存档留存，回滚不清用户数据。无自动迁移、无宿主数据覆盖，复原旧代码也不会把离线数据当宿主数据。

## 玩法、界面和回归边界

保留既有循环：大厅选模式/桌台 → 扣入场费 → 瞄准击球 → 运动碰撞/入袋与轮次切换 → 原规则判胜负 → 基础结算 → 返回/再来一局。跨局只持久化七键；不增加中途棋盘续局，不存物体速度、计时器、PIXI节点、广告回调或随机状态。游戏默认英文；新增状态提示使用英文，主工作区离线页面设置lang=en。原入口未显式设置lang，本轮未修改。

game.js L5491–5492可见固定参数1/60及10、10的物理调用和清力；L5500–5504通过累积ticker delta逐次逻辑更新，没有在该处看到长帧补步上限。L5516–5529显示输入受广告/行动/暂停/局生命周期标志约束。碰撞和各模式细分计分、胜负本轮未完整审计，明确保留原逻辑，不编造新规则或数值。

建议回归条件：同一基线输入、随机种子和1/60步序列下，补丁前后入袋数量、回合与计分、胜负完全相同；物体终点差≤1游戏像素作为待试玩校准的建议容差，非原工程已有承诺。快慢帧30/60/120Hz和长帧恢复不新增击球、奖励或存档事件；不在后台补算棋盘物理。广告中、物体运动中、暂停和结算后输入继续按原门控拒绝。存储耗时不得进入物理循环。

界面沿用现有大厅金币、商城、转盘冷却、结算布局；新增DOM保存状态位于安全区，不遮挡击球、暂停或主要按钮，桌面/手机均可读并提供aria-live。仅失败和恢复显示持久提示，正常保存不弹阻断弹窗。
