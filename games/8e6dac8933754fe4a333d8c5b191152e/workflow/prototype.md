## 新增事件候选与接入边界【产品建议，尚未实现】

这些是供后续实现选择的领域事件，不是竞品任务池，也不表示每个事件都必须配置任务。

| 事件 | 事实提交点与最小载荷 | 待验证项 |
| --- | --- | --- |

| shot_committed | 合法释放实际发射后；matchId、shotId、actor | 低力度取消、重复指针、超时不得算有效击球 |

## 装备首次解锁判定【产品建议】

以 category+itemId 标识资产，所有权为 owned=true 或参考状态属于 unlocked/equiped。只有提交前未拥有、提交后拥有才形成一次 acquisitionId。已有资产切换、自动装备、读档重建与 UI 重绘均不生成首次获取事件。默认自带装备不产生新购事件。

迁移旧档时将已有装备设为迁移基线，不补发历史首次解锁；这是建议，是否允许历史拥有量满足任务需产品另行确定。不要用装备当前状态 unlocked 作为“刚刚解锁”的充分条件。是否把首次解锁定义为竞品“配备球”任务规则仍待直接证据；White 摘要不足以确认该语义。

## 任务循环、状态与界面【产品建议】

循环：查看目标 → 产生合法游戏/装备事实 → 更新进度 → 达标后可领取 → 持久化奖励与任务结果 → 显示后续目标（仅当存在已确认替换配置）。任务状态为 locked/active/ready/claimed；没有证据支持新增倒计时失败或周期失效。进度使用非负安全整数并封顶，完成和领取分别处理。

桌面与手机共用 DOM 任务面板：顶部钱包与任务积分，中央任务目标/进度/独立奖励字段，底部 Claim 和可用性说明；领取中禁用重复输入并保持错误可见。默认玩家文案使用英文：Missions、Reach Level 3、Claim、Claimed、Save failed. Try again.、Unavailable offline。+100 CP 在未定义前只作为待确认字段，不自作解释或投入经济结算。此处未制作界面或素材。

取舍：保留任务完成与领取分离、购买与换装分离；改造参考逐字段存档和依赖动画计分的提交方式；延后无依据的任务池、刷新周期、广告接入与 CP 经济系统。

## 领奖幂等与离线持久化【产品建议】

建议一个带 schemaVersion、revision 的小型离线存档封装，覆盖 wallet、equipment、任务实例状态、必要累计值和去重水位；当前实际存档没有这些保证。任务实例 ID 不复用，奖励金额与配置版本在生成实例时冻结，领取不得相信 UI 传入的金额。

领取由串行命令处理：校验实例存在且 ready、核对未领取 → 在候选快照中同时增加金币/任务积分/已确认的其他资源，标记 claimed 并记录替换结果 → 一次提交同一快照 → 提交成功后替换内存状态和播放反馈。重复 instanceId 返回已提交结果，不再次加币。写失败保留可重试状态与持续可见错误，禁止先展示领取成功。替换必须具备明确配置；缺少配置时保留 claimed，不能自行抽造任务。

可优先评估单键快照方案以降低成本；单键写并不保证任意宿主的持久性，也不解决跨标签页读改写竞争。若支持多标签页，必须有可靠互斥/事务，或明确限制为单一活动写入端；仅 revision 字段不能充当原子比较交换。需验证存储 API 的失败、重启恢复及宿主确认语义；若现有宿主无可靠落盘接口，独立离线版可另选原生存储适配，不能继续把内存 storage 当成功持久化。

加载先捕获解析错误、校验类型/长度/ID/余额/非负安全整数/装备唯一选择，再迁移；未知未来版本不直接覆盖。奖励、钱包与领取标记不得拆键提交。正常进度、购买、升级和结算在事实边界持久化，禁止每帧或每次碰撞写档。去重按顺序号水位、任务实例状态和有界必要记录设计，不能无限积累事件日志，也不能随意裁掉仍可能重放的记录。

纯离线方案不能承诺防玩家改档、回滚旧快照或跨设备同步；本轮目标是正常使用下避免重复提交和部分写入。

## 物理与输入复核边界

【静态推论】game.js _0x49d791 调用 Planck world.step(1/60,10,10) 并清理力；_0x4bf21a 将 ticker 增量累加，while(accumulator>1) 执行逻辑步。已读此循环未见最大补步数，暂停、长帧的实际行为尚未验证。碰撞监听用于碰撞反馈，入袋按到四角中心距离 ≤20 的几何检查处理；输入 _0x36ab44 受玩家回合/可操作/拖拽标记限制，_0x1e39ba 仅力度 ≥0.25 时发射，_0x536112 将拖拽距离封顶后归一化。

【静态推论】_0xbdafb3 在物体静止后处理回合。普通模式存在双方 9 枚得分及红球相关终局判断；模式索引 2 使用目标分数，初始目标变量为 160。不同分支、犯规与动画计分交错，不能将这些概括为已验证的完整规则。

【产品建议】本次任务扩展不改变物理步长、碰撞体、胜负、计分或输入窗口；物理补步优化若需要应单独评审。任务整数进度、资产所有权与奖励到账允许误差为 0；不得用物理位置容差放宽奖励验收。后续同引擎同初态固定输入回归可暂用静止位置差 ≤1 逻辑像素、时间差 ≤1 个 1/60 秒步作为比较目标，入袋临界样例单列，不承诺跨浏览器位级相同；该建议阈值未经测量，超出时先分析而非悄悄改规则。

## 轻量预算【产品建议，非实测】

- 不新增运行时依赖、引擎、位图或字体；复用已有视觉只表示设计方向，不宣称授权已核实。界面采用 DOM 与现有图标候选。
- 任务逻辑、存储适配与 UI 新增部署字节暂定 ≤50 KiB（未压缩，不含开发测试）；新增快照 UTF-8 序列化体积 ≤16 KiB；新增长期内存目标 ≤128 KiB。实际以实现后测量决定是否达标。
- 单领域事件处理 CPU 的 P95 目标 ≤1 ms；单次序列化及写入主线程时间目标 ≤4 ms，必须注明测试设备和采样方法。超预算时优先减少提交次数/数据体积，不能牺牲领奖一致性。
- 事件按类型索引消费者，复杂度随相关活动任务数增长；每帧扫描与每碰撞写档预算为 0。任务展示数量由真实配置决定，本轮不设虚构任务池。
- 最终 dist 展开 <10 MB 为后续交付门槛；当前 ZIP 展开约 5.07 MB 不能证明最终构建已达标。
