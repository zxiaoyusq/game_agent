## 核心结论

1. 玩家定位条拖动时直接更新母球位置，允许暂时重叠；检测命中时设置母球 alpha=0.7 并显示 overlay，未命中恢复 alpha=1 并隐藏 overlay（L1585–1597）。
2. 松开定位条调用 `_0x41684e`，沿基线以 2 个游戏坐标单位的增量，先右后左搜索空位，找到后同时更新母球、定位条和提示（L1599–1601、L3611–3654）。因此代码意图更接近“拖动提示、松手自动避让”。
3. 已读玩家瞄准、释放和母球发射函数中未见重叠复检。不能据此声称正常操作已实测能从重叠位置出杆，也不能声称“重叠必定禁止出杆”。全线占用、同时拖拽与瞄准、回合动画中输入等路径需要真实复现。
4. AI 在候选生成时过滤重叠，失败时另走随机位置寻位；AI 与玩家并非共享一套输入和最终提交检查。

## 玩家定位条坐标映射

定位条构造函数 `_0x1bb809`，类变量 `_0x570109`（L10858–10970）：

- 滑块局部 x 最小值 `0x1e=30`，最大值 `0x1ae=430`，初始值 230（L10860–10876）。
- 拖动开始方法键 `0x219`：检查 `_enable` 对应索引 `0x3f5` 与滑动标志 `0x47d`，保存 `global.x - _0x24b13c/2` 和原滑块 x（L10917–10924）。
- 移动方法键 `0x3db`：`sliderX = originalSliderX + (currentGlobalX - _0x24b13c/2 - initialPointerX)`，再夹取到 [30,430] 并发出 update 对应事件（L10933–10950）。本质为相对拖拽，不是点到哪里立即跳到哪里。
- `value=(sliderX-30)/400`；setter 为 `sliderX=30+400*value`，setter 自身没有夹取、没有发 update（L10952–10965）。
- 实例布局 x=85，y=1024，加入对局容器（L1581–1584）。该坐标是游戏局部坐标，不能直接当作 CSS 像素。
- update 监听检查 `_0x55e693 && _0x209883`，然后 `worldX=162+321*value`，`worldY=828`（L1585–1597；常量 L849–850）。端点分别为 x=162、483，中点 x=322.5。回合重置中心为 x=320，因此滑条 value=0.5 与母球中心存在 2.5 单位差异，不能把它误报成完全同步。
- worldX/worldY setter 将坐标除以 100 写入物理 body，清线速度并同步显示位置（L10720–10749）；显示更新以物理位置乘 100（L10689–10694）。

输入窗口：定位条 setEnable 仅改变 `_enable` 和透明度（L10906–10915）；start/move/stop 都据 enable 判断。stopSlide 只有启用且处于滑动时才清滑动标志并发 stop（L10926–10931）。构造器绑定四类指针事件（L10881–10895），其中索引 0x39c 与 stage 释放监听共用，0x2ea 是另一释放相关事件，具体字符串未执行解码确认。未见 pointer ID 绑定或显式取消处理，跨回合遗留滑动应测试。

`_0x23a7dc(position, threshold)`（L4652–4659）拼接 `_0x2a9c75.concat(_0x3e4566,_0x3231b3)`，对每项调用 `_0x2bd695`，距离严格小于阈值即返回 true，否则 false。它不检查颜色、类型、单项半径、传感器或 active 标志。初始化中这些数组分别接入对手棋子、玩家棋子、特殊棋子（L2971–3005）；所以不是仅对白子检查。是否已入袋/销毁的对象及时移出数组，需要额外核查，不能假定。

`_0x2bd695`（L5846–5852）计算 dx、dy 后调用 Math 的混淆方法处理 dx²+dy²，按几何调用上下文为欧氏距离；Math 方法名尚未通过解码运行确认。`_0x57abb1`（L5686–5698）虽有单项 radius 与状态过滤，但本轮对其名称的全文搜索只返回定义，不能用它替代实际摆位检测依据。

重要数值差异：规则认为距离 >=36.76 不重叠，而物理圆半径和为 37.76，形成宽 1 单位的判定差异区间 [36.76,37.76)。这是代码数值事实及静态风险，尚未验证是否表现为挤压、跳动或可感知问题。规则中没有显式 epsilon，恰好等于 36.76 时严格比较返回不重叠。贴图尺寸、透明边缘和实际光效颜色未观察，物理圆不能等同于可见图案轮廓。

## 松手自动寻位与边界

`_0x41684e`（L3611–3654）：只有当前位置重叠才搜索。偏移 i=0,2,…,320，每次先检查 x+i<483，再检查 x-i>162；找到第一个空位便写 worldX、回算 value、恢复 alpha=1、隐藏 overlay 并 return。

静态边界：

- 搜索候选排除精确端点 162、483，尽管拖动夹取允许端点。只有端点合法时可能找不到。
- 2 单位离散采样可能遗漏窄于步距或不落在采样格点的合法间隙；同偏移优先向右，不是连续空间中的严格最近解。
- 全部候选失败时直接结束，无返回失败标志、无禁射状态、无替代位置或可见错误分支。
- 当前已不重叠时不主动刷新 overlay/alpha；若提示因其他事件滞留，本函数不会统一修正。
- 松开定位条与回合入场动画完成时都会调用本函数（L1601、L3603–3605）。

以上属于静态风险，不是已复现缺陷。

## 出杆入口与限制

母球 pointerdown 绑定 `_0x36ab44`（L1556–1562）；stage 绑定移动 `_0x536112` 和释放 `_0x1e39ba`（L1732–1746）。

- `_0x36ab44`（L3655–3666）拒绝教程摆位步骤、非允许操作/非玩家回合、已经瞄准的情况；否则设置 `_0xf86500=true`，显示瞄准器并清力度。没有调用 `_0x23a7dc`，也没有读取 overlay、alpha 或滑动标志。
- `_0x536112`（L3682–3695）只有瞄准标志为真才处理；将 global 坐标减容器居中偏移，计算方向与拖距，将拖距上限夹到 `_0x647bf3`，力度为距离/上限。上限初始 150（L856），新局按 `75+25*_0x2799f0` 更新（L1762），因此不能固定说最低拖距永远为 37.5。
- `_0x1e39ba`（L3667–3680）只先检查瞄准标志，随后清标志、隐藏瞄准器；力度 >=0.25 才发射，力度为 `strength*100*1.25`，调用清理并在 2300ms 延迟后检测结算。没有在释放时重新检查回合许可或重叠。低力度只取消瞄准，没有走本段发射清理。
- 母球方法键 `0x1cd`（L10674–10687）：隐藏 light，将 sensor 关掉，建立方向速度/冲量向量，唤醒 body，再调用物理方法 `0x311`。该方法自身也没有摆位合法性检查。没有执行解码确认该方法究竟为速度设定还是冲量 API，因此不将其单位误写成已确认的初速度。

结论边界：这些代码足以说明“所读最终发射链路缺少显式重叠门禁”，不足以证明某个正常手势一定绕过松手寻位。事件传播顺序、多指输入、动画和全占用场景尚未运行。

## 玩家、AI 与重置差异

玩家回合 `_0x5e7a5f`（L3568–3610）设操作及玩家标志为 true、启用滑条、value=0.5、显示母球并清 overlay、开启 sensor；母球从 (320,1028) 动画到 (320,828)，动画完成调用寻位并显示 light。允许标志在动画前置位，开始瞄准函数未检查入场动画，因此动画期间输入要实测。

AI 回合 `_0x50a0ff`（L3485–3567）关闭玩家标志、禁用滑条、清 overlay、开启 sensor，从 (320,221) 动画到 (320,421)。421 来自 L848 的表达式。它生成四角候选并排序，无候选转 `_0x3d12d7`。已读四路候选片段均检查摆位重叠：L3902–3909、L4113–4120、L4317–4322、L4513–4518；路径阻挡检测另走 `_0x3ea989`，不能混为摆位检测。

随机兜底 `_0x3d12d7`（L3796–3842）在 [162,483) 取随机 x，y=421，重叠则同样按 2 单位先右后左搜索；找不到仍返回原 pos，没有失败结果。

AI `_0xd6b627`（L3697–3712）先设置 worldY、调用 `_0x4662ac`，随即 return，后续直接发射代码不可达，不能当实际路径。`_0x4662ac`（L3713–3748）改变显示 x 模拟来回摆位；最终 `_0x4b3cc6`（L3782–3794）把候选 pos 写回 worldX/worldY 后发射，没有最终重叠复检。显示 x 动画阶段与物理 body 同步策略不同于玩家 worldX setter，不应合并描述。

发射清理 `_0x24bb4a`（L3039–3050）清瞄准标志、隐藏瞄准器、关闭操作标志和滑条、恢复母球 alpha 并隐藏 overlay。它不显式清定位条内部滑动标志。滑条 setEnable 也不清该标志，禁用时 stopSlide 先 return，存在跨回合状态滞留风险。

新局 `_0x5480e3`（L1754–1806）重置分数与状态、禁用滑条和母球显示、清棋子并重新生成，然后调用玩家或 AI 回合。该段没有显式清 `_0xf86500`；是否调用前已有清理不能仅凭本段断言。`_0xbdafb3`（L3159–3166）等待棋子停止，每 50ms 复查；后续回合分派见 L3409–3435。本报告不完整审计三种模式的计分、胜负与犯规，不把局部九子判断推广为全部规则。

## 物理时间与研究用状态定义

实际参考使用 PIXI 与 box2d，并非本轮创建的原生 Web 新工程。ticker 注册 `_0x4bf21a`（L939–954），累积参数、在 accumulator>1 时减 1 并调用更新（L5499–5504）；每次逻辑更新物理 step 参数为 (1/60,10,10)，然后 clearForces（L5491–5492）。该 accumulator 循环未见补步上限，条件是 >1 而非 >=1。ticker 参数的真实时间单位、后台恢复与慢帧表现未运行验证。

研究核心循环：玩家回合入场 → 定位条拖动与重叠提示 → 松手寻位 → 母球瞄准与力度输入 → 达到 0.25 才提交出杆 → 物理演化 → 等待静止及结算 → 玩家或 AI 下一回合。研究最小状态为回合许可、玩家归属、滑动标志、瞄准标志、母球位置、sensor、重叠判定及提示节点。现有代码未统一表示“摆位无合法空位”状态，这是建议改进的重点。

本研究的成功条件是每个结论可定位到原函数和行号、明确静态与实测边界；失败条件是无源码支持地推断禁射或颜色、把竞品转述当自见证据。没有新增游戏文案或界面，也未改变现有语言。
