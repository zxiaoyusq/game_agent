## 主要结论

1. 普通犯规返子不是无条件塞到中心：_0x464a16 的动画目标是中心，动画完成后创建新棋子，并调用 _0x1f3ae5 搜索空位，再加入棋子数组。
2. 搜索不是全棋盘或二维螺旋：只检查中心起的正 X、负 X、正 Y、负 Y 四条轴线，偏移 0、2、4……98，首次可用即停止；全部失败则保留原位置，没有显式失败返回或兜底。
3. 占位判断为中心距严格小于 30；普通子刚体半径为 16，直径为 32。因此中心距在 [30,32) 时，搜索可接受但几何刚体仍重叠。这是静态参数事实；是否抖动、挤开、保持重叠，尚须运行验证。
4. 扣分立即发生，棋子在动画完成回调中重建；下一回合与胜负由另一条延时回调推进，没有等待返子完成的显式屏障。常规时间安排提供缓冲，但不能等同事务完成保证。
5. 参考 Disc Pool 是 mode=0、初始每方九子、目标九分，不是用户转述的六子样本。5→4 的单纯母球犯规可由当前计分分支解释其形式，但不能据此验证竞品规则或颜色归属。

## 模式、状态和核心循环

证据：game.js 字符窗口 360000–420000 的大厅按钮回调：Disc Pool 发出 play,0；Carrom 为 1，Freestyle 为 2。0–60000 的 _0x8b6dea、60000–120000 的 _0xd3d8fe 与 120000–180000 的 _0xbdafb3 相互支持此映射。
最小状态解释：_0x209883 为当前是否玩家方；_0x530863 为本杆母球入袋标志；_0x5ebd99 表示本杆可续手的结果标志；_0x4d3bf1/_0x41f634 为双方分数；_0x3e4566/_0x2a9c75 为双方在台普通子数组；_0x3231b3 为红子数组；_0x31089b 为待结算入袋子数组；_0x3fddb3 为对局活动标志。这些是审查用语义名，未改写源码。
循环：摆母球和瞄准 → 出杆 → 物理演化与距离判袋 → 等待停稳 → 入袋子返还或计分动画 → 犯规罚分返子 → 延时胜负检查 → 续手或换手。
初始化 _0xd3d8fe 固定循环九次分别创建两方普通子；mode=0 不生成红子，其他模式生成红子。

## 中心坐标与坐标体系

证据：0–60000 的常量、棋盘初始化；60000–120000 的 _0x464a16/_0x52e61d；360000–420000 的 _0x54e9a5。
中心常量 _0x4efd2a={x:0x13d,y:0x13d}，十进制为 (317,317)。返子目标是 C=(317+_0x24c0ca.x,317+_0x24c0ca.y)，不是浏览器页面坐标 (317,317)，也不是直接写物理坐标 (317,317)。
棋盘初始定位 x=320-width/2、y=624-height/2。由此中心公式为 (637-width/2,941-height/2)。纹理实际尺寸未在本次图像读取中核实，不把推定尺寸算出的全局中心当作已验证数值；换桌会更换 texture，定位是否仍与各纹理中心一致也未实测。
_0x541423=100；普通子 worldX/worldY getter 为刚体位置乘 100，setter 将输入除 100 后 setPosition，并调用 update 同步表现 x/y。因此命名 worldX/worldY 接收的是游戏逻辑显示单位。
普通子 update 反向同步 body.getPosition()*100；仅改普通 x/y 不等于移动刚体。返子临时动画对象已 removeFromWorld，动画使用 x/y；完成时重新创建有刚体的棋子，使用 worldX/worldY 定位，随后搜索再通过 setter 更新。容器 _0xcf7ce5 另有随视口增加的半边距，CSS 缩放和页面坐标不能与棋盘局部坐标混用。

## 中心占用搜索

证据：120000–180000 的 _0x1f3ae5、_0x23a7dc、_0x2bd695（距离函数在 180000–240000 窗口）。
_0x23a7dc 合并对手、玩家、红子三个数组，逐一按表现 x/y 计算欧氏距离，小于传入阈值即 occupied。不检查母球，不查询物理世界，也不检查尚未加入数组的临时动画子或待结算入袋子。
_0x1f3ae5 从新子 worldX/worldY 取起点。若中心不占用则原地；若占用，按每个偏移依次检查 +X、-X、+Y、-Y，第一次满足距离不小于 30 的点即采用。新子是在搜索之后才 push，正常调用顺序避免把自己当占用物。
搜索不检查对角空位，不检查棋盘边界，不预留正在飞回的目标点，无显式搜索失败状态；偏移上限为 98，不含 100。正常中心附近通常远离边界，但这不是边界验证。
普通子构造器 _0x54e9a5：Circle(16/100)，动态刚体、bullet=true、allowSleep=true、awake=false，密度 0.45、摩擦 0、恢复系数 1、线性阻尼 1.8、角阻尼 0.2。搜索阈值来自 _0x3ce1ab=15，两者相加为 30，与刚体直径 32 不一致。
红子返还 _0x52e61d（60000–120000）也使用同样的四轴搜索，但在安排动画前计算目标，动画完成后创建红子并 push，没有再次调用 _0x1f3ae5。其期间占位变化与普通返子完成时搜索的行为不同；Disc Pool 不应混用红子结论。

## 母球犯规、扣分与返子时序

证据：120000–180000 和 180000–240000 的 _0x49d791；60000–120000 的 _0x464a16、_0xbdafb3 开头；120000–180000 的结算其余部分。
每逻辑步检查母球到四个袋口的距离，<=20 即设置 _0x530863=true、母球设为 sensor 并播放入袋与 foul 表现。判袋是业务距离检测，不是袋口碰撞回调。
出杆 _0x1e39ba 后，_0x338c29 延迟参数 2300，再进入 _0xbdafb3。其若发现任一棋子或母球仍 awake，则延迟参数 50 后重查；停稳后将 _0x1a373b=-1，并让各对象 sleep。
非 Freestyle 的结算：同杆母球入袋时，本方普通子或红子在入袋列表中走返还动画，完成回调新建刚体、定位、搜索、push；其他可计分普通子走计分动画，其完成回调才加分。
若 _0x530863 为真：先判断 !_0x5ebd99，成立才调用 _0x464a16(_0x209883)；随后强制 _0x5ebd99=false。因此“母球进袋总是额外扣一分”不成立，还取决于本杆标志。单纯母球进袋且已有分数时，本杆未取得续手机会，进入额外罚子路径；本方同杆进子会影响该标志。
_0x464a16：当前方分数<=0 直接返回，不扣成负分，也没有在该函数建立欠子记录。否则创建临时子后立即 removeFromWorld，放在相应分数 UI 位置，当场分数减一并更新 HUD；再安排 time=20+random()*10 的中心飞回动画。完成回调 new _0x54e9a5 → worldX/worldY → type → addChild → _0x1f3ae5 → push 到所属数组 → 移除临时表现。没有恢复原入袋棋子的 ID 或旧速度。
已读构造器显示新刚体是在构造时创建，默认位置尚未设置；随后同一同步回调定位和搜索，不能把这一瞬间直接说成发生了一次物理碰撞。
_0xbdafb3 在安排动画后，以 _0x338c29 安排独立结算：没有待入袋子时参数 500，有待入袋子时为 1000；这不是 await 返子完成。Tweener 时间单位由逻辑更新驱动，_0x338c29 将毫秒参数换为 /1000*60 个逻辑 tick。20–30 tick 的返子动画在名义 60 Hz 下约 333–500ms；是代码换算，不是实测墙钟时间，调度可增加 tick 偏差。
普通返子回调没有本局编号或活动标志守卫。延时胜负/换手回调有 if(!_0x3fddb3)return，但活动布尔值不能区分旧局与新局。重开清理能取消部分挂在数组对象上的 tween；额外罚子临时对象未纳入这些数组，不能据已读清理链保证所有旧回调被取消。实际跨局污染是否可触发仍待测。

## 回合与胜负的先后

证据：120000–180000 的 _0xbdafb3、_0x50a0ff、_0x5e7a5f。
非 Freestyle 的延时结算先检查任一方分数==9，再处理未 cover 红子返还，然后决定续手/换手。胜负分支结合当前方、达到九分的方及红子数组是否为空；Disc Pool 初始化无红子，不能拿 Carrom cover 规则替代该模式。
犯规把 _0x5ebd99 强制置 false，所以正常进入换手。玩家回合由 _0x5e7a5f 开启，对手由 _0x50a0ff 开启；二者重置犯规/续手标志，母球先设 sensor 后摆入基线。玩家启用操作发生在摆入动画完成之前；动画完成调用 _0x41684e 做基线避让。能否提前出杆或被动画覆盖需要实际交互验证。
双方普通子判袋分支中存在“非 Freestyle 且另一方数组已空”时不加入 _0x31089b 的空分支；不能假定所有入袋都必然计分。最后一子、同杆双方入袋、母球入袋组合应单独复现，记录遍历顺序（红子、玩家子、对手子）。
胜负判断依赖延时前的计分动画完成，没有统一的原子结果提交；不能静态保证所有边界局面结算正确。

## 物理步长、输入窗口与误差

证据：180000–240000 的 _0x4bf21a/_0x49d791，360000–420000 的 trimVelocity，120000–180000 的输入回调，420000–480000 的母球实现与 Tweener。
_0x4bf21a 累加 ticker delta，while(accumulator>1) 每次减一并调用 _0x49d791(1)；每逻辑步末尾 world.step(1/60,10,10)，随后 clearForces。此处未见主动补步次数上限；ticker 自身限幅没有进一步核验。条件是 >1 而非 >=1，保留这一边界差异。
表现位置同步和判袋发生在该步物理 step 之前；新物理位置的袋口识别可能在下一逻辑步。不能宣称高速绝不漏袋。
trimVelocity 使用 |vx|+|vy|<0.2 时 sleep，不是速度绝对值为零的证明。
玩家开始瞄准需 _0x55e693 与 _0x209883，且不在拖拽；松手力度>=0.25 才出杆，力度按拖距/最大拖距计算，上限1；调用参数为 strength*100*1.25。母球出杆方法关闭 sensor、唤醒并 applyForceToCenter，参数不能直接称初速度。
基线 X 为 162 至 483；玩家 Y 常用 828，初始化有 826，不能将二者强行合并为同一常量。Delhi 桌 ID=0 跳过回合倒计时扣减；其他桌按逻辑 tick 倒计时。
原代码没有为返子验收声明数值容差。本审查不自行修改参数；建议补测坐标同步误差<=0.01逻辑单位、计分与换手次数必须精确一致，几何无重叠要求应按真实半径和引擎容差明确设定。建议值不是参考实现已达标的结果。
