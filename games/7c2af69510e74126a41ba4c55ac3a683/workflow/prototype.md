## 3. 目标集合、随机索引与次序

令 A=`_0x2a9c75`，B=`_0x3e4566`，Q=`_0x3231b3`，T 为最终目标数组。

| 条件 | V2 构造 T | 判断 |
|---|---|---|
| mode 严格等于数字 2 | A.concat(B,Q) | 保留三组次序，允许组间重复引用 |
| 其他 mode，A.length===1 且 Q 非空 | Q.slice() | **替代** A，不是 A+Q；与附件常规候选器选择分支一致 |
| 其他 mode，其他情况 | A.slice() | 非空 A 不会因为全部受阻而扩大到 B/Q |
| 上述 T 长度为 0 | T.concat(B,Q) | 空 A 时可选 B/Q；这是既有 fallback 策略，不由 V2 新增 |
| 补集合后仍空 | return null | 正常空数组安全，无随机和几何调用 |

`slice/concat` 不修改源数组，但对象引用共享，不是棋局深快照。未过滤空项、稀疏孔、非有限坐标、已移除棋子，长度非零不等于有效目标非零。严格 mode 比较也意味着字符串 "2" 不进入 mode 2 分支；应由入口保证枚举类型，不盲目改成宽松比较。

在解码索引确实对应 `length/concat/floor/random`、原生 Math 未被替换的前提下，随机索引 `floor(r*n)` 对 `0<=r<1` 与 `n>0` 合法。并非 `round` 的末端越界问题；本轮未执行字符串表解码，不伪称动态确认这些别名。测试必须直接确认当前解码器。

第二个 random 独立产生基线 x。新增替代目标循环不消耗随机数，但若当前 helper 消耗 random，额外调用仍可能改变后续全局随机流。概率均匀是“数组槽位均匀”，不是“不同实体均匀”：`[a,a,b]` 会给 a 两份权重。无需因原生 random 不返回 1 就改随机算法；注入测试随机源应强制遵守契约，并覆盖非法值处理。

### 多目标循环的准确行为

- 原目标初始检测通过：不扫描任何七点，也不切目标。
- 初始检测失败：先对同一原目标测试 `i=0..6` 的七个基线点，次序为左到右，包含两端；找到第一个通过者停止。
- 同目标七点都失败：`firstTargetIndex=T.indexOf(initialTarget)`；外层 offset=1..n-1，索引 `(firstTargetIndex+offset)%n`；每个不同于当前原目标引用的项再测试七点。
- 若所有对象引用唯一，indexOf 与随机命中索引一致，恰好覆盖其后所有其他项，再绕回前面的项，原槽位不再测。正常对象由 T 取出且 T 未变，indexOf 不会是 -1；不应把 -1 当作正常必现问题。若 helper 修改 T 或目标并非有效对象（如 NaN），则该前提失效；offset 从 1 起使 -1 情况先访问索引 0，不会立刻产生负索引，但会漏掉最后一槽且不能恢复目标契约，应拒绝/诊断而非默默继续。NaN 目标通常已在此前几何调用中失败。
- 如果随机命中的是重复 a 的较后槽位，indexOf 会落到第一个 a。例：`[a,b,a,c]` 随机命中第三槽，替代顺序是 b、跳过 a、c，而不是 c、跳过 a、b。**不遗漏其他不同引用，但不保留真实随机槽位的循环起点。**
- `alternativeTarget === initialTarget` 只跳过原目标引用；其他引用重复，如 `[a,b,b,c]`，受阻的 b 会扫描两次。坐标相同但引用不同不会去重，也不会被 helper 的引用排除等同处理。
- 第一条成功替代会同时提交 pos、dir、target、true，并 break 内层；外层下一次条件看到 true 而停止。没有成功后继续用旧 target 的赋值漏洞。
- 全部失败的临时候选未写回 fallback，返回的是此前已找到的原合法 pos、原 dir、原 target，false。此前同目标扫描失败也不会覆盖它。

策略限制：不比较入袋价值、距离、力度或风险；七点之间的小窗可漏检；替代目标没有先尝试原随机合法摆位，也没有沿用 2 单位密扫。这些都是有界采样策略，不等于“棋盘确实无畅通路径”。如未来要求穷尽或最优杆，应另立范围，不能在本次只读审查中偷偷增加。

## 4. 合入前问题与修复要求

### F-01：第五参数与“畅通”含义尚未闭合（P0 契约门禁，NEEDS_CONTEXT）

附件 `_carromStartPathBlocked(origin, angle, length, intendedTarget)` 仅有四个形参，正文不使用 arguments；第五参数 true 在该版本被忽略。检测终点是 `min(length, strikerRadius*2)`，不是目标全程。采用“线段最近点距离”检测胶囊区，排除 intendedTarget 的相同引用，半径为 strikerRadius+16，严格小于才判受阻。这不是整杆物理模拟或入袋检查。

因此若 V2 实际仍连旧 helper，标记 true 至多表示**起点短段**通过，目标之前远处障碍可漏检。若当前 helper 已更新为全程模式，风险可能已解决，但本轮没有其正文，不能断言已修复。不能仅看函数形参个数决定语义，须读当前正文和真实引用路径。

要求：提供当前 helper、固定 true 的定义、有限数值与零长度策略、目标排除与碰撞边界；如要求全程，使用连续线段/扫掠圆并将终点定义在目标首次接触处，核对邻近棋子与目标边界，不能简单把目标中心视为“必须走完整段”。用中远段阻挡反例验证 true 与省略参数的行为差异。若只承诺起点短段，须明确元数据命名/契约而不得据此宣称全程畅通。

### F-02：数值、空项与异常防护不完整（P1；正常空数组已处理）

V2 在取 target.x/y、调用方向函数及占位检查前没有结构与有限值检查。可静态推导的反例：
- `T=[null]` 或稀疏孔：在方向函数或随后直接读取 target.x 时抛异常；null 返回分支不会捕获它。
- target 坐标 NaN/Infinity：distance 非有限；附件 path helper 返回受阻，但方向也可能非有限，最后仍可能返回一个坏 fallback。附件执行器验证 pos/dir 只能阻止部分发杆，不能避免此前 throw，且不验证元数据 target。
- 基线边界/y/radius 为 NaN：随机 pos 无效；NaN 比较通常为 false，不证明占位安全。附件 `_0x23a7dc` 没有局部数值 guard；坏非目标棋子可被距离比较忽略或触发异常，而 path helper 对同类坏数据会直接受阻，存在判定不一致。
- `FindOpenBaseline()` 的返回值仅检查 `===null`；undefined、NaN、越界数字都可写进 pos。附件 helper 的正常有限参数路径能返回数值/null，但不能代替当前版本契约。
- 原目标距离用平方再开根，替代目标用 hypot：极大但有限的坐标可能使前者平方溢出；棋盘范围入口约束可消除该问题，不应只以 Number.isFinite 输入替代业务范围检查。
- 检测器抛异常或返回 undefined 等非布尔值：当前 `!result` 可将未定义结果标记为 clear；没有异常隔离或错误诊断。

要求：在唯一实际入口证明或增加数组稠密有效、实体存活、坐标/边界/radius 有限且业务有界的不变量；空有效目标按 null 契约处理。坏棋盘障碍不能仅从目标集合删掉就当不存在，应保守拒绝/诊断。验证 openX 有限、在闭区间内且摆位合法，验证 dir/distance 有限且非退化。统一距离运算或范围限制。helper 严格布尔，异常安全终止并进入既有回合处理；避免吞异常然后继续发杆。此处只给要求，未实施补丁。

### F-03：密扫循环缺少独立上限（P0 条件性冻结风险；附件正常常量下有界）

七点循环最多 7 次；目标循环最多 n-1 次，正常稳定数组不会无限。但之前的 2 单位扫描使用运行时宽度 `W=right-left` 作上界，重复读取边界；没有最大次数或合理宽度检查。

附件常量 left=162、right=483，W=321，正常最坏迭代数 `ceil(W/2)=161`。如果上界为 Infinity 且检查一直受阻，循环不会正常终止；巨大有限宽度也可冻结 UI，达到双精度步进无法再增长时更不能依赖“数字有限”保证终止。W=NaN/负数则扫描直接跳过，不代表数据合法。

要求：验证并冻结合法边界/目标长度；用有业务依据的整数最大扫描次数和整次选杆预算约束密扫与多目标扫描，预算耗尽保留已验证合法 fallback 或安全返回 null，不能输出 NaN。若这些变量在当前运行只能是已验证的不可变常量，可用真实定义与入口测试关闭风险，不能宣称正常棋盘已有无限循环。

### F-04：重复实体、随机起点与额外计算（P2，若承诺实体唯一/按命中槽位则升 P1）

保存随机索引可避免 indexOf 找错实际命中槽位；对替代目标使用身份集合可避免重复 b 的七点重测。是否对初始 T 全部去重需要明示：那会改变原始随机权重与既有行为，不是纯性能改动。普通棋子 id 在附件两组中分别从 0 递增，**不能用裸 id 跨组去重**；同坐标也不是身份。优先确认当前全棋盘实体身份契约。重复引用还可能使附件 `_carromAiBoardChanged` 判棋盘异常并触发限次重试，故不仅是 fallback 循环成本问题。

### F-05：返回结构兼容，但元数据不是执行保证（P1 集成门禁）

- V2 非 null 仍保留 `pos:{x,y}` 与数值 `dir`，没有改成向量或 Promise；null 形状未改变。fallback 从未要求返回 hDot/dist/speed，不能拿常规候选 schema 强加给它。
- 附件 fallback 直接进入 `_0xd6b627(fallback,100)`，不经过常规候选 hDot/dist 过滤；新增字段没有被附件执行链读取。普通属性读取兼容，不证明当前 schema 白名单、序列化、精确键断言或日志处理一定兼容。
- `_carromFallbackTarget` 是共享实体引用，不是可安全 JSON 化的数据；可能包含循环引用或可变状态。日志/埋点不应直接 stringify 整个返回对象或当存档写入。
- 附件 `_0xd6b627` 会添加 `_carromBoardSnapshot`；执行前验证回合、快照、边界、摆位，至多两次重选。附件并不以 `_carromFallbackWasClear` 控制是否发杆，也不会以 target 重新瞄准。
- 附件 `_0x223471` 会按等级概率添加约 0.05–0.10 弧度的正负角偏差，最终方向为 `PI-dir+offset`。所以选择时检测通过与最终首碰/得分是不同事件；快照位移每轴大于 1 才判变化，也不等于发杆时全程清路复核。

要求：在当前所有真实消费者中验证 null、false（仍可发合法备用杆）、true、引用型 target 的契约；不要把 false 改成跳过所有杆，破坏“全部受阻保留”。若新承诺覆盖最终首碰，必须在真实最终角度、摆位与当前棋盘上复核，否则只保留“选杆时检测结果”的弱契约。当前方向 helper 正文未定位，弧度/坐标系需实际核对，不能直接改掉附件的 PI-dir 约定。

## 5. 受阻判断与成本上界（静态估算，不是性能测试）

设 T 槽位数 n，全棋盘障碍槽位数 m，W 为合法冻结宽度，k=ceil(W/2)。假设 helper 纯函数、数组不在调用中变长。

- 原始路径畅通：path helper 1 次，无新增目标扫描。
- 最坏 path 调用：`1+7+7(n-1)=7n+1`；占位受阻的候选会跳过 path，所以实际可更少。相对附件同目标七点版本，新增多目标最多增加 `7(n-1)` 次 path 与相同数量占位检查。
- 不含 FindOpenBaseline 内部的占位调用上界可保守写成 `2+2k+7n`：两次外层占位、密扫每轮至多左右各一次、七点候选每次一次。
- 附件两个判定器每次都 concat 全棋盘并线性遍历，helper 几何检测为 O(m)，fallback 多目标部分为 O(nm)，n 与 m 同阶时为二次项。indexOf 是 O(n)；密扫另为 O(km)。附件 open baseline 另有 O(m log m) 排序与多次占位复核，不能遗漏在总成本中。
- 全程胶囊检测如果仍是一颗棋子一次最近点计算，渐进复杂度未必增加；按路径长度步进的新版 helper 可能另乘采样数，须读实现，不猜。
- 真正耗时还包括 concat 分配、GC、短路分布、常规求杆与限次重试。本轮没有设备、耗时、加载或内存数据。只能要求调用计数、p50/p95/max 与长任务记录，不能宣称移动端无损。

优化应先使用同一不可变棋盘快照，缓存七个基线点占位结果与有效目标身份；不得因缓存跨回合/动画复用而产生过期判定。优化后必须对照选择次序与全部受阻保留。

## 6. 本轮原型定义：审查对象的状态与边界

这是选杆算法审查，不制作新的 Carrom 游戏、规则、UI 或美术；以下是验收约束，不是已实现新原型。

- 核心循环：读取稳定棋盘 → 常规候选失败后调用 fallback → 产生合法 pos/dir 或 null → 由既有执行器延迟移动/瞄准 → 实际发杆 → 物理首碰/入袋 → 既有回合结算。选择器不计分，不直接推进物理或提交奖励。
- 规则状态：mode、A/B/Q、基线边界与 y、棋子半径、随机序列；局部原目标/原摆位、候选游标、检测结果；执行侧 round/turn、快照、重试次数。检测函数应只读，不在搜索时修改棋盘。
- 算法成功：返回有限、合法摆位和可执行 dir；true 仅表示指定检测语义通过。算法 fallback：全部采样受阻仍返回原合法杆、false。不可用：目标有效集合空、无合法摆位或输入异常安全终止，走已确认 null 契约。**未得分不是选杆函数的失败判据，检测 clear 也不是赢局。**
- 碰撞：摆位和路径判定分别验证；附件摆位阈值为 strikerRadius+16，严格 `<`；切线相等不阻挡。实际物理形状、首次接触定义、目标排除、边界容差需当前物理配置证明。
- 物理步长：函数内没有 world.step；本轮未取得当前实际步进器，不能指定或声称已验证 1/60 秒。后续回放必须记录实际步长、补步/截断策略、物理库版本与力度，按固定步长与相同随机输入对照；无需重选引擎或造 Canvas 工程。
- 输入窗口：fallback 为同步计算，无新鼠标/触控窗口。真实发杆稳定边界由现有回合守卫控制；动画期间棋盘变动、暂停/恢复、重开旧回调须在真实链验证。报告不给新时限或计分规则。
- 可接受误差：确定性单元测试要求目标引用、次序、布尔/null 结果精确一致；几何临界测试建议构造边界 ±1e-6 棋盘单位（测试探针，非生产容差）。旧快照每轴 1 单位是历史失效阈值，不是首碰保证或跨浏览器物理误差标准。实际轨迹容差需由当前物理基线定义。
- 界面布局/文案/语言：不新增或修改界面，因此无新标题、HUD、教程或文字资产；默认英文游戏约定不构成本轮改文案授权。界面相关验收仅观察原棋盘、发杆表现和回合反馈，不交付试玩页面。
