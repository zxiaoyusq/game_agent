## 条件推导

记 O 为 0x1aa0e24 的入口 x0；S 为该调用者建立相关栈地址时的 SP；P=S+8；T=S+0x10。P、T 都是调用者栈内地址，不是各被调函数自己的 SP。记 V 为 0x1a09bc4 执行 `ldr x8,[x20]` 时从 P 读取的 64 位值。

| 环节 | 按摘录得到的关系 |
| --- | --- |
| 0x1aa0e24 | 本函数 x19=O；虚调用接收者为 Q=M64[O+0x308]；x8=P；调用目标为 M64[M64[Q]+0x90] |
| 调用 0x1a0c450 | 入口 x0=T，x1=P，x2=前一返回值+0x18 |
| 0x1a0c450 | 本函数 x19=T，x21=P；向 0x1a09bc4 传 x0=T、x3=P |
| 0x1a09bc4 | 本函数 x19=T、x20=P；读取 V=M64[P]，清零 M64[P]，写 M64[T+0x2f0]=V |
| 回到 0x1aa0e24 | 若本函数 x19 仍为 O，则向 0x1a9b9b4 传 x0=O+8、x1=T |
| 0x1a9b9b4 | 本函数 x19=O+8、x20=T；0x1a9bb38 读取 x9=M64[T+0x2f0]；0x1a9bb3c 清零该源槽；0x1a9bb4c 写 M64[(O+8)+0x2f0]=x9 |

因此，在各段值保持不变且路径成立时：

`M64[P] → M64[T+0x2f0] → M64[O+0x2f8]`

偏移计算是 `0x8+0x2f0=0x2f8`。第一处清零的是 P，第二处清零的是 T+0x2f0。搬运的是栈槽所存的值，而非必然把栈地址 P 本身存入 O。只有另有证据表明 V=P，才能作后一种表述。

该模式与转移指针字段相容，但单靠这些指令不能确认 C++ 类型、智能指针类别、所有权协议或值一定是有效对象指针。

## 栈帧审查

1. 必须读取 0x1aa0e24 的完整序言、各处 SP 调整、参数建立位置和尾声，确认上述 S 相同；若 SP 变化，应将各地址换算到同一基准，不能按文字相同直接认作同槽。被调用者自己的栈分配不使已传入的 P、T 自动改变，但正常返回应恢复调用者 SP。
2. 若 T=S+0x10，则 T+0x2f0=S+0x300，8 字节访问覆盖 S+0x300 至 S+0x307。必须证明该范围属于有效可写的临时对象存储，不与保存寄存器、栈保护值、其他活跃局部变量或越界区冲突。若完全位于以 S 为低地址的自有栈帧，相关有效范围至少须延伸到 S+0x308（不含）；这不是已经证实的帧大小，也不是完整对象大小。
3. P 的 8 字节槽为 S+8 至 S+0xf，与 T 的起始地址相邻。若虚函数通过 x8 写出的结果超过 8 字节，则可能覆盖 T 起始区域；是否属于合法的分时复用，须结合结果类型、写入范围及后续构造顺序确认。不能把 x8=P 自动解释为仅写 8 字节。
4. 源槽必须在读取前已初始化；临时对象须在后续访问期间有效。正常 ABI 栈对齐通常要求 SP 为 16 字节对齐，P 仅为 8 字节对齐是否足够取决于实际结果类型。没有序言与类型信息，不能确认对齐和对象生命周期。

## 间接结果寄存器与跨调用活跃性

按通常 AAPCS64 约定，x8 可用于间接结果地址；调用前设置 x8=P 与隐藏返回缓冲区模式相容，但不能证明虚函数实际写入 P、写入多少字节、结果类型或结果是否为非空指针。虚表槽 +0x90 的具体目标及实现仍未知；也需排查调整 thunk 或非标准调用约定。x0 中接收者 Q 与 x8 中结果地址 P 必须区分。

x0–x17 属于调用者保存寄存器，x18 有平台约定，不应当作通用保值寄存器；x19–x29 按通常约定由被调方保存。x19 的保存保证只约束合规调用的正常返回，不意味着函数内部从不改写 x19，也不代表其指向的内存不变。每个函数的 x19、x20、x21 必须分别绑定入口参数，不能跨函数按寄存器编号合并。

虚调用后的 0x18d750c、0x18d7948 可以改写 x8、x9、x0 等易失寄存器。后续应依赖重新建立的栈地址和内存值，不能依赖虚调用后的 x8 或 x9 原值。调用者保存规则不保证栈槽内容不被通过别名改写；须确认这些调用及省略指令未覆盖 P。

`x2=上个返回+0x18` 只能按紧邻且已证实的返回值解释；若是 0x18d7948 返回的 x0，则不能称其为虚函数返回值。摘录未展示足够类型和用途，不能据此命名字段或棋色。

特别需要补齐 0x1a9bb38 到 0x1a9bb4c 之间的指令，包括未提供的 0x1a9bb40 与 0x1a9bb48。若其中有 BL/BLR，x9 不保证保留；若有直接改写 x9，也会切断该值链。必须证明 x9 未改写，或确实保存并恢复相同值，才能把最后的写入关联到前面的读取。第一段 0x1a09bc4 的读、清零、写之间同样需要检查省略操作及路径。

0x1a9bb44 的 `ldr x0,[x19,#0x2f0]` 在当前绑定下读取的是 O+0x2f8 的旧值，不是栈源值。它与替换后处置旧值的模式相容，但未提供后续调用，不能宣称已经执行释放、析构或引用计数操作。若旧值处置在新值写入前后发生，还须检查其异常与重入影响。

## 控制流、异常与别名条件

必须确认各参数设置、BL/BLR、字段读写位于同一可达的正常执行路径，并检查分支是否绕过某次赋值或写入。完整 CFG、展开信息及异常表尚未读取；不能把线性摘录认定为所有路径必经。

若虚调用、0x18d750c、0x18d7948、构造或中间调用抛出异常、未返回或进入清理路径，后续最终写入可能不会执行。异常清理块中 x0 可能为异常对象，x19 可能被改作保存异常值；正常路径中的 O 绑定不能直接套用到清理块。发生源槽清零也不能单独证明目标写入完成，更不能据此证明异常安全。

还需排除 P、T 对象字段与 O+0x2f8 的意外重叠，确认接收者和访问地址有效，并检查外部别名、重入或并发是否改变相关内存。这些普通 ldr/str 不构成跨线程原子转移协议；即使每条访问合法，也不能把整条链称为原子操作。

就 0x1a9bb4c 这一写入时刻而言，只要上述值链条件成立，可推导其写入值为 V；若要断言函数正常返回后或更晚时刻仍保持 V，还须排除后续覆盖、回调和清理修改。V 也可能为零；非空性需要额外证据。

## 旧 ZIP 的辅助作用与身份边界

已读旧 caller_1aa2eb0 在 0x1aa30ac 设置 x0=x19，随后 0x1aa30b0 直接调用 0x1aa3458；它未提供对本次新入口 0x1aa0e24 的身份关联证明。该旧调用者还在 0x1aa30d4、0x1aa31a0 把 x19 改为栈地址，说明不能将整个范围的 x19 永久等同入口对象。

已读旧 0x1aa3458 在入口保存 x19=x0，但在 0x1aa3644 等位置将 x19 改作栈地址。该范围引用 queenCovered 字符串的事实，不能证明本次 O+0x2f8 指向红棋，也不能证明两个入口参数属于同一运行时对象。地址邻近、共用辅助函数或相同字段偏移均不足以建立对象身份。

严格保留三项未知：虚函数实际写入未知；不同调用者的对象身份关系未知；V 所指对象的棋色及红棋语义未知。

## 结论与补证验收条件

结论为“可以条件推导，尚非独立验证的完整数据流证明”：以操作方摘录为前提，V 可从调用者栈槽 P 经临时对象字段 T+0x2f0 搬运到 O+0x2f8。

提升证据等级需补齐：匹配 ELF 构建哈希与地址体系；0x1aa0e24 完整栈帧和路径；虚表目标实际实现及结果写入范围；各传参点与搬运区间的完整指令；0x1a9bb40、0x1a9bb48 对 x9 的影响；异常边与清理；后续覆盖及别名关系。若另要识别棋色或统一调用者身份，需要独立的类型、创建、赋值、比较或只读运行时关联证据。
