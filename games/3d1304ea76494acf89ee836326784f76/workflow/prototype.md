# Carrom 红棋与普通模式状态隔离：原始基线只读复核

## 范围与结论

本轮为 prototype 阶段的只读研究，不制作 UI、不修改参考源码、不运行参考游戏、不推进美术、代码或测试阶段。结论来自已提交原始 H5 与竞品 ARM64 历史文字索引。操作者说明当前开发版已有红棋状态与返场修复，但未提交当前开发版；本文所有旧基线异常均不能直接认定为现版缺陷。

原始 H5 的模式编号已由大厅事件核对：Disc Pool=0、Carrom=1、Freestyle=2。模式 0 不创建红棋；模式 1、2 均创建一枚红棋，但 mode=2 使用类型积分，mode=1 使用覆盖与普通棋计数路径。mode=0 与 mode=1 共用非 Freestyle 结算。覆盖待定、是否续杆、犯规、当前操作者、积分和返场表现对象都是闭包共享变量，未形成独立的红棋状态对象。最需要后续复核的是覆盖被双方普通棋修改、最后棋在返场前结束、动画回调提交计分，以及旧局延迟回调的生命周期隔离。

## 三模式规则差异

|项|Disc Pool 0|Carrom 1|Freestyle 2|
|---|---|---|---|
|初始棋|9+9，无红棋|9+9+1 红棋|9+9+1 红棋|
|普通棋|按 type 归属计数量|同 mode 0|任意颜色归当前操作者，type 0/1/2 分值 50/20/10（L644）|
|红棋|正常初始不可达|入袋后保存表现、待覆盖；不是立即增加普通棋计数|加入待结算数组，按 type 0 加 50；不走 Carrom 袋后保存表现路径|
|覆盖|共享代码仍存在，但正常无红棋|共享布尔由双方普通棋入袋清除，无覆盖 owner 校验|停球结算开头直接清待覆盖标志，非 Carrom 覆盖规则|
|目标|非 Freestyle 的九枚计数条件|九枚计数且在场红棋数组为空等条件|阈值 160（`_0x153877=0xa0`）|
|击球器犯规|返本杆己方棋/红棋分支，条件允许时额外退一枚已得棋|同左，另受待覆盖状态影响|本杆待结算棋全部返场，不加类型分|

### 红棋入袋、覆盖与失败返场

L4833–5159 先遍历红棋，四袋均以中心距离 <=20 判入袋；立即 `_0x5ebd99=true`、`_0x4268e2=true`，移除刚体和在场数组。Freestyle 将棋放入 `_0x31089b`；非 Freestyle 经两段动画后才写 `_0x404020` 并显示 check_unfilled。

L5160–5326 再遍历玩家普通棋，L5327–5489 最后遍历对手普通棋。两方任一普通棋入袋都会在 `_0x4268e2` 为 true 时改覆盖勾选，然后无条件清 `_0x4268e2`。只有己方普通棋（或 mode=2 任意普通棋）才保证把续杆置 true。因此覆盖表现、待覆盖标志与续杆不是同一个状态，也没有在该处验证红棋归属方。

同一模拟更新内的扫描顺序固定为红棋→玩家棋→对手棋，不能当成球真实抵达袋口的时间顺序。红棋与普通棋同帧入袋时普通棋会清待覆盖；普通棋先前帧入袋、红棋后帧入袋时又可能留下待覆盖。红棋动画的后续回调还会写 check_unfilled，可能覆盖早先 check_filled 的表现，需运行复核。

非 Freestyle 停球后，L3422–3426 在待覆盖且不续杆时调用 `_0x52e61d`，再清标志并隐藏勾选。红棋单独入袋会先使本杆续杆；下一杆落空时才走失败返场路径。若下一杆仅进对方棋，该棋仍可清待覆盖，这与显式的“由红棋所属操作者用己方棋覆盖”状态模型不同。此为旧源码分支事实，是否符合产品规则需以当前开发版规则和实际测试判断。

`_0x52e61d` 先搜索中心附近可用点，但只有 `_0x404020` 非空才启动返场 Tween；完成后才创建新 type 0 刚体、push 红棋数组，再移除/清空全局 `_0x404020`。回调读取全局引用，未绑定局号。中心避让按四轴、2 像素步进、偏移 <100 搜索；没有读到穷尽失败后的保证。

### 普通棋、犯规及最后棋

普通棋入袋立刻从在场数组移走，再有条件加入待结算数组。L5185–5186：非 Freestyle 且对方在场棋已经为空，玩家棋不入待结算数组；L5348–5349 为镜像条件。该门槛检查的是对方在场数组，不是本方最后棋或分数。由于玩家扫描在前，同帧双方最后棋可能受到处理顺序影响，不能简单概括为“最后棋一定正确结算”。

非 Freestyle 的 `_0xbdafb3`：犯规时本杆红棋及当前操作者己方棋走返场；对方棋仍可能走计数。无犯规时玩家棋/对手棋分别在 Tween onComplete 才增加各自计数。L3405–3408 若犯规且本杆无续杆则 `_0x464a16(currentPlayer)`，随后清续杆。该函数只有已有计数大于0才扣一枚，立即减计数，动画后重建普通棋。不可外推为零分时记录了罚棋债务。

L3412–3420 先判断任一计数是否恰好9，按当前操作者、其计数和红棋在场数组是否为空选胜负；之后才检查红棋失败返场。因此“红棋已离开数组但还未合法覆盖”与“红棋已覆盖”在此不能仅凭数组空区分，最后棋可能在返场之前触发结束。mode=0 无初始红棋，但仍受共享普通棋门槛、异步计数和最后棋路径影响。

Freestyle L3168–3303：开头清待覆盖；犯规则待结算棋全部返场，清续杆。否则按类型产生加分表现，onComplete 才累加分数。延迟检查任一分数>=160时，按当前操作者直接选择胜负，并非独立比较两边分数。L3287 的红棋返场/扣50分分支在此之前已经清待覆盖，正常控制流下不可仅据该段宣称其有效；且 L3289–3290 使用 `playerScore`、`oponentScore`，与实际积分变量不同，已查到 playerScore 在该文件仅此处出现。不得把这段未证可达代码说成已复现异常。

## 输入、物理与可接受误差

本轮记录原始参数，不改成新物理设计：

- L5491 `world.step(1/60,10,10)`，L5500–5504 用 ticker 增量累加并在 accumulator>1 时补更新；未见该循环的补步上限，且不是 >=1。不能承诺后台长帧无追帧问题。
- 像素/物理比例100（L854）；普通棋刚体圆半径16像素（L10428、10478），规则避让半径15像素（L851），不是完全同一几何；击球器圆半径21.76像素（L10573、10625）。
- 普通棋 angularDamping 0.2、linearDamping 1.8，击球器5与2.8；bullet=true。普通棋和击球器都在 |vx|+|vy|<0.2 时休眠。接触回调还用 Tween 改阻尼（L1374–1413），不应把运动当恒定阻尼模型。
- 入袋为逐更新中心距离<=20的几何检测，不是接触回调触发；检测在该轮物理 step 之前。bullet=true 不能证明离散袋口检测不漏高速跨越。
- 玩家 `_0x36ab44` 检查教程、允许输入、当前玩家、未在拖拽；`_0x1e39ba` 释放力度>=0.25才发射，力度为 strength*100*1.25，归一化上限1。拖拽距离上限随装备为75+25*力度参数。坐标减去布局偏移；放置条范围162至483。
- 发射后约2300ms对应 Tween 时间再检查停球，仍运动则每50ms对应 Tween 时间重查；停球后500ms或1000ms对应 Tween 时间才检查结算。这里不是独立墙钟 setTimeout。
- 桌面与触控、取消拖拽、多指、暂停时释放仍待运行验证；start/release 自身的门控不完全相同，不因上层存在其他事件门控就断言所有输入都受保护。

建议后续验收容差：棋子身份、数量、积分、覆盖 owner、胜负、事件去重必须精确一致，容差0；固定输入在同一构建同一浏览器下跨30/60/120fps运行，终点建议<=1设计像素差、停球时间<=2物理步差，袋口20±0.1像素边界单列，不用位置容差掩盖入袋/胜负差异。这些是建议测试门槛，未在本轮测量通过。

## 暂停、重开与异步计分

暂停按钮 L1575–1579 进入 `_0x5e0129`，设置暂停布尔、禁暂停按钮和大厅交互；L4699 在 Tween、物理、计时之前 return，故主循环中的这些工作冻结。暂停关闭恢复布尔；返回大厅调用 `_0x3771eb` 使活动=false。外部广告会直接 stop/start ticker；历史 SDK 和宿主实际回调未运行核验。

`_0x3846bf` 只调用 `_0x5480e3`，未查到其调用点，不能声称已有可操作的局内重开按钮。可确认的新局入口是大厅选模式/桌面后 `_0x1260d2`→`_0x5480e3`。

清局移除数组对象与其 target Tween，清积分、覆盖标志、红棋表现引用；但 `_0x338c29` 每次使用新的匿名对象作 target，不保存句柄且无 sessionId。主循环先更新 Tweener，再检查活动布尔（L4702–4710），所以大厅里仍可推进旧 Tween。部分回调仅检查活动布尔，下一局活动变true后无法辨别旧局；普通棋加分回调、红棋保存表现与返场重建等回调也未见统一局号验证。清理是局部且 extract 首次命中后退出，不能概括为“已取消所有旧回调”。

分数提交在动画完成而非规则事务内，且 mode、当前操作者、全局表现引用在多个回调执行时读取。这提供跨模式/跨局污染的静态风险条件；本轮没有实际调度这些回调，不报告发生概率或已复现结果。
