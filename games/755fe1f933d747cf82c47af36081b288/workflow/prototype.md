原包是本项目唯一游戏基线。入口实际引用 PixiJS 4.8.9、Planck.js 0.3.27、Howler 和混淆 JavaScript 主脚本，保留原代码、操控、资源与规则。不采用工作流默认 Canvas 2D 重写，也不迁移 Cocos。后续若框架配置影响执行，应调整工作流配置适配原包，而不是替换游戏。

本轮没有启动游戏、联网访问商店、观看竞品视频或查看游戏截图；不存在实际运行通过证据。用户已明确同意使用其公开商店采集资料作为二手来源继续研究。目标市场、设备范围、SDK目标、真实联网方案、商业授权和单局时长均未知。未生成美术、未发布、未更改用户本地项目；仅在研究工作区提取一份只读参考脚本并编写报告。

## 核心循环、规则状态与操控

静态重建的循环：选择模式 → 选择球桌 → 初始化棋盘与比分 → 当前回合摆放击球器 → 拖动瞄准/蓄力 → 释放击球 → 碰撞与进袋 → 等待物体停止 → 回合计分、返子/覆盖或换手 → 终局结算 → 返回选桌并开始下一局。此为代码路径概括，尚无完整对局证据。

状态至少包括模式 `_0x5d148e`、球桌索引 `_0x408018`、双方棋子数组 `_0x3e4566`/`_0x2a9c75`、额外棋子数组 `_0x3231b3`、本杆进袋队列 `_0x31089b`、双方分数 `_0x4d3bf1`/`_0x41f634`、当前回合字段 `_0x209883`、输入/拖动门禁、刚体位置速度、传感器状态、剩余回合计时、教程状态、金币与装备。字段业务名称中部分属于依据分支作出的解释，后续需运行观测确认。

输入窗口：pointerdown处理先排除教程特定步骤，要求 `_0x55e693` 与 `_0x209883` 为真且没有正在拖动；释放仅在拖动状态处理，并立即清除拖动标记。力度低于0.25时不走击球提交分支。拖动距离除以最大拖动距离形成力度并上限截断；最大距离在重开时设置为75+25×装备属性。力度提交表达式为strength×100×1.25，范围候选为31.25至125；这不是已测速度或冲量单位。击球器方法在提交时关闭传感器并唤醒刚体。摆放横坐标常量范围为162至483，属于内部逻辑坐标，不能当CSS像素。取消、多指、窗口外释放与重复事件需后续真实输入验证。

非首张球桌存在更新次数驱动的回合倒计时，耗尽后换手；初始数组为[6000,1500,1200,900,600]更新单位，并叠加装备属性×2。尚未验证真实秒数、后台恢复及ticker钳制行为。不能对玩家承诺固定秒数。

## 物理步长、碰撞与容差

物理世界以(0,0)创建。更新尾部存在固定参数调用 `(1/60,10,10)` 后clearForces；结合唯一World对象及Planck API形态，作为固定步进静态候选。ticker增量累积到 `_0x990fb7`，当严格大于1时逐次扣1并调用更新函数。源码显示有累积补步；尚未核实库ticker上限、长帧丢时与真实快慢帧行为，不能声称全平台确定性。

物理和显示换算常量为100。四边创建静态刚体；棋子使用圆形状半径16/100，设bullet=true、angularDamping=0.2、linearDamping=1.8；击球器设bullet=true、angularDamping=5、linearDamping=2.8。其他fixture属性仍为混淆索引，不未经映射认定恢复系数或密度。棋子与击球器存在速度绝对分量和低于0.2时休眠的候选逻辑，须完成字符串映射及观测确认。bullet标志不等于已通过防穿透测试。

进袋分支使用与四角目标距离≤20的判断，并移除刚体/数组项后播放表现；其属于游戏逻辑距离触发，不应与边界碰撞混为一谈。完整遍历、单杆多子去重、进袋顺序与终局依赖需运行验证。

以下为后续验收建议，均不是原版实测参数：同一构建、同一初始局面和同一固定输入按物理步编号对齐，重复10次，停止位置差建议≤2逻辑像素；碰撞、进袋归属、计分、犯规和胜负必须完全一致。力度边界测试0.249/0.250/0.251，距离触发边界19.9/20/20.1逻辑像素，避免把浮点边界当手感评价。30/60/120Hz与250ms长帧比较相同物理步后的局面；若分支接近袋口导致结果变化，独立记录轨迹与阈值，不放宽胜负正确性。坐标映射建议点击误差≤2逻辑像素；阈值须在首次运行基线后复核，未经用户决策不修改原逻辑。

手感：三竞品均无实测或已观看视频，力度曲线、瞄准辅助、边库反弹、碰撞衰减、输入延迟和单杆等待时间全部未知。原包具有拖动距离、力度门槛及装备属性相关参数，仅能提出“装备可能影响操作尺度”的设计推断，不能判断公平性或优劣。后续须统一初始棋局、屏幕条件和操作任务，分别记录命中率、操作修正次数和主观评分。

模式：原包Disc Pool不生成额外type0棋子；Carrom与Freestyle生成额外棋子；Freestyle走分值目标分支。竞品的同名模式不保证同规则，优先核对红子覆盖、犯规、最后一子、同杆进多子、连杆和超时。
