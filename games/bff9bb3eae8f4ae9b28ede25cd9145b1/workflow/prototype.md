# Carrom Freestyle 超目标胜负规则只读审核

## 范围与结论

本轮为原型阶段只读审核，只新增本报告及已提取的历史研究文本；未修改游戏代码、配置或资源，未执行游戏、构建、单测或浏览器验证。下文测试均为待执行方案。任务是审查当前 Freestyle 结算边界，采用所选技能的证据分级、版本隔离与单一结算 owner 方法；当前材料使用 PIXI、Tweener 等标识，未证明属于 Cocos，因此不套用该模块的 Cocos 专用接口。

1. 当前用户提供片段明确使用双方分数 `>= _0x153877`，因此 170/160 可以触发达标，不能改为必须恰好160。
2. 所示 Freestyle 达标条件没有红球数组为空的检查。用户竞品观察与当前构造样本支持“红球仍在时也可结束”的特定场景，不证明红球入袋后的覆盖或处罚规则。
3. 达标后调用 `_0x47e567` 的布尔值来自 `_0x209883`，而非比较哪一方分数达标；若非行动方已达标或双方同时达标，存在误归属候选风险。正常流程能否到达这些状态尚未证明。
4. 分数在 Tween 的 `onComplete` 内累加，结算使用另一个延迟回调，未见等待全部计分回调完成的显式屏障。普通时序可能足够，但不能据此证明暂停、取消或回调顺序变化时安全。
5. 达标检查先于 `_0x4268e2 && !_0x5ebd99` 扣50分分支，达标后直接return。不过 Freestyle 分支入口先将 `_0x4268e2` 清零，故不能直接宣称“母球犯规扣50被胜利覆盖”；首先应证明该分支在当前结算阶段可达，并确认标志语义。

## 核心循环、状态与责任边界

审核所需循环：合法出杆 → 物理运动与落袋事件 → 等待物体休眠 → 本杆落袋列表处理／犯规返球或计分动画 → 分数与处罚结算 → 胜负或下一行动方 → 结果及奖励。最后一步当前完整owner尚未取得。

最小状态包括：roundId、turnId、settledTurn、局激活状态、行动方、双方分数、目标分、本杆落袋集合、母球入袋标志、红球及覆盖状态、待完成计分／返球回调、结果提交标志。画面红球可见、红球逻辑数组数量及待返球对象是不同证据，不能互相替代。

E-01显示的候选责任：`_0xbdafb3`负责静止后发起本杆结算；计分Tween回调写入双方分数；延迟回调负责达标判断、后续扣分和换手；`_0x47e567`为结果提交入口。没有完整当前源码，尚不能证明它们是全工程唯一写入者。

入口顺序：检查expectedTurn及重复结算 → 检查局激活 → 若仍运动则以参数50再次调度 → 标记本杆已结算 → Freestyle入口清除 `_0x4268e2` → 逐个处理本杆球 → 独立调度最终判断。该去重保护入口，不自动保证每个计分回调、最终判断和奖励都具有同等幂等性。

## 规则判定与风险

### 达标、红球与胜者

`playerScore >= target || opponentScore >= target` 表示至少一方达到或超过目标。所示分支没有红球前置条件，也没有exact-score限制。E-02只覆盖对手超目标导致玩家败局；E-03补充了双方各自构造场景。二者均不覆盖红球已经入袋、未覆盖、同杆母球入袋等组合。

达标后使用行动方选择胜败。反例夹具可设玩家170、对手150、目标160、行动方为对手，当前条件会进入达标并传false；这是静态可构造路径，是否为合法自然状态需要验证。双方都达标亦无明确冲突策略。

### 母球犯规与扣分

E-05约4881—4900行显示母球对象落袋路径设置 `_0x530863=true` 并触发 `_0x21acae`；2718—2770行所示 `_0x21acae` 主要创建和清除犯规表现，不足以证明扣分规则。E-01在 `_0x530863` 为真时选择返球动画，跳过该循环内的普通加分路径，并将 `_0x5ebd99` 清零。因此本段可见的母球处理更接近返还本杆球／取消本段得分及影响换手，不能简化为一律扣50。完整规则仍缺当前落袋处理与其他分数写入者。

E-05的4913、4993、5073、5153行在同一球集合落袋路径设置 `_0x4268e2`，其他球落袋路径可清除它；结合红球数组线索，它属于红球／覆盖候选标志，不能与母球标志混称。当前片段还主动清零该标志。若期间没有其他写入，后续扣50分支不可达；若有迟到落袋或其他异步写入，则须记录实际路径。

如果扣分分支确实可达，当前源码明确先判达标再扣分：170/160会先结束，不会在本分支减50后按120继续。这只是当前控制流事实，是否符合产品规则仍缺竞品对应观察。

### 动画与生命周期

E-01计分动画参数：玩家15+random×10，对手15；返球20+random×10；最终判断参数无球500、有球1000。这些不是已证实的毫秒或物理步长。E-05调度器5662—5674行将传入参数转换为 `(delay/1000)*60` 后交给Tweener，且绑定roundId；当前调度器、Tweener单位和更新顺序未取得。

没有显式pending计数／完成屏障，因此延迟判断先于计分、部分计分后先结束或回调取消造成少计分是待验证风险。不能仅以参数较长判定安全，也不能据此宣称自然对局已出现错误。

计分与返球回调检查局激活及roundId，未见turnId或resultCommitted检查。若同局已换手或结果提交后局仍激活，迟到回调可能继续写分或返球；是否会发生取决于完整生命周期。最终判断回调本体只检查激活状态，当前 `_0x338c29` 是否还提供round/turn隔离未知。E-05结果入口2798—2800行有结果去重，但该历史防护不能替代当前核验。

## 物理、输入与界面约束

本轮保留现有玩法与布局，不新增游戏或改动操作手感。已有表现使用PIXI线索，不能因工程选定原生Web而声称已迁移为DOM/SVG/Canvas新实现。审核界面关注双方分数／目标、当前行动方、红球画面、犯规反馈、胜败面板及金币变化；未实际查看当前画面或确认布局坐标。若后续新增面向玩家的文案，默认English，HTML入口使用lang=en；本轮没有界面改动。

物理步长：当前片段未给出world.step，历史文本的字面搜索也未定位可确认调用，故数值未知，不把50轮询参数或60动画换算当作物理Hz。碰撞：保留现有碰撞体和触发器；E-05可见历史落袋距离阈值20，但当前尺度、碰撞半径与高速穿透未验证。计分：使用整数分与>=阈值，分数、胜负、奖励次数容差为0。输入窗口：建议验收只在当前合法瞄准态接受出杆，运动、结算及结果态拒绝重复出杆；当前完整输入门禁未知。

待执行物理复现需固定同一构建、初始位置速度、输入坐标／力度、随机源及实际物理dt。先取得并记录当前dt、补步／长帧策略与休眠阈值。跨帧率允许位置／时间浮点偏差，但落袋对象、计分、胜者与奖励次数必须一致；空间误差阈值须按当前单位与口袋边界校准后确定，本轮不编造精度。边界球与非边界球分开记录，不能用人为扩大袋口容差掩盖碰撞差异。
