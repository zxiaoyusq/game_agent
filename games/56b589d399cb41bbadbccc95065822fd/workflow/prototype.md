## 3. 等价命题与证明义务

设一次调用为 F，索引 i∈{0,…,6}，目标为 t。基线在实际访问时计算：

`B(i,t) = _0x23a7dc(P(i,t), R(i,t))`。

候选首次访问 i 时保存 `C[i]=B(i,tFirst)`，后续目标只复用该值。需要成立的是：在实际访问序列中，所有后续 `B(i,t)` 与首次值严格相同，并且省去的调用不影响其他可观察行为。输入和依赖完全稳定是充分条件，不是必要条件；棋子变化但结果恰好相同的个别样本不足以建立通用保证。

### 必须核验的充分前提

1. **缓存键完整**：相同 i 对应相同 x、y、坐标系、基线边界及阈值 R。候选生成不能使用目标偏移；阈值不能随目标/棋子类型变化。不得因为“都是第 i 项”就认定位置相同。
2. **依赖稳定**：三数组成员、影响判断的顺序与访问行为、对象坐标、距离函数实现及其环境读取在首次与复用之间稳定。数组连接只复制引用，不冻结棋子对象。
3. **检查可省略**：检查及其依赖不存在会影响玩法的计数器、随机数消耗、getter/Proxy 写入、时间依赖、同步回调、惰性状态刷新或异常差异。无显式赋值不等于纯函数。
4. **返回契约**：正常返回只可能为原始 true 或 false，不是 undefined、0/1、Promise、Boolean 对象或其他 truthy/falsy 值。候选保持原比较/分支语义，不额外强制转换结果。
5. **生命周期封闭**：每次 F 单独创建缓存，不提升到模块、对象、回合或闭包中跨调用共享；没有中途 await/yield 或复用到计时器/动画回调。
6. **控制流不变**：缓存只替换原位置的落点检查，不预计算全部七项；合法目标过滤、目标/位置顺序、随机数调用顺序、提前返回、失败返回、路径检查、方向距离计算、出杆与结算均不变。
7. **运行环境**：常规可信 JS 内建对象与普通数组，缓存索引是整数 0..6，无意外覆盖或原型数值属性污染；距离运算读取普通稳定数字。内存耗尽等资源异常不在“所有运行环境绝对等价”的承诺内，新增数组分配仍需性能评估。

满足上述条件时，可按访问顺序归纳：首次计算与基线相同；复用值与该时刻基线检查相同；对应分支相同，其他执行保持原序，因此完整选杆输出、随机源状态与游戏状态变化相同。**落点检查调用次数、连接产生的临时数组数和 CPU/分配量允许不同，正是优化目的；有玩法意义的被省略副作用不允许不同。**

这不是仅比较 pos 的证明。验收还需比较目标身份（如内部使用）、dir、力度/距离等实际返回字段、null/失败形态、首个可行目标、随机源消费以及后续调用顺序。具体字段以现版契约为准，不从历史猜全。

## 4. 对象坐标与同步时序

普通浏览器主线程 JavaScript 按运行至完成执行；没有挂起或特殊重入时，rAF、定时器、输入事件和 Promise 微任务不会在一个普通同步调用的两条语句之间自动插入。墙钟时间经过、棋子原先有速度，并不意味着主线程对象 x/y 会自行更新。

但同步调用期间仍可能改变坐标：
- 外层目标循环或它调用的路径/角度/距离函数直接执行物理 step、纠正位置、推进 tween、写 worldX/worldY、增删棋子或重置回合。
- x/y 是 getter，读取时刷新物理位置或返回时间依赖数值；函数自身“无写入”仍可能触发访问器写入。
- 某同步调用触发用户回调、dispatchEvent 或宿主桥重入，回调修改棋盘后继续外层函数。
- 连接过程遇到 Proxy、数组访问器、Symbol.isConcatSpreadable/Symbol.species 或被改写的 concat；检查/距离函数被包装或替换。
- 坐标来自 SharedArrayBuffer、共享原生状态或同步访问器包装的其他执行线程；普通 worker 消息不会插入，但共享内存读可能观察并发更新。

对象“可以改变”与“本调用内实际会改变”是两回事。需要现版从首次填槽到最后命中的可达调用链及属性描述证据。不能只审 `_0x23a7dc` 函数体。

函数局部缓存使普通递归/重入的每次调用有独立数组，但重入若修改棋盘，返回后外层数组仍会过期；“局部”不自动处理这一问题。

## 5. 缓存类型、哨兵及惰性语义

`new Array(7)` 是七个空槽；普通干净原型环境下读取空槽为 undefined。true 与 false 都必须视为已计算。

审查推荐的概念写法（仅说明，不是现版补丁，未运行）：

```js
let blocked = positionBlockedCache[candidateIndex];
if (blocked === undefined) {
  blocked = _0x23a7dc(alternativePos, radius);
  positionBlockedCache[candidateIndex] = blocked;
}
if (blocked) continue;
```

使用 `if (!cache[i])`、`cache[i] || check(...)` 会把已缓存 false 当未计算，破坏调用上界与收益；检查副作用存在时还可能改变行为。类型若不保证 boolean，应先明确真实契约，而不是用 `!!result` 掩盖不符合契约的数据。Promise 与 Boolean 对象在 if 中都为真，不能当作等价布尔缓存。

undefined 哨兵依赖检查不会合法返回 undefined，且数组原型无相应数字键。若工程允许原型污染，应显式核验槽是否属于数组自身或用独立已计算标志，并评估额外改动；这属于条件不满足后的方案调整，不宣称拟议补丁已经防护。异常未正常返回时不要缓存、吞掉异常或用 false 替代。

惰性填槽保持未访问位置不调用检查；保留原检查点，避免把原本提前成功、提前失败或非法目标后才调用的计算前移。

## 6. 浮点及可接受误差

缓存不改变几何公式，只复用其原始布尔结果。相同数字输入、相同运算路径与稳定读取，在同一运行环境下应得到相同结果；浮点本身不是重复计算值必然变化的理由。

要求：不同时改 sqrt 为平方距离、不改 `<` 为 `<=`、不重排候选坐标表达式、不量化坐标、不新增 epsilon。`a + b*i/6` 与 `a + b*(i/6)` 可能因舍入不同，不应在本补丁中顺手改写。

即使变化很小，也可能跨过距离阈值：对 P=(0,0)、R=1，棋子由 x=1−δ 移到 x=1+δ，δ 为可表示的小正数，落点结果由 true 变 false。反向变化也成立。**布尔决策、目标选择与随机消费容许差异为零**；不能以“坐标只差 1 像素”验证缓存正确。

NaN、Infinity、负/零阈值、null 棋子、稀疏数组、非数字坐标可能导致原版意外 false 或抛错；本优化不得顺手修正。应分开做输入有效性审查，并保留基线实际行为。JSON 对 NaN、Infinity、undefined、−0 等信息有损，不应用单一 JSON 字符串作为所有边界测试的比较器。跨浏览器不要求物理轨迹逐帧位级一致，但每个环境内应分别执行基线/候选差分。

## 7. 生命周期、玩法状态及降级边界

本轮审查的子循环：取得合法目标与初始落点 → 首目标尝试七位置 → 按原顺序换合法目标并尝试同七位置 → 返回原选杆结果/原失败值 → 交回现版调用者。缓存只用于七位置的占位判定，不用于目标相关路径。

| 项目 | 本轮决定 |
|---|---|
| 物理步长 | 不新增、不修改；现版 step、补步/截断与选杆时机未知。须证明填槽至最后复用不推进影响坐标的 step，或证明结果稳定 |
| 碰撞 | 仅缓存现有落点占位布尔值；历史为距离严格小于阈值，现版确切公式和接触边界待核验；不代替路径/动态碰撞 |
| 成功/失败 | 保持现版首个可行选杆、无目标、七项全阻挡、全路径失败及降级结果；最终形态待现版代码提供 |
| 计分/胜负 | 完全沿用现版；未取得计分和结算规则，不编造 Carrom 模式规则 |
| 输入窗口 | 缓存仅存在同步选杆内部，不允许跨输入事件、动画或回合；玩家输入门禁与选杆调度待核验，不另设窗口 |
| 暂停/重开/新回合 | 每次调用重新分配；不保存缓存；后续重新选杆也新建缓存，旧回合异步结果防护必须原样保留 |
| 界面布局 | 不改棋盘、HUD、教程、按钮或可访问文案；无本轮界面产物。若后续新增玩家内容，默认英文，Web 英文版本 lang=en |
| 可接受误差 | 缓存布尔值、返回选择、失败分支与随机消费零差异；物理轨迹沿用现版容差，本轮不指定新数值 |

降级策略（建议，未实施）：
1. 未能证明稳定读取或纯检查时，保留原版重复检查，不启用缓存；不要强行用快照把原本会变化的算法冻结。
2. 一旦发现调用内可能写棋盘、改阈值或改候选坐标，应撤回优化；若未来必须保留缓存，需要完整失效机制/更完整键并重新审查，不能只靠数组长度或参考对象身份判定未变化。
3. 局部缓存不得用于选杆后动画或发射前复检；保留现版既有重新验证、有限重试、无杆降级、回合失效门禁。历史有防护不代表现版已核验。
4. 出现差分时先禁用候选并保存基线、种子、局面和首个分歧；不可自动挑其他目标、扩大七项采样、改顺序或吞异常来“修复”。
5. 性能收益不足时回退原版；不因检查次数下降而跳过真实性能验证。重选/提交前额外检查若原版没有，属于新的行为变更，不能混入“其他逻辑不变”。

## 8. 失效反例（推理构造，未执行）

| 反例 | 基线与缓存为何可能分歧 | 所需处置 |
|---|---|---|
| 首目标之后路径函数移动一颗棋子离开 i 位置 | 基线后续 false；缓存仍 true，错过可行杆 | 证明无写入，否则不用缓存 |
| 首目标之后棋子移入 i 位置 | 基线后续 true；缓存 false，错误接受重叠 | 同上 |
| 目标不同使 i 对应坐标或 R 改变 | 索引不足以表达检查输入 | 固定输入证明或另案扩充键 |
| 距离读取 getter 每次推进位置；检查消耗 RNG/写计数用于策略 | 省去检查改变读值或后续随机/策略 | 证明纯读取，不能只看本体 |
| 重入回调切换回合/更换数组后返回 | 外层缓存与旧棋盘绑定；局部隔离仍不够 | 生命周期与重入门禁核验 |
| 错误缓存路径检查结果 | intendedTarget 不同，排除对象不同 | 只缓存占位布尔值 |
| 以 falsy 当未计算 | false 重算；不能得到预期调用上界 | 使用明确未计算判定 |
| 跨回合/动画持久化数组 | 旧占位结果污染新棋局 | 仅每次同步调用局部数组 |
| 后续读取本应抛异常或触发必须执行的副作用 | 命中缓存跳过读取，基线抛错/写状态而候选不发生 | 保留原异常契约，证明可省略 |
| 原型数字属性或非 boolean 返回 | 空槽可能读到继承值，或哨兵/真值解释错误 | 明确环境和返回类型，必要时另案加强 |
