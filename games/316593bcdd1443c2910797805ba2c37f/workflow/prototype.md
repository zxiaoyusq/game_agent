# Carrom Freestyle 红棋未覆盖回归审查

## 范围与结论

当前阶段：原型定义；只读审查用户提供的当前结算函数与受控桌面样本，仅新增本报告，不修改游戏源码、资源、测试或历史 ZIP。任务走玩法算法与机制逆向模块，第一步是定位结算提交边界与状态 owner。可见结算入口为 `_0xbdafb3`，但跨杆红棋唯一 owner 尚无法由这一函数确认。

样本事实：红棋已计入玩家50分后，下一杆空杆，分数与历史不变、queen仍为0、turn从true变false。它支持“该次本机样本没有在空杆后撤销红棋收益或恢复红棋”，不能证明竞品算法、其他犯规路径或所有局面都如此。

静态发现：Freestyle分支入口显式执行 `_0x4268e2 = false`；其后可见代码不把该值设为true，却在延迟结算中用它控制返棋及减50分。除非被调函数或外部回调重新写入该变量，该回滚条件无法成立。这是可定位的状态丢失候选，不是完整根因证明。

建议采用持久的红棋状态、固定归属和逐杆事务结算；先完成覆盖、返棋、犯规与分数提交，再判断终局。以下规则是供实现评审的明确建议，不冒充竞品已证实规则。

## 当前函数能证明的路径

### 入口和幂等

1. expectedTurn默认取当前turnId；与当前turnId不一致或已等于settledTurn就返回。
2. 捕获settlementRound；非活动局直接返回；`_0x56abf7()`为真时以0x32即50的定时参数重试。函数实现缺失，不能直接等同于物理静止检测。
3. 通过检查后先写settledTurn，再调用 `_0x89ccbb()`，随后处理队列。它能拒绝入口重复调用，但不自动保证所有异步计分与终局完整、正确或失败可重试。若后续异常，settledTurn已经标记，本函数未显示恢复机制。

### Freestyle（mode == 2）

1. 入口把 `_0x4268e2` 清false，再取得队列副本。字符串字典缺失，不能无条件断言0x3c6必为slice；后续按该副本逐项处理是可见事实。
2. `_0x530863`为真时走重建棋子动画路径；否则按 `_0x1c2aac[...]` 生成加分文字，玩家/对手动画完成后分别累加分数与history。它的具体犯规语义只能作为候选。
3. type和queueIndex用let逐项捕获，round和expectedTurn也被捕获。actor却由安排动画时的 `_0x209883` 选择分支，外层延迟结算继续读取可变 `_0x209883`、`_0x5ebd99` 等字段；缺少不变的整杆上下文。
4. 每项安排动画后从原队列移除。history在动画完成时push，数组追加顺序未必等于入袋先后；queueIndex只能保留当次队列索引，不证明物理入袋时间。
5. 只有 `_0x530863 && queue.length === 0` 时，本函数显式调用 `_carromFreestylePenalty`，并通过pending对象等待。函数实现缺失，无法知道扣分、还棋、历史修改与同步回调约定。非空队列犯规走另一条恢复路径，不能断言它不罚分。
6. 延迟参数初始500，有队列变1000。Tweener的time另有数值与随机项，但单位/实现未知，不能将1000视为所有计分回调完成的证明。
7. `_carromAwaitPenalty`回调仅显式检查活动局，随后先检查任一分数达到阈值，调用 `_0x47e567` 并return；之后才检查 `_0x4268e2 && !_0x5ebd99` 来调用 `_0x52e61d()`并减50；最后决定下一位。由此存在“若回滚本应发生，阈值终局可能先退出”的静态风险。
8. 阈值分支按当前 `_0x209883` 选择胜负参数，而不是在此显式选择达到阈值的一方。是否错误依赖函数参数语义、行动方不变量和其他路径，尚不能定性。

### 跨杆覆盖缺口

此函数没有显式的queenOwner、红棋入袋杆ID、待覆盖期限或暂存红棋分数。若 `_0x4268e2` 是覆盖pending候选，则每次进入mode==2即清零会消除上杆信息；但不能凭变量名映射它就是queenFlag。`_0x5ebd99`可能与续杆有关，不能拿单个布尔值同时代表“本杆有得分”“红棋待覆盖”“谁拥有覆盖权”。必须补齐全部读写点后才能映射。

不能仅删掉清零行：这会保留没有owner、期限、局ID的悬挂状态，可能使对手完成覆盖、重复减分或旧局污染。

### 非Freestyle隔离

else分支按不同棋类分配计数，调用CarromDiscRules.hasWon，并在终局选择中检查红棋数组长度；该分支也把红棋返还处理放在终局判断之后。这里只能审查顺序，不把它当作Freestyle覆盖时序或计分政策。字符串'oponent'必须结合类型字典和生产者核对，不能因拼写就认定bug。

### 旧局与旧杆边界

计分与重建棋子Tween回调显式检查活动局和capturedRound；这是已有局隔离保护。回调未显式比较turnId，因此同局旧杆的晚到回调仍需验证；这些回调是否允许晚到，本轮无实现证明。

50重试依靠入口turn检查，但入口未接收capturedRound；若重开复用turnId，旧重试可能通过新局入口检查。外层500/1000延迟与AwaitPenalty后的回调未显式检查捕获round或turn；活动标志在新局重新变true时，不能单独拦住旧局任务。是否已有计时器撤销机制必须读实现。若 `_carromAwaitPenalty` 内部有保护，本函数无法看见。

## 可实现的建议规则P1（非竞品结论）

定义一杆为一次合法击球输入至物理停止并完成一次原子规则提交；turnId是杆ID，不能假定数值+1就是同一玩家下一杆。

核心循环：放置与瞄准 → 发射一次 → 收集物理事件 → 稳定边界结算 → 覆盖成功/继续覆盖/返棋/换手 → 允许下一杆；达到计分目标时在事务最后判断结束。本轮不新增关卡、成长、存档或美术。

P1选择：红棋价值50；同杆无犯规且至少一枚合格普通棋入袋即覆盖，顺序无关。红棋单独入袋建立pending，原击球者获得恰好一次后续覆盖击球机会；该杆无合格普通棋或犯规则失败、返红棋、取消红棋收益并换手。对手不能替前任owner覆盖。普通棋价值、Freestyle合格棋类型、普通棋犯规罚则与目标阈值从当前规则配置接入，本文不编造数值。

以上下一杆期限、同杆顺序无关、犯规优先都是建议政策；E-03不能证明它们。实现前需要产品选择或补充竞品实测，本轮不因此修改代码。

### 状态与所有者

建议唯一写入者 `settleShot`，表现层只读提交结果。

- `QueenState = ON_BOARD | PENDING | COVERED`。返棋是事务产生的效果，不必永久增加RETURNING业务状态。
- PENDING字段：roundId、owner、pocketShotId、coverShotId（分配下一次合法杆时绑定，初始null）、claimId、provisionalPoints=50。
- COVERED保留owner与claimId用于审计，pending字段清空。ON_BOARD没有owner和待覆盖收益。
- ShotContext不可变：roundId、shotId、actor、rulesVersion、preStateVersion；包含去重后的pocketEvents、foulEvents与物理停止标记。
- Ledger逐笔包含entryId、roundId、shotId、actor、discId、kind、amount、claimId、status；entryId按局/杆/棋子/事件类别确定，重复入袋和重复提交不加分。
- `committedShots`按(roundId,shotId)去重；用stateVersion拒绝过期上下文。owner只在ON_BOARD→PENDING/COVERED时从context.actor取得，之后不从可变turn字段重新推导。

### 转移表

|前态|本杆条件|后态与效果|
|---|---|---|
|ON_BOARD|没有红棋|按普通棋与犯规规则处理，不产生红棋收益|
|ON_BOARD|红棋，无犯规，无合格普通棋|PENDING(owner=actor)，暂存50，安排owner一次覆盖机会|
|ON_BOARD|红棋+合格普通棋，无犯规，任意事件顺序|COVERED(owner=actor)，确认红棋50与普通棋收益|
|ON_BOARD|红棋+任意棋，且犯规|保持ON_BOARD，红棋返还，无红棋收益；普通棋/罚分按现有独立政策|
|PENDING|owner的coverShotId，合格普通棋且无犯规|COVERED，暂存50转正式50，只确认一次|
|PENDING|owner的coverShotId，空杆或仅不合格棋|ON_BOARD，取消暂存50，返棋一次，换手|
|PENDING|owner的coverShotId，犯规，无论是否入普通棋|ON_BOARD，取消暂存50，返棋一次，独立处理犯规罚则|
|PENDING|下一行动者不是owner|覆盖权失效，先返棋取消暂存，再开放对手输入；对手普通棋不覆盖前任红棋|
|COVERED|后续空杆或犯规|不重新打开已关闭claim；是否返已覆盖红棋属于额外政策，P1不返|
|任意|重开/切局|新round初始ON_BOARD，清除本局pending；旧round结果无效果|

最后一枚普通棋与红棋同杆按同杆覆盖处理；红棋单独入袋且已经没有任何可覆盖普通棋时，P1立即判覆盖不可完成，返棋取消暂存，再按独立终局政策处理，不建立永远无法完成的pending。这是建议边界，需与实际Freestyle终局要求核对。

### 分数与回滚

推荐正式分数不含pending的50，HUD另显示 `Queen +50 pending`。覆盖成功才把对应claim从provisional转confirmed；失败删除暂存记录或追加cancel事件，不扣其他收益。

若兼容当前立即显示+50的模式，则显示分数=confirmed+provisional，胜负仅看confirmed。失败追加精确关联claimId的-50冲销，且每个claim最多冲销一次；不能使用“对当前行动者直接减50”来替代归属账本。不得把整个分数恢复为红棋入袋前快照，否则会抹掉期间合法普通棋收益。原history应保留原计分与冲销关联，不能凭最后一条记录删除来猜红棋。

犯规扣分与红棋冲销分开记账，避免一项处罚走两次。已有 `_carromFreestylePenalty` 是否已撤销红棋必须先核对；没有实现不能给出精确总罚分。目标阈值只在全部计分、覆盖、返棋和犯规事务处理完成后，按明确胜负函数判断；不能由当前行动者代替达标者选择胜方。若双方同杆都达标，平分/优先规则需补充，P1不猜。

### 原子结算顺序与伪流程

1. 检查活动round、shot身份、前置stateVersion与未提交状态；验证物理已停止、事件完整且数值有限。
2. 在状态副本中按discId去重并归一化入袋集合；用捕获actor处理已有pending到期，判定犯规，再处理本杆红棋与同杆覆盖。
3. 同一副本生成普通棋账本、红棋claim确认/取消、独立犯规项、返棋命令和下一行动者；不调用动画修改分数。
4. 在提交前再次检查round/stateVersion，原子发布棋盘逻辑状态、账本、owner、下一行动者、committedShots与结果。校验失败不留下半提交。
5. 只有无pending且满足已确定终局政策时进入FINISHED；如果普通棋收益已达阈值而红棋仍pending，P1延后终局至覆盖处理完毕。
6. 表现层消费带roundId/shotId/commitId的效果；分数动画只展示delta。返棋逻辑位置已在提交中预留，动画不能成为棋子存在的唯一依据。
7. 下一杆输入需物理稳定、规则提交完成且必要棋子放置完成；清理失败不能默认成功。异步完成令牌校验epoch，重开取消令牌并递增roundId；所有定时重试、罚分、Tween、上报回调都校验同一上下文。

这个顺序不依赖延长500/1000定时器。若需等待资源或返棋完成，用显式完成信号和可观察错误，而不是猜动画时长。

## 物理、输入与误差：审查边界及未来验证合同

当前摘录无法证明物理步长、碰撞算法、摩擦、质量、半径、力度区间、连续碰撞、速度静止阈值或输入窗口。现有受控样本也不足以恢复它们；不为只读修复分析擅自指定替代参数。现有物理应保持不变。

后续测试夹具建议固定模拟步长1/120秒，仅为新测试器的候选设置；必须先读实际循环，若其步长不同则记录并沿用真实值，不能拿候选当当前实现。记录每杆初始位置/速度、输入力度与方向、随机种子、step计数及入袋事件ID；渲染30/60/120Hz与100ms长帧使用相同模拟输入。

规则层直接使用确定的ShotContext，owner、分数、状态和事件次数容差为0；物理重放建议末态位置容差0.5逻辑单位、首次入袋时刻容差一个实际固定步，且入袋集合与覆盖结论必须一致。上述容差是建议验收标准，未测得也未证明适合当前物理。触袋临界轨迹单列，不用宽容差掩盖计分差异。

输入窗口建议只在AIMING接受一次发射；MOVING/SETTLING/FINISHED拒绝发射且不改变状态；pointercancel不出杆。物理静止后必须等入袋事件冻结与规则提交，再开放下一杆。暂停冻结模拟和输入，恢复时不一次补算整段后台时间；具体沿用策略需读现有代码。结算超时报告BLOCKED，不伪造静止或强制清盘。

碰撞回归包括棋-棋、棋-边、袋口边缘、高速薄边与重复触发；撞击事件不直接加分，只有唯一棋子有效入袋事件进入计分集合。返棋位置需使用现有合法放置算法；无空位时阻止下一杆并报告，不重叠放棋。
