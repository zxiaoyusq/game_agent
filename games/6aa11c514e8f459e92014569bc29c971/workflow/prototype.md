## 2. 变量与必要前提

令 S 为 E-03 两个栈地址共同使用的 SP 基准，T=S+0x190 为构造临时对象，U=S+0x10 为传入容器的临时对象，H 为宿主实例，C=H+0x168 为候选容器地址，N 为新分配节点基址，O=N+0x30 为其候选对象/值子对象起点，v 为入口 w7 的 32 位位模式。

这些是地址角色，不代表已经恢复 C++ 类型。T、U、O 可以是不同存储地址、持有相同字段值的对象副本；“值相等”不等于“对象指针相同”。

条件：
1. w20 在入口保存后至传入 w3 前未改写；0x1b2a800 至 0x1b1af98 的 w3 参数未改变。不能仅凭一次寄存器转移证明跨调用数据流完整。
2. E-02 的构造目标确为 T。E-03 读写地址使用同一实际 S，或已经正确补偿 SP 变化；不同栈帧中相同的文字 sp 不天然同址。
3. x3=U 的传递经 0x1b304b0 到 0x1b30584 后，x21 确实指向该源对象，未改为另一临时副本或别的参数。
4. 每次使用字段前，其字节未被其他构造、更新、销毁、并发或重入路径覆盖。
5. 分配及构造成功，N 被提交到 C 且存活，后续查找返回的就是这个 N 的 O。E-04 的分配本身不证明插入提交成功。
6. getter 使用 O 为字段基准，没有 thunk/基类调整或中间返回值替换。

## 3. 逐步代数核对

### 3.1 栈副本

在共同 S 前提下：

- T+0x174 = S+0x190+0x174 = S+0x304。
- U+0x174 = S+0x10+0x174 = S+0x184。
- 两个源/目的对象起点相差 0x180，字段起点也相差 0x180。
- 8 字节读区间为 [S+0x304,S+0x30c)，写区间为 [S+0x184,S+0x18c)，互不重叠。

因此 E-03 描述的是“对象内相同偏移的字节转存”，不是将字段移到 U+0x304。若两个地址对应不同 SP 时刻，以上结果必须加上实际 SP 差值；摘要尚不足以核对栈分配范围。

### 3.2 节点布局

E-04 的目的字段是 N+0x1a4，而 E-05 返回 O=N+0x30：

`O+0x174 = N+0x30+0x174 = N+0x1a4`。

反向核对：`0x1a4-0x174=0x30`，与返回值偏移一致。故 E-06 若读取这个 O+0x174，读的正是节点复制目的起点。

这条等式对 getter 指向字段的支持，比“+0x30 似为整个对象起点”的类型推断更强；仍不能仅凭它给整个结构命名。

### 3.3 分配边界

8 字节目的区间为 [N+0x1a4,N+0x1ac)，即最后一个字节 N+0x1ab。分配区间为 [N,N+0x1b0)。`0x1ac ≤ 0x1b0`，末尾还剩 4 字节。因此该次复制不因这些偏移而越过所述分配边界。

从 O 观察，节点余下空间为 0x1b0-0x30=0x180；复制区间在对象相对位置 [0x174,0x17c)，仍留下 4 字节。不能由此推出 sizeof(对象)=0x180、对象成员类型或其他复制操作均安全。

## 4. 拷贝宽度、端序与字段类型

- w3 表示 32 位寄存器位模式。若实际写入是 `str w3`，初始化的是对象 [0x174,0x178) 的 4 字节；写 W 寄存器会清对应 X 寄存器高位，但不会清对象中紧邻的 [0x178,0x17c)。摘要没有证明这后 4 字节初始化情况。
- 8 字节复制覆盖 [0x174,0x17c)，并不证明 +0x174 是 uint64_t 字段。它可以是合并复制两个 32 位字段，也可能包含填充。不能将“复制 8 字节”直接称为“selector 为 64 位”。
- 若是同一目标数据端序下普通 64 位 load/store，并且中间没有移位、字节翻转或重组，则 8 个地址字节按原位置保存，与端序无关。仅凭“ARM64”不单独宣布目标为小端；未读取头部或指令序列。
- 小端下，+0x174 的 32 位内容在该 64 位装载值的低 32 位，+0x178 的内容在高 32 位；大端下两者对应相反。完整 64 位原样转存均能保持地址上的字节次序；不能从小端寄存器拆分假设推断大端行为。
- 若 0x1b1afd4 最终是从 O+0x174 的 32 位读取，且参数链和两次复制未改变这些字节，返回的 32 位位模式可等于 v。若是 64 位读取，它还包含 +0x178 的 4 字节，不能断言整个返回值等于入口 w7。
- 若 getter 或索引转换使用符号扩展、零扩展或截断，业务数值解释不同。位模式相同不证明有符号值、无符号值或有效配置 ID 相同；摘要未提供 getter 宽度、返回转换和配置边界。
- +0x174 与 +0x1a4 都不是 8 的整数倍。常规普通非对齐 load/store 不必然无效；但不能从摘要替代对实际指令类别、基址对齐、内存属性和对齐限制的核验，也不据“8 字节复制”承诺原子性。

## 5. 同容器不同入口的别名条件

添加入口与查找入口共享 +0x168 只支持“同一种宿主布局的候选成员”，不是跨调用同一容器实例的充分证据。

必须区分：

1. **成员地址一致**：H_add+0x168 与 H_find+0x168。只有两个 H 是同一存活实例、使用同一完整对象/子对象基准、没有生命周期复用，才可直接认作同一成员地址。
2. **实际存储一致**：+0x168 可能是内嵌容器，也可能是句柄/包装层或指针槽；应沿入口的解引用/this 调整追踪到同一实际容器存储。不同包装地址也可能指向同一底层容器，同一槽地址也可能在中间换绑目标。
3. **键关系一致**：两入口使用相同键构造、比较/哈希/归一化规则并落在同一等价类。selector 可能只是值对象中的配置字段，不证明它就是容器键；不得把本请求中的 selector 与匹配键合并。
4. **节点身份一致**：新节点必须完成提交；查找时未擦除/替换该条目或遭地址复用，并且查找返回该 N+0x30。容器相同且键等价只把范围缩小到对应条目，不自动证明它是本次构造的节点。
5. **消费对象一致**：查找返回值经 0x1b2c3a4 到 getter 时仍为同一对象基准；失败返回、条件替换、子对象调整、对象重建等都需要排除。

容器迁移或重建可能保留值而改变节点身份；地址数值偶然相同也不能证明跨生命周期的身份相同。

## 6. 新增节点与已有键必须分开

| 情形 | 摘要所能支持 | 不可直接断言 |
|---|---|---|
| 键不存在，成功构造并提交 N | 两次复制使候选字段字节进入 N；若随后命中 N，getter 地址对应成立 | 分配就等于提交；每次 add 都走此分支；本次出杆必然读取它 |
| 已有等价键，插入保留已有节点 | 若该语义成立，查找返回旧节点对象，值可能是旧字段 | 新构造 selector 覆盖了旧值 |
| 已有键，原位赋值/更新 | 只有更新路径确实写到旧 O+0x174，才可能读本次字段 | 新节点复制语句本身证明旧节点发生更新 |
| 已有键，替换节点 | 需证明旧条目移除、新节点提交、后续查找命中新节点 | 一次 allocate/copy 就完成替换 |
| 先构造候选节点，再发现重复键 | 候选节点可以复制后销毁，最后仍返回旧节点 | 观察到构造复制即可证明容器字段变化 |
| 容器允许多个等价键 | 需确认查找返回哪一节点、排序/插入策略与键等价关系 | 匹配键就唯一命中本次节点 |
| 查找失败 | 摘要只描述匹配成功返回节点+0x30 | 未命中也返回可用对象；getter 总会执行且安全 |

这些是互斥或可组合的待排查语义，不是声明该实现属于某一种标准容器。未提供 0x1b304b0/0x1b30584 的完整分支和返回契约，不能命名为 emplace、insert_or_assign 或唯一键 map。

## 7. 断言范围

**PASS（摘要条件下）**：

- `0x190+0x174=0x304`，`0x10+0x174=0x184`。
- `0x30+0x174=0x1a4`，节点字段目的地址与返回对象读取地址在代数上相同。
- [0x1a4,0x1ac) 位于所述 0x1b0 字节分配内。
- 普通原样 8 字节复制能保存起始处 4 字节，不需要把整个字段推断为 64 位。

**NEEDS_CONTEXT（仅条件性成立）**：

“若入口寄存器链、临时对象基准、两次原样复制、新节点提交、同一存活容器与键、同一节点命中和无中途覆盖全部成立，则 getter 读取的起始字节来自本次传入值；进一步确认 32 位读取和无业务转换后，才可断言读出的 32 位位模式与入口 w7 相等。”

**不成立的证明方式（不是目标行为反例）**：仅由相同 +0x168 推出同实例；仅由 allocate 推出插入成功；仅由 copy 8 推出 64 位 selector；把重复键路径并入新增节点；仅由调用图推出每次出杆必命中。上述推论均缺必要前提。

E-06 最多提供“该字段在所述消费路径上作为 extraMaxPower 查询索引”的语义关联。不能推出索引范围合法、配置表返回什么值、查询是否成功、缺省处理、倍率/加法规则或最终 Force 数值。也不证明候选 addStriker 名称已与 selector/注册表独立配对。
