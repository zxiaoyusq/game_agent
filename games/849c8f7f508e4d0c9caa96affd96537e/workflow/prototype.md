# Carrom 宿主暂停补丁兼容性复审

## 范围与证据

本轮为原型阶段的只读源码研究，仅新增本报告，不修改游戏源码、资源或测试。新版源码未提供，补丁内容全部来自调用方描述；以下不是新版完整审计，也不是运行结论。

唯一源码参考：ref/mcp-inputs/mac-codex/dd8b79747ae3b111ad0a83ec8088b69b7632ec9f122e685b76601e731d52ffe8/Carrom_current_dd8b7974.js。已通过 read_reference 连续读取字符区间 0—528000，覆盖本报告所引函数及 Tweener 实现。路径中的 dd8b79747ae3b111ad0a83ec8088b69b7632ec9f122e685b76601e731d52ffe8 为输入标识，本次读取结果未独立返回文件哈希，不将其冒称重新计算值。定位采用函数名，未伪造行号。

已读取 casual-game-production/SKILL.md 1.3.0 和本轮冻结的 general、physics、web-common、native-web 四份资料。生产指南用于组织证据和验收，不扩展本次为制作新游戏或框架迁移。旧代码实际使用 PIXI、Planck、Howler，应保留既有工程。

## 结论与设计取舍

独立 hostPaused、取消玩家瞄准、清零补步余额及更新入口阻断，方向上可与旧版并存。公开 resume 只释放宿主自己的暂停原因，不应清除菜单标志 _0x3e61d0，也不应无条件启动 ticker、启用全部 PIXI 控件或解除其他原因的静音。

现有描述不足以证明全局冻结：原生计时器、SDK 回调、声音、既有输入内部状态及同批 Tweener 回调不由两个更新入口完全约束。以下 P1 是交付前应核查或修正的高优先项，P2 是兼容性及语义完善项；没有足够证据定为必现 P0。

## 风险、反例与建议

### P1：早期 pause 对未初始化对象的直接访问

旧版公开 pause/resume 为空；_0x423f7f 在 _0xa07a9b 创建，_0x147a99 在资源加载完成后的 _0xf8ddc7 才创建。若设计中的 `_0x147a99._sliding=false` 没有对象判空，在应用创建前或加载过程中调用 pause 即可抛 TypeError。`app.view.style 存在` 必须逐级检查应用、view、style，不能先解引用不存在的应用。

反例：脚本公开 game 后、资源完成前调用 pause；若先设置 hostPaused 再抛错，第二次幂等 pause 直接返回，可能永远不执行后续输入封锁。即使判空，早期 pause 未遇到 view，后续 view 创建也不会自动继承 pointerEvents=none，两个更新入口只能挡更新，不能替代全部 UI 输入封锁。

建议：将暂停原因登记与已存在对象的副作用分离；对象初始化时应用当前暂停状态。缓存明确的 view 身份和缓存有效标志；resume 仅恢复实际缓存过的对象。验收覆盖 init 前、加载中、对象创建后，以及每个时点 pause/pause/resume/resume。

### P1：匹配原生 setTimeout 不受更新入口保护

旧版 _0x104b9b 的 startRoll 使用 0xbb8=3000ms 原生 setTimeout 调用头像 stop；头像 stop 事件处理又安排 0xbea=3050ms 或 0x3e8=1000ms 的原生 setTimeout 发出 ready。_0x3153fe 注册 ready 回调并调用 showStartingShuffle。上述回调没有宿主暂停判断，也没有在这些位置保存并清理定时器。

反例：匹配 stop 事件已安排 ready 后宿主暂停，墙钟到期仍 emit ready 并建立开局动画。动画可被 Tweener 冻结，但匹配状态与动画注册已经在暂停期间变化；不能直接声称棋局必然已经开始。若期间重开或切场景，旧匹配回调也可能继续向旧对象发事件，需另外核对生命周期。

建议：匹配采用可暂停的剩余时间调度，或将到期动作保留到恢复后且验证场景代次。不要直接换成 _0x338c29：该入口要求 _0x3fddb3 为真，而匹配阶段该值为假，会吞掉回调。验收分别在3000ms回调前、ready计时期间暂停，并在暂停时切场景/重开，确保不提前推进且旧回调不影响新场景。

### P1：Tweener.update 后的检查不能中断其内部回调

旧版 Tweener.update 遍历可变 tweens 数组，逐个调用 update；Tween.update 在 onUpdate 后仍可能执行 onComplete，外层遍历也没有 hostPaused 检查。

反例：某 Tween 回调同步调用 game.pause，返回后当前 Tween 的完成分支及后续 Tween 仍可能修改分数、创建对象或触发AI动作。新增 _0x49d791 在 Tweener.update 后检查，只能阻止本次后续棋盘扫描和物理步，无法撤销这些回调。普通浏览器异步事件不会任意打断同步栈，此问题针对SDK同步重入或回调主动调用pause，不能描述为所有帧必现。

建议：定义暂停生效边界。若承诺 pause 返回后没有业务推进，须在调度循环和关键业务提交前检查，并保留未完成任务以便恢复；仅在一次性 onComplete 开头 return 可能永久丢失任务。验收安排同批两个Tween，前一个同步pause，后一个准备计分/AI击球；检查暂停后的提交和恢复恰好一次。

### P1：广告状态与宿主暂停分属不同控制路径

_0x248455、_0x2e33a4 的 beforeAd 直接 Howler.mute(true)、ticker.stop；广告结束及异常恢复分支直接按 _0x7fd997 || !_0x270daf 恢复静音并 ticker.start。_carromResolveAd 还直接调用奖励业务回调，旧版结算广告回调会增币、保存和切换界面。

反例A：广告中收到宿主pause，广告结束后ticker虽重启，但若两个入口检查正确，物理仍被hostPaused挡住，因此不能称广告必然恢复物理；声音却没有hostPaused参与，可能重新发声。反例B：宿主暂停期间adViewed仍提交奖励及切界面，不满足严格状态冻结。反例C：宿主resume时广告尚在播放，resume只清hostPaused且不启动ticker，有利于保留广告暂停；不要为修复恢复问题改成无条件start。

建议：分别定义模拟、输入、声音、SDK奖励事务的暂停政策，统一组合原因；奖励可明确允许持久化提交，但延后界面表现，避免简单丢弃广告回调。覆盖广告成功、取消、异常、重复/迟到回调及与宿主pause/resume的两种交错顺序。奖励仍须至多一次。

### P2：菜单嵌套应保留，恢复不能越权

_0x5e0129 用 _0x3e61d0 表示菜单暂停，_0x49d791 开头据此return。_0x42b398 内含退出确认和教程子页，通过setEnable控制父菜单；其关闭/返回逻辑独立于宿主暂停。

反例：菜单→教程或退出确认→宿主pause/resume。恢复后应停留在同一子页，父按钮维持原禁用关系，物理仍不更新。独立hostPaused且resume不写_0x3e61d0，原则上兼容；描述未显示破坏它，不能将嵌套问题定为已确认新版缺陷。另需测试宿主暂停期间程序化关闭菜单，确保hostPaused仍有效。

### P2：CSS指针封锁不等于完整DOM/PIXI输入清理

旧版在PIXI stage绑定指针，在window绑定pointerup，在document绑定pointercancel、touchcancel、keydown/keyup；商店还有_drag/_inSwipe，共用按钮有isdown和按下贴图。pointerEvents=none不移除这些监听，也不保证清除已按下状态。仅取消瞄准和滑条不足以清理商店拖拽及通用按钮。参考仅有脚本，不能推断外部HTML不存在其他DOM控件或宿主监听。

反例：按钮按下→宿主pause→暂停期间释放→resume，按钮可能保留按下显示；商店拖拽类似。若键盘keyup也直接被hostPaused挡掉，暂停前记录的_0xb768e8可能残留。旧版左右键switch分支为空，本轮没有证据证明它会造成持续移动，但状态清理仍应保留。

建议：新增动作入口阻断，取消/释放清理允许执行或在pause时统一清理；不得因guard阻止清理。测试鼠标、触摸、多指、pointerupoutside、pointercancel、touchcancel，及按住跨pause/resume。仅恢复后全新的按下动作可发射，旧释放不得击球。

### P2：滑条guard的位置及取消后的合法位置

_0x570109 的startSlide设置_sliding和拖拽基准；updateSlide先改滑块x，再emit update；stopSlide先清_sliding再emit stop。若所谓“滑条update/stop检查”只加在外层监听，滑块本体仍可能先变化。pause直接清_sliding能终止当前拖拽，但startSlide若未挡住，残留PIXI事件仍可能重新置真。

旧版stop监听调用_0x41684e，将与棋子重叠的striker移到合法位置；pause直接清_sliding跳过此逻辑，恢复后可能暂留非法位置。取消瞄准不调用击球合法性校验，玩家释放主要判断strength>=0.25，故需验证取消滑条后能否绕过位置修正，不能仅凭描述判定必现。

建议：在滑条内部start/update做阻断，在取消时明确完成一次合法位置修正或要求新输入完成修正；不得误emit触发游戏动作。验收拖到重叠位置后pause/resume、直接瞄准释放，确认不从非法位置发射。

### P2：取消瞄准并非完全无副作用

_carromCancelAim在_f86500为假时直接return；有效瞄准时清指针和力度，隐藏瞄准，但教程条件成立时调用_0x25e9ed(1)，重新显示教程瞄准并注册Tween。因此“调用取消后所有瞄准视觉都隐藏”不是旧helper的保证。AI瞄准也使用_c5bee4，但玩家取消helper不会因AI瞄准可见而清它；保留AI表现并冻结可合理，不应擅自当作bug。

验收教程第二步拖拽中暂停、菜单已开时暂停、AI蓄力暂停；明确期望是保留教程提示还是隐藏，并检查不生成重复教程Tween。

### P2：可见性与音频保持独立语义

_0x4ad106在隐藏时将_0x270daf=false并刷新音频；恢复可见且局内时调用_0x5e0129打开菜单，而非公开resume。_0x522c35的Howler静音条件仅含SDK音频和可见性。新增hostPaused并不会自动接入可见性静音、菜单或SDK音频订阅。

反例：宿主pause→隐藏→可见→宿主resume，菜单可能因旧可见性行为仍打开，这是旧策略而非resume失败。仅宿主pause但页面仍可见时，背景音乐可继续，因为描述没有音频动作。验收两种生命周期顺序，确保恢复不擅自关闭菜单；是否要求宿主暂停静音应按宿主契约明确。

### P2：重开不应解除宿主原因，早期restart是旧风险

公开restart直接调用_0x5480e3，旧实现递增_carromRoundId并取消部分Tween、重置数组和分数、安排开局，还调用广告准备。它本身不检查初始化，也不识别宿主暂停。已有回合/轮次标记能拒绝很多旧业务回调，但不能据此证明所有匹配原生计时器和广告回调失效。

反例：宿主pause→restart→等待→resume。若允许暂停期间重置，应保持hostPaused及输入封锁，新局模拟不能提前推进；若要求所有状态严格冻结，则restart也需排队。菜单已开时restart还涉及局面与菜单覆盖层一致性，应专项验证。不要在restart中无条件清hostPaused；加载前restart会访问未初始化对象，是旧接口原有边界，不应归咎新增补丁。

### P2：补步余额和恢复首帧

_0x4bf21a累加ticker delta，以while(_0x990fb7>1)逐次减1并调用_0x49d791(1)。_0x49d791在棋局逻辑末尾执行world.step(1/60,10,10)并clearForces。清零余额可丢弃暂停前的不足一步余量，属于可接受取舍，但不证明ticker恢复首帧delta不会含较大间隔。旧文件未提供PIXI ticker实现及版本，不能断言其delta策略。

guard必须在累加前。每轮后检查应退出整个补步循环，并检查减1的位置：若pause在更新中把余额置0，新版又在更新后执行减1，会出现-1余额；旧版原顺序是调用前减1，保持该顺序可避免此反例。若同步pause后又resume，单一布尔检查不能发现中间发生过暂停，可考虑暂停代次截断当前批次。

验收delta=0.5/1/2/10、回调内pause、长时间后台后恢复，记录步数和余额。不要把旧while严格>1顺手改为>=1，它改变现有边界节奏，需另行评估。

### P2：pointerEvents缓存所有权

首次pause缓存inline pointerEvents，重复pause不覆盖缓存；resume必须恢复原字符串，包括空字符串或原先none。若pause时无view，不应resume时向新view写未初始化缓存。暂停期间其他逻辑改style，再恢复旧值可能覆盖其他输入禁用原因。

验收原值为空/auto/none、重复pause、无pause的resume、暂停期间其他原因禁用、view更换。建议使用明确缓存有效性和view身份，或组合输入禁用原因。

## 核心规则与兼容性验收契约

本次不重新设计Carrom。旧循环为摆放→瞄准→力度至少0.25时释放击球→Planck固定步碰撞→口袋距离不大于20的逻辑检测→Tweener驱动结算/返子→继续或换回合→胜负。普通模式胜负依赖外部CarromDiscRules.hasWon及皇后状态，自由模式还涉及160分目标与皇后待覆盖；外部规则文件未提供，不能独立确认全部规则。

界面保留旧PIXI大厅、商店、匹配、棋盘、滑条、暂停菜单及嵌套教程/退出确认。输入窗口除既有回合和教程条件外，新增hostPaused期间禁止新玩家动作；允许必要的取消清理。游戏语言与原有素材本次不修改。

建议验收：

1. 冻结：在pause完成且当前允许的同步边界结束后，暂停5秒，物理位置/速度、回合倒计时、计分、轮次、AI发射次数不再变化；允许的SDK事务另列。单次取消瞄准及显式restart的合法副作用单独记录，不能拿它们掩盖后续推进。
2. 精度：同一运行环境的暂停期间状态期望零变化；恢复轨迹与删去暂停时长的基线对比，可暂定位置容差1游戏像素、计时至多1个1/60秒逻辑步，需实测确认，不能称旧版已有保证。计分、奖励、发射和结算次数要求整数精确一致，不适用浮点容差。
3. 碰撞与计分：运动、近口袋、高速碰撞、皇后飞行、计分飞行动画、罚子返回各时点暂停，恢复后只计分/返子/结算一次，不漏子、不重复奖励。
4. 成功失败：结束判定前后暂停，结果仅提交一次；恢复不重复调用levelComplete/gameOver，不因暂停新增超时失败或额外回合。
5. 输入：桌面鼠标与触屏分别完成拖拽、暂停中释放、恢复后新拖拽、取消、多指、滑条重叠位置、商店拖拽和按钮跨暂停。
6. 生命周期：加载前/中/后，菜单及子页，广告成功/取消/异常，可见性两种顺序，匹配所有原生定时窗口，重开和旧回调迟到均覆盖。
7. 同步重入：Tween回调、计分SDK通知内同步pause；同批后续回调不能越过已承诺边界。检查pause/resume幂等及短暂pause-resume时批次是否截断。
