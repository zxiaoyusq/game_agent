# Carrom 装备属性与击球倒计时源码复核

研究日期：2026-11-12。阶段：原型定义中的专项研究。仅分析本地证据，不修改游戏源码、不运行参考工程、不发布，不推进美术、代码或测试阶段。

## 1. 结论与证据边界

1. **force 不直接提高当前玩家击球的最大施力参数。** 它进入拖拽归一化分母 `D=75+25F`；`s=min(d,D)/D`；满足释放门槛时调用击球方法，施力幅值参数 `P=125s`。同距离、同角度、同局面且尚未饱和时，F 越高，P 越低；满拉均为 125。不能把 P 当作初速度、冲量或现实牛顿实测值。
2. **aim 直接控制显示。** `aimFactor=0.5+0.1A`，引导线 `scale.y=s*aimFactor`。该乘积没有进入已读取的击球施力路径；不能据此声称碰撞更准、物理射程更远或增加反弹预测。
3. **time 增加的是逻辑计数预算。** `N=B[venue]+2T`，B 为 `[6000,1500,1200,900,600]`；不是每档直接加 2 秒。若实际每秒执行 60 次有效逻辑更新，则每档名义增加约 0.0333 秒；这是假设下的换算，未做墙钟测量。
4. **场馆 0 绕过回合倒计时递减。** 分支要求 `_0x3a1262 && _0x408018 !== 0`。场馆 0 仍会初始化预算和头像进度，但不会通过此分支递减和超时换手；不等于所有计时器都停用。

竞品侧唯一已提供信息是调用方对一次装备界面截图文字的转述：力度影响击球力量速度、瞄准影响引导线长度、时间影响最长击球时间。本轮没有实际查看该截图，没有 MCP 独立观察、数值测量、竞品运行、联网身份核验或 APK 反编译。该转述只能作为待对照的界面语义，不证明竞品内部公式，也不能证明其与 ZIP 为同产品或同版本。

## 5. 输入到施力的完整链

L1551–1562 创建引导对象与击球器，击球器 pointerdown 绑定 `_0x36ab44`。L1732–1746 绑定舞台输入和移动/释放处理。

开始拖拽 L3655–3665 的必要条件：教程不处于禁止阶段；`_0x55e693` 与 `_0x209883` 都为真；尚未拖拽。随后设置 `_0xf86500=true`、引导线可见、strength=0，并把引导对象移到击球器位置。

移动 L3682–3695：

```text
pointerLocal = event.data.global - (横向补边/2, 纵向补边/2)
d = sqrt((striker.x-pointerLocal.x)^2 + (striker.y-pointerLocal.y)^2)
D = 75 + 25F
s = min(d,D)/D
angle = atan2(pointerLocal.y-striker.y, pointerLocal.x-striker.x)
```

距离函数 L5846–5852；角度函数 L5617–5622。坐标来自 Pixi global 并扣补边，不是直接读取 clientX/clientY；页面适配 L1280–1330 又设置渲染尺寸、CSS 尺寸和补边。因此 d、D 应称游戏逻辑显示坐标单位，不能直接当设备像素或 CSS 像素。

释放 L3667–3680：必须仍在拖拽；先取消拖拽并隐藏引导，只有 `s>=0.25` 才击球。`P=s*100*1.25=125s`；低于门槛仅取消本次瞄准，不调用该击球和结束输入流程。有效击球后调 `_0x24bb4a` 关闭计时/输入，并安排后续静止检测。

## 6. 引导显示与碰撞物理的分界

L1775 设置 `aimFactor=0.5+0.1A`。引导组件 L10313–10420；redraw 在 L10371–10394：圆圈按 s 缩放、箭头按 s 缩放，引导线纵向按 `s*aimFactor` 缩放并随角度旋转。A=0..5 对应 factor=0.5..1.0；固定 s=0.5，线纵向倍率=0.25..0.5。固定同一装备 F 和拖距后再比较 A，才能隔离瞄准效果；若同时变 F，同拖距的 s 变化会抵消或改变显示差异。

显示长度只能写作 `纹理基准长度 × s × aimFactor × 父级/视口缩放`，还受资源透明边界等影响；本轮未查看线纹理尺寸或测量截图，不报像素长度。这里没有已证实的射线检测、首碰撞截断、反弹预览或真实落点预测。

物理方法 L10674–10687：解除 sensor、唤醒刚体，然后 `applyForceToCenter(Vec2(P*cos(-a+PI),P*sin(-a+PI)))`。玩家传入 `a=2PI-angle`（L3675），代入可得方向为拖拽方向的反向。**这是力向量调用，不是 setLinearVelocity，也不是 applyLinearImpulse。** 世界步进后 clearForces（L5491–5492），故此路径为单次调用后在随后物理步中积分，不能把 P=125 写作速度125。

击球器刚体 L10573–10632：dynamic、bullet=true、linearDamping=2.8、angularDamping=5；圆形半径 `(34*0.8*0.8)/100=0.2176` 物理坐标单位，恢复系数0.5、摩擦0、密度1。普通棋子 L10423–10483：半径16/100=0.16、linearDamping=1.8、angularDamping=0.2、恢复系数0.45、摩擦0、密度1。显示与物理位置按100倍转换（L10528–10564、L10689–10749）。已读构造没有按装备 A/F/T 改写这些材料、半径、密度或阻尼参数。最终速度还依赖质量、积分、阻尼、接触和库实现；本轮未阅读 Planck 库或测量这些结果。

AI 不共用玩家拖距归一化：L3751–3776 将计划力度/100用于引导动画；L3782–3794 实际发射直接传计划力度。L3697–3711 中 return 后的旧逻辑不可当当前有效执行路径。不能把玩家 force 的结论泛化为 AI 参数也一样。

玩家开始 L3568–3609、AI开始 L3485–3502 都启用计时标记并复制同一个 N，分别置头像进度100。**因此当前装备 time 计算出的同一预算也被 AI 开始函数使用，未见对手单独 time 配置。**

更新 L4697–4739：暂停标记 `_0x3e61d0` 为真则直接返回；非活跃局也返回。仅 `计时开启 && v!==0 && remaining>0` 时每次减1，头像显示 `100*remaining/N`；减至0，先 `_0x24bb4a` 再切另一方回合。超时是换手，不直接判整局失败。有效击球也调 `_0x24bb4a` 停止计时；其中 L3044 的 `remaining-1` 没有赋值，不会修改 remaining。

预算在开始回合时就建立，击球器入场动画期间也可能消耗计数（L3570–3607），不能自动等同“入场动画结束后的可拖拽时间”。拖拽不足门槛不关计时。超时会清除拖拽标记，后到的释放因 L3669 返回，不再发射。

Ticker 注册 L937–954；累加器 L5499–5504 将传入 delta 累积，`while(acc>1)` 每次消费1并调用逻辑更新(1)。物理每次固定 `step(1/60,10,10)`（L5491）。这支持“60步为名义一秒”的设计解释，但未读取 Pixi ticker 的 delta标定/限幅、未测实际帧率和后台恢复。严格大于1而非大于等于1可能保留一个单位余量；没有看到本包装器的补步上限，长帧影响待测。

暂停函数 L2015–2023 设置标记并stop/start ticker。没有证据支持后台时间一定扣除或一定补回，不能用墙钟秒数作完成结论。

## 8. 核心循环、状态和界面边界

现有循环：选装备/升级并保存 → 选场馆 → 入局累计属性 → 当前方摆放/瞄准 → 合法释放施力 → 固定步碰撞与入袋反馈 → 静止后计分/犯规处理 → 续手、换手或结算。关键状态是场馆、模式、当前方、拖拽标记、计时开关、预算/剩余、棋子位置速度、入袋列表与双方分数；显示线条与头像条不能替代这些规则状态。

静止检测 L3129–3166 检查所有棋子与击球器 awake 状态，未停则延后重试；trimVelocity 在 L10489–10500、L10645–10653 以 `abs(vx)+abs(vy)<0.2` 休眠，这不是速度模长0.2，更不是0.2像素/秒。

计分：模式2按 `_type` 查 `[50,20,10]`（L644、L3210–3225），动画完成后加分（L3240–3268），目标160（L522、L3283–3285）；其他已读模式按所属方每子加1（L3350–3398），达到9并结合红子/当前方条件判断结果（L3412–3419）。犯规和盖红条件不能压缩为“进9颗一定赢”。L3289–3290 的 `playerScore/oponentScore` 与相邻混淆分数字段不一致，是待运行核查的问题，不作为已复现异常或本轮修复项。

布局以现有商店三行属性槽、棋盘击球器及方向引导、双方头像进度/分数、结算页为研究对象。仅从源码确认这些角色及引用，未声称查看最终画面或独立核验竞品截图。保留现有工程，不提出重新换引擎、重做素材或新增玩法。默认未来玩家文案保持英文，例如 Power、Aim、Time、Your turn、Time up；本轮没有修改文案或页面lang。

## 10. 避免明显性能/包体增长的改造建议（未实施）

先确定属性语义，再改数值：若希望力度提高最大能力，可保留统一拖距D，把F放到 `Pmax(F)` 上；若希望只是更细控制，则保留现公式并调整说明。不要同时改变质量、阻尼和P，避免无法归因；增大P前必须检查高速碰撞和稳定性。

时间若要求每档增加指定秒数，应明确 `N=round((baseSeconds+bonusSeconds*T)*60)`；对场馆0用显式计时开关说明设计。玩家与AI是否共享加时需单独决策。只使用现有数字和状态，不引入额外定时器、依赖或资源；此建议并非已获准修改玩法。

引导继续复用现有Sprite，只改scale；把几何长度、归一化力度、物理施力分别命名，缓存入局属性。不为线长新增每帧物理预测、纹理或第三方库。共用一个属性累计函数供商店与入局使用，并钳制存档升级次数至合法前缀，减少展示与实效不一致。

这些方案避免新增运行依赖和图片资源，但未做性能或字节测量，不能承诺零增长。改造应在另行授权代码阶段执行；本轮只交接建议。
