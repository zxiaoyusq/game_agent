## 3. 规则状态、循环与审查界面

本轮不是新游戏原型；以下是实验需记录的状态定义，不是确认当前实现。

核心循环：观察稳定棋盘和双方前态 → 当前行动方合法出杆 → 物理演化/进袋与母球事件 → 等待稳定并结算得分、历史、红球、罚棋 → 验证返场完成 → 达标结算或继续/换手 → 暂停、重开或下一杆。一次动作只允许一次规则提交。跨局成长、道具、时间限制和存档未证实，不附加设计。

最小前后态：构建/模式/房间配置、session/round/turn、当前 actor、双方 score、原始历史数组顺序、棋盘普通棋按类型数量、红球在板/待覆盖/已覆盖及 owner、当前杆进袋队列、foul、pending penalty/queen、暂停来源、结果已提交标记、逻辑输入是否开放。红球阶段是待核实业务语义；历史变量已有 board/pending 名称并不证明全部状态合法。

计分：现版仅知摘要使用记录 points；用户双黑样例为每黑10。旧附件 `_0x1c2aac=[50,20,10]` 且 `_type` 0/1/2 用作索引，只证明旧源数值映射；不据此确认现版白棋/红球分数或颜色与类型的对应。实验前需从真实界面逐枚得分确认 B/W/Q 的分值。目标160/180与普通棋9+9/12+12按用户输入登记，不合并为一套规则，也不自行改变目标。

成功/失败审查：业务胜者应在完整有效结算后的稳定状态判定，具体 foul/queen 是否延后及双方同时达标政策待取证；测试成功是该行观察与已证函数预期/不变量一致，测试失败必须有前后态或原始日志反例。竞品未知规则的实验先用于发现，不预设 pass oracle。

界面记录布局（不修改现有 UI）：同一未裁剪视频同时看清棋盘、双方 HUD、轮到谁、模式/目标；结果弹窗和暂停面板单独补全帧。证据报告用「版本与场景 → 前态 → 完整输入/事件时间线 → 稳定后态 → 原始文件索引」五栏。仅看到比分下降而没看到返棋颜色/数量及后续轮次，不算完整罚棋证据。

## 4. 现版摘要的输入边界

令 H 为历史，a 为 actor，r 为 current round，M 为筛选 a/r 的记录，n=|M|，e=M[0]，p=e.points，S 为该行动方当前分数。在 E-01 成立前提下，允许罚棋必须满足：n>0、e 为普通棋、p 有效、M 中每项 type/points 与 e 一致、S=p×n。成功动作：移除 e、S 减 p、返同 type 一枚。失败分支：返回 false；调用者后续未知。

**可推导的覆盖边界**
- 纯同色多枚并且账实一致：可进入成功分支；不要求只看本 turn，摘要只筛 current round。历史跨杆累计不能误写成「本杆历史」。
- B→W 与 W→B、B→W→B：均不满足同 type；即使 points 恰巧相同也会拒绝，不存在已知混色选择策略。
- 普通棋→Q、Q→普通棋：前者 every 条件不满足，后者第一项非普通棋；只有 Q 也拒绝。红球只在板上且未入当前行动方历史，不必然触发拒绝；红球由对方持有且只入对方历史，也不应影响本方筛选集合。
- 已覆盖红球如果仍留在本方当前 round 历史，仍会拒绝；如果已撤分并移除记录，能否恢复同色可罚取决于比分是否重新满足等式。phase 标记本身不在摘要条件中。
- 同 type 不同 points：拒绝。S 与账本差1、补分、旧分残留或奖金混入：拒绝；这不是通用「有分即可罚」。空历史但有分、只有旧 round 历史、只有对方历史：均不能从中拿棋。
- matches[0] 是数组位置，不证明时间排序。历史创建者、异步追加、重建存档均可能影响顺序；即使本分支都同类型，删除哪一条 turn/queueIndex 记录仍影响审计追踪。
- 单枚有效记录罚后分数0；连续不同杆再犯规的预期只根据剩余历史重新计算，不把尚未证实的「罚棋债」规则加进来。

**异常数据必须单独测试，不能把合法玩法拒绝和坏数据混在一起**

| 边界 | 需要记录/检验 | 当前证明程度 |
|---|---|---|
| actor | player/opponent 与棋子显示 type 分离；拼写、大小写、undefined、跨 actor 值 | 旧源 actor 接受 player/opponent，但棋盘 type 出现 `oponent`；现版仅摘要 |
| round/turn | round 数字/字符串、过期/未来 round；同 round 跨 turn；新局 ID 是否递增 | 当前具体比较与重开时序未知；旧源用严格比较 |
| H 结构 | 非数组、稀疏项、null、缺字段、重复记录/同对象引用 | 旧源在 filter 中直接 entry.actor；非数组/null 可抛异常，并非安全 false；现版不可据此定论 |
| type/points | type 0/1/2 与字符串、非法 type；points 0/负数/字符串/NaN/Infinity/小数/超大数 | 旧源 p 要有限且>0，不要求安全整数或匹配配置；现版「有效」的精确定义需正文 |
| S 与 n | S 的类型及有限性；n 超过该模式库存；p×n 溢出与安全整数问题 | 摘要代数等式不等于棋数/分值业务校验；旧源没有可见库存上界或安全整数门禁 |
| 重入/异步 | 返回 true 的时刻、扣分与物体返场时刻、重复调用、取消后是否回滚 | 摘要未规定提交原子性；合法同色多枚重复调用可能再次扣分，需调用者去重 |

建议实验输入域：正常玩法产生的数据为主；损坏夹具另标 adversarial，不冒充自然可达状态。不凭 S 推算历史，例如30分既可能为单枚其他棋，也可能为多枚普通棋；同分不等于同条件。
