## 旧快照生命周期与副作用

### 入口及持久状态

默认存档 tutorial=true 表示尚需教学。`_0x13b722` 从存档载入 `_0x183856`，`_0x9b0cd` 将其写回存档对象，`_0x3a0318` 同步运行态后遍历全部存档键写入。教学阶段 `_0x14cbdd` 为内存状态：0 定位、1 瞄准出杆、2 完成。

`_0x5e7a5f` 启用玩家输入，并仅在 pending 且 stage=0 时启动第一步。底部滑条 change 在合法玩家输入时调用 `_0x279414(0)`，使阶段变为 1；滑条 stop 再启动 `_0x25e9ed(1)`。因此“恢复第二步”必须沿现有 stage=1 路径显式处理，不能指望下一玩家回合的 stage=0 条件自动恢复。

### 动画不是纯装饰

`_0x25e9ed(1)`（约 1900–2008 行）显示遮罩、手、教学文字及真实瞄准对象 `_0xc5bee4`。它设置遮罩 zOrder=9、滑条=8、击球器=110、瞄准对象=109，手的起点 y=828，随后演示向下拉至 y=928并横向摆动。

手的循环 tween 每次 onUpdate 都写真实 `_0xc5bee4.strength=(hand.y-828)/(maxDrag*1.5)`，并将 angle 设置为击球器到手的方向。击球器本身还有 scaleX/scaleY 到 1.1 的循环 tween。教学文字另有淡入 tween。动画时间为模拟 tick，不宜直接当毫秒。

这带来关键风险：若只删掉按下的完成调用，手动画仍可在用户拖动期间覆盖真实角度和力度，甚至让没有真实有效拖动的释放通过阈值。只隐藏手也不能停止 onUpdate。

`_0x279414`（约 2009 行）先隐藏遮罩、文字、手，extract 手、击球器、文字的 tween，并将瞄准层级降到 9；参数 1 再设置 stage=2、pending=false 并保存。它没有显式归零角度、力度，未恢复击球器比例，也没有恢复全部层级。遮罩初始化是 Graphics，已读初始化未见为教学遮罩设置 interactive；不能把视觉遮罩等同输入拦截。

Tweener 实现（11490–11563 行）按 target 严格匹配，停止并移除首个匹配 tween 后 break；停止不回滚已经写入的属性，不调用完成回调。addTween 也先 extract 同 target。不要把 extract 当作暂停后可直接 restart 的句柄，或当作恢复比例、层级和角度的操作；新增逻辑应幂等，并核验各 target 没有重复遗留 tween。不要全局 clear，以免清除回合或结算动画；击球器 light 子节点还有自身动画，移除父节点 tween 不等于移除这些子动画。

### 输入与发射

`_0x36ab44` 拒绝暂停、stage=0、非玩家输入或已有拖动，然后设置 `_0xf86500=true`，在 pending && stage=1 时调用 `_0x279414(1)`，随后显示瞄准并将力度置 0。因此完成发生在任何强度检查之前；保存异常还可能打断其后的输入初始化。

`_0x536112` 仅判断 dragging，没有在该函数中校验活动指针、暂停、回合和局代号。它使用指针相对击球器中心的距离，而非相对 pointerdown 的位移；距离上限 maxDrag，strength=distance/maxDrag。maxDrag 在开局为 75+25*force。阈值距离因此是 maxDrag*0.25，不是固定 CSS 像素。

`_0x1e39ba` 暂停时清拖动并隐藏瞄准；其余要求 dragging，先清拖动和隐藏瞄准，再在 strength>=0.25 时调用击球器发射，`_0x24bb4a` 关闭输入和回合计时，并经 `_0x338c29` 调度 2300ms 对应的模拟 tick 延迟后检查结算。无效释放没有恢复教学。

发射实现见 10747–10760 行：关闭 sensor、唤醒刚体、提交速度向量。该函数没有显式布尔成功返回；不能以返回值真/假作为现有成功契约。用户人工摘录将其称为 striker.test。最新代码应核对该方法确实提交速度的位置，再挂完成事件。

stage 输入注册（约 1745 行）使用混淆事件名。本轮未执行字符串解码，不将这些混淆事件强行认定为 pointercancel 或 pointerupoutside。已读射击处理没有活动 pointerId 所有权保护，不能声称已覆盖取消或多指。

### 暂停、重开和存档

`_0x5e0129` 清活动拖动并隐藏瞄准，设置暂停；`_0x49d791` 暂停时早退，动画和物理不继续步进。原恢复路径没有专门恢复 pending 的第二步。页面可见性处理也不能代替完整的拖动取消与恢复协议。

`_0x5480e3` 增加 roundId，清击球器和瞄准对象 tween并初始化新局；所读函数未见重置教学 stage、清手/文字 tween及教学遮罩的完整流程。现有 `_0x338c29` 有 roundId 和对局活动保护，可复用生命周期思路，但教学还需 turnId/提示代号保护，防止旧回调影响新回合。

`_0x3a0318` 无 try/catch、无成功返回、遍历写全部键，不能视作原子事务。local-save.js 先调用原 storage.setItem，再尝试 localStorage；后者失败被吞掉，仅设置内部 dirty[key]，未对外提供成功结果或可见错误。因而“调用保存未抛错”并不能证明 tutorial 已持久写成功，也不能仅在外层加 try/catch 宣称覆盖了存档报错。

## 最小改动设计（建议，未实施）

核心循环：定位击球器 → 第二步演示 → 玩家按下接管瞄准 → 拖动调力度 → 释放 → 无效则重新提示，有效则进入物理演化并完成教学 → 沿原规则结算与换手。

保留 pending 布尔及 stage 枚举，另用少量瞬态数据记录提示是否挂起、活动 pointerId、roundId/turnId、该手势是否已提交。不要用节点 visible 判断教学是否完成。

|事件|状态及动作|持久化|
|---|---|---|
|第二步等待|pending=true，stage=1，无活动手势；复用原手、文字、遮罩与演示 tween|不写完成|
|首个合法按下|记录唯一指针及局/回合；调用纯视觉停止 helper；停止手的 onUpdate、击球器脉冲和文字 tween；隐藏提示，显式恢复正常比例和必要层级；真实力度置0、角度设有限的中性值后启用玩家预览|不写完成，保持 stage=1|
|合法移动|仅 owner 指针、相同局/回合且可输入时更新真实瞄准；保留现有距离映射及0.25阈值|不写完成|
|力度不足释放|清手势、归零真实瞄准、隐藏玩家预览；仍可操作时幂等恢复 `_0x25e9ed(1)`，否则待恢复可操作后再显示|pending保持true|
|有效释放|再次核对玩家、回合、局、未暂停、有限力度/角度和未提交；冻结本次参数、消费手势；提交真实发射并执行原关闭输入和结算调度；随后完成教学|stage=2、pending=false，只提交一次完成|
|取消/暂停/失焦/回合结束|撤销手势，不走有效释放；停止演示与预览，清所有权和力度；可恢复时按当前阶段显示提示|不写完成|

纯视觉停止 helper 可抽取 `_0x279414` 的公共清理部分；原参数0的第一步推进语义保留，参数1的完成语义迁往玩家有效发射提交点。不可从按下改为无条件在 pointerup 调用完成，也不可把完成放入 `_0x24bb4a`：后者还用于 AI、超时等非玩家出杆路径。

有效发射以实际速度提交为边界，不靠进洞、碰撞、计分或动画结束。最新方法若可能拒绝提交，应在该方法增加明确 accepted 契约；若保持旧同步方法，则在速度提交正常完成后登记一次 shotSubmitted。先完成原发射、关闭输入和结算调度，再独立处理教学存档异常，避免存储失败使已运动的盘面失去结算。若提交方法可能部分失败，必须由真实提交状态识别，不能盲目恢复提示并允许重复发射。

存档采用“本会话完成”和“持久完成确认”区分：有效出杆后本会话不再显示提示；tutorial=false 写入失败时记录待重试并持续显示英文反馈 `Progress could not be saved. Retrying…`，游戏和结算继续，不重新出杆、不重复奖励。仅收到存储适配器真实成功结果才清除提示；普通读取可能命中内存缓存，不能证明持久成功。本地适配器需暴露被吞掉的错误/键级写结果；宿主若无确认能力则报告“持久化未确认”。重启可能重新教学，应明确这一限制。不要为本任务重构全部存档，但必须确保后续全量保存不会用旧 true 覆盖已提交的 false；禁止在重试期间来回反转全局 pending。

多触点采用单 owner：第二根指针不能更新角度/力度，不能释放或取消第一根；owner cancel 后其后续 up 无效。pointerupoutside 是否提交沿最新已有正常击球契约处理；真正 pointercancel、失焦、失去捕获统一取消，不因力度足够而发射。离开画布后需可靠收到 owner 结束事件，具体使用 Pixi 支持的事件或指针捕获须在最新版本核实。

暂停进入时取消当前手势；恢复后不沿用暂停前力度，不把菜单点击当 pointerup。重开/回大厅清提示动画与所有权、使旧回调失效；pending=true 的新局重置 stage=0，正常完成后保持完成。取消一次手势只重试第二步，不强制回到第一步。若玩家已完成但手动查看教学，不应重置持久 tutorial；本任务不新增跳过按钮。

## 规则、物理与界面契约

维持现有棋盘、HUD、底部定位滑条及第二步遮罩/手势布局。手势操作期间隐藏教学遮罩和教学文字，显示原瞄准/力度反馈；无效操作后复用现有提示。恢复前先清理旧 tween，归一化比例、alpha 和层级；第二步手势起点应对齐当前击球器位置，核验旧固定 y=828 与玩家实际 y=826/828 的差异，避免恢复时闪跳或残留示范力。

游戏默认英文；本次不改贴图或现有文案，不声称已视觉核对。建议第二步文字为 `Drag to aim and set power. Release to shoot.`，必要的无效反馈为 `Pull farther, then release.`；是否已有等义英文资源需在最新工程核实，优先复用，不复制竞品品牌或资源。

物理步长：旧快照每次逻辑更新调用 step(1/60,10,10) 并 clearForces（5563行）；ticker 累积 delta，在 accumulator>1 时循环减1推进一次（5572行），所读代码未见此循环的显式补步上限。方案不改步长或长帧策略，也不声称跨浏览器逐帧一致。暂停时逻辑早退。

碰撞与计分：保留现有 Planck 刚体、sensor切换、边框和袋口规则；原碰撞回调产生声音/视觉反馈；结算等待对象静止。第二步完成不新增碰撞或分数条件。旧快照可见击球器距洞中心<=20的袋口判断，不能把它当最新全部入袋规则或竞品规则；本次不扩展完整 Carrom 胜负分析。

成功：一个合法玩家手势产生一次有效速度提交，教学本会话完成，存档写入状态可追踪。失败/重试：轻触、strength<0.25、非有限输入、取消和生命周期中断均不得完成教学或出杆；保存失败不否认已出杆，只标记持久化未确认。

输入窗口：仅活动对局、玩家回合、输入启用、未暂停、教学阶段允许、击球器处于合法可出杆状态时开始；释放时重新检查，不能只在按下检查。保留正常回合超时策略；超时切换回合不得算教学完成。

误差：0.25业务边界不加隐式epsilon，0.2499拒绝、0.25及0.2501在其他条件合法时接收。坐标换算测试的数值误差建议<=1e-6游戏单位，事件提交/完成次数必须精确为0或1。动画恢复允许下一个可渲染帧出现；建议以恢复后两个逻辑更新内开始提示作为待验证指标。相同冻结发射参数下，本修改应不改变送入物理的速度和角度；轨迹容差须通过同设备旧/新基线采样确定，不能捏造已测误差或竞品一致性。
