# Carrom 力度对象与间接引用取证

## 范围与结论

本轮为 prototype 阶段的只读材料分析，仅新增本报告，不修改源码、不制作游戏、不发布。游戏原型的物理步长、计分、输入窗口及 Web 构建验收不适用于本次取证任务，不能从材料中补造这些规则。

可支持的结论：0x18b31fc 候选范围保存入口 x0 为 owner，构造一个捕获 owner 的多态函数对象候选并交给 0x1cc7ae0；两条分支调用 0x18b09d4，将输出转移到一个请求大小为 0xa8 的对象并写入 owner+0x20。其余对象分别交给 owner+0x28、owner+0x40 和 owner+0x30 相关位置。现有材料没有提供这些接收函数的函数体、相应虚表内容或后续字段读取者，因此尚未定位到已证实的下游业务消费者，更未还原力度算法或 MatchShotSolver 算法。

所有下列代码地址均为该构建的 ELF link VA，不是文件偏移或运行时绝对地址。FDE 仅作范围候选。

## 1. owner 与函数对象候选

设 O 为 0x18b31fc 入口 x0。0x18b321c 的 mov x19,x0 保存 O；后续分析跟踪寄存器改写，不把 x19 全程视为同一基址。

- 0x18b3228 调用 0x1cc7a10，0x18b3230 将其返回值保存到 x20。该返回值稍后作为接收者传给 0x1cc7ae0；服务身份未知。
- 0x18b3260–0x18b3264 计算 0x27a1db0。0x18b3268 令 x21=x29-0x40；0x18b326c 将 [0x27a1db0,O] 写入该临时存储；0x18b3270 将临时存储地址写入 [x29-0x20]。
- 0x18b3274–0x18b3284 形成调用 0x1cc7ae0：x0=前述接收者，x1=O，x2=sp+0x20，x3=x29-0x40。这是可验证的参数交接，不证明该函数同步执行、复制、保存或注册回调。
- 地址首字加捕获指针、尾部自指针与随后的动态清理结构，相容于 libc++ std::function 的小对象存储/类型擦除包装；这里只能标为函数对象候选。0x27a1db0 是写入对象首字的表地址候选，未经表内容与 ABI 布局验证，不能直接命名为某类完整虚表。

### 两个 BLR 的准确边界

0x18b3288–0x18b32b0 读取包装指针，比较其是否等于栈内存储地址，分别选择表偏移 0x20 或 0x28，再于 0x18b32b0 执行 blr x8。异常清理路径 0x18b3580–0x18b35b0 同样选择 0x20/0x28，于 0x18b35b0 执行 blr x9。

该结构强烈支持清理/销毁候选，而非业务 operator() 的已证实调用。若正常路径仍使用原表地址，相应槽位置为 0x27a1dd0 / 0x27a1dd8；这是地址算术候选，未读取槽值，不能给出目标函数地址。0x1cc7ae0 内部是否另有业务调用完全未知。

## 2. 配置输出及持有位置

0x18b32c4 从 O+8、O+0x10 读取两个值，0x18b32c8 读取 [O]；0x18b32cc 调用 0x1a0a330；0x18b32d4–0x18b32dc 将 O+0x10 所取值与前次返回的 w0 交给 0x1b2ad7c，并把结果保存到 x20。后者成为两条配置构造分支的 x1，不应与开头的服务返回值混淆。

0x18b3320 读取 [[O+8]+0x2b8] 的有符号 32 位值；0x18b332c 调用 0x26c1a2c。0x18b335c–0x18b3360 根据其返回对象 +0x18 是否为零分流：

|调用指令|调用前参数|边界|
|---|---|---|
|0x18b3374 BL 0x18b09d4|x0=0x26c1a2c 返回对象，x1=0x1b2ad7c 返回值，x8=sp+0x38|非空分支|
|0x18b339c BL 0x18b09d4|x0=0x18b2c08 返回值，x1 同上，x8=sp+0x38|空分支；0x18b3388 读取 [[O]+0xd0]，0x18b338c 调用 0x18b2c08|

0x18b09f8 保存 x8 为输出指针，0x18b0a04 保存 x0，0x18b09fc 保存 x1。此布局相容于 AArch64 间接结果参数，但本轮未恢复完整 C++ 原型。

在该被调范围中，0x18b0a64–0x18b0a68 计算 shotPowerLimits 字符串地址 0x11cc3f0；0x18b0a80 调用 0x26c1074，随后检查返回数据标签并于 0x18b0aac 调用 0x26e630c；0x18b0b14–0x18b0b24 将跨度按 16 字节元素计算并交给 0x18b15a4，0x18b0f88–0x18b0fa4 从对应临时序列的前两个元素经 0x2706e20 取得 d0，写入结果 +0x20、+0x28。

这支持“带 shotPowerLimits 键的配置查取与结构构造”解释，但尚未核验 0x26c1074、0x26e630c、0x2706e20 的实现或真实配置数据，不能断言两个 double 的业务命名、单位、数值、上下限顺序或最终力度曲线。整个输出还含其他配置与状态派生值，并非只有这两个字段。

两分支在 0x18b3378/0x18b33a0 将 w0 置为 0xa8，于 0x18b337c/0x18b33a4 调用 0x2798774。按后续使用可标为分配候选，未独立解析该目标符号。0x18b33b8 保存返回地址为 x20，0x18b33c0–0x18b33f4 转移输出的多个字段，其中原输出 +0x20/+0x28 随 q0 写入新对象相同偏移；0x18b33bc、0x18b33c8、0x18b33f8、0x18b340c 将输出尾部 +0x50 起的 0x54 字节交给 0x2798940，表现相容于内存复制，目标身份未独立解析。

关键持有证据：0x18b3414 的 ldr x1,[x0,#0x20]! 令 x0=O+0x20 并读取旧值；0x18b3418 将新对象指针写入 [O+0x20]；若旧值非零，0x18b3420 调用 0x18b3ed0，参数 x0=O+0x20、x1=旧值。这里证实存储与旧值交接；释放/替换语义为候选。

## 4. 类型名与重定位能支持什么

E/analysis/native_字符串交叉引用候选.json 收录含 __ndk1::__function::__func 的类型名字串；构造相关名称带 MatchShotSolverC1ERK10TableLogicO15MatchTableState 与 FvRKN2mc5ValueE，其他名字分别带 startSolving、simulateShot 和不同参数编码。这支持该构建材料中存在相应函数包装类型名字，不证明 0x18b31fc 就是 MatchShotSolver 构造函数，也不证明其参数就是 TableLogic/MatchTableState。

已读的 0x18bc618–0x18bc634 实际做：读取 [x1+8]，与 0x12eb4d8 比较，相等返回 x0+8，否则返回零。它相容于函数包装的目标类型查询辅助函数，不是求解或击球模拟算法。其他四个短范围本轮只读取了索引中的定位信息，没有读取它们的具体反汇编全文。

已有重定位材料列出 type=1027 的加数引用：0x27a2660→0x12eb4d8、0x27a26e0→0x12eb586、0x27a2760→0x12eb63b、0x27a27e0→0x12eb6ed、0x27a2860→0x12eb795；另有 physicsStopped 名称引用。邻近候选 0x2846e38→0x27a2868、0x284a398→0x27b92f8，仅因位于类型名指针附近 ±24 字节入选。没有读取原始重定位表及这些地址的连续内存，不能把邻近关系升级为 RTTI、虚表或算法调用边。尤其当前临时对象首字候选 0x27a1db0 与这些地址并不相同，未建立连接。

配置加载交叉引用文件提供 GameConfiguration.plist、load_configuration 等独立定位，但没有其与本次 owner 链的可达路径，不能据此归因配置来源、加密方式或线上加载。

## 5. 本机提供扫描：未独立运行

以下仅来自用户本轮补充，不是本模型调用工具重扫所得：

- AArch64 .text 对 exact 0x18b31fc 的 BL 立即数匹配为 0 条。
- .rela.dyn 669962 条和 .rela.plt 1255 条重定位中，addend 精确匹配同一入口为 0 条。
- 范围限制：漏间接调用、尾跳、中部入口及其他重定位形式。

已读符号元数据中的两节字节数分别为 16079088 与 30120；按 ELF64 Rela 24 字节条目计算，计数与用户给定值相容。这只是元数据一致性检查，不是对零命中的复验。

零命中只排除了特定匹配条件下记录到的直接边，不能等同于不可达、未使用、死代码，也不排除代码计算地址、虚分发、回调保存、B/BR、基址加偏移或指向范围内部的入口。

## 真实验证与限制

本轮执行了归档条目列举、上述文本读取和人工指令数据流核对；没有独立反汇编、全库交叉引用扫描、重定位重算、原 ELF 哈希复验或运行时观察。没有运行 npm 构建/测试/浏览器验收：当前为只读取证阶段且根目录列举为空，不属于代码或测试阶段。未生成源码、图片、dist 或发布包。

工具返回的条目哈希用于标识已读证据，不代表对反汇编生成过程的独立验证。报告区分文本中直接可见的指令、基于 ABI 形态的推断、既有扫描材料和用户提供扫描；缺少下游函数体与表内容是本轮结论的主要限制。产物仅 /workflow/prototype.md。
