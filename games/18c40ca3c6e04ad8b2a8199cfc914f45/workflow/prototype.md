## 3. 控制流与行为契约

为描述方便，将 `_0x2a9c75`、`_0x3e4566`、`_0x3231b3` 分别记作 A、B、C；只用符号描述，不擅自认定它们是某一颜色、皇后或合法得分集合。

### 3.1 候选规则集合

| 条件 | 初始候选 T |
|---|---|
| `_0x5d148e === 2` | `A.concat(B, C)` |
| 其他模式且 `A.length === 1 && C.length` | `C.slice()` |
| 其他情况 | `A.slice()` |
| 上述 T 为空 | 再执行 `T.concat(B, C)` |
| 扩展后仍为空 | 返回 null，不抽取首目标，不搜索基线 |

这保持数组顺序与对象引用，不过滤非法项，不去重。只有数组结构上为空才触发扩展；例如 `A=[null]` 且 C 为空时，T 非空，不会改从 B 取有效目标。

新增多目标段只遍历 T，不另外拼接 B/C，不回到被前置规则排除的 A。因此“新增段仅沿用原候选集合”可静态成立；“T 内每个对象按当前规则都可合法击打或计分”不能成立为已验证结论。尤其 A 只有一项且 C 非空时，A 被整体排除；这是提供文本中的前置策略，不是新增段造成的遗漏。规则含义需要现版 owner 确认。

### 3.2 局部核心循环与状态

候选集合 → 随机首目标与随机基线位置 → 旧的左右步长扫描 → 若仍无法摆放则调用 open-baseline helper → 初始路径检查 → 首目标七点采样 → 不同对象替代目标七点采样 → 返回第一条 helper 判为未阻挡的杆；没有这样的采样结果则保留初始备用杆。

局部状态包括 T、首目标/当前目标、基线位置、方向、距离、路径布尔标记、已搜索对象身份集合。函数没有提交射击、力度、物理步进、碰撞结算或比分状态。实际调用周期、暂停和回合边界未知。

分支细节：

1. 首目标在查找基线之前抽取。初始位置受阻时，以随机 x 为中心按偏移 0、2、4…尝试右侧再左侧；严格 `< max`、`> min` 排除了这段扫描的端点。
2. 扫描后重查摆放冲突，仍阻挡则调用 `_carromFindOpenBaseline()`。严格返回 null 才提前结束。
3. 首目标原位置方向与距离生成后调用路径 helper。初始位置可用且 helper 判清晰时，不进入新增搜索。
4. 首目标路径受阻，先采样基线 0/6…6/6 共七个点。它们包括两端点，间距为基线宽度/6，不是连续空间求解。
5. 首目标七点无清晰结果，才按循环目标顺序检查不同对象。每个通过筛选的对象在七点循环前加入 Set；即使全部位置均不能摆放，这个对象也被视为已经尝试。
6. 找到清晰路径时切换 `pos`、`dir`、目标及 true 标记；其他失败采样只保存到局部临时变量，不覆盖初始备用杆（以前提 helper 无副作用为限）。

## 4. 发现、假设与未验证风险

### F-01：首目标校验缺失，替代搜索不提供首目标容错

**属性判定：FAIL——“所有目标使用前都经过有效性校验”不成立。优先级：高，触发可达性未验证。**

A2 在 A5 之前。后续过滤无法保护首目标，也无法保证一定执行到替代搜索。

手工反例推演（未执行）：

- T 为 `[null, validTarget]`，随机选中 null，且能找到可摆放基线：方向 helper 可能先抛出；即使它容忍 null，下一行读取 `_0xe88441.x` 仍会 TypeError。有效替代目标得不到搜索机会。
- T 为稀疏数组或含 undefined 且随机落在空槽/undefined：同类问题。`T.length > 0` 不保证抽到对象。
- 首目标对象坐标为 NaN/Infinity/undefined：减法、平方与平方根可能产生 NaN/Infinity；行为取决于方向与路径 helper。helper 若错误地返回 falsy，可将此结果标记 true 并跳过全部替代搜索；不能声称现版 helper 已这样做。
- T 中全部条目无效但 length 非零：没有“无有效目标返回 null”的统一处理。必须区分“空数组”和“无有效对象”。

后续 `Number.isFinite` 拒绝数字字符串，不进行数值转换；首目标路径中的减法却可能转换数字字符串。两条路径的输入契约不同。这是静态差异，实际数据是否含字符串未知。

建议方向仅供后续授权修复：在方向/距离使用之前定义所有目标一致的有效性契约，并明确非法首目标应该保留旧异常行为还是转向有效目标；本轮不修改。

### F-02：Set 去重正确但范围有限；随机分布与搜索顺序受重复项影响

**静态结论：后续搜索按身份去重成立；“整个候选已去重/对象均匀随机首选”不成立。**

- `new Set([firstTarget])` 初始化后，会跳过所有相同对象引用。普通对象按身份匹配，不按 x/y、业务 ID 或深比较。
- 两个不同对象即使坐标相同，都会被搜索。这不必然是缺陷，是否应按业务 ID 去重需规则 owner 决定。
- T 为 `[a,a,b]` 且标准均匀索引随机时，a 被首选的概率是 2/3、b 是 1/3。新增 Set 不影响已发生的抽取。
- 若抽中的 a 位于第二个槽位，`indexOf(a)` 仍返回第一个槽位。搜索由第一次出现位置开始，不由抽中的槽位开始，会影响首个可用替代对象的优先级。
- 固定普通数组下，从 `firstTargetIndex` 循环后移 1 至 n-1，覆盖除该首次出现槽位外的全部槽位；被排除槽位就是已经尝试的首目标。因此重复引用不会造成其他不同对象目标漏查。Set 防止重复首目标及重复替代对象反复做七点搜索。
- 这不是对整个候选数组执行去重：外层仍经过重复槽位，非法对象也未加入 Set，重复非法项仍会重复经过筛选。

前提：T 稳定、数组元素引用稳定，helper 不重入改变局面，坐标为稳定数据属性。getter/Proxy 有副作用或 helper 改写对象时，不能用上述覆盖证明担保实际行为。

### F-03：新增循环有界；旧基线扫描不是无条件有界

**属性判定：新增段在普通稳定数组下有界；“整个函数任意数值输入均有界”为 FAIL。优先级：常规局面待核，异常数值风险高。**

设 n=T.length、W=maxX-minX、U 为首目标加后续通过有限坐标过滤的不同对象目标数（包括实际未必走到的对象）。

- 首目标七点循环至多 7 次。
- 后续外层至多 n-1 次，每个新对象内层至多 7 次；粗上界为 7(n-1) 次后续位置迭代。
- 路径 helper 总调用数至多 `1 + 7 + 7(U-1) = 1 + 7U`，且摆放受阻时不调用路径 helper；提前返回或找到清晰路径会更少。这是调用次数上界，不是帧耗时上界。
- 后续数组槽位遍历仍为 O(n)，正常有限宽度旧扫描约 O(W/2)。open-baseline、冲突检测及路径 helper 的内部复杂度未知，不能给出目标机耗时。
- 在 W 为正常正有限值、步长确实增加的理想计数下，旧扫描最多约 `ceil(W/2)` 轮，每轮至多两次冲突 helper。浮点边界需容差，不应把这个算式宣传为任意 JS Number 下的严格保证。
- 若 W=Infinity 且前置冲突判定持续受阻，旧扫描条件一直满足；JS 浮点计数增到约 2^54 时 `+2` 可不再改变值，从而循环不前进。即使 W 有限但大于该停滞值，也可产生同类问题。它也可能先因找到位置而退出，因此这是条件性反例，不是对当前局面的实测。
- W=NaN 时比较为 false、旧扫描跳过；W<=0 也不正常扫描。七点循环次数仍有限，但生成位置可非有限、重合或处于倒置区间。

应由输入契约限定合理基线范围、有限数值，并给旧扫描独立最大迭代预算；helper 内部也需单独审查。这不是本轮补丁。

### F-04：候选集合未扩大，但规则合法性未证明

**属性判定：新增段保持 T 成立；规则符合性为 NEEDS_CONTEXT。**

新增段沒有引入候选集合外目标。该函数也没有检查对象是否仍在棋盘、是否已进袋、属于当前回合或可计分，以及首碰其他对象是否犯规。不能把 x/y 有限当成规则合法。空候选时拼接 B/C、模式 2 并集、A 单项时仅取 C 等行为存在于所给函数前段；其是否是当前原策略、是否符合规则，需要现版构造者与消费者证据。

### F-05：随机首目标保留，替代搜索有确定性优先偏向

**静态行为，非自动认定缺陷。**

在预期 decoder 和标准 Math 前提下，走到随机初始化时，本函数显式调用随机源两次：一次首目标索引、一次初始 x。候选为空时在此之前返回，不消耗这两次随机数。新增多目标段没有新增随机调用；helper 是否使用随机数未知。

初始路径清晰便直接返回，不比较其他杆。首次受阻后，先优先首目标，再按循环数组顺序；每个替代目标从 minX 端向 maxX 端采样，接受第一条清晰路径。不是最佳得分搜索、随机替代抽样或轨迹优化。重复引用增加首选概率并改变搜索锚点，因此不能声明策略对不同对象均匀公平。是否需改分布是产品取舍，当前保留原显式随机首目标。

### F-06：无目标和全部阻挡时的保留策略

**静态行为可确认；与未提供完整旧版本的兼容性未证明。**

- T 最终长度 0：返回 null，不调用后续选择逻辑。
- 摆放仍受阻且 open-baseline 严格返回 null：提前返回 null，不因换目标而再次搜索摆放。若摆放冲突与目标无关，此顺序合理；helper 契约未提供。
- 有初始可用摆放位置，初始路径、首目标七点及全部不同目标七点均被 helper 判阻挡：返回原始目标、原始位置（可能经过旧扫描或 open-baseline 调整）、原始方向，标记 false。
- 新段失败不会把最后一个失败的 alternativeTarget、alternativePos 或 alternativeDir 写入返回对象。成功则三者一起切换，保证局部配对。
- “全部阻挡”只能指实际检查的路径；七点采样不是连续基线全覆盖，也不覆盖反弹或更复杂路径。false 不证明不存在其他有效杆。

所以局部意图是“找到清晰替代则换杆，否则保留备用杆”，不是“路径阻挡便不出杆”。此处与提供文本中新段之前的返回策略兼容；没有完整同版本基线，不能声称已完成历史版本行为回归。

### F-07：基线和几何结果缺少统一有限性、零距离及返回值检查

**确定的校验缺口；实际后果依赖 helper，NEEDS_CONTEXT。**

- minX、maxX、baselineY、半径没有显式有限值/范围校验。
- `_carromFindOpenBaseline()` 只判 `=== null`，undefined、NaN、Infinity、字符串或越界数都直接写入 x；写入后本函数没有再检查该位置的摆放冲突或合法范围。若 helper 保证返回合法有限数，则此风险被外部契约约束，但该保证未核验。
- 后续 `Number.isFinite(x/y)` 不保证差值、距离和方向有限。两个有限极大坐标相减仍可溢出；初始和首目标七点用平方求和开根，有限大差值平方也可能先溢出。后续 Math.hypot 更抗中间平方溢出，但不修复差值已溢出的问题，也不担保任意尺度的有限结果。
- 目标与位置重合时距离为 0；归一化 helper 若直接除以距离，可能得到无效方向。提供函数没有处理，不能猜测当前 `_0x8b2762` 的实现。
- helper 返回值全部用 `!blocked` 转成布尔标记；若 helper 错误返回 undefined/null/NaN，会被当清晰；返回 truthy 非布尔值会被当阻挡。本函数未严格检查 helper 返回 boolean。
- 七点含端点，旧扫描不含端点。端点合法性由摆放 helper 判断，不能直接把不一致认定为犯规。

### F-08：返回字段与异常传播

正常返回为：

`{ pos: _0x4b85cd, dir: _carromFallbackDir, _carromFallbackTarget: _0xe88441, _carromFallbackWasClear: _carromFallbackWasClear }`

- `pos` 是本函数创建的位置对象；目标保留原对象身份，方向形态由 helper 决定。没有力度、预期分值、袋口、碰撞轨迹或成功率字段。
- 标记因 `!helperResult` 为布尔值，但不保证位置和方向有效。目标切换成功时字段相互匹配，以 helper 无副作用为前提。
- 两个 return null 分支不带字段。消费者必须先处理 null，再决定 false 是否仍允许使用备用杆；当前消费者未提供。不能用旧附件开头的某个调用样例证明现版消费安全。
- “已有 pos/dir 加两个诊断字段通常可兼容”的说法只是一种假设；严格 schema、键遍历、序列化、对象身份缓存等消费者都可能受影响，需现版核验。
- 本函数无 try/catch。数组/decoder/方向/冲突/path/open helper 缺失或类型不匹配、坐标 getter 抛错、Number.isFinite/Set/Math.hypot 不可用等异常均可能向外传播。普通现代浏览器通常有这些 API，但未核验目标 WebView；不推断目标机性能或兼容性。
- Set 仅去重搜索尝试，不是物理命中或计分事件去重；它不能证明结算一次性。

## 5. 物理、规则与界面原型边界

本次不重新设计游戏。品类原型所需的下列项目分清“函数能确认”与“未提供”，不填造参数：

| 项目 | 本轮可定义/记录 | 不能确认的项目事实 |
|---|---|---|
| 局部循环 | 候选生成、初始杆、阻挡后有限采样、保留或替换、返回 | 真正出杆 → 物理演化 → 结算 → 下一回合 |
| 物理步长 | 本函数没有物理 step；七点与步长 2 是空间搜索，不是时间步长 | 固定步长、子步、长帧补步/截断、摩擦、速度与力度 |
| 碰撞 | 所有路径检查均传目标与最后参数 true；E-03 仅提供“至首次接触”摘要 | 扫掠形状、半径、目标排除、首次接触精确定义、物体移动与擦边处理 |

| 成功/失败 | 局部搜索成功：helper 判未阻挡并返回 true；局部无清晰采样可返回 false；空候选/无摆放返回 null | 回合成功、整局胜负、超时或得分保证 |
| 输入窗口 | 这是选择函数，不处理鼠标/触摸输入，不包含 UI 提交状态 | AI 调用是否限于静止回合、重入保护、用户输入与 AI 出杆冲突 |
| 可接受误差 | 未提供，不能擅填；未来需把几何 helper 与物理引擎容差配对 | 长度单位、擦边 epsilon、首次接触时间容差、不同帧率误差 |
| 界面布局和语言 | 本轮不新增或修改玩家界面，无新玩家文案 | 当前页面 lang、HUD、菜单、教程和实际布局均未核验；未来如无其他要求默认 English/lang=en |
