## 核心循环、物理与输入

核心循环：选模式 → 选实际场馆 → 匹配/确定先手 → 新局生成 → 当前方摆放击球器、瞄准蓄力、释放 → 物理运动和入袋 → 全部停球 → 犯规、返子与计分结算 → 胜负判断或续杆/换手 → 结果奖励 → 返回或重开。状态至少区分选择、初始化、玩家可输入、AI等待、运动中、返子/结算中、结果、暂停；生成配置在新局入口解析并冻结，运动与延迟回调不读取可变化的浏览页状态。

静态源码确认 `_0x1392b5.step(1/60,10,10)`，随后clearForces。`_0x4bf21a`累计ticker传入量，在累计量大于1时递减并调用更新；本次保持原累加条件、步进与迭代数，不宣称已经验证实际帧率或低帧率补偿。

棋子构造 `_0x54e9a5`真实Circle半径为16/100物理单位，即16逻辑像素；辅助常量15不是fixture半径。构造可见angularDamping=0.2、linearDamping=1.8、bullet=true、允许休眠；部分fixture属性名仍为混淆调用，不猜测对应含义。击球器构造 `_0x13fb80`半径为34×0.8×0.8=21.76逻辑像素，angularDamping=5、linearDamping=2.8，摆放为sensor，击球前切回非sensor。保持这些参数与原碰撞体系。构造窗口360000–420000、420000–480000。

入袋逻辑以棋子中心距袋中心不大于20逻辑像素判定并移除物理对象；保持检测顺序与阈值。停球判定调用trimVelocity/isAwake，棋子与击球器速度绝对分量和小于0.2时休眠，未停时约每50ms重查。不能把此阈值解释为实测位置误差或擅自改为固定等待结束。

输入窗口保持既有约束：仅玩家回合且输入允许、未处于互斥拖拽时响应；释放强度至少0.25才击球，力按强度×100×1.25计算，最大拉距继续按装备计算。运动、AI、返子、结果与暂停期间禁止新击球。边界补测用强度0.249、0.25、0.251及连点/多指/移出释放；不新增反应限时。

## 六棋布局设计建议

以下为原创对称布局，非竞品布局复刻，尚未动态试打。以棋盘局部中心(317,317)为基准：

- A组6点：(267,267)、(367,267)、(300,300)、(334,334)、(267,367)、(367,367)。
- B组6点：(317,267)、(267,317)、(367,317)、(317,367)、(334,300)、(300,334)。

两组分别具有中心对称性，内层4点与外层8点围绕中心分布；最小中心距34，按真实半径16保留2像素间隙。世界坐标仍加棋盘偏移；显示位置、body位置与zOrder必须基于同一个实际点，对手原有zOrder误引用玩家布局y值不可照搬。双方颜色与归属延续现有构造映射。

实施验收须自动检查12点数量正确、有限、唯一，所有对子距离至少32+1像素；目标坐标允许误差0.01逻辑像素。有效棋盘边界、墙体及袋口坐标需从实际工作副本提取，验证所有圆完全处于有效区、与袋中心距离大于20+16+1、与开局击球器距离至少16+21.76+1；当前未完成这些几何检查，不认定布局已可发布。中心返子应按实际碰撞半径至少32检查，若要修正原30像素搜索，须作为独立缺陷修复明确记录并回归全部模式，避免暗中扩展本次改动。

## 最小实施清单

1. 在实际含存档补丁的源码上建立小范围差异；保留存档适配、key、格式、迁移、余额和装备行为，不替换developer_v2.js。原包GameSnacks.storage与localStorage限制不能代表本地补丁状态。
2. 添加集中规则解析：`isDelhiDiscPool = mode === 0 && venueId === 0`；本局每色数量为6或9，普通模式目标等于该数量，Queen规则仍为mode不等于0；Freestyle目标独立保持160。建议英文标识 `roundRules`、`piecesPerSide`、`winTarget`、`layout`，新局一次生成冻结快照。
3. `_0xd3d8fe`从本局布局长度生成双方棋子；目标分支使用上述待验布局，其他分支原9点数组原样保留。不要截取原布局前6项，不全局替换数字9；商店等无关9循环不得修改。
4. `_0xbdafb3`普通分支所有双方9子比较统一引用同一winTarget，保留相等比较、当前方/Queen判断及犯规返子先后顺序；不改为未经定义的通用>=判断，不把160改为6。HUD不得继续显示与六棋冲突的9子说明。
5. AI继续读取实时在场数组；验证终局后不再启动AI、返场子可再次成为候选。无需新增搜索算法或降低难度。
6. `_0x338c29`以匿名对象Tween承载延迟，完成后直接调用闭包；新局清理中未见统一取消此类匿名目标。将AI等待、入袋、返子、结算回调纳入跨局验证；若工作副本无保护，最小增加本局代号捕获与校验、结果幂等标记，并在重开/离开对局时使旧代号失效。当前仅为风险，未复现漏洞，不全局清空会影响大厅的所有Tween。
7. 不加依赖、联网配置、美术和音频；保持离线资源路径、原引擎与宿主集成。
