## 生命周期与现有保护

当前可见主循环：机器人回合 `_0x50a0ff` → 500ms 调度 → 计算四组候选并过滤 → 选最高 hDot 或 fallback → `_0xd6b627` → `_0x4662ac` 移杆 → `_0x223471` 瞄准 → 瞄准完成后再等待 500ms → `_0x4b3cc6` 提交物理出杆 → 等待 2300ms → `_0xbdafb3(shotTurn)`。最后的结算实现未在当前截取中提供。

- `_0x50a0ff` 先递增 turnId；初次等待回调检查 active 与捕获的 turnId。
- `_0x5e7a5f` 递增 turnId；因此正常切到玩家回合会使旧 AI 等待、移动完成及瞄准完成回调失效。
- 移杆每次调用捕获 roundId/turnId，完成时检查两者与 active；瞄准动画完成亦检查两者。
- 最后 500ms 回调只显式检查 active/turnId，roundId 是否被调度包装补齐未知。
- `_0x4b3cc6` 对有效数字检查后才标记 aiShotTurn；普通顺序重复调用在同一 turnId 下至多调用一次发射。它没有接收“预期 round/turn”，而是读取调用时当前值。
- `_0xd6b627` 的无条件 return 后旧直接出杆路径不可达，不能把该死代码当第二次落杆来源。
- 移杆随机分支在计数 3 时必走最终定位；沿单条正常回调链最多四次移杆 tween，不是无界随机递归。

## 逐项风险、最小复现与测试建议

### 1. 暂停：不能仅凭缺少 pause 判断认定暂停出杆

证据：C 的各落杆链守卫只读 `_0x3fddb3` 与令牌，没有显式 `_0x3e61d0`。但 R 的 `_0x5e0129` 设置 `_0x3e61d0=true`，R 的 `_0x49d791` 在 Tweener.update 之前遇暂停直接 return；R 的 `_0x338c29` 也用 Tweener 承载等待。因此旧版正常暂停路径冻结动画及等待，不会仅因墙钟经过500ms而出杆；恢复后继续剩余流程。不能把它误写为 setTimeout 穿透暂停。

条件可达：若当前调度改为墙钟计时，或暂停仅停止物理、仍推进 Tweener，而 active/令牌不变，则暂停期间落杆守卫仍可通过。反之，若暂停令 active=false 且继续消费一次性完成回调，恢复没有重新排程，链会被丢弃；倒计时若也停止可能停局。

最小复现建议：分别在初始500ms、移杆、瞄准、最后500ms暂停，墙钟等待超过全部动画时长，再恢复；记录暂停状态、模拟tick、待处理回调、发射计数。期望暂停中零发射，恢复后仅一次继续，或按明确取消策略重新规划。必须测试实际暂停入口及后台返回入口，不能只手改布尔值就宣称用户路径已达。

### 2. 重开：已有双令牌保护，但当前外围未知

证据：C 移杆/瞄准完成检查 round/turn；初始及最后等待只显式检查 turn。R `_0x5480e3` 递增 roundId、extract撞针与瞄准器 tween，并调用玩家或AI回合入口递增 turnId；R `_0x338c29` 捕获 roundId。若当前仍保持这些行为，旧链通常被阻断，不能认定重开必然旧杆。

条件可达：若当前重开只递增 round、保留或复用 turn，且当前 `_0x338c29` 不查 round，则已排入最后500ms的旧候选可在新局 active=true 时进入 `_0x4b3cc6`；后者会把旧调用当作当前回合提交。若重置 turnId 复用旧数值，还可能遇 aiShotTurn 数值碰撞，使新局首杆被去重拦截。两种情况均需核对初始化、重开和所有赋值点。

最小复现建议：在各异步边界重开，保留旧回调引用，在新局开启后交付旧回调；合法产品路径同时重复重开20次。期望旧局无位姿写入、无发射、无结算，新局首杆恰好一次。控制桩回调测试仅证明防护能力，不证明真实调度必然重复交付。

### 3. 轮次变化：拒绝旧完成回调不等于取消旧动画写入

静态证明：C 调用 `_0x5e7a5f` 后 turnId 变化，旧 AI 完成回调不能继续调用瞄准/递归/落杆。

条件风险：移动 tween 本身仍可在失效前后继续写同一 `_0x27e1b4.x`；瞄准 tween 同理继续写共享瞄准器。C 的回合切换未显示 extract 旧 tween，只有完成回调守卫，因此可能干扰玩家或下一AI回合的表现及物理映射。是否会被同属性新 tween 覆盖、取消，取决于当前 Tweener 的冲突策略与 x/worldX setter，未读取当前实现，不能确认。

最小复现建议：强制随机分支执行最长四段移动，在每段中触发真实超时/换手，再逐tick推进旧 tween。期望失效动画不再修改共享节点、刚体位置或HUD；捕获并检查每次 position setter 与有效 token。旧版倒计时可触发换手，但其正常时长远长于常规AI链；缩短时长属于边界夹具，不能称自然复现。

### 4. 目标失效：当前候选无法在提交时核对原目标

静态缺口：C 从候选生成后始终沿用 pos/dir；候选过滤仅检查数值、落点范围和当时落点占用。最终提交不查目标仍在世界、仍可击打、坐标变化或棋盘版本。fallback 也只返回 pos/dir，没有目标标识。R 候选结构同样为几何数据，不含目标id；不能据此假定当前全部生成器相同。

条件可达：选定后、同局同轮内发生目标移走、入袋、销毁、回摆或规则目标变化，且未使令牌失效，则旧角度仍进入发射。若当前AI只在完全静止且无异步回摆时运行，该前提可能不可达；需读取当前结算与回摆交接证明，不能把测试注入局面变化当自然路径。

最小复现建议：候选选定后暂存回调，移除/移动目标但保留令牌，再推进；另从真实犯规返子/皇后归位路径寻找同轮局面变更。期望候选失效后重算或明确跳过，不能朝过期目标提交。测试记录棋盘版本与目标身份，不以“没有报错”作为通过。

### 5. 候选被阻挡：生成时过滤不能保证落杆时合法

静态证明：C `_0x50a0ff` 过滤时调用占用查询；fallback在返回前检查落点；`_0x4b3cc6` 仅查有限值，随后把撞针 worldX/worldY直接设到候选pos并发射，没有重新调用占用查询或检查基线。故阻挡发生在选定后且令牌不变时，该局部链确实会提交旧落点。实际错误物理后果取决于发射器及物理引擎。

最小复现建议：初次过滤返回空闲；最终等待期间把棋子中心放到候选落点；调用最终回调，监视发射和位姿写入。期望提交前重新判定，重规划或安全移交，零重叠出杆。路径中新增障碍和目标失效一样，需另核实真实局面变更入口。

路线阻挡须与落点阻挡分开：当前截取没有完整四个生成器。R `_0x3ea989` 是沿线离散采样，不是连续几何证明；fallback本来就是随机朝目标出杆，不保证路线无障碍。碰到其他棋子未必是非法落杆，不能把命中率问题等同生命周期bug。测试应区分“起点重叠禁止”和“路线变化导致重新规划的产品要求”。

### 6. 重复回调：同轮发射去重有效，结算去重未获证明

静态证明：C 在有限值检查通过后、任何发射副作用之前设置 aiShotTurn；正常单线程顺序交付两次最终回调，仅第一调用发射。非法候选被拒绝时不会预先占用去重标记，这是有效改进。

剩余条件风险：重复移杆/瞄准完成可创建并行动画与等待，虽最终通常被发射门闩拦截，仍可能产生额外表现写入。标记在发射调用前写入；若 setter或发射器抛错，则后续清理与结算排程不执行，同轮重试又被门闩挡住，可能停局或仅等待超时。需核实实际发射器是否会抛错；不是已发生异常。

C 将 shotTurn 传入 `_0xbdafb3`，但当前函数体缺失，传参本身不能证明被校验。R `_0xbdafb3()` 无形参，等待运动结束的递归和后续换手没有turn守卫；R 包装仅查round。因此同局旧结算/重复结算可能再切轮或处理错误回合，不能将其直接归为当前缺陷。

最小复现建议：同一最终回调顺序调用两次，断言发射=1、结算排程=1；将同一早期完成回调交付两次，断言无额外共享节点污染；旧结算在下一回合交付，断言不改当前回合、不重复加分。另用发射器异常夹具验证有明确恢复出口，并区分夹具异常与真实可达异常。

### 7. 无候选、无空位及非法数据：有出口，但出口语义和活性待核验

证据：C 空候选进入 fallback；fallback为空时同步 `_0x24bb4a(); _0x5e7a5f(); return`，因此不能称“空候选必卡死”。该路径把“无目标”“基线全封”“某棋子坐标非法使区间算法返回null”合并成移交玩家；无目标若本应先结束比赛，可能遗漏终局，须核实上游规则。

C `_0xd6b627` 与落杆函数遇非法数值直接return，没有重排或移交。正常候选过滤已挡住多数非法值，不能声称一定由标准路径触发；fallback目标未显式检查坐标，若 `_0x8b2762` 返回NaN，调用 `_0xd6b627` 可静默拒绝。若当前外围有持续回合倒计时，只是丢回合/延迟；若该模式不计时则可能无限等待。R 某些模式/教程的计时条件不同，不能假定所有模式都能自救。

最小复现建议：分别设置候选为空但fallback可用、目标全空、基线全封、单个非法棋子、fallback目标NaN、候选在等待中变NaN；断言每项进入一次合法发射、明确移交或终局，不停留在不可操作且无待办的AI状态。无空位移交玩家后还须检查玩家基线是否可用，避免把卡死转移给玩家。

`_carromFindOpenBaseline` 有限遍历和最终占用复查优于仅2单位网格扫描，但不应宣称完整几何求解：相切边界、零宽合法点、重合区间、非法半径/上下界均应验证。旧版占用查询用距离严格小于半径，相切可能合法；当前是否相同未知。

## 审查用原型契约与验收口径

不改变既有Carrom玩法、计分、布局和美术。成功指机器人在有效回合从合法位置恰好提交一次物理动作，物体静止后只结算一次，并进入下一有效回合或既有胜负界面；失败指过期出杆、重叠落杆、重复结算、旧动画污染新回合，或无可操作输入且无合法后续任务的停局。每次入袋计分、犯规返子和终局规则以当前完整规则实现为准，截取不足以重定义。旧版disc-rules的六/九子目标仅作背景。

建议状态表达：AI_SELECT → AI_MOVE → AI_AIM → AI_WAIT → SHOT → SETTLING → NEXT_TURN/RESULT；PAUSED冻结原状态；RESTART/EXIT使所有旧任务失效。逻辑状态、回合所有者、round/turn/action标识、局面版本、shotCommitted、settlementCommitted与UI动画分离。规则不变量是每个动作至多一次提交且最终有出口；动画完成不自动等于仍有落杆授权。以上为建议验收模型，未实施改造。

输入窗口：玩家只能在其可操作阶段拖拽/落杆；AI阶段禁止玩家出杆；暂停时拒绝核心输入；重开和退出要取消待提交动作。保留既有棋盘、两侧或上下玩家HUD、瞄准器、力度/位置控件及暂停弹层，不产出新界面。新增界面如有后续实施，默认英文，示例 Pause、Resume、Restart、Your turn、Opponent aiming；本轮没有生成网页，不声称lang=en已验证。

物理与误差：R每逻辑更新调用Planck step(1/60,10,10)，ticker累计后以 while(accumulator>1)执行更新；未见本读取段的补步上限。当前代码未包含物理循环，不能断言当前步长/长帧策略相同。后续验收以固定1/60秒步长为基线，分别输入30/60/120Hz与250ms长帧，检查相同逻辑事件序列和有限位置速度；补步上限与超额时间处理由当前实现核实后定案。不能把动画time=20解释为20ms；旧版使用逻辑tick。

建议几何测试容差：基线坐标与边界比较采用明确epsilon（初始建议1e-6游戏坐标单位，需与当前尺度校准）；落点距棋子中心不小于有效半径和减epsilon。C的pos.y严格相等可能过滤浮点扰动候选，应覆盖Y、Y±1e-7，而非未经评估直接改比较。生命周期令牌、发射次数、结算次数不允许数值容差。物理最终坐标容差暂不承诺，应以当前引擎、固定种子及实际轨迹建立基线；禁止要求跨浏览器位级一致。

计分和碰撞建议：分别验证起点占用、路线碰撞、入袋触发和犯规返子；每个shot/棋子入袋事件去重。角度扰动C为0或绝对值[0.05,0.1)弧度，属于AI故意误差，不应误报为数值漂移；当前瞄准显示与实际发射的符号配合已调整，需以真实渲染角度setter核验，不以旧版符号认定当前反向。力度仅有限值并不保证业务上下界；后续需核对零/负/极大有限力度的拒绝策略。

## 建议回归矩阵与补充上下文

按初始等待、四段移杆、瞄准、最后等待、发射后等待、静止轮询七类边界，交叉暂停/恢复、重开、退出再进、玩家/AI换手、重复回调；固定随机序列确保直达与最长随机链均覆盖。捕获日志字段建议为roundId、turnId、actionId、phase、paused、owner、boardVersion、callbackId、shotCount、settlementCount、pendingCount，附位置与碰撞查询结果。每次断言旧任务零副作用，同动作最多一次发射和结算；恢复或异常后在明确期限内完成/重排/移交，期限用逻辑tick表述并排除暂停时间。

当前审查无法闭合的最小源码集合：`_0x338c29`、Tweener add/update/extract及同属性冲突策略、当前暂停/恢复/后台入口、重开/退出、所有roundId/turnId/aiShotTurn赋值点、当前 `_0xbdafb3` 全体及全部调用点、返子/皇后回摆与AI启动交接、撞针x/worldX/worldY及发射方法、当前物理ticker与超时分支。无需为本轮报告暂停索取它们；它们是后续将条件风险升级为实际缺陷所需证据。
