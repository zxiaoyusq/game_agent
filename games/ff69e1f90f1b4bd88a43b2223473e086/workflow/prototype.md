## 3. 玩法和审查模型

### 核心循环 / 状态

沿用参考行为：玩家或 AI 回合 → 规划/定位 striker → 瞄准预览 → 提交前复核 → 发杆 → 物理运动/入袋 → 停止与结算 → 续回合、换回合或结果。重规划属于发杆前过程，不产生一杆、不直接计分。

AI 路径：`_0x50a0ff → _0xd6b627 → _0x4662ac → _0x223471 → _0x4b3cc6`。初始常规候选失败使用 `_0x3d12d7` 备用；重新规划出口也使用该备用规划器。

- `_0xd6b627` 检查有限参数后抓取快照，再滑动；其 return 后的直接发杆代码不可达，不应当作实际发杆路径。
- `_0x4662ac` 的 iteration 是表现滑动次数，不是重规划次数。
- `_0x223471` 将 force 限为125（基础100），产生0或±[0.05,0.10) rad 的随机偏差；备用杆先用 helper 消除可安全去掉的偏差。完成预览后延迟500ms才调用提交。
- 成功提交先锁 `_carromAiShotTurn`，再隐藏预览、写 striker world 坐标、施加向量；2300ms后请求本 turn 结算。结算仍检查预期 turn、settledTurn、活动状态和运动停止等条件，不能将2300ms等同必然结算完成。

### 物理、碰撞、计分与成功失败

- 参考更新使用固定 `world.step(1/60,10,10)` 并清力；累积器按单位步驱动更新。这里只证明源码存在固定步长，不保证真实设备帧率或确定性。
- E5显示 coin fixture 半径为16，striker fixture 半径为 `34×0.8×0.8=21.76`（均除以世界比例），与 helper 使用的合并半径 `R=37.76` 一致。fixture 的数值模型不能代替引擎容差/连续碰撞实际测量。
- helper 使用棋子中心到截断线段距离，严格 `< R²` 为挡；精确相切不算挡。fullFallbackPath覆盖到目标接触/估计行程；非full模式仅检查短起始路段。不是墙体、反弹、动态速度或袋口求解器。
- 原计分由入袋与结算路径、`CarromDiscRules` 等既有规则处理，新增分支不增加分数。未完整审计外部规则，不能承诺全部计分/女王规则正确。
- 本补丁的成功条件：该窄失效场景取消旧杆，最多两次重新规划，重新预览后至多提交一次。失败/无候选/超限：结束动作；普通情况转玩家回合；女王待覆盖状态则锁本杆、清成功标志并走现有结算，不能直接跳过女王处理。

### 输入窗口、布局与误差

沿用现有中心棋盘、回合/分数HUD、基线striker和定位滑杆、瞄准线/箭头、暂停菜单；本阶段不增加UI。玩家输入由 pointer 身份及 active、hostPaused、turn actor/输入状态约束；AI预览500ms是演出延迟，不是玩家反应窗口。重开清除按住的指针身份及瞄准状态。

## 4. 新增条件与真值表

A 的发杆失效条件依次为：存在快照且棋盘变化；pos.x超出基线两端；pos.y严格不等于AI基线；起点与棋子重叠。

B 在上述 OR 链末尾追加：

```js
shot._carromFallbackTarget &&
  _carromFallbackSafeDeviation(shot, deviation) !== deviation
```

这里的比较不是 Boolean 安全检查。helper 最终返回：

```js
blocked(shot.dir - deviation) && !blocked(shot.dir) ? 0 : deviation
```

下表前提：target有效且仍在三组数组中、参数有限、距离>R，其他旧失效条件全部为false。

| δ | 实际偏差方向挡 | 原方向挡 | helper返回 | B仅新增条件 | 原方向检测 |
|---|---|---|---|---|---|
| 非零 | 否 | 任意 | δ | 不重规划 | 不调用，&&短路 |
| 非零 | 是 | 否 | 0 | 重规划 | 调用 |
| 非零 | 是 | 是 | δ | 不重规划 | 调用 |
| 0（包括−0） | 任意 | 任意 | 0 | 不重规划 | 提前return，无路径检测 |

目标缺失、参数非有限、目标距离≤R等也提前返回原δ。顶层提交校验能挡住 shot自身/force/δ 非有限，但不等于 helper 对target所有失效都封闭处理。缺snapshot等异常输入下，helper存在 fail-open 行为。

**预览时已经被去掉的偏差同样属于零偏差情况**：后来原路被小幅移动挡住，也不会靠B的新条件重新规划。两方向都被挡时保留δ更不是安全证明。

### 短路与复用出口

前面任一旧条件为true，就不调用新增helper。例如有快照的目标删除/对象替换通常先被 boardChanged 检出。这并非新增条件漏调用导致失败，而是旧条件已进入同一出口。多个条件同时失效，不会各自规划一次。

helper判定0≠δ之后，B不是把旧杆δ改为0立即发射，而是：

1. 按当前turn初始化重试计数；
2. `++count <= 2 ? _0x3d12d7() : null`；
3. 有新杆调用 `_0xd6b627(newShot,100)`，重新快照、滑动、随机偏差和预览；
4. 无新杆/超限结束或结算；
5. return，旧杆不施加冲量。

因此没有新引入“旧偏差预览、临时改成零偏差发杆”的静态错配。重规划可能再次选同目标甚至相同位置，不保证找到安全解。

## 5. 目标身份与小移动

快照记录 `{disc:对象引用, group, x, y}`，Map按对象身份匹配：

- 删除、增加、同坐标新对象替换、跨组移动、重复对象/非有限坐标会被判变化；同组排序不会。
- 目标返场可能创建新对象（女王返场/部分结算返场可见 new），即使id或坐标相同也不能当作原target。
- helper 用 `indexOf(target)` 判断在场；路径检测用 `disc === intendedTarget` 排除该目标。正常target保留身份时只忽略目标本身，不忽略同坐标的其他棋子。
- 正常 `_0xd6b627` 抓取的快照存在时，目标消失由旧boardChanged分支处理；缺快照时，helper发现目标不在数组只返回δ，新增条件不会提供兜底。
- 快照不记录 body、sensor、radius、velocity 等状态；同对象但物理实体/状态失效不一定被捕获。
- 目标≤1每轴移动时 shot.dir 不随之更新。helper使用新target坐标计算行程，但不重算dir，也不强制这条射线命中目标。无其他障碍的“偏差射线错过目标”可仍通过，不能把“未挡”当“必击中/必得分”。

备用规划器随机选目标和基线，先避起点重叠，再采样7个基线位置尝试通路；**全部采样失败仍保留原备用杆**。这说明原策略允许被挡备用，而不是安全求解器；把双挡/零偏差一概改成放弃发杆属于策略变更，不能未经授权混入本次审查。

## 6. 重试上限、重复调用和生命周期

### 计数

- 单一链条的连续三次失效：初始杆失效→count1新杆；新杆失效→count2新杆；再次失效→count3无规划。最多两次调用重规划器，不是最多三次重规划。
- 规划器提前null会提前结束；无候选不必等超限。
- count按turn懒重置。`_0x50a0ff`/`_0x5e7a5f` 都递增turn；重开经其中一条启动，因此无需在重开中显式把count归零才能获得新turn额度。不能声称重开显式重置所有AI计数。
- 重规划分支尚未写shotTurn，正常理由是新杆仍需提交。但没有计划代次或重规划中锁：同turn旧回调再次到达仍可合法进入分支，消费共享count或启动并发预览。这是静态可达风险；真实Tweener是否会产生这种回调须运行取证。
- 成功后同turn再调用会被锁挡住；但跨turn直接重放旧 `_0x4b3cc6` 调用没有传入expectedTurn，函数会取当前turn，不是独立陈旧计划检测。正常封装回调有turn/round过滤，二者不要混为一谈。

### 暂停、广告、退出和新局

- host pause设置标志、清累积器、暂停match timers、取消玩家瞄准并阻断输入；广告以token列表处理嵌套。
- 更新入口在菜单暂停/host暂停/广告时return，不更新Tweener或物理；host/ad在Tweener更新后还会复核。这是正常AI演出冻结的静态基础。
- AI500ms延迟 `_0x338c29` 是Tweener空对象延迟，不是原生setTimeout；其封装捕获round并检查active。不能只靠原生match timer的pause/resume说明AI安全。
- 滑动/预览完成回调捕获round+turn；排出的延迟封装有round，内层有turn。
- B新局 `_0x1260d2` 调重开 `_0x5480e3`：round++、清指针与预览、extract striker和aim tween，重建棋盘并启动新turn；旧空对象延迟即使未extract仍有round门禁。
- 退出 `_0x3771eb` 清active与match owner/timers；在退出状态旧回调被active挡住；随后重开还有round门禁。
- **提交函数本身未检查 hostPaused、广告、菜单暂停、正常合法参数分支的AI actor，也未接收expectedRound/expectedTurn。**正常安全依赖调用链停止及封装过滤。外部直接调用、重入、同turn旧计划回调不能据此宣布已安全。

## 7. 瞄准、实际向量与复核方向

两版读到的相关 renderer/striker 方法相同。令规划角为d、预览使用的偏差为δ：

1. `_0x223471` 存储瞄准角 `a=π+d−δ`。
2. `_0x4b3cc6` 传给striker的方法角 `b=π−d+δ`。
3. striker真实方法生成向量 `F*(cos(−b+π), sin(−b+π))`，所以实际运动输入角为 `d−δ`。
4. helper检测 `d−δ`，符号一致。
5. 瞄准箭头局部向−Y（构造的箭头/遮罩及anchor），renderer旋转 `a−π/2`，将局部 `(0,−1)` 映成 `(-cos(a),-sin(a)) = (cos(d−δ),sin(d−δ))`。world坐标同步与PIXI坐标使用同向x/y，没有源码中的额外Y翻转。

因此正常不可变shot、单一演出链下，预览与实际向量一致，正负偏差都成立。E5是实际方法静态证据，不仅是两个角参数看似相等。

边界：未检查贴图真实箭头画向、完整父节点最终变换或截图。shot对象的pos/dir不是冻结快照，预览后若被外部改dir，提交读取新dir但δ和已显示a来自旧预览；只检查有限/基线/棋盘变化不会保证一致。重规划期间并发旧新预览也可能污染共享瞄准器。这些不是本轮已复现缺陷。

## 9. 风险优先级与后续设计取舍

1. **P1，已证实范围缺口**：零偏差、双挡不会触发新增条件。若目标是“所有实际方向不安全都重规划”，应另设实际路径安全谓词，不能复用当前返回δ选择器作完整证明。
2. **P1，待运行取证**：重规划期间没有计划代次门禁；建议后续方案以round/turn/plan ticket及不可变shot控制预览、回调和提交，避免旧计划消耗额度或污染瞄准器。
3. **P2，异常调用边界**：提交端生命周期和actor检查依赖封装；缺snapshot、target物理状态失效未封闭处理。
4. **P2，模型边界**：目标轻微移动不重算dir；错过目标、动态棋子、墙/反弹、相切数值容差不属于本补丁保证。

这些是建议，不是已实施修复。扩大零偏差/双挡保护会与“全部采样被挡仍保留备用杆”的现策略发生范围取舍；若后续实施，应通过request_user_input确认保留窄补丁还是改为全面安全/放弃策略。本次静态审查无需用户例行确认，亦不自行替用户批准修改或下一阶段。
