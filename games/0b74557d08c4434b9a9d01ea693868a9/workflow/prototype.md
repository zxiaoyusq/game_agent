## 3. 规则筛选先于无效项过滤

令 A=`_0x2a9c75`，B=`_0x3e4566`，C=`_0x3231b3`。仅作代号，不推断它们的棋子类别或竞技规则含义。按片段上下文，将混淆调用作为其表观的 `length/concat/floor/random` 操作审查；现版解码表没有提供，具体映射仍待配对。

表观控制流：

1. 模式严格等于数值2时选择 `A.concat(B,C)`。
2. 否则，原始 `A.length === 1 && C.length` 时选 `C.slice()`，其余选 `A.slice()`。
3. 仅当这个未过滤池的长度为0时拼接 B、C。
4. 之后才过滤 `target && Number.isFinite(target.x) && Number.isFinite(target.y)`。
5. 过滤后长度为0直接 `return null`，不再重新应用规则或补选。

### 静态反例（逻辑推演，未运行）

- `A=[坏项]，C=[]，B=[有效对象]`：A 原始非空，补选不触发；过滤为空后返回 `null`，B 不会被考虑。
- 非模式2，`A=[有效a,坏项]，C=[有效c]`：原始 A 长度为2，选 A；过滤后仅剩a，但不会重走“长度1选C”的分支。若规则按有效在场对象数计数，这会选错规则池。
- 非模式2，`A=[有效a]，C=[坏项]，B=[有效b]`：C 原始非空，所以选C；过滤为空返回 `null`，不会回退到a或b。反之，如果规则确实禁止此时击打a／b，返回 `null` 可以是正确拒绝，不能为了“能出杆”绕过规则。
- `A=[null,有效a]` 与稀疏数组 `[空洞,有效a]`：原始长度均为2；`filter` 会剔除前者并跳过后者的空洞，但此前规则长度已经生效。
- 模式2：先取三池并集，再过滤；只要并集有有效项就不会因空池提前 `null`。它与其他分支的“all invalid”范围不同。

**判断：筛选／过滤顺序有明确的结构性边界，但正确修改取决于长度代表什么。** 如果长度是有效在场棋子数，应先取得可信有效快照再作数量规则判断；如果长度代表独立规则状态，应单独传递那个状态，不让损坏对象替代计数。过滤仅验证坐标，不验证类别、活跃状态、已入袋、回合归属或可击打资格。

## 4. all invalid 返回 null：成立范围

对普通、稳定的数组与数据对象，过滤完成后选定池为空时，`if (!_0x3a50e5.length) return null` 会在随机取目标、放置和方向 helper 之前退出。这是正确的局部空池保护，不应删掉以恢复出杆。

它只保证“最终选定池无坐标有效项”返回 `null`，不是“全盘所有规则允许目标都无效”的证明。未选池的有效对象不会自动补选。还不能保证以下输入也以 `null` 收敛：数组本身为 `null/undefined`、没有 `slice/concat/filter`、getter 抛错、Proxy 访问抛错、helper 抛错。这些会在别的阶段异常退出。坐标为数字字符串、NaN、正负Infinity会被 `Number.isFinite` 排除，不做隐式坐标转换。

## 5. 首次对象去重与环绕搜索

锚点：`firstTargetIndex = pool.indexOf(firstTarget)`、`new Set([firstTarget])`、`targetOffset = 1; targetOffset < pool.length`。

在池不被修改、目标为稳定对象引用、随机索引合法的前提下：

- 首次对象来自池，所以 `firstTargetIndex >= 0`。即使随机抽中首次对象的较后重复槽，`indexOf` 仍取其最早槽。
- 从最早槽开始的 offset=1…N−1，模N会访问其他所有槽一次；因此不遗漏其他唯一对象。它不是从随机抽中槽继续搜索，顺序可能不同，但覆盖性仍成立。
- Set 初始化已经包含首次对象；它在其他槽出现也不会再运行多目标7点检测。首次对象已在此前初始位置和最多7个采样位置检测，故不能说“首次对象只检测一次”。
- 每个后续稳定对象引用最多进入一次内层7点循环。有限N下目标循环有界，不存在由引用重复本身造成的无限环。
- 例：池 `[a,b,a,c]`、首次随机选到后面的a，`indexOf(a)=0`；后续槽序列为b、a、c，重复a跳过，b与c都被覆盖。

### 剩余风险

1. Set 按引用去重，不按坐标或实体ID去重。两个 `{x:1,y:2}` 是两个对象；同一实体的两个包装对象仍会重复搜索。仅凭相同坐标也不宜去重，因为可能是不同实体或异常重叠局面。
2. 随机首次选择发生在去重之前，重复引用有多个随机槽，首次选择概率被加权。例如 `[a,a,b]` 在均匀随机源下a概率为2/3；不能称为唯一目标均匀选择。
3. 外层仍扫描N−1个槽，Set降低的是昂贵内层搜索次数，不是槽扫描次数。大量重复输入仍有过滤与索引／扫描成本。
4. 其他目标重新检查坐标，但初始目标之后没有统一重校验；getter变化、helper修改对象等能破坏前提。Set在搜索前加入对象，如果搜索期间其状态变化，之后不会因重复槽重新尝试。

**结论：不要将现有 `indexOf + Set + modulo` 误判为确定漏搜或无限循环。** 要修改的是身份和快照契约、概率政策及总预算，而不是为了纠错盲目换掉正确的引用环绕覆盖逻辑。

## 6. 非有限数值、异常与普通路径零退化

### 6.1 输入过滤不是完整数值安全门

只有目标x/y被过滤。基线下界L=`_0x55e1a0`、上界R=`_0x187453`、固定y=`_0x429ae3`、半径=`_0x133600`、宽度R−L、helper返回方向和开放x均无有限性检查。

- 有限端点也可能相减溢出，如极大正负端点的R−L变成Infinity。
- 有限目标和起点也可能使坐标差溢出；`Math.hypot` 不能修复已经溢出的差值。
- 普通初始路径和同目标7点路径用 `sqrt(dx²+dy²)`：例如有限dx约为1e200时平方溢出，距离为Infinity；极小差值平方可能下溢为0。多目标分支的 `Math.hypot` 更稳健，但没有检查其最终结果。
- 字符串基线或半径会使 `+` 拼接，不能以减法发生数字转换为由接受它们。
- `!_carromStartPathBlocked(...)` 会将 `undefined/null/NaN/0` 等假值当作“不阻塞”；若helper应返回boolean，必须明确其异常／未知输出不能被误当清晰路径。位置碰撞helper也有相同真值语义风险。

### 6.2 零距离覆盖所有分支

当目标等于初始随机位置或任意采样位置时，距离为0。片段先调用 `_0x8b2762`，随后才算距离，且没有距离大于零／容差的判断。若方向helper按长度归一化，可能得到NaN；若它特判为零向量，输出也未必是有效击球方向；若它返回其他形式，仍需消费者验证其有效性。本轮不知道其现版返回形式，不能直接宣称一定产生NaN。

**普通路径同样缺门禁：** 初始路径被helper判为清晰后，会跳过全部采样与多目标补救，直接返回未经验证的方向。只给新多目标分支加距离校验不能解决这个问题。

建议在调用方向helper前，以快照坐标算稳定距离，校验合法尺度和 `distance > epsilonDistance`；计算方向后按现版表示校验有限性、非退化及归一化要求。容差必须基于物理单位、棋子半径和引擎误差确定，本轮不编造数值。零距离是否同时代表重叠放置取决于碰撞helper是否覆盖目标，不能假定它会先排除。

### 6.3 异常边界

`target && ...` 只防常见空值，不防属性getter和Proxy抛错；两次读取x/y也不是原子快照。`slice()` 只复制数组槽，目标对象仍共享。helper缺失、抛错或返回不合契约的结构，本函数没有局部保护。需要在明确owner的输入／执行边界诊断异常并终止该次动作，不能将程序错误静默视为可击球。

## 7. 基线范围、扫描与提前返回

### 7.1 三种取样域不一致

- 初始随机位置表观来自 `[L,R)`（标准随机源及有限合法L<R前提）。
- 局部扫描使用 `x+offset < R`、`x-offset > L`，严格排除对应端点；offset每次增加2，仅访问围绕随机起点的离散格点。
- 后续7点使用k=0…6，包含L与R两个端点。

必须明确可放置域是否包含端点，及棋子中心与半径是否已经计入L/R。若端点非法，7点分支会依赖碰撞helper兜底，而片段没有独立范围校验；若端点合法且仅端点空闲，局部扫描会错过它。

offset=0会重复检测初始碰撞位，可能正负都测一次。宽度W=0时局部扫描不执行，7点均相同；W<0时扫描不执行，初始与采样公式仍生成反向域位置。不能未经规则许可交换端点。W为NaN使循环不执行；W为Infinity使扫描可能无法有界终止。即使W有限但巨大，数值计数器在约2^54处以增量2不再前进，也不能依靠W有限证明该扫描一定终止；应限制尺度并用有界整数次数驱动。

### 7.2 开放位置 helper 不是已证明的后置条件

锚点：

`if (_0x23a7dc(pos, radius + 16)) { var openX = _carromFindOpenBaseline(); if (openX === null) return null; pos.x = openX; }`

- `undefined/NaN/Infinity/字符串/越界数值` 都不等于 `null`，会赋给pos.x。
- 赋值后没有重新检测放置碰撞，也未验证x合法、y有限或helper使用的半径和域一致。
- `null` 返回发生在7点采样和所有目标备选之前。若helper只作有限采样、使用不同域或容差，后续本可能成功的候选会被提前剪掉。
- 若现版helper保证在同一合法放置域、同一碰撞状态／半径下完整判定没有任何放置位，那么提前返回合理；放置阻塞与目标无关，换目标不会凭空产生放置位。不要反向断言“必须换目标才能解除放置阻塞”。

必须提供现版helper契约及精确实现配对，否则只能判为“提前返回依据未闭合”。有限采样未找到、预算耗尽和证明无合法位置应当区分。

## 8. 搜索预算与搜索能力边界

设过滤后槽数为N，唯一稳定对象引用数为U（1≤U≤N），合法有限基线宽度W>0，局部扫描实际循环次数为K。正常小尺度算术下K约为 `ceil(W/2)`，但预算应由显式最大次数控制，不以此近似替代终止门禁。

忽略helper内部调用、异常、重入与数据变化，对最坏不清晰路径：

- 过滤与槽扫描规模O(N)，Set空间O(U)；首次 `indexOf` 最坏O(N)。
- 初始目标：一次初始路径检测＋最多7次同目标采样路径检测。
- 其余U−1个对象：每个最多7次路径检测。
- 总路径helper调用上界：`1 + 7U`。
- 位置碰撞helper直接调用上界：`2 + 2K + 7U`（初始与扫描后各一次，局部每次最多正负两次，所有目标采样最多7U次）。
- `_carromFindOpenBaseline()` 直接调用最多一次，内部扫描与碰撞成本未知；以上不包含它和路径helper内部工作。
- 若每个路径helper遍历M个障碍，采样部分可能是O(U·M)，当目标数与障碍数同阶时可能接近平方增长。但未提供现版helper，不能断定具体复杂度或设备耗时。

这是调用次数的静态上界推导，不是计时结果。需要限制N（重复槽也计入）、U、K和helper总工作；预算耗尽应有可区分结果，消费者不能无限重试。同目标7点与多目标7点没有搜索所有基线位置，也没有尝试每个目标的随机／局部起点，因此“采样无清晰路径”不等于“无任何可行杆”。它选择首个通过检测的候选，不是评分最优解。

## 9. 返回契约与消费者风险

片段存在三类普通结果和一类异常：

| 结果 | 触发条件 | 消费者应做的事 |
|---|---|---|
| `null` | 选定过滤池为空；或开放基线helper返回null | 不解引用、不提交击球；诊断原因，按已定义回合终态处理，禁止无限递归／定时重试 |
| 对象，`_carromFallbackWasClear=true` | 某次路径helper返回假值 | 仍检查有限合法pos/dir、目标资格、快照／回合是否有效；只表示本检测模型下的起始路径未阻塞，不表示得分 |
| 对象，标记false | 采样均未通过，保留原备用杆 | 依明确规则允许阻塞尝试或拒绝；不得忽略标记后宣称清晰路径 |
| throw／无法有界完成 | 结构、访问、helper或数值异常 | 执行owner捕获／终止／诊断；不能泄漏错误动作到物理层 |

标记false时正常、稳定helper前提下位置与方向仍对应原始目标；寻找替代失败并未自动换目标。这个保留行为在注释中是有意的，不应未经业务授权强改成null。最低要求是有限、合法、非退化，即使允许阻塞尝试也不能例外。

`_carromFallbackTarget` 是共享对象引用，不是永久有效的实体证明。消费者若延迟提交，应核对目标仍在场、规则资格、当前回合／局面是否一致；该函数未提供轮次字段，不能声称已经防止旧结果入新回合。

旧附件可见调用文本只是提醒“直接传入消费者”这一核查方向，不证明现版消费者一定未判空、一定可达或一定崩溃。**R-02／R-06必须在现版所有真实调用方闭合，不仅检查隔离函数。**

## 10. 本次原型定义的适用边界

本轮原型产物是边界审查和验收合同，不是新游戏设计。

- 局部循环：规则状态＋目标池 → 坐标有效过滤 → 随机首次目标与基线 → 放置搜索 → 初始路径 → 同目标7点 → 去重多目标7点 → 对象／null → 消费者提交或终止。
- 规则状态：模式、三组目标及其业务计数；本片段未提供完整规则资格、目标生命周期和回合状态。
- 局部成功：返回经门禁验证的有限合法非退化候选；清晰／阻塞两类分开。局部失败：无规则有效目标、无合法位置、预算耗尽或输入错误；现版只有两种null触发，尚未区分失败原因。
- 物理步长、冲量／速度范围、碰撞体、计分和胜败条件、输入窗口：V5片段未包含，不能从选杆几何推导。本轮不新增这些规则；需现版物理／回合owner提供才能验收物理首碰与得分。
- 碰撞：本轮只核查 `_0x23a7dc` 放置测试与 `_carromStartPathBlocked` 起始路径测试调用，参数中的16含义、`true`含义和误差均未知。
- 可接受误差：有限性和契约是硬要求；零距离容差、方向模长容差、端点／碰撞容差必须与现版单位和helper一致，尚未赋具体值。
- 界面布局、游戏语言及英文文案：未在本轮新增或修改玩家界面，不编造布局和教程；Canvas框架选择不证明附件在用原生Canvas或已经迁移引擎。
- 参考取舍：V5正文是审查基线；旧附件只提供历史上下文；不使用旧helper补齐现版事实，不推断竞品算法、真实胜率或设备性能。
