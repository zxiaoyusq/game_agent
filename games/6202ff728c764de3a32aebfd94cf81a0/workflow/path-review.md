# 机器人路径连续检测补丁：独立静态审查

## 结论

**有限正常输入、理想实数模型下，补丁正确地把旧采样圆盘的并集扩展为首末采样点之间的胶囊区域；不是整条运动路径的连续碰撞检测。** 首、末采样圆盘保留，短段行为保留，原点球不会因为被列入障碍数组而必然自挡。没有发现正常棋盘尺度下必然发生的高严重性新增缺陷；但不能给出“所有 JavaScript 输入下旧 blocked 必保留”或“所有物理合法候选必保留”的保证。

发现一项正常尺度的合法候选损失风险（撞击器路径阈值偏宽，新检测把旧采样间隙也按该阈值封闭）、一项明确的极大坐标浮点兼容性反例，以及异常输入 fail-open。末端/反弹接头盲区和半径收缩是旧行为，补丁未修复，不能误报为新增缺陷。

状态：采样范围语义 **PASS（实数模型、有条件）**；无损物理候选声明 **FAIL**；全输入 blocked 单调性声明 **FAIL**；实际游戏影响程度 **NEEDS_CONTEXT**。这些状态是静态命题审查，不是游戏构建或设备验收结果。

## 2. 前后算法与覆盖证明

记 `O=origin`、`h=step`（第二参数）、`a=angle`、`L=distance`、`u=(cos(a),sin(a))`、`N=floor(L/h)`、`rho=0.9h`。本节假定 h>0、L>=0 且有限、坐标有限、稳定数值字段、理想实数运算。

R：先复制 O，然后循环 N 次，每次先加 `h*u`，再用 `_0x247dad` 检测所有三组棋子，严格距离 `<rho` 才 blocked。

旧采样中心是 `O+h*u,...,O+N*h*u`，不是 O，也不自动加入真实终点 `O+L*u`。

P：N<1 返回 false；否则对每个棋子 B 计算

```
v = B - O
s = max(h, min(N*h, dot(v,u)))
q = v - s*u
blocked = dot(q,q) < rho*rho
```

这相当于到线段 `[O+h*u,O+N*h*u]` 的距离检测（理想单位 u）。

- N=0：两版不做任何路径点检测，false。N=1：线段退化成首采样点，仍检测同一圆盘。
- N>=2：旧每个采样中心都在线段上，因此旧 blocked 圆盘并集包含于新胶囊。新增加的是采样圆盘之间的凹陷区域，不是新增首尾中心。
- 长度整除 h 时最后中心为真实终点；否则最后中心是 `N*h`，保留余段 `L-N*h` 的旧语义。
- 首末中心虽不延伸到 O/真实终点，圆盘/胶囊端帽仍向两端延伸 rho。源码注释“without extending into the origin or final unsampled part”若被理解为障碍判定完全不涉及余段，则不准确：没有延伸中心，但端帽可能覆盖余段中的棋子。
- 同样的严格 `<` 保留了理想模型下的切线放行，不改为 `<=`。

**重要限定：这是几何证明，不是 JavaScript 逐位结果证明。** R 用绝对坐标反复加法并开方，P 用相对坐标、投影和平方比较；舍入顺序不同，见第 5 节。

### 接触终点

撞击器 ghost 为 `C-(15+21.76)*uOut = C-36.76*uOut`；检测 h=43.52、rho=39.168。当入射方向恰为 uOut、最后中心距 ghost 的余量为 r 时，到目标 C 的距离是 `36.76+r`。若 `r<2.408`，目标本身会被挡；旧版最后圆盘也如此。精确瞄准并不因使用连续 helper 而新增这一问题。

组合路径把上一级目标 C 的虚拟接触点设成 `C-30*uOut`，递归下一级仍用 h=30、rho=27；理想同向接触时到 C 至少 30，不误挡目标。递归通过非空输出数组防止再次递归，最大额外一层，不是无限递归。

入射方向可能不与出射方向同向（候选评分有绝对值点积）；投影最近位置可能在内部，目标身份没有通用豁免。新检测可能发现旧样本间的实际穿越，不应把所有这类候选减少都归类成合法候选损失。

### 反弹接头

反弹前后分别调用 helper，并分别从各自原点跳过首步中心。不是对整个折线做一次连续检测，也没有明确的 join 圆盘。第一段尾余量、第二段首段仍须结合各自端帽判断；两端帽不保证覆盖所有反弹接触邻域。

可复现几何输入：折线 `A=(100,100) → J=(170,100) → E=(170,200)`，每段 h=30；障碍 `B=(184,86)`。第一段中心区间 x=130..160，距末中心 `sqrt(24²+14²)>27`；第二段中心区间 y=130..190，距首中心 `sqrt(14²+44²)>27`，两版都放行。距接头 J 为 `sqrt(14²+14²)<27`，接头邻域存在漏检。该输入用于 helper 折线语义，不宣称是当前墙面配置中已复现的实际反弹球局。

### F-01：新增拒绝有物理余隙的撞击器路径（中，影响程度 NEEDS_CONTEXT）

```
O={x:200,y:421}; h=43.52; a=0; L=100;
B={x:265.28,y:459};
```

N=2，旧中心 x=243.52、287.04，B 距两个中心均约 `sqrt(21.76²+38²)=43.79 >39.168`，R=false。P 的投影在内部，垂距 38<39.168，P=true。

若按调用者 ghost 几何所用的撞击器/棋子半径和 36.76 作为接触半径，该障碍对水平移动撞击器有 1.24 的余隙，仍被新 helper 拒绝。原因是 `0.9×(2×21.76)=39.168` 比 `21.76+15=36.76` 大 2.408；原有过宽阈值被补丁连续应用到新区域。

这证明 helper 可损失按上述半径模型合法的路径；没有证明这个水平输入经过当前四方向所有前置条件后一定成为最终候选。真实 fixture 半径、solver slop 和完整棋盘候选影响仍需上下文验证。不能直接把 2.408 改成 epsilon，也不能未经授权改阈值。

## 5. 数值、异常输入及运行边界

### F-02：极大坐标破坏旧 blocked 单调性（低正常可达性，命题 FAIL）

```
O={x:2**60,y:0}; h=30; a=0; L=60;
B={x:2**60,y:0};
```

IEEE-754 binary64 在此尺度的相邻值间距远大于30。R 的 `x +=30` 每次舍入回 O，第一步距 B=0，true；P 使用相对坐标0，最近参数30，残差(-30,0)，900不小于729，false。输入都是有限数，故仅做 Number.isFinite 不足以提供全域兼容保证。当前正常棋盘坐标远小于此值，没有证据表明游戏能自然产生该输入。

正常棋盘范围也有微小边界差异的理论可能：反复加法与 `N*h` 不同；`cos²+sin²` 浮点值不严格为1；P 的投影未除以 `dot(u,u)`；开方比较改平方比较会变更极贴阈值点的舍入。本文没有已执行的正常尺度失去旧 blocked 的具体浮点反例，不把理论可能当实测缺陷。

两版都用 floor(L/h)，N 在整倍数附近可因商舍入少1。N=0↔1 的跳变尤其明显。没有 epsilon 或明示误差预算。静态建议的验收是区分数学切线与稳定余隙样本，后续扫 `k*h±delta` 和 `rho±delta`；delta 应来自坐标误差契约，不自行声称已接受任意误差。

### F-03：异常输入 fail-open，负步长新增不兼容（防御风险，中，运行可达性 NEEDS_CONTEXT）

| 输入 | P 的静态行为 | R/归因 |
|---|---|---|
| O=(0,0),h=30,a=NaN,L=60,B=(30,0) | sin/cos/projection/residual 为NaN，比较false，最终false | R也false，既有fail-open |
| O=(0,0),h=30,a=0,L=NaN,B=(30,0) | N=NaN，N<1不成立；end/along为NaN，false | R不进循环，false，既有 |
| O=(0,0),h=30,a=0,L=60,B={x:NaN,y:0} | 跳过异常棋子意义上的false，无显式报错 | R同类问题 |
| 同上，B=null | 访问disc.x抛TypeError | R访问距离函数也会抛错（若执行到该样本/棋子） |
| O=(0,0),h=-30,a=0,L=-60,B=(-30,0) | N=2，clamp区间倒置；along=-30，残差0，半径平方729，true | R阈值-27，距离不可能小于负数，false；新增不兼容 |
| O=(0,0),h=0,a=0,L=60，空棋子集合 | N=Infinity、end=NaN，P有限遍历后false | R循环无上限；补丁改善终止性，但未标记无效 |
| O=(0,0),h=30,a=0,L=Infinity，空集合 | P有限遍历后false | R无限采样循环；不是新增死循环 |

当前观察到的正常调用 h 只有30/43.52，负数/零步长不是这些调用能直接生成的。坐标和角度可受上游异常影响：四方向先读棋子字段，最终候选 finite 过滤发生在 helper 之后，无法作为 helper 的前置保障，也不能阻止此前抛错。private helper 不等于公开接受不可信输入的接口。

P 无新的按路径长度无限循环，for-of 遍历成本取决于棋子数量。新增 for-of 需要 iterable Array/Symbol.iterator；源码原已使用 let、箭头函数、Number.isFinite、Map 等现代特性，未发现仅凭 for-of 就能定性的目标浏览器兼容退化。未执行任何浏览器兼容性测试。

### 时序边界（既有，不算新增路径补丁）

`_0x50a0ff` 真实调用四方向，非 `game.test` 中 return 后的不可达片段。候选在动画后发射；旧有 `_carromAiBoardChanged` 检查每轴位移超过1才重试，允许各轴<=1的棋盘变化，且发射前不是重新检测完整路径。点位每轴1的变化最大可达sqrt(2)，可影响近边界通道。补丁不改变这些时序/角度扰动行为，不能从静态无挡推断实际射击一定无碰撞或获胜。

## 6. 复杂度与候选集合

设棋子总数 M，N=floor(L/h)，一次 helper：
- R 最坏 O(NM)，每样本最多 M 次开方，反复计算三角函数；无挡时循环 N 次。
- P 最坏 O(M)，每棋子常数次投影/平方，sin/cos各预计算一次，无逐棋子开方。
- 两版都构造拼接棋子数组，额外空间 O(M)。P 即便N<1仍先拼接，不能称短段O(1)总成本。
- 最好情况不一定更快：某些采样提前遇到障碍时 R 已可早停；没有 wall-clock 数据，不给毫秒或帧率改善数字。

四方向每层基线尝试上限固定（直线含特殊点及6个网格点，反弹4个点），递归只增加一层。若首层 T 个目标，每个回退展开最多 M 个辅助目标，则路径调用数量最坏 O(TM)，P 检测部分最坏 O(TM²)，T≈M时O(M³)；R 多一个最大采样数因子。排序和其他几何操作另计。补丁改善 helper，不把整个 AI 搜索变成 O(M)。

候选语义：
- 对固定输入的一次 helper，理想模型中新 blocked 集扩大，旧 clear 可能变 blocked，F-01给出有余隙的风险。
- 完整候选列表并非简单“旧集合取子集”：拒绝原来最佳直线会让 best score 达不到0.7，开启反弹；降至0.5可能开启组合；特殊候选不再提前break也可能继续采其他位置。最终候选可增可减，排名与 fallback 都可能改变。
- 不能从 helper 改进、候选数量或性能复杂度推断机器人自然胜率。
