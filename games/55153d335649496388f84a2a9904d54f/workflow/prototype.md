### 3.2 history 写入、撤销、清空和计分调用

1. `_0x5480e3` 新局：清待罚棋和待红棋临时状态，round递增，history置空、红状态board、双方分归零，清盘面数组后 `_0xd3d8fe` 建盘。`CarromDiscRules.target/layout` 被读取；mode2两色各9、非mode0建红。没有12＋12／180传玩配置。
2. `_0xbdafb3(expectedTurn)` 入口：匹配当前turn、拒绝重复 settledTurn、检查超时票据、局激活；仍有运动则50ms调度重试，停止后标记本杆已结算。mode2复制本杆队列，计算 `queenShot={actor,foul,queen,ordinary}`。
3. **无犯规红棋**：循环内同步 `history.push({type:0,points:50,actor,...})`，直接给行动方加50并刷新Freestyle HUD；玩家调用 `_carromReportScore`。红棋飞字只作表现，不再次加分。
4. **无犯规普通棋**：飞字 finish 内玩家 `+=points`／对手 `+=points`，push绑定闭包中的type与queueIndex，更新对应HUD；玩家上报SDK、对手不向SDK上报玩家分。finish有幂等、active＋round＋turn检查。延迟结算屏障主动执行剩余finish再判红与终局。
5. **犯规本杆队列**：每颗普通／红子创建同`_type`返场实体，没有新分和history。finish幂等且校验active＋round＋turn；结算屏障强制未完成finish，按盘面标签归白／黑／红数组。处理后从原待结算队列移除。
6. **既往普通罚棋**：仅 `_0x530863 && _0x3daed1.length === 0` 时调用 `_carromFreestylePenalty(actor,onReturned,state)`。成功后立即 `history.splice(entry)`、扣entry.points并刷新HUD；玩家上报SDK；实际实体恢复在Tween完成／强制finish中。
7. **红棋撤销**：`_carromReturnFreestyleQueen(owner)` 找当前round、原owner、type0第一条history；缺失则用pending.points或0兜底；同步创建红棋、避碰、push红数组，splice红history并设置returnCommitted，扣原owner相应分、刷新HUD、玩家上报SDK。它不是既往普通罚棋。
8. `_carromReportScore(value)` 使用 `try { GameSnacks.score.update(value); } catch ...`，SDK异常有隔离。不能沿用旧摘录“此函数没有try/catch”的结论。

**顺序限制**：普通history插入顺序可能由飞字完成先后决定，红history又同步预记；`queueIndex`是本杆扫描队列位置，不是物理时间戳。两者均不能直接用于证明“最后实际入袋子”。

### 3.3 既往普通罚棋的精确资格与返盘路径

关键代码锚点 `_carromFreestylePenalty`：

```js
var matches = _carromFreestyleHistory.filter(function (entry) {
  return entry.actor === actor && entry.round === _carromRoundId;
});
if ((actor !== 'player' && actor !== 'opponent') || matches.length !== 1) return false;
var entry = matches[0];
var score = actor === 'player' ? _0x4d3bf1 : _0x41f634;
if ((entry.type !== 1 && entry.type !== 2) ||
    !Number.isFinite(entry.points) || entry.points <= 0 ||
    score !== entry.points) return false;
```

此为资格过滤，不是“从任意多条记录中找最后普通棋”：筛选包含该actor本局红棋记录；`matches.length`必须恰好1。

成功路径：`new _0x54e9a5(entry.type,skin)`→临时动画子 `removeFromWorld()`→HUD位置Tween回中心（20至小于30个Tween单位）→立即删history／扣分；restore再 `new _0x54e9a5`、设置worldX/Y、`_0x1f3ae5`避碰、push对应白／黑数组、移临时sprite、清pending并回调。restore具有幂等、局激活和round保护，**本体没有turn检查**；外围结算继续路径另查turn。

`state.cancel`停止Tween、移临时子、pending=false；`state.finish`停止Tween、置中心并走相同restore。`_carromAwaitPenalty`每50ms检查，累计20次仍pending调用finish。`_carromDiscardPendingPenalty`负责重开／离场清理。本机制是项目容错，不是竞品罚则；扣分和实体恢复仍分时提交，恢复步骤抛异常等边界未运行验证。

`_0x54e9a5`构造真正刚体fixture；`removeFromWorld`销毁body；worldX/Y setter同步物理位置。`_0x1f3ae5`是避碰搜索，不是刚体注册，当前有轴向、对角线及有界网格尝试，候选全部占满时仍需验证。

### 3.4 红棋状态、提交与换手

C2 `freestyleQueen(previous,shot)`：
- board：本杆入红且不犯规，若ordinary>0则covered，否则pending。**同杆普通子覆盖红棋为代码注释明确的产品假设。**
- pending：只有同owner行动、无犯规且ordinary>0才covered；否则返红、撤原owner分、状态board。
- covered：保持，不因普通母球犯规自动撤销红分。

C1结算先等既往罚棋，再强制当杆返棋finish及计分finish，再调用C2红状态决策；必要时返红撤分，然后判断终局，最后续杆或换手。**既往普通罚棋在红决策之前尝试，红撤销后不重新尝试罚普通棋。**

终局：红非pending且任一方积分>=160；唯一达标方决定胜者，双方同时达标保留行动方优先。`_0x47e567(true)`玩家胜，false玩家败；该优先策略不是竞品已确认规则。犯规强制续杆false；未终局时 `_0x5e7a5f`开玩家回合、`_0x50a0ff`开对手回合，并递增turn、重置犯规和续杆。

区别其他返棋：`_0x464a16`按阵营返白／黑、数量分减1、用传统HUD，调用位于非mode2分支，不能套为Freestyle积分处罚。`_0x52e61d`为另一传统红返场Tween。mode2尾部虽保留 `_0x4268e2 && !_0x5ebd99`返红扣50片段，mode2结算开头将旗标置false；红扫描曾置true不证明在这次重置后又自然置true。不得把该遗留段作为当前自然红犯规规则，需可达性动态证据。

## 6. 最小区分实验与判定标准（未执行）

## 7. 原型／实现设计建议（仅设计，未改源码）

### 7.1 核心循环与规则状态

循环：确认行动方和摆位→瞄准拉力→释放一次输入→固定物理步推进→收集入袋事件→等待运动停止／超时结算票据→计算当杆返棋、红棋与既往处罚→一次提交积分／账本／盘面→胜负或续杆／换手→新局清理。

建议状态：`ready → aiming → simulating → settling → ready/terminal`；暂停只冻结当前owner任务，不创建第二结算；`queen`独立为board/pending/covered；暂未确认欠罚保留为策略接口而非默认启用。唯一规则owner负责所有积分、得分撤销、返棋和胜负，表现层仅消费提交事件。

参考取舍：保留C1已存在的单普通子受限资格、局次清理和完成保护作为当前行为基线；不把P2/P4未经完整历史的样本直接硬编码进联网。C2同杆红覆盖是显式产品假设，应独立标记，不借一般规则网页包装为原厂事实。当前阶段不做24子替换、引擎迁移、美术或非授权功能开发。

### 7.2 物理步长、碰撞与输入窗口

- 当前S：`_0x4bf21a(delta)`累积delta，while累积>1每次消费1并调用 `_0x49d791(1)`；每tick扫描入袋后 `world.step(1/60,10,10)`、clearForces。这里delta是逻辑单位；视频约60fps不是游戏逻辑帧率证明。
- 当前S：普通子物理半径16，dynamic/bullet，初始sleep，angularDamping0.2、linearDamping1.8、density0.45、friction0、restitution1。入袋判定是棋子／母球到四袋中心距离<=20，不是只凭刚体接触回调。母球先扫，再红→白数组slice→黑数组slice，各袋按索引0到3；**同tick队列有扫描偏序，不等于跨色真实物理先后**。
- 当前S：扫描后flush超时票据；仍运动 `_0x56abf7`检查trimVelocity/isAwake并重试。暂停／广告阻止逻辑与Tween推进；`_0x338c29`以ms/1000*60转Tween单位，查active与round，wrapper本体不查turn，调用者另查。它不能与wall-clock `_carromMatchSchedule`混为同一计时器。
- 原型提案M：输入只在本方ready／aiming且无重叠阻挡、未超时、无暂停／结算／终局时接受；pointer释放提交一杆并锁定turn，不允许第二释放／旧pointer触发。超时边界在固定tick记录，先处理该tick已采集事件再裁定；跨tick事件以tick＋事件序号追踪，同tick无可靠细分时间时保留明确稳定规则顺序，不能宣称是真实物理时间。
- 回合时限：C2仅mode0/table0六棋Delhi为20×60再加timeBonus×2，其余返回originalTicks＋bonus。**不能从该特例推定Freestyle必为20秒**；Freestyle实际base时限需要场馆与输入入口动态核验。
- 拟议验收误差M：同构物理回归在同实现／同种子／同tick输入下，积分与事件集合、history净账、返棋数量、终局和行动方须完全一致；坐标误差暂定≤1逻辑单位、袋事件检测允许≤1固定步（16.67ms），均为测试建议不是已测性能。30/60/120fps只改变渲染，应得到相同规则结果；丢帧、长暂停、贴袋高速越界需单独实验，不能以位置容差掩盖入袋漏判。

### 7.3 策略与稳定提交边界

1. 按`entry/mode/venue/rulesVersion`建立独立配置：棋数、值、红棋、目标、罚子集合／选择、同杆额外罚、欠罚、红覆盖与终局优先级；HUD、玩家与AI读同一配置。不默认全部联网或传玩共享。
2. 每颗棋使用稳定`discId`，入袋事件用`eventId/round/turn/physicsTick/sequence/actor/type/value`；撤销用反向账目／状态，不从总分猜类型，也不从Tween完成顺序猜最后子。保留queueIndex仅作扫描序辅助。
3. 策略接口分别负责`selectPenalty`、`resolveShotReturns`、`resolveQueen`、`resolveDebt`、`resolveWinner`。未闭合字段标provisional，不能无证切M1/M2/M3。需要真正选择默认产品规则或迁移框架时，必须先请求用户决策；本轮没有选择或编造确认。
4. 构造结算计划：当杆犯规返子／不记新分→撤销失败红覆盖→按已证策略选择额外罚子及欠罚→核验库存／净账→一次提交→渲染返场／飞字→解锁回合。顺序是设计建议，竞品真实顺序待证。
5. 提交以round/turn唯一令牌幂等；完整计划完成前不发布半扣分状态。避免当前“立即删history扣分、后Tween恢复实体”跨时窗口。重复回调、暂停、取消、新局和离场不得再次写状态；异常给明确失败终态和诊断，不能静默等到无限。
6. 成功／失败：单局>=目标后的唯一达标方成功，另一方失败为当前项目基线；红pending和双达标按待验证配置处理。实验报告的PASS仅针对实际覆盖用例，不把静态相容提升为竞品还原完成。
