## 状态、循环和输入契约

现有核心循环为玩家/AI 回合 → 发射或放弃/超时 → 等待物体静止 → 一次结算 → 计分及返球 → 终局或下一回合。

关键状态：`_carromRoundId` 为局代次，`_carromTurnId` 为回合代次，`_carromSettledTurn` 去重结算，`_carromAiShotTurn` 去重 AI 提交，`_carromResultCommitted` 去重结果；`_0x4268e2` 表示待处理的红球状态，`_0x404020` 为暂存 sprite，`_0x3231b3` 为盘面红球集合，`_0x5ebd99` 控制续回合，`_0x3fddb3` 表示局内活动，`_0x3e61d0` 为内部暂停门。

现有界面通过 PIXI 展示盘面、双方 HUD、底部摆位滑条、瞄准反馈、暂停及结果遮罩，物理由 Planck 承担；本轮不将该参考实现改写为 DOM/SVG，也不冒称其为新建原生 Web 成品。

玩家瞄准入口 `_0x36ab44` 检查暂停、玩家回合和输入许可；释放按 pointer 标识匹配并清除瞄准锁，力度至少 0.25 才发射。`_0x24bb4a` 关闭输入；`_0x5e7a5f` 进入玩家回合时立即开放输入，随后播 striker 入场动画。因此返球必须在调用该回合入口前完成，不能把 striker 入场动画当作输入屏障。

普通模式每颗普通球计 1；Freestyle 的本文件分值表为红球 50、类型 1 为 20、类型 2 为 10，目标初值 160。普通胜利条件委托外部 `CarromDiscRules.hasWon`；外部实现未提供，不能据此确认具体桌型阈值或竞品规则。

物理每次逻辑更新使用 `step(1/60,10,10)` 并清力；ticker delta 累积后以 `while (accumulator > 1)` 补步，所读入口没有补步上限。入袋为中心距离不超过 20 的几何触发，与物理接触回调分开；返场避让检查距离 32，先轴向再对角及有界网格搜索。红球返场 tween 为 15 个逻辑 tick，按 60Hz 名义约 250ms，并非硬实时保证。

审查验收不允许对回合顺序、计分次数和跨局隔离设置容错；位置轨迹允许浮点误差但不允许重复实体或重叠后仍报告成功。AI 盘面快照的既有阈值为每轴位移大于 1 判变化，它不是全局物理精度承诺。20ms 是用户观察分辨率，不是实现容许窗口。

## 正常回调时序与一次提交

`_0xbdafb3(expectedTurn)` 拒绝过期或已结算回合；物体仍运动时经 `_0x338c29` 重试。确认静止后先写 `_carromSettledTurn`，关闭倒计时并休眠物体。延后结算先校验局号和回合号，再完成普通球回收/计分回调。

非终局屏障路径调用 `_0x52e61d(callback)`，且当前结算回调立即 return。返场完成先校验活动局、局号、sprite 身份，再创建红球实体、定位避让、加入 `_0x3231b3`，移除旧 sprite 并将 `_0x404020` 置空，最后调用 continuation。continuation 再校验局号和回合号，清待返标记及勾选提示，然后换回合。JS 同步调用顺序上，新实体入集合先于玩家输入开放。

结算入口锁、计分回调局部 finished 锁、AI 回合提交锁和结果提交锁分别负责不同层次，不能互相替代。红球 helper 没有独立 pending/finished 事务对象；重复正常完成会因 `_0x404020` 已置空而被身份检查拒绝。标准流程中未发现本次新增 continuation 会重复换回合的可证路径。

## 可证遗留缺口与最小复现

以下为源码控制流推演，均未在本轮运行。构造状态仅用于定位，不代表自然对局必然到达。

### D1：sprite 缺失时清掉返球义务并继续回合

证据：新增条件包含 `&& _0x404020`。为假时进入旧回退，调用 `_0x52e61d()`，随即清 `_0x4268e2` 并换回合；helper 内又以 `_0x404020 && Tweener.addTween(...)` 包住实体重建。

最小条件：mode=1、活动局、待返=true、续回合=false、双方未达 hasWon、盘面无红球且 `_0x404020=null`，让合法当前回合进入静止结算。推演结果：不创建红球，待返标记清除，回合推进。它不会因为缺 sprite 永久等待，而是直接丢失恢复义务。该分支缺口为代码可证；缺失状态自然出现的频率未证。

### D2：终局判定先于返球屏障

证据：普通延后结算先执行 hasWon 分支并 `_0x47e567(...)`、return，随后才定义/进入红球屏障；判胜还直接读取 `_0x3231b3.length`，未同时读取待返义务。

最小条件：mode=1、待返=true、续回合=false、sprite 存在、盘面红球集合为空，并使至少一方 hasWon 返回 true。推演结果：直接提交结果，不调用返场，标记仍未处理。代码可证终局会越过返球；该盘面是否合法、应当判负还是先返球，需规则证据，不能仅凭本文件认定胜负规则错误。两版均有此顺序，并非 bf0c 新回归。

### D3：公开 pause/resume 不执行暂停

证据：导出对象中的 `pause: function () {}`、`resume: function () {}` 两版均为空。内部 UI 暂停 `_0x5e0129` 则设置 `_0x3e61d0=true`。

最小复现：宿主仅调用公开 `game.pause()`，保持 ticker 驱动返场。源码推演：调用本身不会冻结返场或逻辑。若宿主契约要求该 API 暂停，这是确定的接口实现缺口；若宿主另行停 ticker，则宿主整体行为需要实际集成验证。

## 条件风险与已存在的安全边界

### 暂停与恢复

内部暂停的逻辑更新 `_0x49d791` 在 Tweener.update 之前 return；局内延迟 `_0x338c29` 也是 tween，不是墙钟 setTimeout。因此经内部暂停门冻结时，返场、结算等待和倒计时一同停下，恢复后沿原局继续；暂停本身不会清掉待返状态或把它当失败。此保护沿用 f66。

最小待验：返场进行到一半 → UI pause → 等待超过名义返场时长 → 确认局号、回合号、位置、计分、待返标记未变化 → resume → 只重建一颗红球、只推进一次。广告停止 ticker 与内部暂停是不同入口；外部 Tweener 独立驱动不在所读证据内。

### 重开与旧局回调

`restart` 调 `_0x5480e3`：丢弃 pending penalty/pocket，递增局号，重置结果及红球状态，清 striker/aim tween；暂存红球移出父节点并置空，再清盘和生成新布局，回合入口递增回合号。旧 `_0x338c29` 有局号检查；返场完成有局号及 sprite 身份检查；新增 continuation 又检查局号和回合号。因此标准 restart 后，旧返球完成不能重建旧红球或换新局回合。

限制：restart 没有显式 extract 已暂存红球的返场 tween；旧 tween 仍可能继续写入已摘下的旧对象，直到完成后被局号检查拒绝。这是残留动画/清理风险，不足以认定新局被污染。最小待验：返场中 restart，再交付旧 tween 完成回调，比较新局红球数量、分数、回合号和输入权限。

restart 也不清 `_0x3e61d0` 或内部暂停弹窗；在 UI pause 中经公开 restart 后，新布局仍停在暂停门后，需走原弹窗恢复。是否违背产品重开语义尚无契约，列条件风险，不宣称已发生死锁。

### sprite 存在但返场不完成

屏障路径没有超时、finish/cancel 或失败 continuation。若外部取消该 sprite 的 tween、对象销毁导致异常，或引擎未交付完成，当前回合已标 settled 且 continuation 不执行，可能长期停在等待期。标准 pause 会恢复、标准 restart 会使旧回调失效，二者本身不是此风险的证明。

最小待验：进入正常屏障后仅取消红球 tween，不重开、不退出；继续驱动逻辑，观察是否有恢复机制。此为故障注入条件风险，本轮未证明正常运行会丢完成事件。

### 完成 helper 与终局生命周期

红球完成 helper 校验局号及 sprite 身份，没有检查回合号或 `_carromResultCommitted`；外层 continuation 检查回合号，但实体重建发生在该检查之前。标准屏障不推进回合，故不会自行形成过期回合；若外部在等待中强制结束同局或换回合，helper 仍可能先重建红球。`_0x47e567` 只加结果提交锁，并未令局号失效或关闭 `_0x3fddb3`，所以结果锁不等于取消所有旧动作。

最小待验：正常返场已开始时，在同局强制提交结果，再交付返场完成，检查是否仍创建实体/推进回合。需外部或调试触发，不能称为自然对局已证缺陷。

### 返场位置搜索失败

`_0x1f3ae5` 搜索有限轴向/对角/网格候选；找不到空位也直接写回原位置，没有失败返回值。helper 仍会创建实体并通知成功。构造所有候选均被占用可检验该边界；自然盘面能否覆盖全部候选未证。此问题两版均有，本次回调表示代码执行完毕，不保证空位搜索成功。

## 后续验收条件（本轮未执行）

1. 正常非终局待返：实体加入红球集合之前输入许可始终关闭；完成后恰好一颗红球、一次回合递增。
2. AI 无候选、无效参数、重试耗尽及回合超时：待返时统一结算；等待期间到达的旧 AI 发射回调不产生冲量。
3. 重复结算、重复动画完成：计分、红球实体、结果、回合推进分别最多提交一次。
4. sprite=null、sprite 被摘下、tween 被取消分别验证；不得把非空引用等同于有效可完成动画。
5. 暂停前后、暂停中重开、返场中重开、退出再开始：旧回调对新局的计分、对象数量、回合及输入影响均为零。
6. 同时满足 hasWon 与待返义务：先由规则负责人确认预期，再核对最终胜负及返球顺序，禁止把构造盘面当竞品政策。
7. 固定输入在快慢帧及长帧下检查无重复入袋/计分；物理使用 1/60 步，时序不变量零容错；记录实际调度和位置误差，不承诺跨浏览器逐帧一致。
