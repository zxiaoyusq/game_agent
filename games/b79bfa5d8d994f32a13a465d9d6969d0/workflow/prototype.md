### 1.2 可推断、不能推断与可能矛盾

**可谨慎推断**：
1. 该开关可能至少影响 Freestyle 中可操作期的滑条空白处点击定位。开时明显移动、关时未观察到移动，方向符合假说。
2. 如果两次操作确实均命中同类轨道区域并处于合法放置状态，则“关后不跳转”是开关生效的一个候选解释；这两个前提目前只有转述。
3. 开启样本描述滑块与母球一起变化，符合位置联动设计；不能证明联动发生在同一帧或来自同一个 owner。

**不能推断**：
- 不能证明开关是位移差异的唯一原因，不能给统计显著性或量化概率。
- 不能推定 Carrom、Disc Pool、其他桌面/设备/版本也相同；同机减少设备差异，但不消除回合、方位、局面、计时、遮罩和命中差异。
- 不能推定关闭时拖动也失效，或棋盘直接点击母球/基线也失效；该样本仅涉及轨道空白处。
- 不能推定竞品初始默认值、是否持久化、重启后是否保持、是否按账号/模式存储。
- 不能推定精确坐标映射、点击按下或抬起时生效、触控和鼠标语义一致，以及约 360 就是合法最小/中心位置。
- 不能断言 8866f05e 有误触、取消、暂停、存档或引导缺陷，也不能断言其上述功能已正确。

**矛盾分类**：

- 现版“始终允许点击”与竞品“关闭样本未移动”属于产品能力/策略差异的候选，不是现版坏了的证明。现版可能有意采用固定默认行为。

## 3. 产品默认与可选开关

### 3.1 推荐设计

- 偏好字段建议名：`tapToPositionStriker`，布尔值。名称仅为设计接口，不声称现版已有此字段。
- 默认 ON；同一浏览器配置/本地档案内跨操作方共用，不能每轮随机复位。当前只建议承诺 Freestyle；其他模式须先定位输入路径并验收，再决定开放。未知模式中隐藏不适用选项，不能展示一个无效开关。
- ON：合法放置期，轨道空白处有效点按把滑块与母球定位到目标合法横向位置；滑块拖动仍可用。
- OFF：相同空白处点按不改变位置，不改变瞄准/力度/计分/回合；滑块拖动、键盘精调仍可用。不要扩大成“禁用所有点击放置”。
- 棋盘点击、母球拉瞄准、力度和射击保持现有契约，本轮不设计它们的新开关。
- 偏好与比赛规则/AI 行为分离，不给开启者扩大合法基线范围、不改变射击力度上限。快速重定位可能影响限时操作速度，因此不能断言两种输入方式完全无竞技差异；本次样本不能说明竞技公平性。

### 3.2 体验取舍

| 方案 | 收益（设计推断） | 成本/风险（尚未实测） |
|---|---|---|
| 固定 ON | 快速粗定位、减少抓滑块动作、保持所述现版习惯 | 误触可能导致跳位，拖动习惯玩家没有退出路径 |
| 固定 OFF | 防空白误触，滑块精调语义稳定 | 点击用户需要找滑块，降低发现性/效率，改变现版默认 |
| 默认 ON + 可关闭（推荐） | 延续默认并支持拖动习惯，可按反馈调整 | 增加设置、存储、引导和验收组合；状态必须可解释 |

不根据两个竞品样本立刻反转全体用户默认，也不为点击效率牺牲非法状态的输入门禁。离线可统计本地误触撤回/偏好变化用于人工试玩，但不引入联网埋点或未经同意的上传。

## 4. 核心循环、状态与输入契约

### 4.1 循环与状态

本功能嵌入既有 Carrom 循环：观察局面→合法放置母球→瞄准/调力→击发→物理演化/进袋→既有计分与犯规结算→下一操作方或比赛结果。不是新增游戏模式。

建议独立状态包括 roundId、turnId、activeSide、phase、合法位置区间、strikerPosition、轨道归一化值 u、当前 pointerId、gestureOrigin、gestureStartPosition、偏好与保存状态；渲染/动画不能成为唯一位置来源。

| 逻辑阶段（设计命名，非现版符号） | 轨道点按 | 滑块拖动 | 退出边界 |
|---|---|---|---|
| placement：玩家当前方、母球允许摆放、无阻塞层 | 按偏好 ON/OFF | 允许 | 开始瞄准/击发/到时/打开设置 |
| aiming / charging | 不接收新轨道定位，避免旧瞄准向量与新位置混用 | 本方案不新增，保持已核验旧契约 | 松手射击或取消 |
| simulating / settling / opponent / result | 禁止 | 禁止 | 既有结算与下一回合 |
| settings / paused / hidden | 禁止底层输入 | 取消当前手势 | 关闭后重新校验回合与操作期 |

是否允许瞄准期重新摆放需要现版证据；未核验前不擅自扩大输入窗口。到时或回合切换时以 turnId 拒绝迟到的 up，不因偏好开关重新计时。

### 4.2 触控与点击/拖动区分（候选阈值）

- 统一 Pointer Events，一个主 pointerId；第二根手指不得抢夺位置，兼容鼠标触控不注册两套产生重复提交的监听。
- CSS 坐标经 bounding rect/缩放/设备像素比映射到逻辑坐标；不能把样本屏幕 x=500 写成游戏目标值。轨道轴向值 `u=clamp((x-trackStart)/(trackEnd-trackStart),0,1)`；对不同方位通过明确变换映射到基线，不能假定翻转后方向一致。
- 命中优先级：设置/遮罩→滑块扩大命中区→轨道空白命中区→棋盘。滑块中心与手指保持初始抓取偏移，开始拖动不跳位；ON/OFF 均允许这条路径。
- 空白点按建议在 up 提交：同一回合、同一指针、未取消，按住时间≤350ms、移动≤8 CSS px，up 仍在轨道命中区。阈值为本轮设计候选，后续真人触控试玩决定；不声称竞品或现版采用此值。
- 从空白处开始且超过点按阈值：取消空白点按，不自动变为滑块拖动，也不穿透开始瞄准。这样 OFF 不会因拖动空白区而绕过开关，ON 也不因滑动误跳。长按不定位，提示拖动滑块即可。
- 滑块命中目标与开关行高度建议≥44 CSS px；扩大的是命中高度，不改变合法基线长度，不侵入射击/棋盘命中区域。
- pointercancel、lostpointercapture、打开设置、页面隐藏、回合结束或视口重排均取消；拖动恢复手势前最后已提交的合法位置，清除捕获与旧指针，不自动射击。具体恢复应通过现版唯一 owner 接入，不新建旁路。
- 开关在设置层点击时先取消底层手势，再更新内存偏好；关闭设置后下一次新手势读新值。不得在拖拽中途热切换手势解释。
- 定位目标处于被棋子占用的非法位置：本方案建议拒绝并维持原位置，显示 `Position blocked. Try another spot.`；不瞬移挤开棋子、不默认吸附远处。若现版已存在不同合法化策略，进入集成前需核对并保持，重大差异须询问用户。

### 4.3 成功、失败、碰撞、计分与误差

- 功能成功：一次有效定位使滑块/母球对应同一合法位置，或 OFF 时有效忽略空白点按；没有击发、积分或回合副作用。无效/取消输入是拒绝，不是玩家输局。
- 比赛胜负、超时、母球进袋犯规、Queen/cover、Freestyle 分值与奖励继续使用已确认原规则。本轮没有完整规则输入，不编造黑白红分值或胜利门槛；一个完整局循环及结算回归仍是后续必验项。
- 点击/拖动放置是输入状态更新，不是施加物理冲量；位置合法化用既有几何/碰撞检测。击发后才进入模拟，进袋触发与实体碰撞分开，单物体/单 shotId 进袋仅计一次；开关不能修改球半径、摩擦、恢复系数或袋口判定。
- **物理步长决策**：现版参数未知，本次开关集成不改物理步长或碰撞器。后续先记录现版步长、迭代数、最大速度、连续碰撞和静止阈值，建立回放基线。若另行授权独立 Canvas 行为验证夹具，可候选固定 dt=1/120s、渲染插值、单帧最多8补步、后台暂停并清累计；这仅为验证夹具建议，不是 d201/8866f05e 事实，更不能偷偷替换现有物理系统。
- 可接受误差（后续验收目标）：有位置更新时逻辑映射误差≤0.5逻辑单位、屏幕滑块/母球联动映射残差≤1 CSS px；OFF/取消的已提交逻辑位置应严格不变（渲染可有≤1 CSS px测量误差）；点击不产生任何速度/得分变化。同一物理参数及同一最终放置/击发输入，ON/OFF 轨迹与结算应按基线一致；30/60/120fps 轨迹暂定终点误差≤1逻辑单位、得分与犯规事件一致，需现版标尺核定。这些是待测目标，不是本轮验证结果。
- 高速边缘/薄墙/袋口与重复回合必须回放；若基线有穿透或卡死，本轮开关不趁机改物理，登记并返回对应设计/代码范围处理。不要静默重开或奖罚用户。

## 5. 离线存储、旧数据与引导兼容

### 5.1 存储方案

1. 先核对现版唯一存储适配器/键名/校验器，继续其读写通道；不绕过宿主或建立 competing localStorage 第二 owner。若现版确无通道，再由统一适配器封装本地存储。偏好不要求网络。
2. 建议逻辑结构为 `inputPreferences: {schemaVersion: 1, tapToPositionStriker: true}`；这是新域结构建议，不要求把全局存档版本改成1。字段可适配现有逐键结构，不能未经核验就指定实际 storage key。
3. 有效布尔 false 必须保留；不能用 `storedValue || true` 或 `Boolean("false")`。旧字段缺失默认为 ON，以保持用户所述现版习惯。只在证实历史编码后迁移 JSON布尔/字符串等格式，不泛化接受任意0/1/字符串。
4. malformed JSON、null、数组、类型不符分别校验，当前字段回落 ON，不重置金币、解锁或 tutorial；保留可诊断原因。未来未知 schemaVersion 不破坏性覆盖，按明确兼容读规则运行或提示当前会话状态不可保存。
5. 切换立即改变会话偏好并尝试持久化；本轮不提供 Save/Cancel 的半提交语义。读取失败时采用会话默认但保持可见警告，用户更改后成功写入才更新为已保存。
6. 写失败内存仍可用，设置层与退出后的可见状态区域显示 `Couldn't save. This setting applies only to this session.`；提供 `Retry`。错误提示不能仅关闭弹窗就消失，也不能 resume/flush 一调用就消除。只在当前最新偏好确实写成功后清除；异步旧成功不能误清新值失败。
7. 偏好读取完成前不开放新轨道定位，避免启动瞬间 ON 后跳 OFF；本地失败快速回退，不为此阻塞 Replay。缓存内存状态，别在 pointermove 读写存储。
8. 页面隐藏/宿主恢复只重试待写，不覆盖会话里的最新选择；多页冲突建议当前页有未保存改动时保留本页并显式反馈，无改动时在稳定边界接纳外部值。浏览器数据清除后回默认不是持久化成功；隐私模式/禁存储的“只此会话”必须说明。

### 5.2 引导兼容

- `tutorial` 完成度与点击偏好分别存储；缺新字段不能强制重播引导，切换 ON/OFF 不清旧进度，不恢复奖励资格。
- 首次引导先教两种设置都可用的拖动，再在 ON 时可选补充点按；OFF 下文字不得要求点击轨道才能过关。
- 若旧引导已有点击空白区硬门禁，需用等价合法放置结果替代或提供拖动路径。不能强行将设置改 ON 来通关；这是假设性的兼容风险，未证明现版有该硬门禁。
- 用户主动从设置打开教程不改变偏好、不隐式暂停/恢复奖励，不让退出教程的点击落到轨道。提示只在合法放置阶段出现，瞄准/模拟时消隐。
- 文案：ON `Tap the bar or drag the handle to position your striker.`；OFF `Drag the handle to position your striker.`；通用目标 `Position your striker, then aim and shoot.`。仅第一次成功合法定位可结束相关步骤，OFF 空白无操作不算完成。

## 6. UI 原型定义与“先效果图控件、后接入”流程

### 6.1 布局与英文文案

默认沿用既有游戏标题，不新造品牌；游戏显示内容用 English，后续页面 `html lang="en"`，不随中文系统环境切换中文。

设置层居中面板，标题 `Settings`，输入分组 `Controls`；一行左侧标题 `Tap to position striker`，右侧 ON/OFF 开关；下方说明：`Tap an empty part of the position bar to move your striker. Dragging the handle always works.`。开关有可辨认的状态文字/图形，不仅靠颜色。其下保留既有设置项目的位置关系（具体需现版截图核对），底部返回控件 `Back`，必要时展示保存警告和 `Retry`。

ON/OFF、pressed、hover/focus、disabled/unavailable、保存失败与窄屏换行均需设计；比赛中面板不得露出可点击的底层轨道。关闭后回原界面，不移动母球、不击发、不自动重开。大厅设置是否存在需现版材料确认，不假装已确定其入口。

轨道保持原位置并提供可关闭的简短提示；OFF 不将轨道整体灰掉，因为拖动仍有效。未来 DOM 语义：开关具备可访问名称和 checked 状态，Space 切换，焦点可见；滑条具备 slider 语义和方向键精调，键盘定位不受空白点按偏好影响。

### 6.2 后续阶段交接顺序（计划，非已产物）

1. 美术阶段先清点授权/来源及真实现版视觉输入，绘制同布局 ON/OFF 与保存失败效果图、窄屏/桌面代表图；不能把竞品未附截图当参考图。
2. 从确认的效果图拆分面板、开关底座/滑钮与状态、图标、焦点/按下反馈等可复用控件；文字尽量实时渲染，不整屏烘焙，避免英文文字素材不可读。
3. 控件重组预览，验证触控目标、文字换行、ON/OFF识别、轨道不误禁用、遮罩层次。效果图仅用于评审，不作为运行时整屏资源。
4. 在已有目标授权范围内推进美术内部步骤，不例行逐阶段索要确认；但出现与现版严重冲突、需改变风格/放置合法化/输入窗口等重大取舍时，必须通过 request_user_input 取得真实回答。本轮没有发起确认，也没有 AI 代替用户确认。
5. 代码阶段读取确认产物/资源清单再接入：设置 owner→偏好存储→轨道输入门禁→引导→生命周期。玩法状态、输入、Canvas表现分离，不加载 Cocos 或宣称 Creator 操作；若现版实际上为 PIXI/Planck 且要求保留其工程，不能凭历史片段自行迁移成 Canvas。取得现版后先核对实际架构，框架/保留需求冲突时暂停询问。
6. 浏览器同状态截图/交互验证后交接测试阶段，不能用效果图或控件截图替代运行态验收。

本轮只产出文字布局/控件规格，未生成图片、未拆资产、未创建 art-manifest，也没有称为美术完成。
