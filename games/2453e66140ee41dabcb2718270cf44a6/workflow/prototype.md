# Carrom 点击轨道摆位：竞品对照与接入契约

## 0. 范围与结论

本轮仅为原型定义/静态分析。没有修改游戏代码、没有运行附件、没有启动浏览器或连接设备，没有实测竞品或开发版当前 3833b7ad。本文不是补丁、可玩原型或验收通过证明；不推进美术、代码、测试阶段。

**建议复用现有 slider 的数值与事件链：轨道按下绝对定位，滑块按下保留相对拖动；两者共用 update → 母球预览 → stop → 原有避碰收尾。** 不增加棋盘基线点击入口，不直接从轨道事件写母球刚体，不合成击球事件。仅在 pointerdown 中加一次位置赋值，不足以满足暂停、教程、遮罩、多指与无合法位置安全要求。

本文契约是供当前版本复核的建议，不是用户已确认实施的决策。当前文件身份、命中区、引擎事件语义等缺口不妨碍提出契约，但在代码接入前是阻塞门禁；本轮不请求用户重复提供材料，不自行解决重大范围取舍。

## 2. 历史源码的复用点与风险

### 2.1 所有者及现有链路

1. slider 实例 _0x147a99，构造族 _0x570109：负责 _enable、_sliding、_dragPosition、_tempPosition、滑块 x 和 value。
2. 按下保存起点，move 用 `tempPosition + pointerDelta` 改滑块 x 并夹紧；没有按下时绝对定位。因此依照该路径，纯 down/up 无 move 不会主动跳到按下位置。这是历史结构推导，不是现版实测。
3. move 发 update；游戏联动消费者把 value 映射为母球 worldX，设置玩家基线 worldY，再做重叠提示。只写滑块 x/value setter 不会自动走消费者；点击新增路径必须显式走同一个 update 通知。
4. stopSlide 把 sliding 清为 false 后发 stop；游戏消费者调用 _0x41684e 做避碰，并按教程阶段恢复下一步提示。结束后母球可能被修正，value 也反向同步；因此点击坐标不一定等于最终母球位置。
5. value setter 在历史片段中只做线性赋值，没有自身 clamp、finite 检查或自动 update。不能把 setter 当成完备的安全入口。

### 2.2 历史边界不能误当已安全

- slider 的 down/move 明确检查宿主暂停、广告、enable/sliding；片段中未见完整的菜单暂停、局生命周期、瞄准互斥或指针 ID 过滤。
- stopSlide 片段只检查 enable/sliding；联动 stop 消费者又有宿主/广告/玩家条件。门禁可能发生变化：清理和玩法提交必须分开，不能因禁用而遗漏清理。
- setEnable(false) 清除 sliding，但没有展示全套指针所有权清理。
- 宿主 pause 与 _carromAdPause 在 sliding 时直接调用原避碰并清 sliding，有特定教程恢复逻辑。不能同时再伪发 stop，导致双重收尾。
- _0x41684e 有有界左右采样，再用 _carromFindOpenBaseline；后者返回 null 可以表示无位置或棋子数据异常。历史收尾未提供显式成功/失败返回值，全堵塞时不保证可击球。
- _carromFindOpenBaseline 选空隙候选并复检，不等于最近合法点。原左右采样有右侧优先和端点严格不等式。本次不改最近点策略，不承诺竞品也是此策略。
- 教程 step 0 在 update 消费时切至 step 1，stop 再显示 step 1；“无实际变化的 update”也可能推进教程。当前是否要保留无位移拖动事件语义须复核，点击新增行为不能悄悄扩大完成条件。
- 玩家回合入场动画期间 enable 可能已打开；需区分能摆位与“回合变量为真”，避免轨道赋值与 tween 竞争。
- 瞄准已有 pointer identifier/native pointerId/type 相关逻辑，但 slider 片段未展示同等级策略；不能推定瞄准多指保护自动覆盖摆位。

## 3. 原型动作、规则状态与界面

### 3.1 核心循环

观察静止局面 → 点击轨道粗定位或拖动滑块精调 → 显示母球合法/重叠预览 → 同一手势正常结束后原放置 owner 收尾 → 确认合法位置 → 从母球开始另一独立手势瞄准/击球 → 原物理演化/入袋/计分/回合转换。

本改动只覆盖摆位子循环，不增加自动击球、额外得分、回合消耗、撤销、重开机制、存档或新的胜负规则。单局时长、力度、关卡及其他模式沿用项目，不依据一次 Freestyle 样本另定值。

### 3.2 状态模型（语义名，非声称已有 API）

- 游戏资格：matchActive、roundId、turnId、isPlayerTurn、placementAllowed、entrySettled、aimActive、hostPaused、menuPaused、adBlocked、modalBlocked、tutorialStep、tutorialPlacementAllowed。
- 手势：Idle / DraggingThumb / DraggingTrack / Finalizing；附 ownerPointer（原生/框架 ID 配对及 type）、gestureId、开始局/回合、layoutRevision、起始局部指针 x、起始滑块 x、最后预览值。
- 放置：previewValue、committedValue、placementValid；滑块表现不是唯一玩法事实来源。
- 终结：每 gesture 至多一个终结。正常终结可尝试一次原收尾；取消只清理，不等同 stop 成功。局/回合变化后旧提交全部失效。

### 3.3 界面布局与英文文案

保留棋盘、玩家基线、下方现有轨道/滑块、回合 HUD、暂停入口与现有教程/遮罩层级。不新增满屏透明命中面、不让轨道命中区延伸至棋盘基线，不以 alpha=0 判断不能交互。

轨道背景和边框不是同一命中语义：只让明确轨道带接收点击；装饰越界部分不自动可点击。滑块实际命中区优先，触控放大区若需要，必须按 CSS 像素核验且不压住相邻控件；不在缺尺寸证据时直接扩大到全容器 bounds。

本轮没有 UI 产物；若后续新增提示，默认英文、页面 lang=en，中文浏览器环境也不自动切换语言。建议文案：
- `Tap the track to position your striker. Drag the handle to fine-tune.`
- `Position blocked. Release to adjust.`（仅原收尾确实具备自动调整时使用）
- `No valid position available.`
- 可访问性标签：`Striker position`、`Position unavailable`。
不修改已有教程图片或宣称图片文字已核验；不将英文默认变成当前游戏已审计完毕的结论。

## 4. 点击轨道与拖动滑块事件契约

### 4.1 共用输入窗口

新手势仅在活动比赛、玩家回合、正式摆位窗口且入场结束时接受；宿主暂停、菜单暂停、广告/模态阻断、瞄准、击球运动或结算均不接受。教程仅在原 owner 明确允许摆位的阶段接受。教程 step 0 的合法露出不能被“存在任意遮罩即拒绝”误封；下一步瞄准阶段若轨道在遮罩下，应拒绝轨道而不重排层级。

在 down、move、正常 up 收尾前分别重新检查资格与 roundId/turnId。布局变化默认取消手势。阻断后先清理，不依赖阻断状态恢复后收到 up 才结束。

update 消费者可能同步推进教程或禁用输入，因此发 update 前建立所有权，返回后再核对 gesture、局/回合及门禁，不能无条件重新写 sliding=true 或恢复旧基准。教程 step0→step1 若只是同次摆位的下一步提示准备，可保留该已接受手势的一次正常收尾，但不得再接受 step1 的新轨道 down；若遮罩或原 owner 已撤销当前摆位资格，后续 move 必须取消并只做允许的清理。两种行为按当前教程真实生命周期配对，不能把教程阶段变化一概当成普通续拖，也不能因加门禁而漏掉原 stop 提示。

### 4.2 事件表

| 输入/时机 | 必须行为 | 禁止行为 |
|---|---|---|
| 无手势时在滑块命中区 down | 取得单一 owner，记录 p0/q0；不跳动，保持手指抓取偏移 | 把滑块中心吸到指尖；因轻抖切成轨道跳转 |
| 无手势时在轨道带、滑块命中区外 down | 取得同一类 owner；取局部指针 x、clamp 为 q1；值变化时走原 update 预览链；随后以 p0=本次 down、q0=q1 建相对拖动基准 | 直接写刚体、立即 stop、创建击球/教程完成事件 |
| owner 的 move | q=clamp(q0+p-p0)；共用 update/联动链，终点重叠可保留原阻塞提示；不按 move 次数计分 | 使用另一指针坐标；不断用累积增量引入漂移 |
| owner 的正常 up / 框架等价 upoutside | 同步处理最终坐标（若有效）→ 先锁住终结/清 sliding → 一次原 stop/放置收尾 → 读取修正结果并复检；释放所有权 | 只监听 click/pointertap 再补一次定位；以同一次 up 击球 |
| 同手势重复 up、合成 click、重复原生/框架终结 | 因已终结而无操作 | 第二次 stop/update/教程推进 |
| 非 owner 的 move/up/down | 不移动、不终结；第二指不能取得瞄准或其他棋盘玩法所有权 | B 指 up 结束 A 指拖动；A 松开后自动把 B 接管为新摆位 |
| cancel、lost capture、blur、hidden、禁用、暂停、广告、切场景/重开/换回合 | 走唯一取消入口、立即清理 owner/capture/sliding/temp；旧事件失效；按取消策略处理预览 | 将 cancel 伪装正常 up；强制启用被别的暂停 owner 禁用的控件 |
| 空白/棋盘基线/装饰点击、右键、缺 ID、无效坐标 | 不接受，不改变业务状态 | 把所有全局 x 都送到 slider |

轨道 down 后 move 的连续性是关键：**q0 必须记录跳转后的滑块位置**。否则下一 move 会回到跳转前的位置。抓取滑块时仍记录跳转前的现有位置，不能将轨道和滑块按下统一为绝对赋值。

正常的“点击”在本建议中为轨道 down 即预览、up 一次收尾，不依赖时间/位移阈值；竞品具体触发时机未知。轨道长按不重复提交，也不增加自动重复机制。若未来用户要求 up 才跳转或滑动阈值识别，将改变手势语义，需另行确认，而非本轮声称已对齐。

### 4.3 终结与取消策略

- 正常 up：共用原 stop owner，保留避碰与教程后续提示顺序；只有复检成功才标记摆位可击球。
- 宿主暂停/广告：优先兼容历史 owner 已有“必要避碰后清 sliding”路径，不新增第二份收尾；该路径只可在同局同回合执行，不构成新击球或教程完成。扩展指针所有权清理须和该路径配对。
- 原生 cancel/失去捕获/窗口失焦：建议撤销未终结预览至本手势前已提交值，同步 slider 和母球，并重新检查合法性；不恢复已被换回合/销毁的旧对象。此为建议，不是历史实际行为。若当前取消已保持预览，应先对照并在代码接入前明确保留或变更，不能伪称兼容。
- 布局变化：默认取消而非在途中套新矩阵。恢复后要求新 down，不续用旧基准。若要不停手续拖，必须重新基准化并专项确认，不能只改 CSS 尺寸。
- 清理始终可执行；玩法更新/教程提示/避碰提交只能在对应 owner 允许时执行。捕获释放引发的 lostpointercapture 必须幂等。

### 4.4 指针、传播与缩放事件

只保留一个业务事件来源，优先沿当前框架事件；不能给同一个动作同时绑定 DOM pointer、框架 pointer、touch/mouse/click 四套逻辑。若需要原生捕获/窗口兜底，原生事件仅映射给同一 gesture 的清理/终结，不成为另一提交者。

原生 pointerId 与框架 identifier 不假设相等，按 originalEvent 及当前依赖真实语义配对；ID=0 合法。匹配 pointerType；鼠标仅主键，笔仅主接触，不处理右键/悬停。多点策略为“先取得玩法所有权者独占”，不仅是每个控件各自一个 sliding 布尔；瞄准活动时禁止 slider 开始，slider 活动时禁止母球瞄准开始。第二指在屏上未重新 down 不接管。

轨道命中后标记由 slider 消费；是否 stopPropagation 要先确认祖先必需的 bookkeeping，避免阻止必要 stage up 监听。取消和清理不能依赖事件一定冒泡。仅对接受的手势在合法事件源上处理 preventDefault；touch-action 按现有画布策略局部核验，不全局禁止页面缩放或滚动。禁止覆盖宿主 pointerEvents；暂停恢复必须由原宿主 owner 恢复原值，多个暂停原因未清空前不得启用。

## 5. 坐标空间、映射与可接受误差

### 5.1 通用坐标链

区分：浏览器 viewport CSS client 坐标 → 画布内容区域的 renderer 逻辑坐标 → slider 局部坐标（滑块中心所在父空间）→ value∈[0,1] → 棋盘/母球世界坐标 → 物理单位。

设 canvas 内容 rect 为 (left,top,width,height)，renderer 逻辑尺寸 W,H：

- gx=(clientX-left)×W/width；gy=(clientY-top)×H/height。
- (pX,pY)=inverse(sliderWorldTransform)×(gx,gy,1)。必须包含父容器平移、缩放、旋转；不可仅减画布中心。
- q=clamp(pX,qMin,qMax)；v=(q-qMin)/(qMax-qMin)。
- 母球 wx=bMin+v×(bMax-bMin)，wy=当前玩家合法基线。放置消费 owner 负责物理单位换算。

若框架 event.data.global 已是 renderer 逻辑坐标，从逆矩阵一步开始，不再按 DPR/CSS 重新缩放。原生 Canvas 若 backingStore=W×DPR，逻辑映射用 W，不能重复乘 DPR。CSS 旋转/斜切等使 getBoundingClientRect 比率公式不成立时，使用真实逆变换或拒绝该布局；普通 scroll/页面 zoom 应读取最新 rect。frame/anchor/装饰 bounds 不替代滑块中心的数值区间。

### 5.2 历史数字示例（只用于证明空间不同）

E-04/E-06/E-08 可见历史 slider x=85，父比赛容器 x=extraWidth/2，滑块局部范围 [30,430]，跨度 400；母球基线 x 范围 [162,483]，跨度 321，玩家 wy≈828。渲染基础尺寸 640×1137，横向扩展与 CSS 缩放另算。

在无其他变换、extraWidth=0 且 gx=500 的**演算假设**下：pX=500-85=415；v=(415-30)/400=0.9625；母球 wx=162+0.9625×321=470.9625；滑块屏上逻辑中心为 500。母球与滑块屏上 x 未必一致。故不能将竞品 x≈500 的转述直接作为本项目母球 worldX=500 的要求，更不能把 365→500 的像素差直接代入 slider 局部位移。

旧拖动减 extraWidth/2 后求差，在父平移固定、没有额外缩放时平移量相消；这只说明其相对拖动局部可成立，不说明绝对轨道定位只减中心就正确。尺寸变化时相消前提消失。

### 5.3 容错门禁及建议验收阈值

以下为本轮提出的验收指标，不是实测数值或现版配置：

- NaN/Infinity、缺字段、rect 宽高≤0、不可逆矩阵、qMax≤qMin：拒绝/取消；不写业务状态，不把无效 v 默认为 0.5。返回值与最终坐标都复检 finite。
- down 必须先命中真正轨道/滑块，再 clamp；轨道以外按下不能靠 clamp 吸到端点。已开始手势 move 横向越界可 clamp；初始 y 不在轨道带不得触发。命中区边界采取确定半开边界及优先级，杜绝双归属。
- 滑块按下零移动跳变=0（模型误差≤10^-6 逻辑单位）；转换往返误差≤10^-4 逻辑单位（正常可逆矩阵）；clamp 与 value 边界误差≤10^-6，不允许 NaN。
- 母球映射误差≤0.1 棋盘逻辑单位；相同无碰撞 v 在不同视口映射到同一 wx，显示中心偏差≤1 CSS px。避碰修正的位移不计为点击映射误差，须独立记录原目标与最终目标。
- 屏幕指尖不具备像素级精度；数字阈值用于程序映射，不承诺真人点按同等精度。滑块优先命中区不因≤1px 手抖切换输入模式；当前原拖动事件频次保持，不为新增轨道默认加死区。
- 首次合法轨道 down 预览应在下一个有效渲染帧可见；目标正常前台 60Hz 下≤50ms，30Hz≤100ms（待测指标，不承诺暂停/后台时限）。
- 最大碰撞穿透容忍为 0 个已确认非法放置：接触判定的数值 epsilon 只处理边界，不得靠放宽安全半径把重叠认成合法。物理重复轨迹不要求跨浏览器逐帧位级一致。

## 6. 物理、碰撞、计分与无可放位置

### 6.1 步长与玩法保持

历史 _0x49d791 末尾可见 `world.step(1/60,10,10)` 与 clearForces；_0x4bf21a 累积 ticker delta，while>1 补逻辑步。历史长帧片段未见显式最大补步上限；宿主/广告清累积，菜单逻辑有自己的停止条件。这是历史静态证据，不是现版帧率测试。

接入契约：保留现版真实固定步长、迭代次数、阻尼/速度、碰撞 fixture/sensor 与长帧策略；摆位事件不调用 world.step，不按手指频率积累冲量。若当前与历史参数不同，以配对当前基线为准，不在点击功能里“顺手优化”步长。后续如需调整补步上限或迁移物理库属额外范围，需重新确认。

摆位预览与物理击球分离；不能把沿轨道“瞬移路径穿过棋子”当成一次真实碰撞/入袋得分。本功能验证目标是最终放置合法，不擅自增加沿途障碍阻挡或扫掠碰撞规则。

### 6.2 碰撞与计分

历史 _0x23a7dc 以圆心距严格小于传入半径检测棋子集合；放置检查传入 _0x133600+16，历史 _0x133600=34×0.8×0.8=21.76，合计 37.76 逻辑单位。不能用画面缩放后的半径替代该玩法安全距离。正式当前接入须核对安全距离、棋子集合与 sensor 含义，保持其 owner。

历史结算片段引用 window.CarromDiscRules，Freestyle 有 Queen 待决/回退逻辑，其他模式也调用外部胜负规则；本次未核验完整规则模块，不据局部片段宣称复原全套计分参数。本文不据此复刻竞品、不改计分或胜负。点击/拖动摆位的分数、奖币、入袋队列、Queen 状态变化均应为 0；成功摆位不是比赛胜利，无位置不是新增比赛失败/犯规/跳回合。比赛胜负、超时及计分只由原结算链处理。

### 6.3 无可放位置：失败关闭而非硬塞

正常 stop 后调用同一放置 owner，**无论其是否有返回值，都复检最终：finite、在合法基线区间、基线 y 正确、非重叠、仍为本局本回合**。value 根据最终母球反向同步。不要另写一套不一致的碰撞算法，也不擅自用最近点替换原右侧优先策略。

- 有合法修正：显示原 owner 修正的位置，slider 同步，placementValid=true，可开始新的瞄准手势。
- 原收尾没有找到或棋子数据异常：placementValid=false，退出 sliding/清所有权，禁止瞄准开始及击球提交；保持最后已提交且仍合法的位置（若有），否则显示阻塞预览，不制造可击球刚体状态。再次输入可以尝试，但不能把 enable 强置 true 绕过暂停/回合条件。
- 原 owner 返回 null 不足以判定“棋盘必然全堵”，它也可能代表异常数据或端点/候选策略限制。日志必须分开记录未找到、数据无效和真正空区间为空；本功能不伪称获得完备求解证明。
- 不移开棋子、不删棋子、不把母球塞进重叠、不自动跳回合/计犯规、不设 while 无限找点。原有计时/超时继续归原 owner；若需无位置自动跳回合，是规则变更，须另问用户。
- 即使当前瞄准已有 gate，也必须复核击球提交瞬间的放置合法性，防止预览后局面变化。此要求跨 slider 与母球输入边界；若当前缺失，需要单独批准代码阶段的最小安全接入，不声称仅改 slider 就能保证。
