# Carrom 单对手与离线 2v2 架构核查

日期：2026-11-12。阶段：原型定义；本轮仅分析，不制作或修改游戏。

## 结论

参考 H5 已读业务路径是本地玩家对一个本地自动对手。轮次、输入、棋子归属、计数及结算均围绕双方编写。离线 2v2 可以复用一个棋盘和一次击球模拟，但必须把席位、团队、控制器和棋色拆开；增加两个头像不能形成四席规则。此结论来自静态阅读，不代表已运行验证，也不能用于判定用户所述竞品的对手身份。

## 存储与离线入口的实际限制

E4 的 Dt 构造从 URL/hash 的 gameData 初始化内存对象 `g`；getItem 读 g，setItem 可通过可选 channel 发送并更新 g。初始化通过 Pn.ba 读取当前 script 的 data-target-origin，缺少时创建无消息实现并使 channel 为 null。E2 所读 developer_v2.js 标签没有 data-target-origin，因此该标签配置下不能从这条通道推出持久化；刷新是否保留不能宣称已验证。E4 同时把 window.localStorage 的 getter 改为抛错。E1 自带 GameSnacks fallback 的 storage 方法为空，也不是离线持久化。

E3 引用外部广告 SDK；E1 有广告及宿主音频调用。完整离线改造需独立存储适配与宿主/广告边界，不能仅复制 HTML 后称离线完整。存储写失败、坏 JSON、结构验证、模式版本迁移都需另做。本轮没有运行浏览器验证这些风险。

## 静态发现的具体风险

1. `_0xbdafb3` 的 Freestyle queen 处罚分支出现 `playerScore -= 50 / oponentScore -= 50`，而主要计数使用混淆变量。记录为潜在未定义标识或计数不同步风险；未执行该分支，不称已复现错误。
2. 延迟函数 `_0x338c29` 依靠 Tweener 空目标回调；部分回调只检查全局 `_0x3fddb3`，没有独立 matchId/turnId。旧局回调在新局重新变为 active 后可能越界生效，属于静态竞态风险。
3. 计数增减与动画完成耦合，四席切换应等规则结算提交而非依赖视觉时长。
4. AI 的候选起点与滑杆范围固定为上方水平基线；玩家使用下方水平基线。若要求四边真实出杆，需旋转到统一局部坐标后搜索并映射回世界坐标。只做上下两条队伍基线会更省改造，但不是四边席位玩法，应显式说明。
5. 结算入口没有在其函数开头呈现基于 matchId 的幂等凭据；不能承诺重复调用不重复奖励。

## 离线 2v2 建议模型（新设计，未实施）

推荐评估基线为一个真人加三个明确标注的 AI，四席围桌、对角同队，团队共享一个棋色与剩余数。此为可比较的建议假设，不代表用户已批准开发，也不代表竞品规则。

状态建议：`seats[{seatId,teamId,controller,side,aiProfile}]`、`teams[{teamId,color,pottedCount}]`、`turnSeatId`、`phase`、`shotId`、`matchId`、`rulesVersion`、`rngState`、棋子 ID/位置/速度、`settlement`。一张物理世界和一个 striker 即可；四席不要求四套物理库或四个同时出杆对象。

核心循环：选择离线团队局 → 明示四席与 AI → 当前席摆位/瞄准 → 提交一次击球 → 固定步模拟 → 汇总进袋与犯规 → 原子更新团队计数及胜负 → 保留席位或转下一席 → 团队结算。建议未得分/犯规按 0→1→2→3→0；有效进本队棋是否由同席连杆、同队换席或结束团队回合，必须在未来实现前选定规则，本轮不把任何一种写成竞品事实。

建议首版使用 Disc Pool：两队各 9 枚，无 queen；对方棋误入袋计对方团队，striker 入袋如何处罚、最后一球与犯规同时发生的优先级须写入规则表。若采用返还己方一枚并换席，应明确零分时处理；这仍是设计候选。胜利由合法结算后本队目标清空产生，结果页同时标记两名队员获胜；钱包仅结算当前本地账号。

界面建议：中央棋盘，周边四头像显示姓名、AI 标识与当前席高亮；顶部两组团队棋色/计数；底部仅当前真人席启用摆位与力度；准备页说明 Offline Team Match，AI 行动显示 Teammate is aiming / Opponent is aiming，不伪装等待在线玩家。未来默认玩家文案用英文；本轮未创建界面。

### 物理、输入与误差

源码事实：E1 `_0x49d791` 调用 world.step(1/60,10,10) 并 clearForces；`_0x4bf21a` 累积 ticker 参数并在大于 1 时逐单位调用更新。未见该循环内显式补步上限，真实长帧行为未测。进袋按棋子到四洞中心距离 ≤20 逻辑像素检测；普通棋圆半径 16，striker 半径表达式为 34×0.8×0.8=21.76，坐标比例 100。trimVelocity 使用 |vx|+|vy|<0.2 进入休眠。玩家 release 在 strength≥0.25 时发射，拖距由 `_0x647bf3` 限制；出杆后关闭输入，约 2300ms 后开始运动结束检查，仍运动则约 50ms 后再查。以上时长由代码及 60 逻辑步约定解释，非墙钟测量。

未来设计建议：保留 1/60 秒固定物理步；每渲染帧最多补 5 步，超长间隔暂停并清累积时间，避免后台返回时集中出杆。规则只在 aiming 且 seatId/turnId 匹配时接受输入；拖拽取消、过期 release、AI 回调及重复提交不得发射。单次模拟超过 15 秒进入明确恢复/错误流程，不静默改判胜负。误差候选为同浏览器固定种子固定输入的静止位置差≤1逻辑像素、停止时刻差≤2物理步；计数、当前席与胜负要求完全一致，进袋边界用内外两组测试且临界带单独报告。跨浏览器不承诺位级一致，误差标准需后续实际测量校准。

## 低包体取舍

|建议|原因与风险|
|---|---|
|保留单棋盘、单物理世界、共享 AI 算法|新增三席主要增加状态和 UI，不能由席位数直接推算 CPU 或包体倍增；AI 仍需测每杆搜索耗时|
|头像使用现有几何占位或少量本地资源|减少新增图集；参考素材商业授权未核实，本轮不移交为可商用资源|
|优先重构规则与生命周期，暂缓邀请、表情联网、账号钱包|离线不需要匹配服务器；不能用虚假等待掩盖 AI|
|四边坐标转换复用候选搜索|减少四份算法复制；反弹、洞编号、角度正负与镜像是重点风险|
|按击球完成后的静止边界存档|比序列化物理引擎中间态轻；需保存当前席、团队、棋盘和结算凭据，恢复不重复扣费领奖|
|独立离线入口与存储层|移除外部宿主必需依赖后才能称完整离线；移除 SDK 与替换存储需未来代码阶段实施|

参考 ZIP 展开约 5.07 MB 仅表明当前归档库存；没有生成 dist 或 ZIP，没有测量未来 2v2 包体，不承诺小于 10MB。未来部署目标可设 dist 展开小于 10MB，必须实测全部相对资源、字体与音频，不以外置 CDN 转移必需资源。
