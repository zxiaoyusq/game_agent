# Freestyle 母球犯规：只读取证与条件性方案

## 范围与结论
本轮为 prototype，attempt=1，仅研究与定义方案；未修改游戏源码、运行游戏、构建或执行动态测试，未推进美术、代码或测试阶段。任务采用逆向总集及玩法机制模块的证据分层、版本隔离、唯一结算 owner 和未知清单方法；模块绑定 Cocos 的 API 与案例字面值不套用本项目。

当前摘录中，Freestyle（条件 `_0x5d148e == 2`）在母球犯规标记 `_0x530863` 为真时，把本杆 `_0x31089b` 队列中的棋子返场，不进入正常加分动画；随后清除续杆标记并按现有路径换手。该分支未见对既往总分直接扣除或从既往得分历史选子返场。普通模式的 `_0x464a16` 调用处位于另一分支，不能直接作为 Freestyle 处罚实现。结论限定于用户提供的当前摘录和独立读取的历史文件，不能证明完整当前工程不存在其他路径。

用户观察的竞品20→0、换手，只支持该具体样本的分数变化；不能推出固定扣20、清零、返最后一子、返白子或任意通用公式。用户受控本地样本与当前摘录相容，但人工移子并设置分数没有建立真实得分历史，不能据其证明自然对局的返子规则。

## 路径核查
### 母球入袋与结算
历史主逻辑4812–4901：母球距离任一袋中心不大于 `0x14`（20坐标单位）时设置 `_0x530863=true`，设置 sensor 并播放入袋动画。它是几何入袋判断，不能混同物理碰撞接触回调。当前摘录未包含该入口，历史路径向当前版本迁移仍需核对。

历史3197–3354和当前摘录：`_0xbdafb3` 等待 `_0x56abf7` 报告无活动物体，再调用 `_0x89ccbb` 休眠对象、处理队列。当前摘录新增 expectedTurn 与 settledTurn 检查，历史函数没有这段回合结算去重；两版均不能混称同一完整实现。当前结算函数为候选唯一 owner，需完整当前调用链确认后才动代码。

### 三种返子不可混用
1. 本杆返子：Freestyle 遍历当前入袋队列，犯规时按原 `_type` 与 `type` 创建棋子，调用 `_0x1f3ae5` 摆位并加入对应活动数组。不加本杆分数；队列随后移除条目。若本杆队列为空，该循环不返任何子，也不因此扣既往分。
2. 普通模式既往得分返子：历史3085–3144 `_0x464a16`，按玩家侧布尔值选类型1或2，要求对应计数大于0，先减1，再动画创建一枚棋子。历史3468–3470仅在非Freestyle分支调用。当前摘录中的减1也不是减20；若直接移植到积分模式会混用“枚数”和“积分”，且按玩家侧选颜色不能追溯 Freestyle 中实际进子的颜色。
3. Queen 独立返场：历史2926–2998 `_0x52e61d` 依赖 `_0x404020` 临时对象，创建类型0，具有局次与对象身份保护。不能假设它适用于所有 Freestyle 红球情形。

### 红球与同杆歧义
历史4910–4917红球入袋设置 `_0x4268e2=true`、续杆标记并在模式2加入本杆队列；普通棋入袋如5241–5258会清除 `_0x4268e2`。Freestyle 结算入口又无条件将 `_0x4268e2=false`。因此后续延迟函数中 `if (_0x4268e2 && !_0x5ebd99)` 的可达性需要完整路径与时间序列证明；不能只看其中减50语句就说母球犯规固定扣50。

历史3340–3341使用 `playerScore/oponentScore`，当前摘录改为 `_0x4d3bf1/_0x41f634`。独立检索历史文件只找到该处 playerScore 引用，提示历史疑似错变量路径；没有运行它，不声称已观察到 ReferenceError，也不能把当前变量修正当成处罚条件已正确。

历史同一更新函数先检查母球，再红球、类型1、类型2，最后步进物理。队列顺序可能受逐帧扫描顺序影响，不必然是现实入袋先后。最少区分：母球单独、母球+一普通子、母球+多普通子、母球+红球、母球+红球+普通子，以及红球跨杆状态；不能从其中一类推广全部。

### 计分历史是否可追踪
历史648分值数组为 `[50,20,10]`，类型0对应红球创建路径；类型1/2的颜色映射尚未解码核验，不把用户“白棋”直接映射到类型1。当前摘录正常得分按数组及 `_type` 累加，但未给出当前数组定义。

历史队列在结算中逐项消费；正常计分动画使用分值文本对象后清理原入袋显示对象。活动数组表示盘上棋子，不等于某方已得分历史。未见已读取路径建立可持续追溯的 scored-disc ledger；`history` 字面检索无匹配仅为辅助，不能证明全工程绝无其他名称的历史结构。已有每色局部 id 也不足以天然成为全局唯一棋子身份。

总分20可有不同组成，且可能来自人工赋值；颜色所属数组也不等于 Freestyle 得分归属。不能由分数倒推出特定棋子身份、得分顺序、红球状态或应返数量。不得以 score/20、score%20 或按玩家侧固定颜色重建历史。

## 不猜测通用公式的最小实现方案（未实施）
第一步只增加观测与真实得分账本，不改变现有处罚结果。取得当前完整代码并确认 owner 后，规则、输入、表现与存档分开；保留现有工程，不引入新引擎或为本研究重写物理。

账本条目建议：`{discId,discType,points,scoredBy,roundId,turnId,sequence,status}`，status区分pending、scored、returned；唯一身份至少组合局次、类型与生成序号。人工移子与赋分明确记录为synthetic，不生成虚假的scored条目。对存量只有总分的状态标记historyUnavailable；不能倒推补账。

用纯规则函数 `resolveFreestyleFoul(snapshot, shotEvents, ledger, policy)` 产生结算计划：本杆撤销积分、同杆返场、既往扣分、历史返子、红球状态、控制权及依据分开表示。`policy` 必须有版本、适用前置条件和证据ID；未确认字段为unknown，不能给固定20/50或清零作为默认。未知情况不扩展处罚，沿用当前行为并输出诊断；这只是兼容措施，不称竞品规则还原。

如后续证据确认需要扣既往积分并返子，仅在该条件覆盖范围选择账本条目及其真实分值；扣分下限、欠账、选子顺序、零分处理与红球规则分别取证。若证据只确认分数变化而不确认返子，不顺便创建棋子；若需要精确历史而缺账，不以总分猜颜色或数量。不得用 E-01 构造一条“score==20则清零”的生产补丁来冒充机制。

在停球且本杆入袋已收集完整的稳定边界，由唯一结算owner按 roundId+turnId 提交一次计划；先校验目标棋子与合法返场位置，再同步更新规则状态，表现只播放提交结果。返场失败应保留pending并阻止开启下一杆，提供诊断/受控恢复，不重叠生成、不提前扣完后丢失棋子。动画回调不得再次加减分；旧局/旧事务回调只能清理自身临时对象。新局取消旧pending。是否允许同局回合变化后仍处理返子，需以结算事务归属判断，不能盲目给所有动画套当前turn相等。

## 原型规则与物理验收定义
核心循环：观察盘面→摆位/瞄准并击杆→物理运动与入袋采集→停球结算→返场/计分反馈→续杆或换手。目标本轮为解释犯规路径与证据缺口，不新增成长、关卡或存档。历史目标积分初始160，但不据此确认当前完整胜负规则或竞品阈值。

状态建议为aiming、moving、settling、returning、nextTurn、ended；新局增加roundId，出杆/回合及结算事务有独立标识。合法输入仅在当前操作者且aiming开放；moving/settling/returning禁止重复击杆；取消拖拽不提交出杆；暂停冻结逻辑与输入，恢复不补算后台墙钟时长。现有实际输入细节待当前源码核验。

历史物理证据：5563使用 `1/60` 秒、10/10求解参数调用世界步进；5571–5576累积渲染传入量并以大于1循环逻辑更新，尚未核实该量单位和长帧补步上限。10501与10551–10554普通棋圆半径16坐标单位；10569–10573使用速度绝对值和小于0.2令其休眠；不能将这些视为当前已核验配置。袋口几何阈值20、碰撞半径16和停止阈值各有用途，不能互换。

后续受控重放暂定固定步长1/60，使用原物理配置与合法力度范围；速度/力度上限从当前代码读取后写入夹具，不编造。显示长帧采用最多8次补步后丢弃剩余累积并记录超限（拟议调度方案，需回归后决定，非当前事实）；精确轨迹比对按固定tick驱动，不以墙钟超时强制成功结算。高速入袋、边缘接触与碰撞穿透单列验证。

可接受误差拟定：规则分数、棋子身份/数量、犯规与换手次数误差为0；同一构建、相同初态/输入固定tick的停球坐标容差0.5棋盘单位，入袋tick差≤1仅在相同入袋集合且同杆顺序无规则影响时可接受。对阈值边缘及不同事件顺序必须单列，不以容差吞掉规则差异。物理跨浏览器不承诺逐位一致；容差需实际样本校准。普通返子中心距至少32仅有历史静态依据，当前半径未核验前不能升级为当前验收结论；还需检查母球、边界与全部候选拥堵。

成功：一杆只结算一次，实际分数与返子和证据覆盖的policy逐项一致，完成后正确转移输入权；未确认的政策明确保持unknown。失败：重复结算、错误侧扣分、无账猜子、同杆重复返子、红球双重处理、未完成返场却可击杆、跨局回调污染或非有限物理值。达到目标分与犯规同杆的优先级必须单独核对；当前摘录在延迟函数先检查达标再处理红球候选分支，不证明这就是正确规则。
