# Carrom 原生消息与离线机器人证据复核

## 范围与结论

本次为 prototype 阶段的只读分析与开发验收定义。未修改游戏代码、未发布、未运行竞品原生程序、未下载或反编译完整竞品 APK。研究方法采用已选 game-competitor-analysis 与 apk-engineering-analysis 技能的证据分层规范；没有联网研究、实机测试或 APK 工具执行。

结论：调用方所贴 ARM64 指令支持若干输入寄存器值写入栈上消息对象的具体位置；不支持将它们命名为角度、力度、玩家编号或直接声称网络发送。当前 H5 已有几何候选机器人，应先验收共享规则、生命周期、断网和结算，再优化策略与表现；不需要外部大模型才能完成此方案。以下所有新阈值、状态机与工期均为本项目建议，非竞品参数、非已实现能力。

## ARM64 入参审查

[摘录事实] 0x1aa3ddc 将 x0 改为 sp+0x28，0x1aa3e04 以该地址调用候选构造函数。因此不能把 BL 时的 x0 当进入调用者时的原 x0，也不能从此确定原 x0 的用途。可见片段从 0x1aa3dc0 开始，未展示开头的栈分配指令；局部偏移换算仍可按片段内稳定 sp 进行，完整函数边界与序言待原文件核验。

|进入当前函数的值|调用前保存|后续使用|可以支持的结论|
|---|---|---|---|
|d0|0x1aa3df4 fmov d9,d0|0x1aa3e48 stp d9,d8,[sp,#0x50]|低 64 位写至对象 +0x28|
|d1|0x1aa3df0 fmov d8,d1|同上第二个元素至 sp+0x58|低 64 位写至对象 +0x30|
|w2|mov w21,w2|stp w21,w20,[sp,#0x60]|低 32 位写至对象 +0x38|
|w4|mov w20,w4|同上第二个元素至 sp+0x64|低 32 位写至对象 +0x3c|
|x1|mov x22,x1|复制到 x1 后调用 0x2754434 或 0x1942334|作为关联处理函数的输入；业务类型未知|
|x3|mov x19,x3|0x1aa3e64 mov x1,x19；BL 0x1fa6914|作为关联对象处理输入；不能仅由地址命名方法|

[结构推断] 常见 AAPCS64 下，通用寄存器参数通道 x0–x7 与浮点/SIMD 通道 v0–v7 分别分配。d0/d1 不是因为编号为 0/1 就等于整个函数的第一、第二个源码参数；w2/w4 同样不能直接称为第三、第五个源码参数。x0 可能是 this，也可能是普通参数；隐藏参数、聚合类型、调用约定与完整调用者尚未恢复。d8/d9 与 x19–x24 的保存使用符合跨调用保留值的习惯，但不恢复原始签名。FMOV 在此是寄存器位模式移动，不是证明角度或力度的数值转换；STP D 只证明 64 位存储，不能单独证明 double 语义。W 寄存器写入不证明有符号性、枚举或布尔类型。

## 对象偏移与字段编号审查

对象基址 B=sp+0x28。栈地址减 B 后才能讨论成员：

|栈位置|对象相对位置|本段操作与边界|
|---|---|---|
|sp+0x38|B+0x10|读改写 w8；OR 1 与 OR 0x3e 合并置低六位，可能为 presence bits，但不是字段 schema 的独立证明|
|sp+0x40|B+0x18|加载指针、与间接加载的值比较并选择处理路径；具体字符串/对象类型待验证|
|sp+0x48|B+0x20|空指针时调用 0x1fd4458 并保存，再以 x1=x19 调用 0x1fa6914|
|sp+0x50 / +0x58|B+0x28 / +0x30|保存进入函数的 d0/d1 位模式|
|sp+0x60 / +0x64|B+0x38 / +0x3c|保存进入函数的 w2/w4 低 32 位|

[审查结论] C1 将栈 +0x50、+0x58 换算为对象 +0x28、+0x30，以及 +0x60、+0x64 换算为 +0x38、+0x3c，算术成立。必须区分对象 +0x38 与栈 +0x38，二者不是同一位置。0x1aa3e34 的 x0=B+0x18 是成员地址，不应误写为原始函数入参。

[条件性结构推断] 若 C1 所述解析函数确实属于该类型，且每个标签分支确实把值存入相同成员，则标签 0x11、0x19 对应字段 2、3，结合本段可建立 d0→成员 +0x28→候选字段2、d1→成员 +0x30→候选字段3 的链。当前没有实际读取这两个解析函数的完整指令，因此字段对应仍属依赖调用方跨文件关联的候选，不是本轮独立恢复。对 w2/w4 与字段4/6 的对应也必须读取各解析分支的存储指令，不能按成员排列或 OR 位图顺序补全。

|C1 标签|按 tag>>3 算得字段号|tag&7|可支持的格式范围|
|---|---|---|---|
|0x0a|1|2|长度限定，可为 string/bytes/子消息/packed 数据等，不能仅据此定类型|
|0x11|2|1|64 位线格式，不能仅据此区分 double/fixed64/sfixed64|
|0x19|3|1|同上|
|0x20|4|0|varint，语义、有符号性及枚举/布尔未知|
|0x2a|5|2|若解析分支及默认实例都关联 +0x20，可加强 table state 子对象候选；字段名与完整结构未知|
|0x30|6|0|varint，取值范围未知|

这些标签的位运算结果可直接复核，但未证明这些比较覆盖完整 tag、所有分支、未知字段和全部消息版本。只比较低字节还需检查高位与快慢解析路径，防止把低字节相同的其他 tag 当成同一分支。内存布局受构建、继承、指针和对齐影响，绝不等同 wire offset。scc_info 大小不是消息字节数；98 个具名对象不是全协议消息总数，118 条限定重定位不是全程序依赖图。默认实例指针、RTTI/vtable 相容布局均不能证明网络发送、时序或业务规则。

[摘录事实] 0x1aa3ea4 以 x1=B 调用 0x1fa989c，随后有其他 BL；不掌握被调函数语义，不能将其直接命名为序列化或发包。0x1aa3ef0 RET 后还有异常清理及 0x1aa3f30 起的不同代码，不能因相邻就纳入同一正常调用链；FDE 与控制流须另核验。所有原生地址限定为 C1 所述构建的 link VA，不是运行时地址或跨版本定位符。

## 原型取舍、规则与界面契约（开发建议）

保留现有 Pixi 表现与 Planck 物理入口，不因本轮原生Web配置重写框架；规则、输入、机器人、事件与存档逐步分离。吸收局/回合/击球/结果的内部记录概念，舍弃复制未知原生协议、服务端交互和强制进袋。原生消息只用于理解证据层级，不作为开发依赖。

核心循环：合法放置母球→瞄准并释放→共享物理演化→收集进袋及犯规→一次规则结算→续杆/换手/终局→可重开。成功为按模式达成有效胜利；失败为合法结算后的对手获胜或明确弃局。技术异常为独立错误状态，不冒充玩家战败。没有新增强制局时长；每局时长先收集分布，避免硬等待拉长对局。

模式规则沿用现有行为作为对照，不宣称它是正式Carrom标准。Disc Pool无Queen，双方各9；Carrom含Queen；Freestyle按type表50/20/10与目标160建案例。计分、同杆双方子、母球犯规、Queen进袋/覆盖失败/返场、最后子与罚子组合必须先形成输入盘面→事件→预期状态的规则表，争议规则未定前不得修改实现或宣称通过。

输入窗口：仅 PlayerReady/PlayerAiming 接受放置和瞄准；提交只允许一次，暂停、BotPlanning、运动和结算阶段拒绝射击。参考释放 strength>=0.25、最大拖拽150逻辑单位仅为现有基线；后续修改必须记录对照。pointercancel与失焦取消未提交手势；恢复不自动补发。当前场馆0的计时分支与其他场馆不同，必须记录实际时间规则，不能统一宣称全部限时。

布局保留大厅模式→场馆→本地对手展示→棋盘与双方HUD→暂停→结算。拟增加稳定的本局对手名字/头像与明确“Offline Opponent”，局内和结算一致；名称组合在开局决定，不联网伪装真人。英文为默认玩家文案，例如“Your Turn”“Opponent Thinking”“Paused”“Resume”“Restart”“You Win”“You Lose”；后续页面lang=en，中文浏览器仍显示英文。本轮未改界面或查看图片，不对当前美术质量作结论。

## 离线机器人状态机与取消边界（建议）

MatchPreparing→TurnReady→PlayerReady 或 BotPlanning→BotPositioning→BotAiming→ShotCommitted→Simulating→Settling→TurnReady或MatchEnded。Paused 保存进入前状态；Disposed/Cancelled 为不可回流终态。以上为拟定状态机，不是从原生符号恢复的竞品时序。

状态最少含 matchId、turnId、shotId、phase、boardRevision、mode、owner、棋子ID/类型/位置/速度、scores、queenState、pendingEvents、randomSeed与随机游标。规则层唯一拥有比分、Queen和胜负；物理层提供碰撞/袋口观察，机器人只产出位置、方向、力量提案；表现只读结果。存档只保存版本化已提交检查点，写失败持续提示；不承诺任意半杆恢复，首版若不能安全保存则明确只支持同进程暂停。

每个异步任务携带 matchId/turnId/boardRevision及取消令牌；提交前再次检查 phase、owner和局面版本。pause冻结模拟、决策任务、计时和相关动画，取消当前手势；resume清除墙钟积压并只恢复一份任务。退出、重开、终局递增生命周期版本并移除所有旧任务，旧回调即使触发也不得提交。仅检查局活动布尔不足以防止旧局回调在新局活动后生效。搜索分片间必须检查取消；已经提交的出杆不可重新施力。

候选顺序：按规则生成合法目标集合→筛查起点与有限数值→复用几何候选→校验路径→选择→提交前重验。无几何候选时，若仍有合法动作可选择合法保底杆；全空且已终局则取消并结算，全空但规则未终局则报状态错误，不能对undefined算角或固定乱射掩盖错误。

事件以(matchId,shotId,eventId/pieceId)去重，记录放置、方向、力量、随机偏差、进袋、返场、犯规、Queen状态、比分变化与交接。结算先提交规则快照，再播动画，不以动画回调作为唯一加分事实；重复回调、跳过动画不得重复加分或扣费。内部格式是自研调试契约，不兼容性声称竞品协议。

## 物理、碰撞与误差验收契约（建议阈值，未执行）

- 步长先保持1/60秒与现有10/10迭代参数作为回归基线；渲染插值与规则分离。拟限制单帧最多5次补步、前台delta最多100ms，超过部分丢弃并计数，恢复后台清空积压。必须比较修改前后轨迹，不能默认为无手感影响。
- 力量作为现有施力入口的参数而非速度或冲量，玩家与机器人同样校验有限值、位置合法及模式范围。不得只截断HUD而让物理收到超范围力量。
- 区分棋子/岸边实体碰撞与袋口距离触发；母球的现有袋口半径20逻辑单位不自动外推所有棋子。逐类核对各袋口阈值，以r−0.1、r、r+0.1及高速跨越轨迹测试；触发只记一次。
- 固定seed、固定盘面与输入，在30/60/120Hz渲染及一次100ms长帧下按相同模拟tick比较：同浏览器非袋口临界案例末态位置差<=1逻辑单位、进袋集合/比分/owner/胜负完全相同。临界盘面独立报告敏感性；跨浏览器暂用位置差<=2单位，不承诺位级确定性，规则结果分歧即阻塞交付。
- 通过睡眠与速度阈值连续稳定至少15个模拟tick再结算的方案需与现有静止判定对照。若一杆模拟超过30秒仍未结束，停止继续提交，记录诊断并进入可恢复错误，不强行判胜。阈值均待目标设备验证。

## 断网、成本与性能边界

[H5事实] R3 index.html 使用外域 adsdk 脚本，随后直接访问 window.h5sdk.init；未展示SDK缺失保护。静态上支持“断网可能影响外壳初始化”的风险，未实测实际阻塞范围。R4 game.html 的引擎脚本使用相对路径，并有 developer_v2.js 及service worker查询/注销逻辑；未完整读取所有依赖，不能声称离线冷启动通过。

[建议] 分别验收外壳入口、直达game.html、宿主容器三条路径。覆盖清空缓存后外域全拦截但本地静态服务器可达的冷启动、已加载中断网、无任何服务器可达的缓存重开；最后一种只有正式支持Service Worker/宿主离线资源包后才能承诺。广告和统计失败不能阻止单机开局；激励广告不可用时显示“Unavailable Offline”，不虚发奖励。资源不得移到CDN后仍声称完整离线。AHA与实体设备本轮无验收能力。

机器人应完全本地计算，零外部模型请求、零按杆API费用。仍有开发、测试、电量和资源成本；未知网络SDK可能产生请求，不能由机器人本地性推断全应用零网络。建议不引入模型权重、额外物理求解引擎；先给几何搜索加计数和耗时，再决定是否增加有限预演。

建议预算：最终部署展开<10,000,000字节，同时报告ZIP压缩前后体积；参考5,074,490字节不能当已合格dist。AI增量代码/配置目标<=200KB未压缩；先复用已有头像资源，未经授权核验不宣称可商用。头像清单存在5张只证明条目存在，不证明当前随机使用。

性能目标须在指定中档Android Chrome实体设备复核：每搜索片段<=4ms、每杆AI计算p95<=50ms、最坏<=100ms；超预算分片且保留合法保底动作，不用固定等待掩盖计算。60Hz设备活跃物理帧p95<=20ms，无机器人引发>50ms主线程长任务；若设备只能30fps须单独声明支持档位，规则仍按固定步长。拟人等待单独计时，初始建议可见等待0.6–1.8秒、可取消，不将它当CPU耗时或竞品基准。记录热机、设备、浏览器、盘面、样本数与长尾。连续20局后刚体/监听/任务无残留增长；稳定堆内存相对基线增长<=5MB为初始排查阈值，需排除GC噪声。

工期估计：假设一名熟悉当前混淆工程的Web工程师、一名兼职QA，现有素材可研究使用且无需大规模解混淆。P0生命周期/规则表/断网适配/日志约4–7工程人日，测试约3–5人日；P1策略与节奏约3–5工程人日、2–3测试人日；P2有限预演与设备优化另估3–6工程人日。合计仅为依赖上述假设的工作量，不是报价、排期保证或实际费用；复杂规则确认、授权和宿主适配另计。
