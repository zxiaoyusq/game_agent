本轮为 prototype 阶段的竞品只读研究，按用户明确范围交付研究报告，不制作游戏，不推进美术、代码或测试阶段。物理步长、碰撞、计分、成功失败、输入窗口、误差、界面布局及英文游戏文案均不属于本次研究交付；不能从未解码配置推定这些规则或数值。

## 可证联系与断点

归档与补证在 ELF 标识、decryptAES128 字符串地址和引用点上相容。结合操作者补证，可以提出原生方法名分支 → 0x2711b58 通用桥候选 → 0x27232e0 调用候选 → 指定 Java 类/签名的静态桥接解释；其中新增跳转及调用边仍仅为操作者报告。0x27232e0 的具体 JNI 职责、调用类型、参数转换和异常路径未独立确认。

签名 ([B[B[B)[B 只说明接收三个 byte[] 并返回 byte[]，不能确定三个参数依次代表输入、密钥和 IV。decryptAES128 的名称与算法字符串支持研究 AES/CBC 路径，但不替代 Cipher.init 的操作模式、参数来源与分支验证。辅助方法叫 encrypt 也不能单凭命名认定实际执行加密或解密。

尚缺的核心连接为：目标配置身份/读取位置 → 实际读取字节及可能的封装、切片、解压等变换 → 桥调用时的输入数组 → Java Cipher.init/doFinal → 返回数组 → 配置解析和应用。当前没有任何已读证据闭合这条数据流。配置文件长度可被 16 整除不证明 AES；.plist 后缀也不证明内容是 XML 或二进制 plist。

## 潜在调用点与优先级

1. 优先反查 0x2711cb0 的调用者，同时纳入 BL、B 尾调用、BLR/BR、函数指针及重定位；归档旧直接调用扫描不足以覆盖这些情形。检查调用前后寄存器、返回值、生命周期及错误处理。
2. 获取 0x2711b58 和 0x27232e0 完整相关指令，追踪类名、方法名、签名及三个数组的构造、顺序、长度和所有权；确认是方法查找/调用还是其他包装层。
3. 由 0x1e3f710 文件名短引用追踪实际消费者，不先把短范围定性为文件加载器；从 0x1e36818–0x1e3b6d8 及 0x1e41898–0x1e41b0c 追踪读文件、解析器、异步回调和桥之间的边。
4. 将 0x1c112cc–0x1c11440 与 0x1cbf2fc–0x1cbfc44 作为任务注册、下载分支研究候选，区分内置配置、缓存配置、下载配置及失败回退，避免把同名流程合并。
5. 若要追踪消费字段，可再研究 shotPowerLimits 的 0x18b09d4–0x18b15a4 及其已报告调用者 0x18b31fc；这只是下游字段线索，不能反推字段来自指定文件或加密桥。
