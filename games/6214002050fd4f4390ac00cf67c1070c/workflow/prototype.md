## 规则边界与保留的假设

确定修复目标：mode1中，被本杆犯规判定退回的本方普通棋不得覆盖待确认红球；该失败覆盖应使红球返场，且所有返场真实完成前不得终局或开始下一杆。其余模式保持现有分支，尤其不得把 `freestyleQueen` 的mode2策略直接套入mode1。

以下是本设计的兼容性假设，均不是竞品规则：

1. 无犯规的红球与本方普通棋同杆入袋允许覆盖，按本杆事件集合判定，与扫描顺序无关；当前扫描顺序下可发生同杆覆盖，但反顺序的预期属设计假设。
2. 红球单独合法入袋后，拥有者获得下一次覆盖机会；拥有者下一杆无合法本方进球或犯规，则返红球。对方棋不能替拥有者覆盖。
3. 本杆发生母球犯规时不允许覆盖，即使仍有其它普通棋事件；沿用当前代码本杆本方棋返场策略。未扩展其它犯规类型、罚球数量或欠罚规则。
4. 现有9颗目标、普通棋计1、终局胜负选取和犯规历史退棋规则不重写；只延后到状态与返场完成后执行原有终局判据。无普通棋得分的特殊终局政策、对方末棋进袋等未知项列为独立问题。
5. 暂停保留覆盖资格与事务，重开/离局使旧事务失效；超时放弃覆盖机会时返红球，不能将pending带给对手覆盖。

这些假设用于形成可实施方案，不代表已获新规则确认；实施若要求改变上述兼容政策，应在代码阶段前明确产品决定。当前报告无需为未知竞品规则暂停。

## 最小状态和算法

保留PIXI/Planck及现有交互，不迁移引擎、不改物理。新增仅mode1使用的小型规则状态及本杆账本；可以内联纯函数，不要求新依赖或全局重构：

- `queenState={phase:'board'|'pending'|'covered'|'returning',owner:null|'player'|'opponent',round,pocketTurn,coverTurn}`。`coverTurn`在获得实际下一杆时绑定，不能简单假定连续整数等于一次真实击球；timeout同样通过统一回合出口处理。
- `shot={round,turn,actor,queenPocketed,ownPocketedIds,opponentPocketedIds,foul}`，棋子事件按稳定id去重；原id在双方各自重复且返场新对象未必有id，故采用round内带类型的唯一token，并在返场保留token。账本不依赖 `_0x31089b`，该队列存在末局跳过入队分支（例如L5683–5684、5846–5847）。
- `settlement={round,turn,phase:'collecting'|'returning'|'committed',returnJobs,scoreCommitted,decisionCommitted,advanceCommitted}`。复用已有round/turn入口守卫；延迟回调另校验事务对象身份，避免旧回调完成新事务。

具体修改点：

1. 红球四袋路径只为mode1记录queen入袋和owner，不在动画回调建立规则事实；保留入袋表现。两方普通棋共8个袋分支在mode1只记录事件，不填勾、不清pending；mode0、mode2保留原逻辑。记录须在移除物理体前锁定类型/token。
2. 真实击球开始前建立账本，覆盖玩家L4046–4067和AI实际发射入口；不能在AI规划重试时清账本。母球扫描置foul时同步到当前账本，布尔值持续到停球。未发射的小力度取消不消耗覆盖机会。
3. `_0xbdafb3` 静止确认后冻结不可变shot及queenState快照，再按现有策略计算普通棋保留/返还、罚棋；有效覆盖数必须来自最终保留的本方普通棋token，不能用原始进袋数、动画完成数或 `_0x5ebd99` 代替。
4. mode1覆盖纯判定：已有pending且本杆是owner的覆盖机会时，`!foul && retainedOwnIds.length>0` 才covered，否则returning；board状态本杆红球入袋：foul→returning，无犯规且有有效本方棋→covered，否则pending。已covered时普通母球犯规不得撤回历史已确认红球。owner不匹配的异常pending保守转returning，不给新actor覆盖。
5. 同杆红球和普通棋使用集合判定；跨杆使用持久queenState及覆盖机会，不能每次准备回合重置queenState。红球单独合法入袋本杆结束仍pending并续杆，不能按“本杆没有普通棋”立即返场。
6. 返场任务全部完成、计分仅一次提交、queen决策提交后，再运行原有终局判据；pending/returning期间不得将“红球数组为空”等同于covered。pending允许拥有者下一杆，不允许终局。末棋无覆盖等既有胜负判定继续保留，但必须读取最终状态。
7. `_0x4268e2`在mode1仅作为pending/returning的兼容投影，规则单一来源为queenState；勾选图标由committed covered决定。`_0x5ebd99`在犯规优先处理后依据有效事件决定续杆，不承担queen状态。mode1分支绕过旧L3738返球逻辑，避免双返。

生命周期：准备输入 → 发射并锁定actor/turn → 物理扫描只收集 → 全部静止 → 冻结本杆 → 判犯规和有效进球 → 生成返场任务 → 等待全部真实返场 → 提交一次规则/HUD → 终局或进入下一杆。准备函数递增turn、重置shot只发生在事务committed以后；暂停不推进该链；重开/离局取消事务并清新状态。L5206–5217超时直接换人的出口也应在mode1统一处理pending归还，避免旁路。

## 返场重试、多球与动画

不直接扩大共享 `_0x1f3ae5` 的行为；为mode1事务提供返回成功/失败的放置包装，必要时抽出其候选生成部分。每项返场任务使用 `jobKey=round:turn:token:reason`，状态waiting/placed/cancelled。红球使用同一个round级queen token，确保同杆新入袋和历史pending不会各创建一份。

- 先确定合法位置，再创建/激活物理体并入数组；不可先置完成标志再找位置。仅在物理体、数组和表现对象均建立后标placed。返回false时不清任务、不清returning、不转covered。
- 可沿用原搜索候选次序；候选须对实际棋子圆形、当前母球及同批预留位置检验，同时在有效台面内且不在袋触发范围。计算统一使用世界坐标，不能混用带容器偏移的屏幕坐标。测试包装排除被放置对象自身，避免数组内自碰撞。
- 多球确定性串行提交：本杆普通返棋按稳定token顺序，然后历史罚棋（仅既有规则需要时），再红球；每成功一颗立即更新占用或预留集合，后续球不得选同点。测试调换任务顺序只要求守恒、不重叠及规则结果一致，不要求坐标完全一致。
- 每50ms有效游戏时间重试失败任务，最多20次为一批；未找到位置保持阻塞，不通过超时强制重叠落子或丢球。第20次后暂停自动重试并显示可诊断的 `Unable to place returned discs. Retry or restart.`，Retry重跑同一任务集合，Restart走既有重开；这是异常恢复设计，尚未实现。此受限搜索不能保证找到所有理论空隙，失败应可见。
- 动画超时可跳过表现直接尝试合法放置，不等于放置已完成；采用同一幂等finish。晚到onComplete不得再创建物理体或重复扣分。普通棋现有强制finish数组可复用，但须接入统一任务状态。
- 红球返场不能只依赖 `_0x404020`。从 `_carromPendingQueenPocket` 或HUD引用捕获旧sprite并取消相关Tweener；引用不存在仍可按queen token创建返场实体。取消入袋动画后禁止其旧回调重挂HUD/清新状态；所有4个袋的内外回调校验round和事务/queen版本。
- 暂停入口L2357及更新入口L5180表明暂停会停止更新和Tweener推进；重试使用同一游戏时间调度，不用独立墙钟强制提交。恢复继续当前任务；重开L1811清任务、递增round，旧回调只清理其自己的临时表现。

## 物理、输入和界面契约

既有循环为观察/摆母球/瞄准 → 发射 → 碰撞运动/入袋 → 停球结算 → 续杆、换人或结算。保留当前棋盘、上/下双方HUD、红球勾、瞄准及暂停布局，不新增关卡、成长或计时玩法。玩家界面默认英文，后续若新增异常提示用上述英文；本轮无页面变更，不声称已检查lang或最终文案。

已读L5989使用Planck固定步长1/60秒、速度及位置迭代10/10；L5998–6002 ticker累积补步，长帧未见本片段内补步上限。保留这些参数，长帧上限调整不纳入补丁。入袋为扫描距离≤20游戏单位的触发，不是仅靠碰撞contact；扫描顺序当前母球→红球→player→opponent，且扫描后才step。不得把数组或扫描顺序作为规则。圆形体、阻尼与碰撞原参数沿用，不为修规则改力度/袋口。

玩家输入窗口沿用L4024–4068：未暂停、玩家回合、可输入、匹配pointer，释放strength≥0.25才发射；结算/返场时关闭输入，重复释放仅一次，取消不结算。默认鼠标/触控保持当前转换。

验收误差为设计阈值而非已测结果：规则计数、owner、token、犯规及提交次数零误差；固定步长日志精确1/60；非临界初始位置扰动±0.5游戏单位、速度±1%仍应得到相同事件级结果；返场中心间距至少实际半径和减1e-6浮点容差（普通棋原搜索门槛32，最终以实际半径核验），边界同样1e-6，仅作数值比较容差。袋口边界另测20−0.01、20、20+0.01，不把跨阈值结果差异判成失败；不得用位置容差掩盖球数或规则不同。停球/动画耗时可随帧率变化，以事务事件最终一致为准；有效游戏时间30秒未完成物理或返场则报告失败/阻塞，不强判成功。
