# Carrom 最后一棋与同杆胜负边界复核

本轮为 prototype 阶段的原始 H5 基线只读规则审查，不制作新游戏、不修改游戏源码、不推进美术、代码或测试验收阶段。日期：2026-11-12；attempt=1。采用冻结 casual-game-production/SKILL.md 1.3.0 及本轮四份品类/框架资料，其通用生产要求按本次只读研究范围适用。

## 结论

原包 Disc Pool（模式 0）存在颜色处理顺序与入队条件耦合：双方仅余一子、同一逻辑步均位于袋口阈值内时，玩家数组先处理，玩家最后一子入队；随后对手最后一子因玩家数组已空而不入队。初始比分 8:8，隔离实验得到 9:8、玩家胜，与出杆方及四个袋口组合无关。跨逻辑步则先检测入袋的一方入队并获胜。这是原包实现事实，不是已确认的产品规则，也不证明竞品采用该规则。

原包在动画完成回调中加分，然后依靠固定延迟读取比分判断胜负，没有显式等待全部计分回调完成。人为提前结算的隔离实验可产生先换手、后到 9 分而未在该次回调结算的情况；这证明函数依赖回调顺序，不能证明原始 Tweener 在正常运行中实际会产生此逆序。

## 同杆与队列复现

核心循环为摆放母球→拖动瞄准/蓄力→释放出杆→物理运动与入袋收集→停止检测→队列动画/计分→终局或下一回合。这里“同杆”不等于“同一逻辑步”；同一杆内可跨多个逻辑步检测入袋。

状态映射：_0x209883=true 为玩家出杆；_0x4d3bf1 玩家分；_0x41f634 对手分；_0x31089b 待处理入袋队列；_0x530863 母球犯规；_0x5ebd99 当前方入袋续杆标记；_0x3231b3 Queen 数组。

可运行命令：node scripts/carrom-baseline-audit.cjs。脚本读取已核对 SHA 的研究副本，按行截取原始字符串解码器、两色入袋正文、结算、返子、距离和空目标函数，在 Node vm 中隔离调用。没有执行完整参考游戏；物理、PIXI、音效、平台上报和动画调度均为明确替身。

## 母球犯规单独分析

母球在 _0x49d791:4740–4830 检测距离 <=20 后设置 _0x530863=true、置 sensor，并在入袋动画完成时调用 _0x21acae。_0x21acae:2701–2754 为犯规提示表现，不直接决定扣分或胜负。

_0xbdafb3:3312–3347 对犯规杆中的 Queen 或当前方棋子安排返场，另一方棋子仍可走计分分支。3405–3408 在没有当前方入袋标记时调用 _0x464a16，随后清除续杆标记；因此犯规后不会因本方入袋续杆。_0x464a16:3052–3107 在当前方已有得分时立即扣 1，并异步生成返场棋子；已有得分 <=0 时直接返回，不出现负分。返场对象真正加入数组在动画回调中，本轮替身只完成第一批回调，未验证所有新建对象的完整物理生命周期。

关键交互风险：最后一子若因“另一色数组已空”未入队，它同样绕过队列内的犯规返场分支。此条件可由静态调用链确定，但现有 41 用例没有组合覆盖“双方最后子+母球犯规”、仅对手子入袋、零分犯规和多个本方子返场，不能把单独犯规用例视为这些场景已通过。终局判断先于后面的 Queen 返场/换手分支；Disc Pool 无 Queen，其他模式不能直接套用本轮结论。

## 物理、输入与可接受误差

原包 _0x49d791:5491 使用 Planck step(1/60,10,10)，随后 clearForces；_0x4bf21a:5499–5504 累积 delta，while(accumulator>1) 执行一个逻辑步，没有在该片段看到补步上限。入袋是步进前的中心距离 <=20 判定；棋子半径常量为 15（851 行），不把画面半径或袋口圆当作刚体碰撞验证。未执行 Planck 实际碰撞、高速穿透或快慢帧轨迹复现，摩擦及恢复系数未完整追踪。

输入入口 _0x36ab44:3655–3665 要求可瞄准、玩家回合且没有进行中的拖动，并含教程门禁；释放 _0x1e39ba:3667–3680 要求 strength>=0.25 才出杆，力度为 strength*100*1.25。更低力度不提交出杆。本轮不新增 UI，保留现有菜单、棋盘、比分、犯规提示和结算界面；不声称已核验其视觉呈现、默认语言或浏览器行为。

本次规则验收采用离散结果精确相等：队列成员、比分、胜者和回调次数不允许误差。未来物理实验建议固定初始状态、固定输入与 1/60 步长，采样同一逻辑步，先以位置 1 像素、事件时刻 1 步作为待确认容差；该值属于建议，未由真实轨迹标定。测试袋口距离 20±epsilon 的边界应与碰撞轨迹分开。

## 无需新增 UI 的修复与补测建议

1. 入袋收集按 shotId、pieceId 去重，全量记录后再统一处理；删除以“另一色数组是否为空”决定是否记录本子事件的耦合。保留既有动画与 HUD。
2. 在物理停止后，以出杆前快照和整杆事件一次计算返子、比分、胜者与下回合；动画只播放已提交结果。避免用动画完成回调作为唯一记分来源，避免用固定 1000ms 猜测计分完成。
3. 结算增加 lifecycle/shot 标识及结束幂等门禁，旧回调不得影响新局；_0x47e567 本身未见明确的已结算门禁，重复调用与奖励风险应补测，当前未证明自然路径一定重复触发。
4. _0x3d12d7 在候选数组空时返回显式无目标，由回合控制器选择结束、等待或受控恢复；禁止继续访问 undefined。
5. 以表驱动测试覆盖双方出杆、四袋组合、同一步/跨步、两种事件入队顺序、母球事件先后、零分罚子、双方最后子加母球、仅对手入袋、多个本方子、重复事件、重开旧回调及比分超过 9。合法终局谓词是否改为 >=9 须与业务规则一起确定，不直接以数值替换掩盖重复记分。
6. 补充使用原始 Tweener 的集成实验，重放不同随机动画时长和帧增量，验证所有记分完成后才结算；现有逆序替身实验只用于暴露依赖，不作为真实竞态已发生的证据。
